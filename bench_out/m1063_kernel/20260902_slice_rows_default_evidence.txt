# M10-6.4 默认 slice_rows 32→16 证据（2026-09-02，i9-9900K 8C16T）

## 动机：2K 解码瓶颈剖析
- sample 采样（bench_out/m1063_kernel/profile_dec_2k_product.txt）：
  t8 下 worker 有效利用率 ~56%，其余为帧间串行等待（barrier 尾部失衡 + demux）。
- 根因：34 带（sr32）/8 线程 = 4.25 带/线程，带内 DC/熵链路串行 → 尾部失衡吞掉近半并行度。
- 线程扩展（2K sr32 hq 码流，内核口径）：t1 60.96 / t2 121.11 / t4 218.95 /
  t8 257.11 / t12 246.35 / t16 245.72 fps —— t8 后饱和，确认是调度粒度而非线程数问题。

## slice_rows 粒度扫描（2K hq rate，内核解码）
