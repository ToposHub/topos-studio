# 阶段4 开放项关闭：t8/t16 静机交错对复验 + 默认线程口径追认（2026-09-02 晚，i9-9900K 8C16T）

## 背景与问题重述
- 昨日 parse 否证文档留下开放项：负载 15~36 下 t16 批量 5/5 交替对胜 t8
  （中位 +14%），与阶段4 单点（t16 362 < t8 379，非成对、加负载窗口）矛盾，
  静机复验前不动默认。
- 复查源码发现**默认口径三处文档与代码分叉**：
  - tpool.c thread_default：`def = ncpu; clamp(TC_SLICE_MAX_THREADS=16)` →
    本机默认**已经是 16**。M3 时该表达式 = min(8,ncpu)（当时上限 8）；
    M10-6 仅提上限，注释未同步 → 16 逻辑核机默认静默 8→16。
  - tpool.h 头注释仍记"默认 min(4, ncpu) 不变"（M3 前口径）。
  - topos_binding.slice_threads docstring 同记 min(4, cpu)。
- 产品侧暴露面：导出显式 min(8,cpu)、后台缓存显式 1——**只有解码路径
  （播放/scrub，ToposMediaSource 等）吃 native 默认**。即：产品解码一直
  跑在 16 线程上。本次复验即为该默认定去留。

## 方法
- 机器：重启后 4 分钟起测（开机 Spotlight 索引退场后），全程 1min load
  ≤ 5，无昨日 15~36 的重负载源；测量以进程对交错抵消共同漂移。
- 工具（已入库 tools/bench_t8_t16_paired.py）：每对两个独立子进程
  （env TOPOS_SLICE_THREADS 8/16），序平衡（偶对 8 先、奇对 16 先）；
  子进程预取全部包 bytes → 输出平面一次分配 → 1 遍预热 + 5 遍计时，
  报中位 fps。批大小 2K=8 / 4K=4（阶段4 最优）。
- 码流：阶段4 产物 topos_vs_ref/20260902_065735_2k（36 帧，27 slice/帧，
  批 216 任务走栈）/ 20260902_065819_4k（24 帧，51 slice/帧，批 204 走栈）。

## 插曲：复验首版脚本段错误（非原生缺陷）
- 症状：约隔一个子进程 SIGSEGV，崩点固定 dec_frames_core_impl+2175
  （finalize 的 conceal 计数循环，status_out 指针近空，故障地址 0x36）。
- 取证：macOS 崩溃报告 4 份同栈；纯 C 复现器（/tmp/batch_crash.c，公共
  API 同形态 40 遍 ×6）零崩溃 → 与 Python 侧相关。
- 根因：**脚本 bug**——make_views 仅存 numpy 数组地址不持引用，循环重绑
  arrs 后平面缓冲被释放，worker 解码写入已释放堆内存，踩坏后续批次
  tc_alloc 的 reqs/views（finalize 读到垃圾 task_base → 崩）。绑定契约
  本就要求调用方保活（产品平面池持 entry.arrays；昨扫描写法是单个持久
  大数组）。修复=keep 列表保活，3×40 遍全绿。
- 落地：tools 脚本内置保活；topos_binding.make_views docstring 补保活
  警示。原生库无改动。

## 结果（12 对/分辨率，成对 t16/t8 比值）
- 2K bs8：中位 t8=486.7 / t16=484.6，比值中位 **0.998**（打平；
  全对 [1.023 0.998 1.000 1.070 0.992 1.015 0.998 0.994 0.994 1.007 0.997 0.964]）
- 4K bs4：中位 t8=114.8 / t16=117.1，比值中位 **1.020**（**12/12 全正**；
  t16 每对 116.1~117.4 极稳，t8 有两对深坑 97.6/104.7）
- 对照（昨日负载 15~36）：t8 380.7 / t16 481.3，5/5 对 t16 胜（中位 +14%）。
- 阶段4"t16 362 < t8 379"未复现——该点为加负载窗口的非成对单点，已被
  本静机成对数据取代。

## 决策
1. **默认维持 min(ncpu, TC_SLICE_MAX_THREADS)（本机 = 16），不改代码**：
   静机 2K 打平、4K +2.0% 且方差更小；负载下 +14%（解码路径是默认的
   实际消费者，且 t16 鲁棒性更好——t8 偶发 −10~15% 深坑）。
   M10-6 提上限时默认"被事故升到 16"，本次以成对证据追认为正确值。
2. 编码侧注记（不阻塞）：M10-6 实测 8P/16L 机编码 t8/t16 = 7.93/7.28
   （−8.2%，负载 5~6）。产品编码路径显式 min(8,cpu) 不受默认影响；
   SDK 编码用户在 16L 机可用 TOPOS_SLICE_THREADS=8。开放项：编码默认
   是否按物理核数分化（需 per-context 线程数 ABI，V2.1 再评估）。
3. 文档三处陈旧口径修正：tpool.c thread_default 注释、tpool.h 头注释、
   topos_binding.slice_threads docstring。
4. 顺带记录：静机（重启后）2K 内核批解 ~486fps，显著高于昨日"永久脏机"
   的 429（阶段4 验收数字）；ProRes 同窗基线 448 亦为脏机口径，公平比值
   需静机重测 ProRes（后续候选，不改变已锁验收记录）。
