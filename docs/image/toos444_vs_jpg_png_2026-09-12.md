# topos 444（GBR 12-bit）vs JPEG vs PNG8/16 三方对照（实测）

日期：2026-09-12 · 工具：`tools/bench_toos444_vs_jpg_png.py` ·
数据：`tools/toos444_vs_jpg_png_2026-09-12.json`（prores422HQ / DNxHR HQX 各 2 帧 × 2K/4K）
口径：GBR 直存（无 YUV 变换/无色度二次采样，平面序 G,B,R——已用可区分图案
探针钉死）；RGB8 参考（与 422 对照同源）；8-bit 内容 ×16 入 12-bit 容器；
PNG16 = cv2/libpng level6（12-bit 内容的正确归档对手）；JPEG = PIL/libjpeg。

---

## 一、阶梯（双素材×2 帧均值）

### 4K 2160p

| 编码 | PSNR(RGB8) | 体积 | 编码 ms | 解码 ms |
|---|---|---|---|---|
| topos-444-high | 51.73 dB | 7.26 MB | 60.8 | 35.5 |
| topos-444-ultra | 51.81 dB | 7.89 MB | 44.5 | 33.7 |
| jpeg-q95-444 | 50.20 dB | 1.60 MB | 129.9 | 83.2 |
| jpeg-q100-444 | **57.90 dB** | **3.87 MB** | 161.6 | 109.3 |
| png8-lossless | 无损 | 5.91 MB | 628.1 | 111.0 |
| png16-lossless(12bit) | 无损 | 7.06 MB | 2254.6 | 201.8 |

2K 1080p 同构：topos 51.7~51.8dB / 2.06~2.23MB / enc 14.3~15.5ms / dec 11.6~11.8ms；
JPEG q100 57.1dB / 1.16MB；PNG8 1.60MB；PNG16 1.93MB / enc 562.7ms / dec 54.1ms。

## 二、结论（对照「444 同样碾压 JPG 与 PNG？」）

1. **速度：对 PNG 仍碾压，对 JPEG 优势收窄为 2~3×。**
   vs PNG16（12-bit 归档对手）：编码 **37×**（44.5 vs 2254.6ms）、解码
   **5.7×**；vs PNG8：编码 10~17×、解码 3~6×；vs JPEG q100：编码 2.4~3.6×、
   解码 2.4~3.3×。PNG16 的 zlib 大缓冲编码（2.3s/帧@4K）使速度差距比
   422 对照更夸张。
2. **画质：档位带仍在「JPG 与 PNG 之间」，但预设档位不打 PSNR 竞赛。**
   topos-444 预设（qp58/63，444 Compact 矩阵，视觉无损定位）= 51.8dB；
   JPEG q100（接近透明的 8-bit 极限档）= 57.9dB 且体积只有一半——**在
   8-bit 内容、PSNR 口径下，JPEG q100 是更小的更高质量选择**。topos-444
   需要更低 qp（`--qp 28` 数学无损档）才进入 JPEG 到不了的区域。
3. **体积：topos-444 ≈ PNG16（7.26 vs 7.06MB@4K），且二者都显著大于
   JPEG q100/PNG8**——12-bit 容器存 8-bit 内容有固有膨胀（系数 ×16），
   双方对称承担。8-bit 归档的体积王仍是 PNG8（无损且更小）。
4. **444 的真实价值 = 12-bit 保真 + 速度**（本基准素材只有 8-bit 内容，
   12-bit 优势按结构论证）：JPEG/PNG8 结构上存不了 12-bit；PNG16 能存但
   慢 37×/5.7×；topos-444 档位带 51.8dB 视觉无损、12-bit 域往返
   57.6~61.4dB（远超视觉无损门槛），面向 10/12-bit 高位深源（RAW/EXR
   衍生）的归档与调色中间片。

## 三、与 422 对照（toos_vs_jpg_png_2026-09-12.md）合并的定位结论

| 场景 | 建议 |
|---|---|
| 快速预览/交互（10-bit 422 足够） | 422-low/medium（体积最小、全链最快） |
| 视觉无损归档（10-bit） | 422-ultra：55.5dB、≈PNG8 体积、编码 14× 快于 PNG |
| 高位深（10/12-bit）工作流中间片 | 444-high/ultra：12-bit 保真、≈PNG16 体积、编码 37× 快于 PNG16 |
| 位精确归档 | PNG（无损）或 topos `--qp 28`（数学无损档） |
| 极小体积 8-bit 交付 | JPEG q95-444 仍有每字节 PSNR 优势（8-bit 封顶 + 有损为代价） |

## 四、口径注意

- 8-bit 内容 ×16 入 12-bit 容器的固有膨胀对 topos/PNG16 对称；真实
  12-bit 源的绝对体积会高于本表（双方同向）。
- 444-high（qp63）编码慢于 ultra（qp58）为实测事实（稀疏块分布下
  token 化路径差异），量级 8~37%。
- PSNR ≠ 感知；GBR 直存无色度损失，PSNR 已接近纯编码损失口径。

## 五、追加诊断：「444-ultra 不如 422-ultra？」——两个原因，都可量化

prores 4K 单帧对照（同源 RGB8 参考域 PSNR）：

| 配置 | PSNR | 体积 |
|---|---|---|
| 422-ultra（10-bit **qm0 flat** qp58） | 56.15dB | 4.70MB |
| 444-ultra 预设（12-bit **qm2 Compact** qp58） | 52.05dB | 6.67MB |
| 444 + qm0 flat（12-bit qp58） | **55.31dB** | 14.26MB |
| 444 + qm1（12-bit qp58） | 52.32dB | 8.55MB |
| 444 qm2 **qp28**（数学无损） | ∞ | 28.92MB |
| 444 qm0 **qp28**（数学无损） | ∞ | 35.85MB |

1. **主因 = 量化矩阵档位差**：444-ultra 预设用 qm2（444 Compact，ADR-I011
   按 12-bit 内容 ~4.5MB/1080p 锚点调的「紧凑视觉无损」），比 422-ultra 的
   qm0 flat 粗。同 qp58 下把 444 换成 qm0，PSNR 52.0→55.3dB 追平
   422-ultra——代价是体积 6.67→14.26MB。
2. **次因 = 12-bit 容器固有成本**：同 qm0 同 qp58，444/12-bit（55.3dB@
   14.26MB）比 422/10-bit（56.2dB@4.70MB）贵 3 倍体积——多出的钱买的是
   无色度二次采样 + 12-bit 深度。
3. **感知口径**：52.0dB 与 56.2dB 都远超视觉无损门槛（≈50dB），两者
   人眼均不可分辨——「不如」只在 PSNR 数字与体积上，不在观感上。
4. **选型含义**：8/10-bit 内容且 4:2:2 可接受 → 422-ultra 是更优解
   （更小、同观感）；444 档位给 10/12-bit 源与无色度损失需求；要 444
   拉满保真 → `--qmatrix 0`（+3 倍体积）或 `--qp 28`（数学无损，29~36MB@4K）。
   档位预设是否重调（444-ultra 换 qm1 等）属 ADR-I011 修订决策，本文只
   登记实测。

## 六、追加：追平代价精算 + 内容类型反转（444 的主场）

### 6.1 在 422 原生实拍素材上追平 422-ultra 的代价（4K qp/qm 扫描）

| 素材 | 422-ultra 基准 | 444 追平点（最小体积） | 倍数 |
|---|---|---|---|
| prores422HQ | 56.15dB @ 4.70MB | qm1 qp45 = 59.03dB @ 18.53MB | 预设 2.8× / 422 的 3.9× |
| dnxhrhqx | 54.80dB @ 6.81MB | qm1 qp45 = 56.39dB @ 21.66MB | 预设 3.2× / 422 的 3.2× |

**「翻一倍」不够——是 3~4 倍**：12-bit 容器膨胀（2~3×，结构性）+ 422 原生
素材让 444 的零色度损失优势无从兑现（双重叠加）。无损膝点附近 PSNR 陡升
（qm2 qp50→45：53.4→56.1dB），追平点对 qp 敏感。

### 6.2 RGB 原生内容反转（合成 1080p 锐利彩条/文字状边缘）

| 配置 | PSNR | 体积 |
|---|---|---|
| 422-ultra（10-bit qm0） | 54.66dB | 0.46MB |
| 444-ultra 预设（qm2） | **54.72dB** | 0.69MB |
| 444 qm0 | **∞（数学无损）** | 0.74MB |

422 的 4:2:2 色度二次采样在锐利彩色边缘上的损失，恰好吃掉其矩阵优势——
444-ultra 预设**追平** 422-ultra；444+qm0 直接数学无损且体积可控。

### 6.3 最终定位

- 422 原生实拍素材 → **422-ultra 最优**，444 纯浪费（无优势可兑现 + 容器税）。
- RGB 原生（图形/文字/屏幕录制/合成）→ **444 主场**：预设即持平且无色度
  损失，qm0 可数学无损。
- 高位深源（10/12-bit）→ 只有 444 能装（422 上限 10-bit）。
- 「画质持平」的体积代价强烈依赖内容类型：3~4×（422 原生）↔ ~1×（RGB 原生）。

## 七、行业对照：ProRes 422HQ vs 4444 是否也存在「444 容器税」？

工具：`tools/bench_prores_4444_vs_422hq.py`（PyAV/libav prores_ks，预设对预设）
数据：`tools/prores_4444_vs_422hq_2026-09-12.json`

### 7.1 场景 A：422 原生实拍素材（4K，10-bit 域逐平面 PSNR vs 源）

| 编码 | 体积 | Y / U / V PSNR |
|---|---|---|
| 422HQ | 3.14~3.42MB（602~657Mbps@24） | 60.1~65.1 / 63.0~68.3 / 61.6~68.2 |
| 4444 | 4.02~4.59MB（771~880Mbps@24，**+28~35%**） | 63.4~67.3 / 64.3~68.8 / 61.3~67.9 |

**结论：ProRes 没有同样的问题。** 4444 在 422 素材上多收 ~30% 码率但
**画质同向提升**（Y +2.4~3.4dB）——因为 ProRes 档位是码率目标，4444 的
增量预算足以覆盖容器开销还有剩。topos-444 预设的问题（画质反降）是
ADR-I011 的 qm2 紧凑矩阵选择 + 12-bit 容器税叠加的**本库特有现象**，
不是 444 形态的固有规律。

### 7.2 场景 B/C：RGB 原生内容（1080p 合成）

| 内容 | 422HQ | 4444 |
|---|---|---|
| 4px 彩条（温和） | 54.66dB @ 0.60MB | 52.39dB @ 0.89MB（平手区，均视觉无损） |
| **1px 交替互补色（色度奈奎斯特极限）** | **9.40dB（结构性毁坏）** | **50.32dB @ 0.91MB** |

「444 只在色度密集内容上赚」的原则与 topos 完全一致；极端色度内容下
4:2:2 是结构性无法表达（混叠），4444 稳定交付。

### 7.3 合并定位（topos + ProRes）

1. 「444 更贵」两边都真，但「444 画质反降」只有 topos 预设有——修复
   方向即 §五 登记的 ADR-I011 重调（444 预设换 qm1/qm0 或加 max 档）。
2. 444 的收益域 = 色度密集 RGB 原生内容 + 高位深；422 原生素材上
   ProRes 用码率换画质、topos 可用 `--qmatrix 0 --qp 45` 达到同样效果
   （代价曲线见 §6.1）。
