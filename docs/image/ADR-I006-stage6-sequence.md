# ADR-I006：阶段 6 —— 图片序列与有界预取

日期：2026-09-05
状态：已接受
前置：ADR-I001..I005

## 决策与交付

| 项 | 决策/执行 |
| --- | --- |
| 帧号语法 | `<prefix><frame><suffix>`；十进制帧号（支持负号）；padding 补零作用于数字位（负帧号 `shot.-012` ⇄ pad=3 互逆） |
| 枚举 | 目录扫描按帧号升序；start/end/step 过滤；空洞不进入列表；step ≥ 1 硬校验 |
| 缺帧策略 | 冻结三种：`skip`（默认，跳过）/`error`/`hold`（保留前一已解码帧，且不伪造帧号——返回实际来源槽位）；**绝不伪造成功** |
| 文件被替换 | 读取时实时 `os.stat` 指纹（size+mtime_ns），与扫描态不一致即刷新槽位并绕过缓存重新解码；文件消失按策略处理。**修复实测**：初版用扫描态指纹导致替换后命中旧缓存（测试抓到后修正为实时指纹） |
| 预取 | 单后台线程 + generation cancel：seek/换向/close 均使旧代失效，旧代 worker 立即退出且结果不落新帧；窗口 = prefetch_depth（有界） |
| 缓存 | 只缓存解码平面（encoded packet 不缓存）；LRU 字节记账硬上限；单帧超预算直接不缓存（不无界增长）；GPU texture cache 属渲染层既有 deferred-release，不在本层 |
| CPU 订阅 | 帧级并行=1（预取单线程）× slice 级并行=codec 进程预算（TOPOS_SLICE_THREADS）——不过度订阅 |

## 验收

- 序列 8 帧顺播/反向/取消：预取线程至多 1 个、close 后收敛 ✅
- 队列/内存有界：窗口 ≤ depth、平面缓存 ≤ 字节预算、超预算单帧不缓存 ✅
- 缺帧策略可配置且不伪造成功 ✅
- 文件被替换：指纹失效重解码（测试锁定）✅
- 15/15 测试通过 ✅

## 已知限制（阶段 7 再测）

- 冷/热缓存与 NVMe/NAS 分位数矩阵按 benchmark_protocol 在阶段 7 实测；
- 1000+ 帧长序列压测列入阶段 12 收口（本阶段以合成 8/32 帧验证不变量）。
