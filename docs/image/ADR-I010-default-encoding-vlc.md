# ADR-I010：`toos encode` 默认编码策略——V2 VLC 熵编码 + 视觉无损 qp

日期：2026-09-05
状态：已实施（门禁全绿）
关联：ADR-I008/009、`SDK.md` §5/§7、`perf_report_stage7.md`

## 背景

用户产品目标：**默认 10-bit（4:2:2）、体积接近 PNG 8-bit、解码快；未来扩到
4:4:4 12/16-bit**。实测（1080p25 实拍 H.264 素材前 2 秒 50 帧，i9-9900K
macOS，release 构建）发现旧默认的体积远离目标：

| 配置（旧默认） | 单帧体积 | 说明 |
|---|---|---|
| V1 Rice + qp28 + GBR 4:4:4（16-bit 容器平面） | 12.3 MB | 对 12.4 MB 裸平面压缩率仅 ~2% |
| PNG 8-bit L6（同素材 RGB 8-bit） | 2.04 MB | 对照组 |
| PNG 16-bit L6 | 2.37 MB | 位深对齐对照组 |

诊断（合成内容矩阵 + `tc_frame_encode` 三熵模式对照，数据见下）确认这**不是
bug**，而是策略问题：codec 的 spec v2 canonical VLC 熵编码（M9/ADR-C027，
含 AQ/RDO 编码器内部策略）早已存在且被视频链使用，但 image CLI 从未启用；
且 GBR 4:4:4 16-bit 容器输入让"裸体积"先天翻倍。

## 实测依据（4:2:2 10-bit，同一实拍素材）

熵模式对照（qp30，1080p 一帧）：

| 熵模式 | 包大小 | 相对 |
|---|---|---|
| V1 Rice（旧默认） | 7.89 MB | 基准 |
| V2 + Rice（parity 锚） | 6.87 MB | −13% |
| V2 + canonical VLC | 6.87 MB | −13% |

VLC + AQ + RDO 的 qp 扫描（两帧实测，PSNR 以 10-bit 满幅 1023 计）：

| qp | 帧0 / 帧25 体积 | PSNR | 8-bit 源舍回失配 |
|---|---|---|---|
| ≤49 | 4.45~4.75 MB | ∞（数学无损） | 0 |
| 52 | 4.02 / 4.32 MB | 96~100 dB | **0（逐位无损）** |
| 55 | 3.56 / 3.87 MB | 78~80 dB | 5 px |
| 58 | 3.06 / 3.37 MB | 68~69 dB | 1223 px（0.03%） |
| 61 | 2.45 / 2.78 MB | 62~63 dB | 2.7% |

关键洞察：素材源为 8-bit 时，10-bit 容器低 2 位是幻影位。**qp52 解码值舍回
8-bit 后与源 4,147,200 采样逐位一致**——误差只落在幻影位，不伤真实内容；
qp58 仅 0.03% 像素 ±1（PSNR 68 dB，远超视觉无损阈值）。

速度（release，含 CI 噪声的保守值）：VLC 模式解码 **10~14 ms/帧**（PNG 8-bit
解码 31.5 ms，16-bit 56 ms）；进程内编码 16~33 ms。"解码更快"的产品约束保住
且扩大了优势。

## 决定

1. **`toos encode` 默认 = spec v2 canonical VLC**（`cfg.reserved[0]=1`），
   并默认启用 AQ/RDO（`reserved[1]/[2]=1`，编码器内部策略，m7 路径带确定性
   降级；解码侧无新要求，位流恒为合法 V2-VLC）。
2. **默认 qp = 58**（视觉无损档）。质量档锚点写入 usage：
   qp28 = 数学无损；qp52 = 8-bit 源无损；qp58 = 默认；qp61 = 体积优先
   （≈PNG 8-bit 体积）。
3. **`--entropy v1` 逃生门**：逐字节退回旧 Rice 位流（兼容旧工作流）。
4. CLI 完成行显式报告 `entropy vlc|v1` 与 qp（诊断面，测试钉死）。

不采用/留待后续：

- `--target-bytes`（按目标体积的 qp 搜索）：公共 API `tc_frame_encode_sized`
  的精确位计数按 Rice 推导，与 VLC 组合未经验证，本轮不做；
- 旧默认 GBR 4:4:4 路径不受影响（`toos_tools.py` PNG↔toos 仍显式传
  `--pixel-format 2 --qp 28`，PNG 互转保持无损默认）；
- 视频→toos 序列的推荐流（ffmpeg → 4:2:2 10-bit raw → CLI 默认）写入 SDK §5。

## 影响

- 体积：同素材 4:2:2 10-bit 序列 **12.3 → 3.28 MB/帧（−73%）**，为 PNG 8-bit
  的 1.6×（qp61 档可达 ≈1.2×）；解码 13.9 ms/帧，比 PNG 快 2.3×。
- 兼容性：读路径不变（V1/V2 全支持）；旧文件照常解码。写出的新默认文件
  `IDSC.payload_major=2`（spec §6.1 交叉核对第 10 项天然满足，deep validate
  通过）。
- 门禁：ctest debug/ASan/UBSan 57/57 ×3、pytest image 62（新增 5 项默认策略
  钉死：8-bit 源精确、qp52 位精确、v1 逃生门、VLC<V1、默认 qp 报告）、
  check_exports 216≥36 全绿。

## 未来（对齐用户路线图）

- 4:4:4 12-bit（XQ）与 16-bit 容器：V2 码本已按 pf/bd 全枚举开放
  （ADR-C027 D-6）；qp 档位需按位深重标定后再定默认。
- 熵编码进一步逼近 PNG 体积（方向：帧内方向预测 / 上下文自适应算术编码）
  属独立性能课题，另行立项。
