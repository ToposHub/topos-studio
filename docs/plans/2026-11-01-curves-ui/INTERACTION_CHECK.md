# 曲线工具实机交互检查

日期：2026-11-01（Asia/Shanghai）。

## 实际操作

- 打开用户运行的 Resolve Color 页面，操作预览下方播放条，从原位置向前拖动并松手，观察视频与曲线背景直方图。
- 原 Topos 窗口读取数次超时，随后原进程已退出。使用测试工程 `2K_h264.topos` 的 `/tmp` 副本启动当前代码，避免覆盖原工程。
- 在修复版 Topos 切换至 Color，显示 Curves；将预览播放条从约 25 秒拖至约 9 秒，松手后视频和背景直方图更新。操作播放及暂停，窗口可继续交互，检查时曲线未停留在黑屏。
- 轮廓线修改完成后再次重启验证实例，查看 Color 页实际宽画布、YRGB GPU 纹理与轮廓线显示；最终版本已加载到该验证窗口。

## 由对照与诊断发现并修正

1. 拖拽预览与播放状态不同，原先只检查播放状态不足以冻结背景直方图。现补充 scrub 开始/结束，且先冻结再暂停，防止暂停回调提前发起分析。
2. 非阻塞 tryLock 跳过 blit 时，Qt 默认会丢弃 FBO，可能出现黑闪。改用 PartialUpdate；无帧/clear 时显式清空，防止残留旧图。
3. 父画布 paintEvent 更新透明子覆盖层，会反复触发重绘。移除该 update，保留正常 Qt 子控件重绘机制。
4. 较高工具行下固定最小宽度仍可能使画布接近正方形。除提高基础最小宽度外，按工具高度提高画布与面板的最小宽度。
5. 用户进一步澄清“连续”指轮廓线粗细一致：原先以纵向距离计算线宽，且固定大小纹理被非等比缩放。改为欧氏像素距离轮廓、实际物理像素尺寸的专用纹理，以及 DPR 对应的 1 个逻辑像素线宽。通过实际 GPU 对平缓与陡峭段的垂直线宽比较检查。

## 验证边界

- CUA 的 drag 返回时鼠标已松开；前后静态截图不能证明拖拽中每一帧都没有瞬时黑闪。对此另外用真实 Cocoa QOpenGLWidget 测试：在绘制出一帧后连续 5 次模拟 mutex busy，读回 Qt 自身 FBO 确认像素保持；随后 clear 确认旧像素消失。GPU 回读仅在测试中使用。
- 另测空闲曲线 paint 次数不持续增长，明确排除父子覆盖层的重绘循环。
- 自适应最小宽度经过 UI 几何回归，并在最终版本重启后的 Color 页面查看了宽画布显示。
- 未改变 Resolve 调色参数，未将测试操作写回用户原工程。
