# 混音页片段编辑实测与后端实施计划

2026-11-21 · Topos Studio

混音页生产片段编辑器已经有可用的后端。当前代码从 `ProjectClipEditor` 经窗口控制器把整段增益、帧级淡化、采样级字段、单端曲线、处理栈和改时长事务写入活动时间线。已有处理栈 DSP、预渲染缓存、实时混音、成片音轨和 Stem 的消费路径。实际工作的重点是把现有链路对齐，补齐边界、失败回退和物理音频设备验收。

审计范围是从混音页打开真实音频片段和源素材的生产入口。效果器注册和交付的已有基线见 [片段编辑实施进度](2026-11-18-clip-editor-and-mixer-roadmap-status.md) 和 [影视声音后期完成报告](2026-11-19-film-post-audio-audit-and-roadmap-status.md)。先看下表的 **P0-1 至 P0-3**，它们中存在峰值误报、静音声道串音或试听与交付不一致的风险。

## 一、用户素材实测

本地读取三份 MP3，原文件均为 44.1 kHz、立体声、容器报告 86.913 s。使用测试宿主加载真实混音页 dock，在 24 fps 序列打开各素材源区间 `[10,15)` 秒。三段分别生成 `float32[2,240000]` 的 48 kHz 工作 PCM 和非空频谱。静音选区 `[0.6,4.4)`，检查两端之外保持原样、中间区域确为零、撤销逐样本恢复、重做再次静音。

| 素材 | 原始切片峰值 dBFS | 首次标准化到 −6 dBFS 后实测 | 同范围改到 −3 dBFS 后实测 | 基础加载、频谱、静音和撤销/重做 |
| --- | ---: | ---: | ---: | --- |
| 地下城堡人声.mp3 | +0.904 | −5.996 | **+3.904** | 通过 |
| 地下城堡音乐.mp3 | −7.281 | −6.001 | **−4.281** | 通过 |
| 地下城堡音效.mp3 | +1.189 | −6.001 | **+4.189** | 通过 |

峰值取处理后的浮点 PCM 绝对值最大值。浮点解码峰值可以超过 0 dBFS，这里保留该观测。正值说明后级如果直接量化为整数 PCM，可能出现削波。表中的数值来自解码样本，未以响度计或实际音箱主观判断替代。

三份素材的 UI 复测均通过。复测顺序为加载→静音→撤销/重做→两次标准化→撤销回到原始 PCM→框选后仅左声道 −6 dB（右侧逐样本不变）→首个包络节点→150% 预览与取消→淡化曲线与撤销。自动化通过 Qt 离屏宿主验证模型、界面事件和送往试听会话的 PCM。

另用三份素材分别做交付抽查。给同一五秒切片施加 −12 dB 整段增益与相同的中段静音栈，调用成片混音入口生成 Master PCM，通过生产 Stem 写入器实际写出 48 kHz/24-bit WAV 并重新解码。三个文件均为双声道、每声道 240000 个样本，静音区间为零，解码 WAV 与成片 Master PCM 的最大绝对差均为 `1.19e-7`，相当于 24-bit PCM 的一个最小量化步长。抽查覆盖成片音频渲染与实际 Stem 文件。物理声卡、耳听 A/B 和完整成片容器验收见 P2-1。

## 四、逐项实施与验证

### P0-1 重复标准化和响度匹配

**复现与根因**。生产面板以现行处理后 PCM 测量，`upsert_step` 随后用相对该 PCM 的新增益替换旧步骤。以音乐为例，原峰值 −7.281，首次实效增益约 +1.28 dB。第二次计算约 +3 dB 并替换原步骤，落点变为 −4.281。响度匹配同样先在含旧步骤的数据上测量，再把旧 `range_gain` 换掉，还要验证 dBTP 上限的实际效果。

| 步骤 | 实施方法 | 验证方法 |
| --- | --- | --- |
| 1. 固化目标与身份 | 给匹配结果保存稳定操作身份，匹配键包含处理器、操作、半开区间和声道集合；同一匹配更新保留已有 step ID 和排序。为旧工程无操作身份的响度步骤制定识别和迁移方法；保留其他历史 range_gain。确定替换和旁路后重新启用的语义。 | 新旧工程往返；同区间手动增益、峰值标准化和 LUFS 并存；单声道与双声道、不同选区、不同目标更新测试。 |
| 2. 计算正确的基准 | 按既有 render prefix / suffix 机架顺序，渲染到目标步骤的插入点；替换时移除本次要替换的系数。优先复用原 PCM、已有预渲染基底及块处理器。如果目标步骤之后有非线性处理，分别定义插入点目标和最终输出读数；若后级会改写目标，明确呈现。 | 恒定 0.25、正弦和含噪音频依次做 −6→−3→−12 dBFS；插在滤波、降噪前后各一例；验证 A/B、旁路和选区变动不污染测量。 |
| 3. 正确处理峰值上限 | 用 `loudness_analyzer` 按支持布局的 BS.1770 规范测量 LUFS 和 dBTP；限制所请求的增益，必要时允许进一步衰减以满足 true peak。静音、少于测量窗口、不可用后端和选区边缘防爆音分别给明确状态。 | 含帧间峰值的正弦、长静音、反极性立体声、过载素材、400 ms 边界；独立测量 true peak。检查临界目标不会反复加入相同增益。 |
| 4. 核对实测再更新界面 | 创建候选步骤、用同一渲染路径重新生成本次影响范围并复测，验过之后用既有命令提交。将请求键和工程 revision 带回 UI，过期结果不写回。界面展示实测值或受 true peak 限制的结果。 | 三段 MP3 的最新目标误差建议 ≤0.15 dBFS；稳态 LUFS 目标误差建议 ≤0.2 LU，达不到时确认峰值上限生效。一次撤销恢复旧步与实际 PCM，一次重做重现。 |

### P0-2 源解析、声道和多声道重采样

**已单独复现**。44.1 kHz 四声道 WAV 只给源 CH1 振幅 0.25，转 48 kHz 后只得到 4458 个样本，选中的原静音声道出现约 0.281 峰值；同率解码该声道为零。当前多声道循环共用一个状态型 mono resampler。片段取样 worker 也没有传 `channel_map`，预渲染计划已传，导致未处理片段与渲染基底可能不同。

| 步骤 | 实施方法 | 验证方法 |
| --- | --- | --- |
| 1. 解析统一规格 | 将实际音频流身份、源布局、patch 选道、绑定来源、采样区间、指纹、反向标记纳入不可变规格和解析接口，缓存键覆盖影响样本的全部信息。重连、同路径替换、patch 或流切换均更新请求。 | 两轨 MP4 或双音频流容器、绑定外部 WAV、独立声道 patch 的 one-hot 测试。变更后缓存应失效，旧回调不得覆盖。 |

### P1-1 变速、频谱修复、降噪及变长后的坐标

**代码发现与复现**。当前 `resolve_clip_audio_spec` 读取源区间，原生变速的输出域在独立试听未完整映射。变速预览直接在原 PCM 上拼接后再应用部分栈，提交走长度事务。某些预渲染步骤存在变速/倒放/长度约束，多处通过硬编码 guard 控制。已用左右相同的 2 kHz 输入复现仅选左声道的 `spectral_repair` 同时改右声道（峰值差约 0.234）。预渲染频谱分支没有消费请求的 channels。

| 步骤 | 实施方法 | 验证方法 |

### P1-2 worker 输入快照、可取消和性能

处理预览已加过期回包过滤。仍需把 cache plan、参数和源引用在 UI 提交时解析为不可变快照。后台现有 `_compute_base_pcm` 会通过绑定方法读取当前编辑器状态，某些异常返回源声同时写面板的共享状态。FFT 改尺寸、单击变速预览、部分响度与噪声测量仍可能在 UI 线程同步计算。底层取消当前主要阻断发布，无法马上尽早终止高耗时计算。

1. 提取 `PreviewRequest` 和 `PreviewResult` 的明确版本、读取区间、来源/失效原因；在 worker 只使用快照。把缓存未就绪、解码已失败、DSP 失败、取消、源声显式回退分开。源声回退留待用户明确切换 A/B；已验证的旧预览可以继续显示并标记状态。
2. 将 FFT、变速预览、采集底噪、LUFS/标准化候选移到可取消作业。FFT 切换优先复用已发布 PCM，独立更新矩阵，不打断设备会话；视窗优先生成，连续请求节流，按总字节预算管理 PCM/多级缓存。
3. 隔离项目之间的请求和任务生命周期。清理被取消的 pending 回调，合并同键缓存请求，长任务按窗口或块检查 token。关闭 Dock、工程切换、重连、切片、撤销、取消接续时，释放线程、PCM、设备和文件句柄。
4. 用可控屏障构造 A 慢、B 快、A→B→A、失败→重试、缓存命中同步回调等顺序。确认最终 UI、PCM 和诊断属于同一新请求。对 5 分钟 stereo 以及超长录音记录 UI 事件延迟和峰值 RSS；建议目标为稳定运行时输入响应 95 分位小于 50 ms，并随窗口限制峰值内存。设备频繁切换无悬挂线程。

### P1-3 交互入口和编辑空间

1. 把当前被生产过滤器吞掉的声道头、右键菜单和频谱上下文逐项接线。静音/独奏为试听，Ø 相位反转为工程命令。频谱 heal、attenuate、仅试听该频带分别接修复处理器和带通试听；每条命令的只读、锁轨、PCM 未就绪状态使用实际能力禁用。
2. 完善空白选择与整个片段操作的语义。删除、裁剪明确当前范围和保留/涟漪规则；音频锁轨不允许通过右键或快捷键绕过。包络插值需核对编辑器呈现与模型求值结果再开放平滑切换。标记点、清空及跨变长位置按模型 ID 验证。
3. 只在产品面板替换不可用的原型控件。启用快捷键前和全局播放、删除、撤销对照；从波形进入、从时间线退出、源监视和灰态工具用键盘可达。测试 Qt 实际按键/鼠标，避免只发信号绕过过滤器。手工走窄 dock、中文及英文、100%/200% 缩放，长文件名省略后保留 tooltip。

### P2-1 实际项目和设备验收

1. 导入三段 MP3 各到一个对齐轨。先保留原轨路径，复制一个测试工程。取时间线 0–5 s 对应各自源 10–15 s，分别做仅左声道选区增益、去噪/频谱测试、变速和 20 ms 淡化。保留未处理基线，逐动作撤销/重做；保存、关闭、重开、重连后重复导出。播放器和编辑器都核对序列/片段 ID 的匹配。
2. 先输出浮点 PCM 或无损 WAV 再比较。Stem、成片的 WAV/PCM 音轨、实时浮点 mix 使用相同采样率、声道、gain 与路由。对齐首样本和预卷，比较选区边界、通道身份、静音区间、淡化曲线、RMS、LUFS 和 true peak。AAC 另行记录编码器延迟和量化差异，按对齐后的容差验收。按 44.1/48/96 kHz 和 23.976/24/29.97 fps 展开，记录 `clip_id`、输入指纹和测试版本。
3. 物理设备用 macOS 内置输出/USB、Windows 默认输出/USB 各至少一组。听 A/B、跳区间是否爆音、Solo 是否立即生效、选区循环、返回时间线与主播放互斥、播放时拔设备或改采样率。记设备帧率、缓冲和最大反馈延迟。若涉及第三方交付，再另跑 AAF 往返与真实 5.1/7.1 系统。
4. 所有失败用 WAV 合成可公开的最小样例留在单测，真实素材留在本机，不把用户素材或机器路径写进工程测试依赖。
