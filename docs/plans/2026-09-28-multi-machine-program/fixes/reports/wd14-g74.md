## AUD-28119 [Major/bug] `_slide_preset` 非法 direction 静默回退 "up"

**状态：FIXED**

**根因**：`sign = {...}.get(direction, 1.0)` 把拼写错误/大小写错误的方向静默按
"up" 处理；direction 是 AI/编辑器填充的 preset 参数，缺显式验证。

**修复**（motion/presets.py）：抽出模块级 `_SLIDE_DIRECTIONS` 表；`_slide_preset`
对未知 direction 抛 `ValueError`（文案列出合法值），与 `resolve_easing` 对未知
缓动名的处理一致。

## AUD-28200 [Major/risk] `with_step_gap` 无界负 gap → layout 深层延迟 ValueError

**状态：FIXED**

**根因**：编辑入口（`with_step_gap`/构造）不校验累积 cursor，越界重叠推迟到
`layout()` 里 `TimeRange.__post_init__` 才抛，报错无 step 上下文。

**修复**（motion/sequence.py）：`SeriesGroup.__post_init__` 中做布局预演——逐 step
校验累积 cursor 非负，越界即抛 `ValueError` 并点名 step_id 与帧值。由于
`with_step_gap` 经 `dataclasses.replace` 重走构造器，编辑期即刻拒绝；任何可构造的
组 `layout()` 不再抛延迟异常。适度的负 gap（重叠）不受影响。

## AUD-28203 [Major/doc-gap] `duration` 非有限端点 + measure_spring 哨兵混淆跳变

**状态：FIXED**

**根因**：`spring()` 把 `measure_spring` 的返回值当作"已收敛"凭据，而 600 既是
"恰在 600 收敛"也是"600 帧内从未收敛"的哨兵——慢弹簧传 `duration` 后在
`local_frame >= 600` 处从远未到位的物理值瞬跳到 `to`（渲染可见单帧突跳）；docstring
"after duration frames it is to" 与实现矛盾。

**修复**（motion/spring.py）：
- snap 判据改为**实际静息**：`abs(value - to) > duration_rest_threshold` 时直接返回
  物理值，绝不 snap（哨兵 600 不再授权跳变）；
- `duration` 语义落实为"延迟精确到靶的 snap 至该端点"（`local_frame >= settle 且
  >= duration` 才返回 `to`），跳变幅度恒 ≤ 阈值 0.005；
- docstring 重写为真实契约：弹簧渐近收敛无固定时长，短于物理 settle 的 duration
  不截断运动。AUD-28202 近临界分支（`_NearCriticalZeta` 闭式解）原样保留并有回归
  测试守护。

## AUD-28206 [Major/bug] `shifted()` 负向越界静默 clamp 到 0

**状态：FIXED**

**根因**：`max(0, start + delta)` 把"平移"变成"平移+钳制"，兄弟间距被静默压缩。

**修复**（motion/time_range.py）：越界（`start + delta < 0`）抛 `ValueError`，
docstring 指明组级平移应由调用方先对 delta 取公共下界再逐成员平移；合法边界
（恰为 0）不受影响。仓库内无生产调用方（仅 re-export 与测试），无连锁改动。

## AUD-28301 [Major/bug] extract_fragment 不做时间原点归一化

**状态：FIXED**

**根因**：宿主轨道存全局帧，选区快照只做空间归一化；插入路径
（`retime_fragment_to_page` 的 `frame + start`、`fragment_max_keyframe_frame` 的
页扩展）都假定 0-based 预设帧空间，非 0 起始的动画存成预设后错位/撑页。

**修复**（presets/fragment.py）：新增 `_normalize_time_origin`——对折叠
（scene 级动画并入 local）之后的全部轨道，按**片段级**最小关键帧帧整体平移到 0
（保留元素间相对 stagger；`min == 0` 时恒等返回）。`extract_fragment` 在折叠后调用，
docstring 同步更新。

## AUD-28320 [Major/bug] _import_folder 冲突时只改文件夹名、不改 preset.json

**状态：FIXED**

**根因**：copytree 原样复制旧 preset.json，rescan 按 preset.json 内的 preset_id 做
记录键 → 新 id 查不到（假失败，文件已落盘）且两条记录争一个键遮蔽原预设。

**修复**（presets/library.py `_import_folder`）：copytree 后若 id 被去重
（`preset_id != original_id`），以 `manifest.to_dict()`（已带新 id、规范化
category）重写 `target/preset.json`。代码预设（无 preset.json）同样落地一份
`entry="build.py"` 的 manifest——扫描器优先读 preset.json，加载器仍执行 build.py。
重复导入同一冲突源两次均得到独立记录，原记录不被遮蔽（幂等合并）。

## AUD-28900 [Major/bug] lens_flare 呼吸缩放绕包围盒左上角，光斑中心对角漂移

**状态：FIXED**

**根因**：`kind="circle"` 圆心在局部 (r, r)，渲染变换
`translate(x y) rotate scale` 使 scale 绕元素原点（包围盒左上角）缩放，halo_big
scale 1.0→1.07 时圆心漂 ±22px，与静止的 core (890,550) 错位。

**修复**（lens_flare_stack/build.py）：仿 pie_donut_chart 的 idiom——halo_big 与
ring_teal 改 `kind="path"`，`_disc_path(radius)` 生成绕局部原点的圆（两段弧闭合），
transform (x,y) 即圆盘中心（halo 880,540；ring 890,550，与 core 共轴）；width/height
保留 2r 供编辑器包围盒。径向渐变为 objectBoundingBox 50%/50%，路径 bbox [-r,r]²
与原 circle bbox [0,2r]² 的渐变映射等价，视觉不变；缩放/旋转自此绕圆心。测试用真实
SvgSceneRenderer 断言帧 0 与帧 26 的 halo 组 transform 均含 `translate(880.000000
540.000000)` 且 scale 由 1.0 变 1.07。

## AUD-29200 [Major/bug] floating_orbs 循环尾段关键帧压缩，速度突跳约 8 倍

**状态：FIXED**

**根因**：y 轨道末段 `96-(72+phase) = 24-phase` 帧要完成与前段相同的 2×drift 行程，
phase 接近 23 时行程压缩 8 倍（orb 8：73.2px 压进 3 帧）。

**修复**（floating_orbs/build.py）：改为**相位平移的 96 周期三角波**——极值点在
`24+phase`（-drift）与 `72+phase`（+drift），回绕值 `edge = y + drift·phase/24`
（中段摆动点）同时作为帧 0 与帧 96 的关键帧。四个分段（45/48/…/3 帧不等）的
行程/时长比恒等于 drift/24（orb 8 实测 1.525/1.525/1.525 px/帧），平均速度全域
均匀，回绕无缝。测试对全部 18 条 y 轨道断言首末值相等且分段速度比 < 1.02。

## AUD-29702 [Major/bug] `from_dict` 的 ValueError/TypeError 逃逸 PresetError

**状态：FIXED**

**根因**：合法 JSON 但非合法场景文档（顶层数组、`width: "abc"` 等）在
`TeachingSceneDocument.from_dict` 抛原生异常，调用方（asset_library_panel、
motion_graphic_editor_window）只捕 PresetError，异常冲进 Qt 事件循环。

**修复**（presets/loader.py）：`from_dict` 包进 `try/except (TypeError, ValueError)`

同文件 90-92 行 JSON 读取、`_load_code_scene` 的模块边界处理一致（core 侧已核实
不抛 PresetError，无双重包装）。
