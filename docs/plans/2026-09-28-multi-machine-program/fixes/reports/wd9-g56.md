## AUD-16310 [Major/bug] remux 流映射未加 `?`

**状态：FIXED**

**根因**：`_remux_segment` 的 `-map 0:v`/`-map 0:a` 是必选匹配，ffmpeg 匹配
不到流即报错退出（`Stream map '0:v' matches no streams`）。纯音频素材
（media_type=="audio"）两种模式都走 remux、无音轨视频在 remux 模式必失败。

**修复**（consolidate.py `_remux_segment`）：`0:v`→`0:v?`、`0:a`→`0:a?`
（与已有的 `0:s?` 对齐），docstring 写明 AUD-16310 语义。三流全缺的素材仍
会因"无任何输出流"失败并按段记录 STATUS_FAILED——这是正确行为。

## AUD-16311 [Major/risk] 同步阻塞 + ffmpeg 无默认超时 + 不可取消

**状态：FIXED**（核心侧根因修复；UI 线程调用方迁移见"遗留"）

**根因**：`consolidate_project` 是同步 API，`ffmpeg_timeout` 默认 None 不限
时，无进度回调/取消点；唯一调用方 media_pool_panel.py:5652 在 Qt 菜单槽内
直接同步调用。

**修复**（consolidate.py，核心侧三件套；调用方文件不在白名单）：

1. **默认有界超时**：`_DEFAULT_FFMPEG_TIMEOUT_S = 1800.0`（30 分钟，覆盖
   ProRes 长分段），`ffmpeg_timeout=None` 时落到该默认值；显式传参仍可覆盖。
2. **进度回调**：新增 `progress_cb: Optional[Callable[[ConsolidateProgress], None]]`
   与冻结数据类 `ConsolidateProgress`（phase/asset/segment_index/
   segment_count/completed_segments/total_segments），每个分段开始时上报
   `phase="segment"`，全部完成后上报一次 `phase="done"`；total 由与主循环
   同口径的预统计得出。
3. **取消检查点**：新增 `cancel_check: Optional[Callable[[], bool]]`，在
   分段边界（每个 asset 的每段迭代开头）检查，返回 True 抛新异常

   与既有的单段失败隔离策略相同）。

API 完全向后兼容（新增均为可选参数），media_pool_panel 调用不变（
test_media_pool_log_ui 13 项通过验证）。

## AUD-16413 [Major/risk] 持锁 emit Qt 信号

**状态：FIXED**

**根因**：`add_clip` 在 `with self._lock:` 内 `clip_error.emit`/`clip_loaded.emit`
（threading.Lock 不可重入），直连槽回调再进任意加锁方法即自锁；且
`clip_loaded` emit 时句柄尚未写入映射表。

**修复**：`add_clip` 重构——信号一律在锁外 emit；句柄先入表（锁内）再
`clip_loaded.emit`，直连槽观察到一致状态。`clip_error` 在 open 失败路径
（本就无锁可持）emit。

## AUD-16414 [Major/risk] 全局锁内重 I/O

**状态：FIXED**

**根因**：`open_clip`（磁盘探测 + 解码器初始化，可达数百 ms）、
`get_clip_info`、`close_clip` 都在 `self._lock` 临界区内，媒体打开期间阻塞
所有并发帧请求。

**修复**：`add_clip`/`remove_clip` 重构为"锁内只做映射表读写、I/O 全部锁
外"：

- add_clip：锁内查重 → 锁外 open/get_clip_info → 锁内入表（并发双开竞速
  保留先入表者，输家会话锁外 close）→ 锁外 emit。
- remove_clip：锁内减引用/出表 → 锁外 close_clip。
- 新增竞速测试（barrier 同步双 add_clip：opened=2、closed=1、active=1）。

## AUD-16415 [Major/risk] _stats 无锁读写

**状态：FIXED**

**根因**：`record_request`（多步累加+重算均值）在锁外调用，与锁内写、
`reset_stats` 整体换对象、`_maybe_report_stats` 无锁读 `len(_asset_to_clip)`
并存——并发下丢计数、均值漂移。

**修复**：新增 `_stats_lock`，统一锁纪律并写明锁序（只允许
`_stats_lock → _lock` 单向嵌套，绝不反向）：

- `record_request`/`record_quality_switch`/`to_dict` 读取/`reset_stats`
  换对象全部在 `_stats_lock` 内；
- 质量切换检测随 `record_request` 移入同一 `_stats_lock` 临界区（同时消除了
  原来在 `_lock` 内改 stats 的反向嵌套）；
- `_maybe_report_stats` 的 `active_clips` 改经加锁属性
  `active_clip_count`（旧代码锁外裸读字典长度）；
- add/remove 的 `clips_opened/clips_closed/active_clips` 更新移到 `_lock`
  之外、`_stats_lock` 之内。

## AUD-16501 [Major/risk] 交互预置位线程无 join 保护

**状态：FIXED**

**根因**：`_do_preposition` 线程（"DecodeInteractivePreposition"）直接
start、不进任何注册表；close 三路径只对 preposition 事件做 0.12–0.3s 协作
等待，线程阻塞在单次 C 层解码内（8K/长 GOP 单帧可超 0.3s）时，
close_source/close_all/invalidate 会销毁它正在使用的池克隆 VT 源——播放
预取线程对同一风险有 `_join_playback_prefetches(timeout=2.0)` 强保护，
保护标准不一致。

**修复**（edit_gpu_decode_manager.py）：

1. 新增注册表 `_interactive_preposition_threads: list[(asset_path, thread)]`
   （与播放预取共用 `_playback_prefetch_lock`）；线程注册后再 start，
   `_do_preposition` 的 finally 里自摘除。
2. 新增 `_join_interactive_prepositions(timeout=2.0, *, asset_path=None)`：
   与播放预取同强度（2s）；按素材过滤（close_source 用）/全量
   （close_all/invalidate 用）；每轮防御性摘除已退出线程（注册方异常路径
   未自清理时不空转到超时）。
3. 三条关闭路径接线：取消信号（generation bump）发出**之后**、事件等待
   之前 join——先让协作中止生效，再给阻塞解码留有界收尾窗口。

## AUD-16502 [Major/risk] 预取 dedup 检查-添加非原子

**状态：FIXED**

**根因**：`_kick_playback_prefetch` 的 `if key in pending: return` 与
`pending.add(key)` 无锁，多轨并行解码下两个线程可同时通过检查、为同一
source_key 各起一个预取线程，破坏"每条流同时最多一个预取线程"不变量。

**修复**：检查 + `_closing` 判断 + `add` + `_lease_source` 全部并入
`with self._lock:` 单一临界区（检查-登记-租约原子化）；解码线程 finally 中
discard 不变。

## AUD-16503 [Major/risk] _closing 不阻止创建路径

**状态：FIXED**

**根因**：`close_all` 置 `_closing=True` 后永不复位，该标志只影响 LRU 逐出
（`_evict_sources_if_over_cap`）；`_get_or_create_source`/`warmup_source`
等创建路径不看它——stop 超时或迟到解码会重建会话写入 `_sources`，此后无人
再调 close_all、逐出又被禁用 → VT/FFmpeg 会话泄漏到进程退出。

**修复**：四处创建入口加 `_closing` 闸门（close 后管理器明确不可再用，
按证据建议的第一种语义）：

1. `_get_or_create_source`：入口直接返回 None（调用方走 CPU 回退/持帧），
   不触 `_create_source`、不写 `_sources`；
2. `warmup_source`：入口直接返回；
3. `_ensure_interactive_source_pool_warmup`：入口直接返回；
4. 预置位线程创建点：`_closing` 时不再 start 新线程。

## AUD-16601 [Major/risk] present slot lease 提前返回泄漏

**状态：FIXED**

**根因**：`_ensure_composite_fbo`（`_process_task` 入口）acquire 的
WRITING lease，在 `not task.layers`、`not track_textures`、
`gpu_track_render_incomplete`、`transition_*` 错误、composite_cache blit

帧是 no-op。

## AUD-16602 [Major/bug] 输出池尺寸变更立即释放全部纹理

**状态：FIXED**

**根因**：`_ensure_composite_fbo` 的 need_rebuild 分支立即
`tex.release()` + `_present_pool.release_all()`——在途未 ack 的
GpuPresentFrame（READY/IN_VIEWER）仍指向旧纹理名，Viewer 的
glWaitSync/blit 采样已删除且可能被复用的 GL 名 → 花屏/混帧/驱动级未定义
行为（分辨率/代理切换即触发）。

**修复**：旧池改为**退役延迟释放**：

1. need_rebuild 时旧 `(pool, entries)` 整体进入 `_retired_output_pools`
   （带退役时间戳），新池照常重建；不再立即 release_all + 删纹理。
2. `_drain_retired_output_pools()`（每帧 `_process_task` 开头排水）：
   旧池全部 slot 回到可写态（FREE/RELEASABLE，即 Viewer 已 ack）才真正
   `tex.release()`；超时 `_RETIRED_OUTPUT_POOL_TIMEOUT_S = 2.0s` 未回收的
   由 `ctx.finish()`（ModernGL，本线程 current 上下文）兜底强释放——防
   Viewer 永不 ack 时退役纹理无限滞留。（不直接触 PyOpenGL 的 glFinish：
   无 GL 进程里解析/调用 GL 入口点本身就是段错误，测试复现后改用
   ModernGL。）
3. `ack_present_slot` 把 ack 同步转发给退役池（slot_id 相同的误投由
   `OutputSlotPool.ack` 内部吞掉并 debug 记录，不会崩溃），在途旧帧 ack
   后退役纹理即具备释放条件。
4. `_cleanup` 末尾 `force=True` 无条件排空。

## AUD-16603 [Major/bug] 调整剪辑 grade 用槽位索引 1000+（1001 张纹理）

**状态：FIXED**（即 w5b-g4 报告"协调提示"预警的可达缺陷）

**根因**：`_apply_adjustment_clips` 调
`_apply_preview_grade(..., 1000 + adj_index, ...)`，而
`_ensure_graded_track_fbo` 按索引顺序填充轨槽数组——首个带 grade 的调整
剪辑帧会顺序创建 1001 张全尺寸 RGBA f1 纹理（1080p 约 8.3 GB、960×540 代理
约 2 GB）。此前被 AUD-16600（ValueError 先抛）掩盖，w5b 修复后 scoped 合成
每次回传单条调整项（adj_index 恒 0 → 恒用索引 1000），已可达。

**修复**（按任务特别说明的方向：按需 dict/稳定键分配，杜绝索引预留）：

1. 新增 `_adjustment_grade_texes/_adjustment_grade_fbos`（稳定键 → 纹理
   dict）与 `_ensure_adjustment_grade_fbo(key, w, h, *, pin_glo=None)`：
   按调整剪辑 clip_id（缺省 `adj_{i}` 序号键）惰性分配，容量
   `_ADJUSTMENT_GRADE_SCRATCH_CAP = 2`、FIFO 淘汰；`pin_glo` 让淘汰跳过
   当前链路仍在引用的 grade 输出（防 use-after-release）。
2. `_apply_preview_grade` 新增 keyword-only `scratch_key`/`pin_glo`：
   调整剪辑路径走 dict 分配；轨道路径行为不变。
3. `_apply_adjustment_clips` 的 grade 调用改为 `scratch_key=grade_key,
   pin_glo=current_glo`，不再出现 1000+ 索引。
4. 防线加固：`_apply_preview_grade` 对无 scratch_key 的轨槽索引加护栏
   （`index < 0 or index > _MAX_GRADED_TRACK_TARGETS(64)` 时警告并跳过
   grade，返回源纹理），畸形 track_index 不再触发无界分配。
5. `_cleanup` 释放 dict 内全部条目。
