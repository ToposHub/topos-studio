## AUD-27900 — FIXED

**位置（修复前）**：`src/features/teaching_animation/export_service.py:213-214`
（`export()` 无 backend/pixel_format 校验直达 `_write_sequence`）、
`497-502`（`svg_sequence` 把 `frame.data` 原样写 `.svg`、`html_sequence`
直接 `frame.data.decode("utf-8")`）。

**根因**：HTML 后端（`HtmlVectorSceneRendererV1Adapter` /
scene_renderer_router.py:188, 317-321）产出的帧是 `pixel_format="rgba8"`
的像素字节，SVG 后端才产出 `pixel_format="svg"` 的 UTF-8 文本
（svg_renderer.py:572）。旧写入器只按 `format_name` 分派、从不看帧的
`pixel_format`：HTML 场景 + 默认 `svg_sequence` → 每帧 RGBA 字节以
`.svg` 扩展名写盘（manifest 正常、交付全损）；`html_sequence` →
`UnicodeDecodeError` 崩溃。

**修复**（`_write_sequence` 重写，`export()` 分派不变）：

1. 逐帧读取 `frame.pixel_format` 分流，扩展名与内容强制一致：
   - `format_name == "rgba_sequence"` 或 `pixel_format == "rgba8"`：
     经 `FrameAdapter.from_rendered_frame`（校验帧并原样透传 rgba8）二进制
     写 `.rgba`；SVG 帧 + `rgba_sequence` 保持原 Qt 栅格化路径不变；
   - `pixel_format == "svg"`：`svg_sequence` 写 `.svg`（字节原样，保持
     字节级可复现）；`html_sequence` 解码 UTF-8 包 HTML 壳写 `.html`；
   - 其他 `pixel_format`：抛 `TeachingExportError`（fail-closed，不静默）。
2. 请求的是矢量文本序列（svg_sequence/html_sequence）但后端给了 raster 帧
   时，manifest 写入 `delivery_note` 记录实际交付内容，保持交付可审计。

**既有正确行为保持不变**：svg+svg_sequence（字节写 `.svg`）、
svg+html_sequence（文本写 `.html`）、svg+rgba_sequence（Qt 栅格化）、
rgba8+rgba_sequence（透传）四个组合逐项回归测试锁定。

**回归测试**：`TestSequenceExportPixelFormatRouting` 6 个用例
（raster×3 格式、svg×2 格式、未知格式 fail-closed）。

## AUD-28001 — FIXED

**位置（修复前）**：`src/features/teaching_animation/module.py:812-824`
（`_get_html_service_for` 按 scene_id 永久缓存 `TeachingAnimationAIService`，
service 构造时捕获场景快照）、`2190`（confirm 取缓存 service）、
`2247-2288`（`service.apply_html_layer` → `updated = service.scene` →
`store.register(updated)` 无条件覆盖）。

**根因**：缓存 service 持有构造时的场景快照（ai/service.py:26-38，
仅 `update_scene` 会替换）。仅写共享 store 的编辑——编辑器场景命令、
`_confirm_scene_edit_request` 的 `store.register`、工程重载
`replace_all`——不会同步进快照。下一轮 AI 确认时 2181 行的 revision 检查
只比较 store 与 plan 快照（通过），但 `SetHtmlLayerCommand(layer).apply
(service.scene)` 仍作用于旧快照，`store.register(旧场景+新层)` 静默回滚
用户在两轮 AI 编辑之间的修改。**已实测复现**：用未刷新的旧实现跑两轮
编辑 + 中间一次 `store.register(replace(scene, name="用户重命名"))`，
第二轮后 store 场景 name 回滚为 `'Target Clip'`（数据丢失确证）。

**修复**（`_get_html_service_for`）：命中缓存时校验
`service.scene is not scene`（store 当前对象），不一致即调用
`service.update_scene(scene)` 从 store 重读最新文档刷新。module.py 中
`_html_services` 的唯一写入点在该方法内（820/823 行已核对），两个调用方
（`_handle_model_html_generate_response`:1316 与
`_confirm_html_generate_request`:2190+）全部经此入口，覆盖完整。刷新为
O(1) 幂等操作（仅替换 context_provider 场景引用，registry/template 会话
状态不受影响）。confirm 处既有的 revision 陈旧检查（2181 行）与
`approved_scene_hash` 复核保持不变，作为第二道防线。

**回归测试**：`TestHtmlServiceCacheRefresh` 2 个用例——
① 缓存 service 在 store 更新后取用时 `service.scene` 跟随 store 当前对象；
② 端到端两轮 AI 编辑 + 中间 store-only 用户改名，第二轮写入后改名保留
（旧实现下该用例必失败，已用未刷新实现模拟验证）。

## AUD-28202 — FIXED

**位置（修复前）**：`src/features/teaching_animation/motion/spring.py:46-52`
（欠阻尼分支 `omega_d = omega0 * sqrt(1.0 - zeta*zeta)` 后
`(zeta*omega0/omega_d)` 无防护）。

**根因**：判别走 `discriminant = c*c - 4*m*k` 与走 `1.0 - zeta*zeta` 是
两条独立舍入路径。**已实测复现**审查给出的崩溃输入
`SpringConfig(mass=1.0, damping=3.4641016151377544, stiffness=3.0)`：
`discriminant = -1.776e-15`（进欠阻尼分支）而 `zeta` 舍入为精确 `1.0`，
`omega_d = 0.0` → 旧公式抛 `ZeroDivisionError: float division by zero`。
`spring()` 被 presets 的每帧 MotionFn 在预览/导出烘帧循环逐帧调用，
未捕获异常将中断渲染任务。

**修复**（`_step_response` 统一近临界分支）：

- 新增 `_NearCriticalZeta = 1e-12`；`abs(zeta - 1.0) <= _NearCriticalZeta`
  时直接求解析临界解 `1 - e^{-omega0 t}(1 + omega0 t)`。该闭式同时是：
  ① 原 `discriminant == 0.0` 精确临界分支（折叠入此，公式不变）；
  ② 欠阻尼分支 zeta→1 的数学极限（`cos(ωd t)→1-(ωd t)²/2`、
  `(ζω0/ωd)sin(ωd t)→ω0 t`），因此整个带宽内数学正确而非仅是防崩护栏；
  ③ 消除过阻尼侧 `discriminant` 微正时的 `(s2·e^{s1t}-s1·e^{s2t})/(s2-s1)`
 灾难性消去（原代码同样存在，本次一并覆盖）。
- 舍入只能把 zeta 推离 1 约 1e-15，1e-12 带宽充分覆盖且余量三个数量级；
  该带宽内两分支差异 O((1-zeta²)·t²e^{-ω0t})，远小于 0.005 收敛阈值。
- 进入欠阻尼分支前先过护栏，保证 `1 - zeta*zeta > 0`（无 sqrt 域错误、
  无零除）；过阻尼分支仅在 zeta 显著大于 1 时进入（此时 s2-s1 远离零，
  无消去）。

**回归测试**：`TestNearCriticalDamping` 5 个用例——审查崩溃输入全帧
有限且收敛、临界闭式逐点精确、近临界单调无过冲、`measure_spring` 有界、
明确欠阻尼（仍过冲）与明确过阻尼（单调）行为不变。
