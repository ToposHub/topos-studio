## 1. BUG-A3-01 [Critical/bug/S] — FIXED

**位置**：`src/app/controllers/deliver_controller.py`
`_batch_export_single_file`（修复前 L1655-1657 的 `else` 分支与 L1671 的读取处）。

**根因**：sidecar 存在性检查 `if os.path.exists(project_path):` 的 `else`
分支（无 `.topos` 文件）只设置 `self.engine.layers = [Layer("Layer 1")]`，
从不给局部变量 `project_data` 赋值；约 20 行后翻转状态恢复
`if isinstance(project_data, dict):` 读取该变量抛
`UnboundLocalError`。上层 `_process_next_batch_file` 的 `except Exception`
将其记为 FAILED（error=UnboundLocalError），用户看到"渲染失败"。

**修复**：`else` 分支补 `project_data = None`（附 BUG-A3-01 注释说明），
与证据文档建议方向一致。翻转状态恢复随后自然走"无工程数据"路径。

**pin 用例翻转**（协议处理）：
`tests/app/test_deliver_controller_coverage.py` 中
`test_missing_topos_sidecar_crashes_with_unboundlocal_bug`（`pytest.raises(UnboundLocalError)`
锁定旧行为）翻转为 `test_missing_topos_sidecar_exports_successfully`：
断言返回输出路径 `nosidecar.jpg`、`engine.layers` 复位为单个全新
`Layer("Layer 1")`、`set_flip_state` 未被调用、保存缓冲为 uint8。
同文件 `_prime` 辅助中"BUG-A3-01 workaround"注释一并移除（不再需要侧车兜底）。

**回归测试**：`tests/app/test_fix_w5g4_aud5.py::

## 2. BUG-C4-01 [Critical/bug/S] — FIXED

**位置**：`src/app/controllers/color_controller.py` 六个遮罩结构入口：
`on_mask_shape_added` / `on_mask_shape_removed` / `on_all_masks_cleared` /
`on_mask_group_added` / `on_mask_hierarchy_updated` / `on_brush_stroke_added`。

**根因**：这些方法直接改动 `layer.mask_shapes` 数据树并置 dirty、重渲染，
但从不调用 `engine.history.push_state`；同文件的
`on_duplicate_mask_shape` / `on_copy_masks_to_layer_requested` 早已用
`copy_image=False` 快照证明遮罩结构的可撤销语义存在，只是这 6 个入口没接上。

**修复**（与 duplicate/copy 模式完全对齐）：

1. 新增私有辅助 `_push_mask_structure_snapshot()`：
   `push_state(img_full_original, layers, active_layer_index, copy_image=False)`
   （HistoryManager 入栈时经 `to_dict` + deepcopy 冻结图层树，undo 可完整回放）。
2. 六个入口在**改动数据树之前**调用该辅助：
   - `on_mask_shape_added`：`if not layer: return` 之后；
   - `on_mask_shape_removed`：`get_mask_item_by_id` 存在性检查之后
     （删除不存在的 id 不产生空快照，保持既有 noop 语义）；
   - `on_all_masks_cleared`：清空循环之前，带守卫
     `any(lyr.mask_shapes or lyr.ai_matte ...)`——无可清内容时不产生空 undo 步；
   - `on_mask_group_added`：`if not layer: return` 之后一次调用，
     覆盖"多选打包"与"新建空组"两个分支；
   - `on_mask_hierarchy_updated`：**必须在 `extract_items` 之前**——该步骤会
     就地清空群组 children，压栈晚了快照会捕获被拆散的中间态（代码注释已说明）；
   - `on_brush_stroke_added`：`if not layer: return` 之后（每条落笔 = 一个 undo 单元）。
3. 语义边界保持：参数微调路径（`on_mask_shape_updated` 防抖 / `process_mask_update`）
   刻意不入栈，未被触碰（新增测试
   `test_mask_param_debounce_still_not_undo_pinned` 锁定该边界）。

**pin 用例翻转**（协议处理）：
`tests/app/test_color_controller_coverage.py` 中
`test_mask_add_remove_clear_group_never_push_undo_state_bug_pin`
（断言 `pushed == []`）翻转为
`test_mask_add_remove_clear_group_hierarchy_push_undo_state`：逐操作断言
add/remove/clear/group/hierarchy 各 push 一次且 `copy_image=False`；另补
`test_clear_all_masks_without_content_commits_no_snapshot` 守护空清零不产生空快照。

**回归测试**（`tests/app/test_fix_w5g4_aud5.py`，用**真实** HistoryManager
而非 `_FakeHistory`，验证 undo 真正回放出改动前的遮罩树）：

- `test_mask_remove_is_undoable_with_real_history`：删窗 → undo → 窗口（含 type）恢复；

## 3. AUD-R2-007 [Major/process/S] — FIXED

**位置**：`tests/edit/ai_editing/test_credential_store.py::
test_credential_storage_preference_round_trip`。

**根因**（测试环境脆弱，产品代码无缺陷）：测试只 monkeypatch 了
`credential_store.USER_AI_CONFIG_PATH`（该模块的导入绑定），但
`get/set_credential_storage_preference` 调用无参的
`load_user_ai_config()` / `save_user_ai_config()`，其默认路径在
`user_ai_config` 模块内部解析——patch 对其无效。后果：

1. `assert ... == "file"  # default` 读的是宿主机真实
   `~/.topos/ai_profiles.json`，宿主偏好为 keychain 即失败
   （已实测复现：用 `HOME=<fakehome>` + keychain 配置运行，原测试
   `AssertionError: assert 'keychain' == 'file'`）；
2. 更糟：`set_credential_storage_preference` 会**写**宿主机真实配置文件。

**修复**（仅测试，产品语义零改动）：monkeypatch
`user_ai_config.USER_AI_CONFIG_PATH`（shim 交换后与
`src/shared/ai_models/generation/user_ai_config` 是同一模块对象）到
`tmp_path`，同时保留 `credential_store.USER_AI_CONFIG_PATH` 的隔离
（覆盖 FileCredentialStore 默认路径）；并加两条
`load_user_ai_config(config_path)` 断言证明偏好真实落盘、reload 存活。

**验证**：

- keychain 偏好宿主（fake HOME）下测试通过，且 fake 配置文件内容保持
  `keychain` 未被测试改写；
- 真实宿主 `~/.topos/ai_profiles.json` md5 前后一致（HOST CONFIG UNCHANGED）。

**回归测试**（`tests/app/test_fix_w5g4_aud5.py`）：
`test_credential_preference_resolves_via_user_ai_config_default`（隔离点语义 +
反证只 patch credential_store 侧无效）、
`test_credential_preference_default_is_file_on_pristine_config`（纯净配置默认恒为 file）。
