## AUD-10904（Major/bug）树行选中/可见性切换调用 `view.refresh()` 重置视口

**状态：FIXED**

**根因**：`SplineView.refresh()` 语义是"丢弃 `_viewport` 重新 fit"（spline_view.py
`refresh()` 置 `self._viewport = None`），而 `_on_curve_selected` /
`_on_curve_visibility_toggled` / `_set_all_curve_visibility` 三处把它当"重绘"用，
每次树交互都丢弃用户缩放/平移，与同文件 `attach_to_shared_selection` 引用的
plan §7.2「selection does not reset zoom」相反。

**修复**（spline_panel.py）：
- `_on_curve_selected`：`refresh()` → `update()`（选择不重置缩放）。
- `_on_curve_visibility_toggled`：默认只 `update()`；仅当该勾选使可见曲线
  "从无到有"（其余曲线均不可见且本曲线刚变为可见）时才 `refresh()` refit。
- `_set_all_curve_visibility`：Show all 仅在之前完全无可见曲线时 refit，
  否则保视口 `update()`；Hide all 不再清视口。

**验证**：新测试 `TestAud10904ViewportPreserved`（4 用例：选择保视口、可见性
切换保视口、无→有才 refit、Show all 在有可见曲线时保视口）。

## AUD-10905（Major/bug）视图级 `current_frame_changed` 信号从未连接

**状态：FIXED**

**根因**：`_init_ui` 只连接了 keyframe_changed / curve_settings_changed /
curve_selection_changed / key_selection_changed 四个视图信号；
`SplineView.current_frame_changed`（标尺拖动时由 `_do_playhead_seek` 发射，
spline_view.py）全库无接收方——标尺拖动只改视图内部帧，合成时间轴不 seek，
且面板下一次 `set_current_frame` 同步会把播放头弹回。

**修复**（spline_panel.py）：`_init_ui` 中
`self._view.current_frame_changed.connect(self._on_view_frame_changed)`，新处理器
`_on_view_frame_changed` 走 `seek_to_frame(int(frame))`——按证据建议转发进
seek 路径获得 [start, end] 范围钳制后再发射面板级 `current_frame_changed`
（与工具栏 transport 同一路径；无回环：set_current_frame → view.set_current_frame
不再发射）。

**验证**：新测试 `TestAud10905RulerSeekForwarded::test_wired_in_init_ui`。

## AUD-10911（Major/perf-opportunity）`_do_multi_key_drag` 的 sel_set 按按下时刻帧快照匹配

**状态：FIXED**

**根因**：origins 快照只记 (curve, idx, frame, value, hl, hr)，每 tick 用
`k.frame in sel_set`（按下时刻帧集合）匹配被拖键——首个非零移动事件把
`k.frame` 移离快照值后，后续所有 mouseMove 中匹配恒假 → 键被 continue 跳过，
多选拖拽冻结在第一个增量（松手提交滞后位置）。

**修复**（spline_view.py）：按证据建议"以对象身份标记归属"：
- `_begin_key_drag` 的 origins 增记 key 对象本身
  `(cc, ki, kk, frame, value, hl, hr)`；`_sv_mouseReleaseEvent` 的解包改为
  `origin[0]`。
- `_do_multi_key_drag` 重写：`by_curve` 以 `id(kk)` 索引；每 tick 先把被跟踪键
  **重置回 origins 帧位**再应用总 delta，邻域钳制始终按 origin 相对目标判定
  （消除旧实现"上一 tick 位置参与钳制"的双重计数隐患）；右移降序/左移升序
  遍历（与 AUD-10912 同规则，块内相邻键不互相撕裂）；邻位索引用预建
  `pos = {id(k): i}`（顺带消除 `keys.index(k)` 的 O(n²) 与 dataclass 相等性
  误匹配）。

**验证**：新测试 `TestAud10911MultiDragFollows`（第二次 move 后键继续跟随、
块间距 10 保持、原帧消失）；既有 `test_spline_multi_select.py` 全绿。

## AUD-10913（Major/bug）键垂直拖动/改值时手柄 y 不随值平移

**状态：FIXED**

**根因**：三处同型代码只按 `delta_frame` 平移手柄 x，值变化后手柄 y 留在旧
高度（手柄是数据空间绝对坐标）——broken/bezier 手工手柄的键上下拖动后手柄
不再贴合键，曲线非预期过冲/扭结。

**修复**（spline_view.py，三处同型全部修复）：
- `_do_key_drag`（939-943 型）：计算 `delta_value = new_value - key.value`，
  手柄 y 同步加 delta_value（x 平移不变）。
- `_do_multi_key_drag`（907-909 型）：手柄 y = `hl0.y() + (new_value - v0)`
  （从 origin 全量平移）。
- `_edit_key_dialog`（1456-1458 型）：同 `_do_key_drag` 处理。

**验证**：新测试 `TestAud10913HandleValueTranslation`（垂直拖动后
handle_left/right.y == 旧值 + delta_value 且 x 不变；对话框路径的平移数学）。

## AUD-11002（Major/bug）拾色器实时预览每中间色各推一步 undo，取消不回滚

**状态：FIXED**

**根因**：`currentColorChanged` → `self.setColor(color.name())` → 每次
`_begin_change`/`_notify_changed` 独立配对成立（old 快照每次被置 None），
拖一次颜色 = N 条 `sticky_note_modified` undo 记录；Cancel 时已应用色不回滚。

**修复**（sticky_note_item.py，按证据建议"预览不通知 + accept 后一次性提交"）：
- 打开对话框时 `_begin_change()` 捕获 pre-dialog 快照一次。
- 预览路径直接改 `self._color` + `_apply_fill()` + `update()`（不发
  `_changed_handler`/`_modified_handler`，无 undo 记录）。
- `finished(Accepted)`：落定 final 色后 `_notify_changed()` —— 整个交互恰好
  1 条记录（颜色未变时 no-op 丢弃）。
- `finished(Rejected)`（含 Cancel/Esc/关闭）：回滚 old_color 并丢弃快照
  （`_change_old_data = None`），零记录。

**验证**：新测试 `TestAud11001ColorPicker`（3 个中间色 0 记录、accept 后恰
1 记录且 old/new 正确；cancel 回滚 0 记录）。

## AUD-11010（Major/bug）`commit_move` 未删除被拖拽关键帧的原帧（拖动=复制）

**状态：FIXED**（按证据三项建议全部实施）

实测复现（修复前，项目 venv 探针）：
`begin_move([(0),(10)]) + update_move_preview([(5,0.0),(15,45.0)]) + commit_move()`
→ 轨道帧 `{0, 5, 10, 15, 20}` —— 旧帧 0/10 残留，拖动产生"复制"。

**根因**：`commit_move` 注释宣称"Drop a source keyframe if the preview moves
it"，循环体却原样 append 全部关键帧（丢弃逻辑未实现）；新帧 upsert 又用
linear/auto 默认，丢失原插值/手柄；`update_move_preview` 按"新帧号"累积存储，
一次拖动的每个中间帧都会成为关键帧。

**修复**（timeline_commands.py）：
- `DragTransaction` 增加 `sources`（每轨 src_frame → 源关键帧 dict）；
  `preview` 改为 `src_frame -> (new_frame, value)` **同键覆盖**语义
  （`update_move_preview` 签名改为 5 元组 `(node, param, src_frame, new_frame,
  value)`，中间位置被覆盖而非累积）。
- `begin_move` 从 before 快照提取每个被选关键帧的源 payload。
- `commit_move`：从 before 关键帧中**剔除被移动的源帧**后，把每个移动键以
  **源 payload（interpolation/tangent/handles）+ 新帧新值**重新加入（按列表
  组织，同帧冲突交给服务层 `duplicate keyframe frame` 校验拒绝——对齐代码注释
  "collisions validate downstream" 的既有契约；旧行为是 dict 合并静默吞并）。
  顺带删除了原实现中从未使用的 min_val/max_val 死代码（AUD-11013 所指）。

**锁定旧行为的既有测试处理（协议）**：
`tests/composite/test_timeline_commands.py` 的 4 处
`update_move_preview` 调用点（`test_move_press_move_release_one_undo_per_track`、
`test_move_across_two_tracks_one_undo_each`、`test_cancel_move_does_not_touch_graph`）
随新 5 元组契约更新；首个用例同时补上审计点名的盲区断言（`0 not in frames`、
`10 not in frames`）。测试原意图（每轨一条 undo、未动键保留、cancel 不触图）
完整保留。

**验证**：新测试 `TestAud11010MoveNotCopy`（3 用例：源帧剔除 + payload
bezier/broken/手柄随迁；三次连续 preview 仅最终帧落盘 3/5 不残留；未被视图
上报的选中键不被误删）。更新后的既有 3 用例全绿。

## AUD-11012（Major/bug）`paste_keyframes` 值不经范围归一化，越界值静默落盘

**状态：INVALID**（审计描述的缺陷在当前代码不复现）

**证据**（项目 venv 实测探针，2026-09-29）：
```
clipboard.entries = [ClipboardEntry(relative_frame=0, value=5000.0)]  # 越界
r = cmds.paste_keyframes(t.id, "rotation", 100)
→ r.ok == False, r.error_code == 'value_out_of_range',
  r.error_message == 'value 5000.0 outside parameter range [-3600.0, 3600.0]'
→ 轨道帧保持 [0, 10]（无任何落盘）
```
原因：`CompositeEditService.apply()` 先过 `validate()`
（edit_service.py:288-296 → 338-380），`set_keyframes` 分支对**每个**关键帧调用
`_validate_typed_value(pdef, data.get("value"))`（edit_service.py:374），float/int
