## 设计决策与残留说明

- **AUD-7502 的正确性/性能折衷**：第一版按上波建议做纯 per-(node_id, param_revision) 缓存，被既有测试 `test_render_scheduler.py::TestParamsHash::test_different_params_different_hash`（两个快照 revision 同为默认 0、内容不同，必须得到不同 hash——正是 P1-8 反序列化图的镜像）击落。终版 memo 命中加内容相等性比较，正确性与"每次重算"完全等价，性能上仍是 memcmp vs dumps+md5 的量级差；`is` 快路径覆盖同快照对象的重复 plan（tiling probe 等 analysis-only 调用）。参数含 ndarray 等使 `dict ==` 抛 TypeError/ValueError 的场合保守回退全量重算（窄异常，不掩盖领域错误）。
- **AUD-8412 / AUD-8905 的 FIXED\* 定性**：两处的根因修复与新 API 均已落在白名单文件内并有单测证明（viewer 种子使 b2 分支 lod 0；has_tangent 使 key 分化/缓存 miss），但生效需各一行白名单外接线（`base_evaluator.py:598` 传 `viewer_node_id=viewer_node_id`；`scene3d_node.py:4540` 传 `has_tangent=bool(m.get('has_tangent'))`）。两处默认参数都取旧值语义，未接线前生产行为不变（零回归），供 orchestrator 派发后续 1 行批次。
- **AUD-8703 的导出面**：DEFORMER_SHEAR/DEFORMER_SPHERIFY 维持导出（deformers/__init__.py `__all__`）——移除属 API 面变更且 `signature()`/spec 面已引用；本批使其"导出即报错（ValueError 带已实现清单）"而非"导出即静默无效"，与审计建议二选一中的报错路径一致。
- **AUD-8706 的语义选择**：审计给出两条路线（逐变形器上报真实标志 / 统一 False 由调用方决定）。栈内 6 个实现无一"按面重算"，且标志全仓无 render3d 外消费者——选统一 False（诚实、零行为风险），避免为凑 True 引入逐变形器返回签名变更。
- **AUD-8402 与既有 PBO 测试**：`test_get_latest_nonblocking_returns_none_when_pending` 断言 `r is None or r.request_id == 2`——与新交付语义兼容（无需改）；该测试原本"恰好只断言 None"的掩盖效应由新测试 `test_nonblocking_delivers_just_completed_frame` 补上。
- **hdri 灰度归一化与 LDR max 归一化的顺序**：三通道复制放在 is_ldr 归一化**之前**，灰度复制与去伽马顺序无关；注意函数按实际 max（如 128）归一化是既有契约，新测试按其断言（=1.0），不改动该语义。
