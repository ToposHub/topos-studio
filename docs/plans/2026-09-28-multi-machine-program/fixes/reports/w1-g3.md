## 1. AUD-2000 [Critical/risk/M] — `_PlanWorker` 非原子摘除/恢复 `on_state_changed` 的跨线程回填竞态

**状态：FIXED**

### 根因

`_PlanWorker.run()`（原 ai_edit_controller.py:146-169）用「先摘掉
`service.on_state_changed`、finally 恢复」的方式挂起 worker 线程内的状态回填。
`_start_plan`（原 :5000-5003）对未结束的旧 worker 只做 `wait(2000)`，LLM 请求
常超 2s（代码注释自认可达数十秒），于是出现两个规划 worker 重叠：

- 旧 worker A 摘掉回调（`on_state_changed = None`）后进入长 `plan_variants`；
- 新 worker B 启动，读到 `original_cb = None` 并再次置 None；
- A 的 `finally` 把 `_on_service_state` 恢复 → B 线程内 service 状态变化直接在
  worker 线程调用 `panel.refresh_state(...)`（跨线程操作 QWidget，可崩溃）；
- 或 B 的 `finally` 把恢复值 `None` 写回 → 状态回填永久失效。

dispose()（:740 置 `on_state_changed = None`）后，幸存 worker 的 finally 也会
复活旧回调。

### 修复（根因级：不再摘回调，改为线程安全挂起门闩）

src/app/controllers/ai_edit_controller.py：

- :28 新增 `import threading`。
- :116-155 新增 `_PlanStateGate`：`threading.Lock` 保护的引用计数门闩
  （suspend/resume/suspended）。计数语义保证重叠 worker 互不干扰；过量
  resume 不为负。
- :175-196 `_PlanWorker.__init__` 新增 keyword-only 参数
  `state_gate: _PlanStateGate | None = None`（缺省私有门闩，向后兼容旧
  测试/调用方，如 tests/ui/test_p1_plan_cancel.py 的既有构造）。
- :198-239 `run()` 重写：
  - 不再读写 `service.on_state_changed`（回调保持安装）；
  - 进入时 `gate.suspend()`，`finally` 中 **先 resume 再 emit**
  `cancelled`/`failed`/`finished_plan`——信号以排队连接切回主线程，若
  emit 时门闩仍挂起，主线程 `_on_plan_finished → _refresh_state` 的补回填
  会被门闩误丢弃（emit 在 finally 之前执行的旧顺序存在该窗口）；
  - 信号发射移出 try/except，异常路径语义与原实现一致（record_error 仍
    在 except 内、挂起期间执行）。
- :533-535 controller `__init__` 新增 `self._plan_state_gate = _PlanStateGate()`。
- :871-876 `_on_service_state` 开头检查 `self._plan_state_gate.suspended()`：
  挂起期间直接丢弃快照并 return（不 emit `state_changed`、不碰 panel）；
  worker 结束后由 `_on_plan_finished`/`_on_plan_failed`/`_on_plan_cancelled`
  在主线程经 `_refresh_state()` 统一补一次回填（原有机制不变）。
- :5076-5079 `_start_plan` 构造 worker 时传入共享门闩
  `state_gate=self._plan_state_gate`。

dispose() 无需改动：worker 不再写 `on_state_changed`，dispose 的
`self._service.on_state_changed = None`（:740）不再会被 worker 的 finally
复活；幸存 worker 期间触发的回调被门闩丢弃。

### 测试证据（tests/app/test_fix_layer_ai_library_aud.py）

- `test_plan_worker_never_touches_service_callback`：属性协议记录
  `on_state_changed` 全部写入，worker.run() 全程零次写入（旧实现会有
  None + 恢复共 2 次写入），且规划期间回调保持安装。
- `test_plan_state_gate_reference_counting`：重叠挂起/恢复计数正确、不为负。
- `test_plan_worker_resumes_gate_before_emit`：emit `finished_plan` 时门闩
  必已恢复。
- `test_on_service_state_dropped_while_gate_suspended`：真实
  AiEditController（MagicMock panel/service）下，挂起期间 `_on_service_state`
  不触碰 `panel.refresh_state`、不 emit `state_changed`；恢复后正常。
- `test_overlapping_workers_no_cross_thread_backfill_no_callback_loss`：
  端到端复现竞态场景（worker A 的 plan_variants 阻塞超过 B 的完整生命周期，
  共享同一 service 与门闩）：panel 零回填、`on_state_changed` 零次被 worker
  改写且始终是原回调对象；两 worker 结束后门闩归零、主线程回填恢复。

## 2. AUD-2900 [Critical/bug/M] — UPDATE_AUX_TEX 用 `id(layer)` 作 layer_id，与渲染端 UUID 键不匹配

**状态：FIXED**

### 根因（交叉验证成立）

- 渲染端绑定键：`async_renderer._bind_aux_textures_single_layer` 用
  `l_id = layer.get('id')`（layer dict 的 UUID 字符串，来源
  image_engine.py:108 `"id": layer.id`）查 `layer_textures`；
- 引擎权威约定：`image_engine.remove_layer` 用
  `layer_id = layer.id  # Use UUID string (matches keys in
  baked_textures/ai_plugin_textures/layer_textures/matte_cache)`；
  `REMOVE_LAYER`/`CLEAR_AUX_TEX` 的清理（`_do_remove_layer`/`_do_clear_aux_tex`）
  均按该 UUID 键释放；
- `Layer.id = str(uuid.uuid4())`（layer.py:409），`id(layer)` 是 int 内存地址，
  永不相等 → `on_apply_grade_from_library` / `on_apply_grade_from_preset` /
  `on_apply_preset_categories_requested` 提交的 LUT3D/warper 纹理存入
  `layer_textures[id(layer)]`，渲染绑定按 UUID 查找落空（回退
  identity_lut/default_warper_tex，调色/变形静默不生效），且这些条目永不被
  REMOVE_LAYER/CLEAR_AUX_TEX 回收（孤儿 GPU 纹理）。

### 修复

src/app/controllers/layer_controller.py 三处 `id(layer)` → `layer.id`
（deepcopy 保留源 UUID 字符串，与渲染端/清理路径一致；与
image_engine.py:1293/1479 等既有提交键对齐）：

- :355 `on_apply_grade_from_library`（原 :352）
- :471 `on_apply_grade_from_preset`（原 :466）
- :777 `on_apply_preset_categories_requested`（原 :770）

每处附注释说明键约定，防回归。审查建议中的「渲染端数据侧加 str 键断言」
落在 async_renderer.py（白名单外），未实施。

### 测试证据

- `test_apply_grade_from_library_uses_layer_uuid`
- `test_apply_grade_from_preset_uses_layer_uuid`
- `test_apply_preset_categories_uses_layer_uuid`（真实 GradeClipboard 粘贴
  lut+warper 类别后重提交）

三者断言提交的 UPDATE_AUX_TEX 中 lut3d/warper 的 `layer_id` 均为 str 且等于
当前 `engine.layers[i].id`（并 sanity 校验 UUID ≠ `id(layer)`）。

## 3. AUD-3800 [Critical/bug/M] — `rename_item` 目标已存在时 `os.rename` 静默覆盖同名文件

**状态：FIXED**

### 根因

POSIX `rename(2)` 对已存在的目标普通文件做原子替换且无提示；原实现
（library_panel.py:599-603）无任何冲突检查，用户输入重名即静默丢失被覆盖
文件（含其 `.topos` 工程关联）。

### 修复

src/app/ui/library_panel.py:599-617 `rename_item`：

- 计算 `new_path` 后先做冲突检查：`os.path.lexists(new_path)` 为真则
  `QMessageBox.warning` 提示已存在并 return，不执行 rename（lexists 连
  悬空符号链接也拦截）；
- `new_path` 与原路径相同（用户未改名）时直接 return，视为 no-op，不触发
  冲突告警；
- 补充 `path: str` / `-> None` 类型注解（遵循 .clinerules 新代码强类型）。

### 测试证据

- `test_rename_refuses_existing_target`：目标重名时两个文件内容均原样
  保留、弹出 warning、无 critical。
- `test_rename_allows_new_name`：不重名时正常完成重命名、无任何弹窗。
- `test_rename_same_name_is_noop`：同名输入为 no-op、无告警。
