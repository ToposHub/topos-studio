## 1. AUD-10700 [Critical/bug/M] — 多选/pinned 场景编辑非首个 section 写入错误节点 — **FIXED**

### 根因
控件回调（`lambda v, k=key: self._on_param_changed(k, v)` 等）在**用户交互时**才读取面板级 `self._current_node_id`（= `set_nodes` 钉住的第一个选中节点，原 1887 行）；`_create_*_row_for_section` 仅在构建期间临时交换该上下文，构建完成即恢复，因此第二..N 个 section（或 pinned section）的编辑全部路由到第一个节点；去重比较也用第一节点的 `_current_parameters`，导致第二节点与第一节点同值的编辑被静默丢弃。

### 修复（node_properties_panel.py）
采用证据报告建议的第一方案：**构建时以默认参数绑定 node_id + `_on_param_changed` 增加 node_id 参数**。

1. `_on_param_changed(self, key, value, node_id=None)`（现 4466-4538 行）：解析 `route_id/route_params/route_type`——`node_id` 指向其它节点时改用该 section 的 `parameters` 快照与 `node_type` 做 trim_range 分支、去重、写回、`parameter_changed.emit(route_id, ...)`；node_id=None/等于当前节点时行为与旧版完全一致（含 `_current_parameters` 面板缓存同步）。`mode/blur_type/keyer_mode/text` 可见性重建 handler 均带 `node_id=route_id` 路由，按 section.node_type 判型，多选两个同类节点时重建的也是**被编辑**的 section（旧行为会重建第一节点的 section）。
2. 新增 `_routed_parameters(node_id)`（紧随其后）：picker/drag 闭包的 fire-time 读取（初始色、当前路径、当前向量）也按所属节点解析。
3. 全部行构建器的信号闭包改为 `n=self._current_node_id` 默认参数绑定（构建期上下文交换期间捕获正确节点）：
   - `_create_combo_row` / `_create_bool_row` / `_create_channel_combo_row`（label 重置 + combo/checkbox）
   - `_create_numeric_row`（2960/2995/3004/3011 同类：label 重置、drag_changed、slider_changed、无 slider 分支 lambda、autokey lambdas）
   - 旧版 `_create_param_row` 尾部（reset_param/checkbox/line_edit）及 `_attach_version_stepper(node_id=)`

## 2. AUD-10801 [Critical/bug/M] — `Qt.ItemFlag.UserRole` 不存在，Add Node 弹窗构造即 AttributeError — **FIXED**

### 根因
PyQt6 中枚举按类拆分，`UserRole` 位于 `Qt.ItemDataRole`，`Qt.ItemFlag.UserRole` 访问即抛 AttributeError；`NodeSearchPopup.__init__ → _populate_tabs → _populate_all_tab` 在第一个真实节点条目即触发。

### 修复（node_search_popup.py）
7 处 `Qt.ItemFlag.UserRole` → `Qt.ItemDataRole.UserRole`（原 341、366、387、475、544、552、617 行；与 graph_node_search_popup.py 的正确写法一致）。`NoItemFlags` 用法本身合法，未动。

### 测试证据
- 新测试 `test_node_search_popup_constructs_and_stores_user_role`：构造不抛异常 + UserRole 数据往返（constant/blur 可读回）。
- **范围外发现（供 AUD-10802 归属方参考）**：构造修复后，`_filter_list` 的表头判断 `item.flags() & Qt.ItemFlag.NoItemFlags` 恒为假（NoItemFlags==0），表头条目 `node_type=None` 会进入 `filter_text in node_type` 抛 TypeError——即搜索框首次键入仍会崩。此为 AUD-10802（Major，未列入本批）登记的表头判断缺陷的实际表现形态，本批未越权修改，测试中也明确注明避开该路径。

## 3. AUD-10910 [Critical/bug/M] — 右键菜单 Delete/Select all 直接 connect 模块函数 → `self=False` → 槽内 AttributeError 终止进程 — **FIXED**

### 根因
`_sv_contextMenuEvent` 中 `act_del.triggered.connect(_delete_selected_keys)` / `act_all.triggered.connect(_select_all_keys)` 连接的是 arity=1 的模块级函数；`QAction.triggered(bool)` 把 `checked=False` 作为唯一实参传入 → `self=False` → `self._model` AttributeError，PyQt6 默认打印回溯后 abort。

### 修复（spline_view.py:1311/1349）
改为 `lambda _checked=False: _delete_selected_keys(self)` / `lambda _checked=False: _select_all_keys(self)`，与同菜单 1301/1303/1307/1323/1334/1345 行的既有正确写法一致（附注释说明 AUD-10910）。`act_fit.triggered.connect(self.fit_view)` 连接的是类体内定义的真方法（174 行），绑定方法 0 参槽由 PyQt 截断多余 bool，无此问题，未动。

### 测试证据
- 新测试 `test_spline_context_menu_delete_and_select_all_receive_view`：monkeypatch 记录桩替换两个模块函数 + 捕获 QMenu，触发两个 action，断言收到的实参是 SplineView 本体而非 False（修复前该用例以 `False != view` 失败）。
- 回归：tests/ui 全部 spline 套件（menu_hotkeys/multi_select/axis_modes/extrapolation/snap/tangent_input/hit_test/render/zoom_pan）`105 passed`（与 keyframes 合并运行）。

## 4. AUD-9500 [Critical/risk/M] — `_retry_renderer_init` 引用未定义 `viewer_node_id`，重试路径必抛 NameError — **FIXED**

### 根因
`_retry_renderer_init`（composite_page.py 1532-1588）函数体内从未定义 `viewer_node_id`（唯一定义在 `on_enter` 的局部作用域），`initialize_renderer()` 成功后构建 RenderRequest 即 NameError，从 QTimer 槽逃逸 → qFatal。

### 修复（composite_page.py，现 1553-1562 行）
照抄 `on_enter` 1417-1422 的既有防御写法：
```python
resolve_viewer_node_id = getattr(self, "_resolve_viewer_node_id", None)
viewer_node_id = (
    resolve_viewer_node_id()
    if callable(resolve_viewer_node_id)
    else self._resolve_preview_node_id()
)
```
（`_resolve_viewer_node_id` 是本类方法，5096 行；与 1755 `update_color_output` 同路径。）

### 测试证据
- 新测试 `test_retry_renderer_init_resolves_viewer_node_id`：以最小 fake self（renderer=None + initialize_renderer 置入 fake renderer + `_resolve_viewer_node_id → "viewer-node-1"`）直接调用 `CompositePage._retry_renderer_init`，断言不抛异常、提交 `EVALUATE_GRAPH` 且 `RenderRequest.viewer_node_id == "viewer-node-1"`（修复前该用例 NameError）。
- 回归：CompositePage 相关 UI 套件（selection_attach / keyframes_panel_multiselect / composite_keyframes_dock / transport_linkage）`50 passed`。
