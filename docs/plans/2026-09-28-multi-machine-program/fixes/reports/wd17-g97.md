## AUD-37300 — ClipFrameMapper 边界闭区间与 TimelineClip 语义不一致

**问题**：`timeline_to_source_frame` 用闭区间放行
`timeline_start + timeline_duration`，speed=1.0 时返回 `source_end + 1`
（越界 source frame 且不报错）；`TimelineClip.timeline_to_source_frame`
（`src/features/edit/core/timeline_v2.py:373`、`src/shared/media/timeline.py`）
均为开区间上界。

**修复**（coordinate_map.py:127-140）：
- 边界校验改为 `timeline_start <= timeline_frame < timeline_start + timeline_duration`，
  错误信息区间标注同步改为 `[start, end)`；
- 类 docstring 与 `timeline_to_source_frame` / `clip_local_to_source_frame`
  docstring 显式声明闭开区间语义；
- `clip_local_to_source_frame` 委托同一校验，自动获得一致边界。

**验证**（TestAud37300TimelineBoundary，7 用例）：
- 正例：最后一个有效帧 139 → 199 仍可映射；`clip_local 99` 正常；
- 反例：`timeline_frame == 140`（= timeline_end）抛 ValueError（修复前返回 200）；
- `clip_local == timeline_duration` 抛 ValueError；2x 速边界同样拒绝；
- 与 shared `TimelineClip` 在 [40,140) 逐帧 parity，上界帧两者都拒绝。

## AUD-37302 — build_corner_pin_export 缺少矩阵有限性防护

**问题**：TRS/AFFINE 模式的 WEAK/VALID 变换未做有限性检查（仅 HOMOGRAPHY
有 `check_homography_stability` 兜底），单个坏帧使 `transform_corners` 抛
`ValueError("单应性投影出现非有限值或齐次除零")`，`build_corner_pin_export`
/ `write_corner_pin_export` 整体失败，与旧接口 `build_corner_pin` 的
skip 行为不一致。

**修复**（corner_pin.py:311-339）：
- 调用 `transform_corners` 前增加 `np.all(np.isfinite(...))` 检查；
  非有限帧按坏帧条目处理：`corners=None`、`area/area_ratio=0.0`、
  `valid_geometry=False`、`geometry_reason="变换矩阵含非有限值"`；
- 有限矩阵仍可能齐次除零（w 分量近 0），补 `except ValueError`（具体
  异常类型）按同一坏帧标记，不再让整次导出抛异常；
- 好帧条目结构不变（回归用例覆盖）。

**验证**（TestAud37302FiniteGuard，5 用例）：NaN/Inf 矩阵帧只标记自身、
好帧 8/10 仍有 corners；齐次除零矩阵标记不抛；正常矩阵四角输出不变；
FAILED 帧既有 `include_missing` 语义保留。

## AUD-37306 — 分桶均匀化后的全局截断按桶序整桶丢弃点

**问题**：`_balance_by_grid` 把各桶按 dict 插入序（≈强纹理桶在前）拼接后
`selected_arr[:max_features]` 截断，576 上限 > 240 上限的场景下后插入的
弱纹理桶被整桶丢弃，破坏"保证几何求解的点位分布"目标。

**修复**（feature_detector.py:107-165）：
- 截断改为 `_round_robin_select`：逐桶轮转取点（桶内保持响应降序），
  每一轮所有未空桶各贡献 1 个点，`limit >= 非空桶数` 时每个非空桶至少
  贡献 1 个点——截断发生在轮次之间而不是桶之间；
- 桶序 = 各桶最强点的响应序（`goodFeaturesToTrack` 降序 + dict 首次
  插入序），全局最强点仍最先入选（响应优先保留）；
- 空选择返回 `(0, 2)` 形状空数组（与既有空结果约定一致）。

**验证**（TestAud37306RoundRobinTruncation，6 用例）：强纹理桶独大
（5+2 点、limit=4）时弱纹理桶保留代表（旧代码输出全部来自 A 桶）；
3 桶 × 3 点、limit=5 时三桶均有代表；不触发截断时不丢点；
`per_bucket_limit` 桶容量语义与"桶内响应最强优先"保留；limit=0 返回
`(0,2)`；真实角点图端到端检测两个纹理象限均有分布。

## AUD-37312 — redetect_reference_points 重新从 0 编号，锁定/排除集合语义错位

**问题**：重新检测后观测按新检测顺序从 0 重编号，旧 `locked_feature_ids` /
`excluded_feature_ids` 指向的旧编号会错位作用到任意新点上，"锁定点永不
被删"承诺失效。

**修复**（point_manager.py:106-171）：
- **锁定点观测原样保留**（ID 与坐标不变）——重新检测后
  "锁定点永不被删"依然成立；
- **新检测点从既有观测的最大 feature_id 之后编号**（`next_id = max(旧
  IDs, default=-1) + 1`）：旧 ID（包括排除集合中的 ID）不会命中任何
  新点，排除语义不再误伤新检测；旧排除 ID 对已不存在的点悬挂、天然
  无害；
- 锁定/排除集合本身不修改（与既有验收测试
  `test_redetect_does_not_touch_lock_sets` 的契约保持兼容）；
- 返回值 = 保留 + 新检测总数，`result_version`/`modified_at` 递增不变。

**验证**（TestAud37312RedetectIdSemantics，5 用例，stub sampler/detector
注入，不依赖 fixture）：锁定 ID 0/3 的旧观测与坐标保留；新点 ID 为
[5,6,7]（不与旧 ID 碰撞，排除 ID 1 不命中任何新点）；集合不变、计数
= 2+3；`active_observations` 过滤后无新点被旧排除误伤；无旧观测时仍从
0 编号（兼容既有行为）。

## AUD-37403 — 低纹理参考模板使外观门控静默失效、诊断恒报满分

**问题**：`_ref_template` 只做 ≥12px 尺寸检查；实测（本项目 .venv，
cv2 4.11.0）`matchTemplate(常量图, 常量模板, TM_CCOEFF_NORMED)` 返回
**1.0**（0/0 规约为满分）。pattern 取在天空/墙面/黑场等近常量内容上时，
任意 warp 与模板的 NCC 恒为 1.0 → 外观门控形同虚设，遮挡帧只要几何自洽
仍可能 VALID；`FrameDiagnostics.appearance_similarity` 恒 1.0 误导面板。

**修复**（tracker_2d.py:56-63, 861-889）：
- 新增模块常量 `TEMPLATE_MIN_TEXTURE_VAR = 1.0`（拉普拉斯方差下限，
  范围有测试锁定）；
- `_ref_template` 增加纹理能量检查：`cv2.Laplacian(t, CV_64F).var() <
  TEMPLATE_MIN_TEXTURE_VAR` → 返回 None，让低纹理模板走**显式无门控
  路径**（`_appearance_similarity` 对 None 返回 1.0，语义为"门控禁用"
  而非伪满分），并 `logger.debug` 记录；
- 副作用修复：`_template_recapture` 的回退路径同样经 `_ref_template`，
  低纹理模板不再进入整帧 matchTemplate（此前常量模板处处满分 1.0 ≥
  阈值 0.60，会锚到任意位置）。

**验证**（TestAud37403LowTextureTemplate，9 用例）：平坦/近平坦模板
→ None；纹理模板正常返回（模板图/平移矩阵/矩形均正确）；小尺寸防线
保留；常量 NCC=1.0 根因行为文档化断言；None 模板 → 1.0（无门控）；
纹理模板对错误内容得分 < 0.45（门控拦截有效）、对参考帧 > 0.99。

## AUD-37410 — 缓存键未包含 shape_geometry，遮罩形状变化后返回陈旧结果

**问题**：`make_key` / `key_for_request` 的键不含 `TrackRequest.
shape_geometry`，而它实质改变初始特征检测（tracker_2d 光栅化形状掩码）。
同包围盒内改遮罩形状、其余参数不变时命中旧键，直接回发按旧形状计算的
跟踪结果。`tracking_service._cache_key_for`（AUD-24907）曾在服务侧追加
几何摘要绕过，shared 层根因未修。

**修复**（tracking_cache.py:1-45, 76-131）：
- `make_key` 新增 `shape_geometry: Optional[dict] = None` 参数（追加在
  位置参数顺序末尾，既有调用方零影响），payload 增加 `"sg"` 字段；
  `key_for_request` 传入 `request.shape_geometry`；
- 新增 `_normalize_shape_geometry`：浮点统一 `round(…, 6)` 规避抖动
  （与 pattern/search 同策略）、dict 按键排序（键序无关）、tuple 视同
  list、bool/int 直通、非有限浮点与其余不可 JSON 化值以 `repr` 参与
  （键构造对任意几何都可成功）、None 与空 dict 分别编码；
- 模块/类 docstring 同步声明键包含全部影响结果的输入。

**说明**：`tracking_service.py` 的服务侧摘要（白名单外，未改动）与本次
修复叠加后仅是冗余编码，语义不变、无需迁移（内存 LRU，无持久化键）。

**验证**（TestAud37410CacheKeyShapeGeometry，7 用例）：同包围盒内改形状
（椭圆 a/b、矩形三向互异）键互异；几何相同（键序不同、tuple/list 等价、
浮点抖动 1e-10）键稳定；None / {} / 几何 三者互异；NaN 与不可序列化值
不破坏键构造；`key_for_request` 与显式 `make_key` 一致；端到端改形状后
`cache.get` 未命中旧结果；`dataclasses.replace` 仅改几何即换键。
