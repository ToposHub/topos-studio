## 逐条明细

### AUD-39712 [Major/bug] create_yuv_program 用 CWD 相对路径加载外部 shader — FIXED

- `video_upload.py` 新增模块级 `_video_yuv_shader_candidates()`：首选 `<repo_root>/src/features/color/shaders/video_yuv.glsl`（由 `Path(__file__).resolve().parents[3]` 锚定，`src/shared/video/` 深度上溯三级即仓库根，与 `ffmpeg_locator.py`/`monitor_output.py` 既有惯例一致），次选原 CWD 相对路径（冻结部署等特殊布局兼容）。
- `create_yuv_program()` 按候选顺序探测 `is_file()`，全部缺失才回退内置 shader，且回退必留 WARNING（不再静默降级）；`except Exception` 窄化为 `(OSError, ValueError, moderngl.Error)`。
- 测试：任意外启动目录（`monkeypatch.chdir(tmp_path)`）仍加载外部 VS（以外部文件独有注释行作标记断言）；候选首位为绝对路径且真实存在；候选全缺失时回退内置并产生告警。

### AUD-39720 [Major/risk] run_yuv_gpu_self_test 外层异常路径不清理 output_tex/fbo — FIXED

- `yuv_gpu_self_test.py::run_yuv_gpu_self_test`：`output_tex`/`fbo` 在 try 之前初始化为 None（此前为 try 块内局部变量，except 分支不可达引用）；外层 `except` 调用 `_cleanup_self_test_resources(fbo, output_tex)` 后再返回失败结果。自检本身运行在渲染线程，清理不违反「GL 仅渲染线程」铁律。
- 早退路径复核：upload_failed/upload_returned_none 发生在资源创建前（无需清理）；all_black/all-transparent 路径原有清理保留。
- 测试：render 阶段抛异常 → 输出纹理与 FBO 各恰好 release 一次；readback 阶段抛异常同样清理；上传阶段失败无资源创建、无误清理崩溃。

### AUD-39801 [Major/risk] _upload_planar_r8 回退丢失 subsampling，R8 池不可用时 8-bit 422/444 崩溃 — FIXED

- `yuv_gpu_upload.py::_upload_planar_r8` 新增 `subsampling: Optional[str] = None` 与 `alpha_bit_depth: Optional[int] = None` 参数；`_r8_pool is None` 回退时按 subsampling 分发到 `upload_yuv422/upload_yuv444/upload_yuv420`（均透传 a/alpha_bit_depth），不再一律 `upload_yuv420`（旧路径在 420 尺寸断言 `u_h == h//2` 处 AssertionError）。`subsampling=None` 时按平面形状推导（u 全尺寸→444，u 高==y 高→422，否则 420），直接调用亦安全。
- 三个内部调用方（upload_yuv420/422/444）与统一入口 `upload_yuv_planar` 全部显式传入 subsampling 与 alpha_bit_depth（顺带修复了 r8 重定向路径此前丢弃 alpha_bit_depth 的问题）。
- 测试：444/422/形状推导三分发各一例（mock 级）+ 真实 GL 端到端一例（`_r8_pool = None` 后 8-bit 422 上传成功走 float16 路径，旧代码此处必崩）。

### AUD-39802 [Major/bug] run_r16ui_self_test 覆盖共享的 yuv_matrix/color_range 且不恢复 — FIXED

- `yuv_gpu_upload.py::run_r16ui_self_test`：进入时保存 `_yuv_matrix`/`_color_range`，新增 `finally` 无条件恢复（覆盖 通过/校验失败/异常 全部出口）。此前自检强制 BT.709/limited 后不恢复，真实首帧以自检参数渲染（BT.601/full 内容首帧颜色错误）。
- 测试：异常路径恢复（mock）+ 真实 GL 完整自检后恢复（预设 BT.601/FULL，自检跑完仍是 BT.601/FULL）。

### AUD-39803 [Major/risk] run_r16ui_self_test 异常路径泄漏 FBO 与输出纹理 — FIXED

- 同函数：`output_tex`/`fbo` 提前初始化为 None，`except` 分支先 `_cleanup(fbo, output_tex)` 再置失败态返回（与 AUD-39720 同构修复）。
- 测试：render 抛异常时自检创建的 4 通道 f1 输出纹理与 FBO 各恰好 release 一次（`_RecordingCtx` 记录每次创建的对象后断言）。

### AUD-39804 [Major/bug] 纹理池在容量未满时优先抢占 busy 槽位，稳态下每 (plane_type,尺寸) 仅 1 张纹理 — FIXED

- `yuv_gpu_upload.py::YUVTexturePool::_acquire_texture` 获取顺序重排为：① 空闲匹配槽复用 → ② **容量未满则新建槽位** → ③ 池满才抢占匹配尺寸/类型的 LRU 槽 → ④ 池满且无匹配尺寸时重建最旧槽。旧顺序是 ③ 在 ② 之前：第二帧即抢占仍在轨的第一帧纹理（GPU 写读竞态 + 池容量形同虚设）。
- 稳态行为：在轨帧各占独立槽位直至池满，之后按 LRU 抢占最旧——符合「固定池大小 + 双/多缓冲」的池化语义；消费方持有纹理引用（如 video_async_renderer 的 `_yuv_y_tex`）不再被下一帧覆盖。
- 既有两处编码旧行为的测试同步更新（见总表下方说明），其余 56 项池/上传相关既有用例零改动通过。

### AUD-39805 [Major/bug] _last_upload_mode 全局单值决定渲染 shader 分发，混合位深多轨道时采样器类型不匹配 — FIXED

- 新增 `_should_use_integer_sampler(y_tex)`：以本帧 Y 平面纹理的 `dtype == 'u2'`（R16UI 池纹理的固有属性）逐帧判定 usampler2D 分发；dtype 不可得（mock/非 ModernGL 对象）时回退 `_last_upload_mode`（兼容旧行为）。
- `render_yuv_to_rgb`（原 2615）与 `render_nv12_to_rgb`（原 2793，计划标注的同型缺陷）两处分发点全部改用该判定。混合位深场景：8-bit 轨道（R8 直传）上传把全局 mode 改写后，仍持有 R16UI 纹理的轨道渲染不再错走 sampler2D 路径（反之亦然）。
- `_last_upload_mode` 保留（统计/计时展示与 mock 回退用途），不再是分发的唯一依据。
- 测试：u2 纹理 + mode 被改写 → usampler；f1 纹理 + mode=r16ui → float 路径；无 dtype 对象 → 回退 mode；NV12 分发点同款双向断言。

### AUD-39806 [Major/risk] render_nv12_to_rgb 每帧创建/销毁临时 VBO/IBO/VAO，且异常路径泄漏 — FIXED

- 新增 `_get_nv12_quad_vao(shader)`：VBO（复用共享 `_quad_buffer`，惰性创建）与专用 IBO（`_nv12_quad_ibo`）只建一次，VAO 按 shader 对象 id 缓存（缓存持有 program 强引用防 id 复用误命中；上限 8 个防外部每帧换 shader 的无界增长，超限整体释放重建）。
- `render_nv12_to_rgb` 每帧仅 `vao.render(...)`——无临时 GL 对象创建，render 抛异常时无对象可泄漏（缓存对象生命周期归 `release()`）。`_release_nv12_quad_resources()` 挂入 `release()`（VBO 由既有 quad 释放逻辑统一处理，多路径共享不重复释放）。
- 与 G-P0-01（NV12 shader 只编译一次）配套，NV12 float 路径的 program/VAO/VBO/IBO 均为常驻复用。
- 测试：两次渲染仅 1 个 VAO、2 个 buffer（VBO+IBO）且 render×2；release 释放缓存 VAO 与两个 buffer；render 抛异常无临时对象产生且缓存对象仍随 release 释放；外部不同 shader 各自缓存。
