## AUD-37803 [Critical/bug/M] — FIXED

**问题**：Apply 按钮把 `clicked(bool)` 的 `False` 当 `QListWidgetItem` 传入槽，`False.data(...)` 必崩 `AttributeError`（Qt 槽内未捕获默认 abort）。

**位置**：src/shared/ui/audio_mixer/preset_dialog.py:98（连接）、147-153（槽）。

**修复**：按钮连接改为零参 lambda（`self._apply_btn.clicked.connect(lambda: self._on_apply_clicked())`），丢弃 clicked 携带的 checked(bool)；`itemDoubleClicked → _on_apply_clicked(item)` 的双击路径保留原带参方法（该信号传真实 item，语义正确）。lambda 零参连接与本文件 SnapshotBar（W14）既有模式一致。带参槽 `_on_apply_clicked(item=None)` 签名不变，回退 `currentItem()` 逻辑不变。

## AUD-37808 [Critical/bug/M] — FIXED

**问题**：`_init_ui` 已连接 `_output_combo.currentIndexChanged → _on_committed`，`_load_initial_state` 先 `setCurrentIndex`（output 指向 Bus 时索引变化）后加 send slots → `_on_committed` 在 `_send_slots` 为空时 emit `routing_committed(track_id, {output_bus_id, sends: []})`；消费端 `edit_controller._on_mixer_routing_committed`（edit_controller.py:3421-3488）以替换语义 `mgr.set_track_routing(track_id, bus, [])` + 逐条 `RemoveSendCommand` → 仅仅打开对话框就清空该轨全部发送。

**位置**：src/shared/ui/audio_mixer/routing_dialog.py:212（连接）、261-270（装载）、303-310（收集）。

**修复**（状态锁方案）：
1. `__init__` 中 `self._loading = True` 包裹 `_init_ui()` + `_load_initial_state()`，装载完成后复位 `False`；
2. `_on_committed` 开头 `if self._loading: return` —— 初始化程序化变更不发射 committed，仅用户交互后发射（符合 .clinerules"对话框初始化不得提前发射 committed 等副作用信号"）；
3. 装载完成后调用一次 `_validate_and_warn(self._collect())`：纯校验（显示既有告警，如目标 Bus 已删除的 send），不发射任何信号 —— 履行模块 docstring"打开即校验"承诺且不引入副作用。

**行为验证**：构造后 `_loading is False`、`_send_slots` 完整、`_collect()` 的 sends 完整；模拟用户改选输出目标后 committed 正常发射且 payload 含完整 sends。

## AUD-37809 [Critical/risk/M] — FIXED

**问题**：`Send.__post_init__` 对空 `target_bus_id` 抛 `ValueError`（timeline_v2.py:1602-1604），三条用户路径在 Qt 槽内未捕获：(1) 无 Bus 轨时点"+ 添加发送"（`default_target=""`）；(2) 选"(选择 Bus)"占位项后任一字段变化触发 `collect()`；(3) 既有 send 的目标 Bus 已被删除（combo 停在占位项）后任何编辑。

**位置**：routing_dialog.py:78、136-141、283-287；timeline_v2.py:1602-1604。

**修复**（构造前校验/过滤，保留 Send 的构造校验契约）：
1. `_SendSlotWidget.collect()`：空 target 时返回 `None`（与 `_removed` 一并被 `_collect` 跳过），永不构造非法 Send；
2. 新增 `_SendSlotWidget.is_target_empty` 属性；`_validate_and_warn` 检测存在空目标的存活 slot 时在告警区追加提示（"不允许无声跳过"原则），用户可感知该发送不会生效；
3. `_init_ui`：`bus_tracks` 为空时"+ 添加发送"按钮 `setEnabled(False)` + tooltip 说明（按钮存为 `self._add_send_btn` 便于测试）；`_on_add_send` 兜底守卫（防程序化触发）：无 Bus 时 `QMessageBox.information` 提示并 return，不再走到 `Send(target_bus_id="")`；
4. **timeline_v2 侧防御**：`EditTrack.from_dict`（原 2753 行）对 `sends` 原始 dict 做过滤 —— 仅接受 `isinstance(s, dict) and s.get("target_bus_id")` 非空的条目，且容忍 `"sends": null`（`data.get("sends") or ()`）。历史/损坏数据中的空 target send 不再让整个 EditTrack 反序列化失败（此前单条脏数据即阻断项目加载）。

**未改**：`Send.__post_init__` 的 ValueError 保留（.clinerules"构造前校验必填字段"），由调用侧保证不传空值。

## AUD-37900 [Critical/bug/M] — FIXED

**问题**：Limiter 参数编辑只接 `limiter_committed` 且处理器只 emit `track_effects_preview` → 用户修改永不进命令栈（不持久化、不可撤销，undo 其它链命令或重开项目即丢失）；`limiter_preview` 信号完全未连接。

**位置**：src/shared/ui/audio_mixer/track_mixer_widget.py:1166-1168（连接）、1174-1191（处理器）。

**修复**（对齐同文件 compressor 路径，1224-1244 行范式）：
1. `_open_limiter_editor`：`limiter_preview → _on_limiter_edited(inst, p, commit=False)`、`limiter_committed → _on_limiter_edited(inst, p, commit=True)`；
2. `_on_limiter_edited` 增加 `commit: bool = True` 参数：commit 分支 `_refresh_effect_list()` + emit `track_effects_committed`（命令栈/持久化），非 commit 分支 emit `track_effects_preview`（实时听感）。与 `_on_compressor_edited` / `_on_reverb_edited` 等 7 类效果器完全同构。
