## 设计决策与残留说明

- **AUD-5306 `_COLOR_CORRECT` 不加 `u_mask_channel` 的原因**：`tests/composite/test_fix_nodes1_aud2.py::test_marker_params_cover_shader_uniforms` 把该 shader 的 uniform 集与 `ColorCorrectNode._effect_params` 做**严格集合相等**锁定，nodes/ 与既有测试均不在本批白名单；加 uniform 必然破坏该契约。故采用审计核心诉求的确定性方案：启发式 → 恒定 Rec.709 luma（与 merge 默认通道 u_mask_channel=0 完全一致），歧义消除、六节点遮罩语义统一；白底兜底 mask 行为逐位不变。其余五 shader 无同类 uniform 契约锁定（已逐一核查 test_fix_evaluators_aud2/test_fix_nodes1_aud2 的 FakeProgram 均只做子集断言），完整落地选通道 uniform，评估器后续可用 `_set_uniform_if_present(prog, 'u_mask_channel', ...)` 接线。
- **AUD-5307 `_FUSED` 用 GLSL 恒等初始化器而非 Python 侧默认值**：当前 `_apply_fused_chain` 只设 lift/gamma/gain/offset（base_evaluator 超白名单不可改），`uniform float u_grade_whitepoint = 1.0;` 等初始器保证未设置时阶段输出逐位不变（真实 GL 读回验证 0.0/1.0/1.0/0.0）；同时补齐审计指出的"按全参数集设置 uniform 将 KeyError 丢图"隐患。注意 `_FUSED_COLOR` 当前无生产驱动（`_apply_fused_chain` 固定取 'fused' 程序），其修正为纯正确性对齐，无行为回归面。
- **AUD-5409 采用"重挂子链"而非"仅淘汰无后代叶子"**：审计给出两个方向；"仅叶子"方案在线性历史（最常见形态）中唯一叶子是受保护的 current 节点，**剪枝将永远无法执行**，max_nodes 硬上限失效。重挂方案保持 .clinerules"undo 树结构变更保持链完整"硬约束（父链无洞、keep 节点可达、游标不落 ghost），代价是被截断段的动作不可再撤销——这是"从最旧端截断"的固有语义，审计原文亦承认其为"近似预期"。AUD-5408 的合并删除路径（先行修复）保持原样未动。
- **AUD-5410 的 `pending_action` 瞬态字段**：不改 `to_dict` 输出（action 键仍由 `self.action` 序列化），round-trip 对称；`load_from_file` 异常日志同步升级 error 级。剪枝不可恢复节点时复用 AUD-5409 的链保删除 helper，两处共享同一不变量。
- **AUD-5412 游标推进语义**：undo 失败后推进到父、redo 失败后推进到子——两方向都与"已应用前缀"一致，重试永不重放（审计的"禁止静默重放"）；group 子动作失败后继续处理剩余项，使 group 尽量收敛到目标态，每个失败都有独立 error 日志（含位置）。
- **AUD-5601 残留（预存引擎缺陷，非本批范围）**：`ExpressionManager.detect_circular_dependency` 的 DFS 在首轮即把起点标记 visited，`dep_key not in visited` 使起点永不重新入栈，环检测恒 False（连自引用都漏）。该文件属 wd4-g29 批次域（其 AUD-11511 刚为该类加过 RLock，但未触及此逻辑缺陷）。本批完成 plan 路径接线 + `xfail(strict=True)` 行程锁（reason 完整描述缺陷与修复后预期），引擎修复落地后该 xfail 会以 XPASS 强制失败提醒翻正。
- **并发工作树说明**：本批执行期间 wd5-g30 在同一工作树落地 node_plugin.py 的 AUD-5200（PLUGIN_DIRS parents[4]）修复；两批改动区域无重叠，全部标记与编译已复核共存，邻接测试（含其 test_fix_wd5g30_aud.py 51 用例）全绿。
