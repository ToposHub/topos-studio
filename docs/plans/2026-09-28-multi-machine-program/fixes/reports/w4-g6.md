## AUD-34703 — FIXED

**位置（修复前）**：`src/shared/media/ffmpeg_source.py:2311`（回退入口，另见 2336-2366
fallback 链消费、2576-2579 与 2664-2672 平面切片）。

**根因**：`_convert_frame_planar` 在 planar 缩放失败或格式未映射时，复用 packed 路径的
`_get_reformat_fallback_chain(original, rgb48le/rgba64le)`，把帧 reformat 到 packed
RGB 终点格式后仍调用 `_extract_planes_from_frame` 按平面布局切片：packed 帧只有一个
交错平面（line_size = 6×width），`samples[:, :plane_width]` 只取每行前 1/3 样本；
`DecodedFrame.pixel_format` 标成 packed 名而 `planes` 是错乱单平面——布局标志与实际
切片不一致，GPU planar 上传路径拿到坏数据。

**修复**（`src/shared/media/ffmpeg_source.py`）：
1. 新增 `_reformat_to_planar_fallback(frame, source_pix_fmt, w, h) -> tuple[frame, fmt]`
   （位于 `_get_planar_format_for_scaling` 之后）：取 fallback chain 的**中间格式**
   （全部是同族 planar YUV：yuv420p/yuv444p/yuv*p16le/yuva*p 等），逐候选在目标
   尺寸上 reformat，以其为终点交付；全部失败时原样返回源 planar 帧（放弃缩放，
   保持正确布局），绝不落到 packed。
2. reformat 失败与未映射两个 fallback 块均改走上述助手；成功时 `pix_fmt`/`frame`
   同步为该 planar 格式，`proxy_reformat_fallback` 诊断标志语义不变。
3. 提取前新增布局一致性防御：若 `pix_fmt` 仍以 `_PACKED_RGB_PREFIXES`
   （`rgb/bgr/argb/abgr`，模块级新常量）开头，抛
   `MediaDecodeError("Planar output not available: ...")`——显式失败优于错乱数据。

**行为变化**：回退成功的输出从"单平面 1/3 截断错乱数据"变为完整 planar YUV
（如 yuva444p12le → yuva444p）；所有 planar 候选都失败时从"错乱 packed 切片"
变为"未缩放的源布局 planar 帧"；planar 合约下任何 packed 输出都显式报错。

## AUD-34900 — FIXED

**位置（修复前）**：`src/shared/media/hwaccel.py:866-878`。

**根因**：`FFmpegHwaccelSource.read_next_frame` 硬解分支直接
`self._container.decode(self._video_stream)` 建迭代器，跳过了父类
`read_next_frame`（ffmpeg_source.py:1246-1272）的三段式 seek 落地契约：
(1) 不消费 `_pending_av_frame` → 普通 GOP/Intra seek 后返回 N+1 帧（off-by-one），
落地帧永久滞留；(2) 不走 `_pull_next_frame_from_seek_session()` → SLICE 会话帧被
跳过；(3) 建迭代器前不调 `_resync_main_session_if_needed()` → HEVC 类 seek 后
主（hwaccel）容器 demux 位置从未回同步，`_main_resync_pts` 悬挂，返回完全错位的帧。

**修复**（`src/shared/media/hwaccel.py`，硬解分支重写）：逐字对齐父类契约——
先 `if self._pending_av_frame is not None` 消费落地帧（经 `_convert_hwaccel_frame`
转换，`_current_frame = max(_current_frame, decoded.frame_index + 1)`），再
`_pull_next_frame_from_seek_session()` 续读 seek 会话（同款 max 语义），最后才在
`_resync_main_session_if_needed()` 之后建主迭代器（`_current_frame += 1`）。
转换统一经 `_convert_hwaccel_frame`（内部自行分派 planar/packed），CPU 分支
（`_using_hwaccel=False` → `super()`）不受影响。

**行为变化**：硬解模式下 `seek_frame(N)` 后的首次顺序读返回第 N 帧而非 N+1 帧；
SLICE seek 会话续读与会话耗尽后的主会话回同步与父类（CPU 路径）完全一致。
`read_frame_planar`/`_read_next_frame_planar` 未被覆盖、本就走父类正确路径，未动。

## AUD-35205 — FIXED

**位置（修复前）**：`src/shared/media/macos_vt/vt_compression.py:185-198`。

**根因**：`_native_pointer` 对非 int/c_void_p 的 native_handle 先试 PyObjC
（`objc.pyobjc_id`），失败后落入 `pointer = int(hash(value))` 兜底——把任意哈希
整数当 CVPixelBufferRef 传给 `VTCompressionSessionEncodeFrame`，原生层解引用
野指针 → 进程级崩溃（ctypes 回调无法拦截）；hash 为负时经 `c_void_p` 回绕成
非法地址。注释自称 "defensive ABI guard"，实为伪造指针。

**修复**（`src/shared/media/macos_vt/vt_compression.py`）：
1. 删除 `hash()` 兜底分支：PyObjC 路径失败（无 PyObjC / handle 非指针对象）直接
   `raise VideoToolboxCompressionError("videotoolbox_surface_handle_not_pointer_like")`
   （保留 `from exc` 因果链）。
2. 有效性检查从 `if not pointer` 收紧为 `if not pointer or pointer < 0`：负整数
   同样按 `videotoolbox_surface_handle_null` 拒绝，不再进入原生层。

int/c_void_p/PyObjC 三条正常路径行为不变（`submit()` 现有调用
`_native_pointer(surface.native_handle)` 合约不受影响）。

## AUD-35900 — FIXED

**位置（修复前）**：`src/shared/media/topos_source.py:1309`（调用点）与
`:1996`（`planes[3] = scratch` 替换点）。

**根因**：`read_next_frame` 单帧路径直接把 `entry.arrays`（池条目自己的列表，非
拷贝）传给 `_assemble_decoded_frame`；alpha 移位分支原地执行 `planes[3] = scratch`
——`entry.arrays[3]` 被替换，原始 alpha ndarray 失去最后 Python 引用被释放，而
`entry.views[3].pixels`（条目创建时 `make_views` 绑定的裸地址）仍指向已释放缓冲；
条目再次被 `decode_views_request` 复用时原生解码写入已释放内存（use-after-free）。
另两处调用（1273/1796）传 `list(arrays)` 拷贝，恰好掩盖了该缺陷。

**修复**（`src/shared/media/topos_source.py`，双保险）：
1. **根因**：`_assemble_decoded_frame` 不再原地改写调用方列表——alpha 移位结果在
   局部副本上替换（`planes = [*planes[:3], shifted_alpha]`；无池路径的表达式移位
   同样处理）。`entry.arrays` 与 `entry.views` 永不解耦，任何调用方传法都安全。
2. **调用点对齐**：1309 改传 `list(entry.arrays)`，与 1273/1796 两处一致（防未来
   回归的纵深防御）。
3. **连带根因修复（复用门）**：`_entry_free` 的 scratch 判忙检查原写法
   `scratch = entry.alpha_scratch; sys.getrefcount(scratch) > 2` ——局部变量自身
   持有一份引用，把基线从 2 抬到 3（实测：`sys.getrefcount(h.a)`=2 而
   `x=h.a; sys.getrefcount(x)`=3），导致**带 scratch 的条目永远判定为忙**：alpha
   流的池条目从不被复用、每帧全量临时分配（M2/P1-13 的滚动复用对 Topos 4444
   a8/a10/a12 静默失效）。改为直接以属性表达式调用
   `sys.getrefcount(entry.alpha_scratch) > 2`，与 arrays 同基线口径。该缺陷同时
   是审查报告所述触发链（"消费方释放后 `_entry_free` 判空闲并复用"）失真的
   原因；修复后复用门按文档语义工作，且由第 1 条保证复用安全（views 不悬垂）。

**行为变化**：alpha<16-bit 流每帧装配后 `entry.arrays[3]` 仍是原始 raw 缓冲
（`entry.views[3].pixels` 指向的内存始终存活）；消费方释放移位帧后条目可被池
正常复用（scratch 复用，零新分配）。
