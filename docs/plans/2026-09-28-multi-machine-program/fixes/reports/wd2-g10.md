## AUD-03901（Major/risk）Cancel 回滚外观项双重发射预览信号

**状态：FIXED**

**根因**：`_restore_preview_snapshot` 程序化 `setCurrentIndex`/`setValue`
会逐项触发已连接的 `currentIndexChanged`/`valueChanged` →
`_on_preview_setting_changed` 逐项发射；末尾 `_emit_batch_preview()` 再对
全部 previewable key 发射一次。`_on_restore_defaults` 正确使用了
`_preview_blocked` 状态锁，此路径漏用，直接违反 .clinerules
"程序化更新控件须状态锁防递归信号"。

**修复**（preferences_dialog.py `_restore_preview_snapshot`）：恢复控件值
全程包在 `self._preview_blocked = True ... finally: False` 中，末尾
`_emit_batch_preview()` 统一发射（每 key 恰好一次）。try/finally 保证
中途异常（如快照缺键）不会把 `_preview_blocked` 永久留在 True。

**测试**：`test_cancel_rollback_emits_each_preview_key_once`——改
ui_scale 后 Cancel，断言 `("ui_scale", 100)` 恰出现一次且批次共 3 条
（旧实现为 2 次/4 条以上）。

## AUD-03903（Major/bug）Cancel 回滚不完整：FE 直写与模块页副作用无法撤销

**状态：FIXED**

**根因**：`_apply_settings` 中 `fe_main.save_config(fe_conf)` 直接写 FE
自己的 config.json；`page_obj.apply(cfg)` 可产生模块级副作用。Cancel 只
还原宿主 config，两者永久保留。

**修复**（preferences_dialog.py）：
1. `_fe_config_snapshot: dict | None` 字段；`_apply_settings` 首次覆写 FE
   config 前捕获快照（`dict(fe_conf)`，仅本会话首次——Apply→Apply→Cancel
   回滚到打开时状态）。
2. `_on_cancel` 在 `self._applied` 时依次调用：
   `_restore_config_snapshot()`（宿主，见 AUD-03904）→
   `_restore_fe_config_snapshot()`（`fe_main.save_config(dict(snapshot))`，
   失败 `logger.exception`）→ `_rollback_module_pages()`。
3. `_rollback_module_pages`：对实现可选 `rollback()` 钩子的模块页逐一
   调用（duck-typed `getattr`；ModularPreferencePage 协议与各模块页
   实现都在本批白名单之外，故从对话框侧引入可选钩子，未实现者安全
   跳过）。失败 `logger.exception`，不中断其余页回滚。
4. FE 覆写块的 `except Exception: pass` 同步改为 `logger.exception`。

**测试**：`test_cancel_after_apply_restores_fe_config`（Apply 后 FE 停用
列表写入、Cancel 后还原到打开时值）、
`test_cancel_without_apply_never_touches_fe_config`（未 Apply 不触碰 FE）、
`test_cancel_after_apply_calls_module_page_rollback`（rollback 被调用；

## AUD-03904（Major/risk）Cancel 裸替换 config_manager.config 绕过 _file_lock

**状态：FIXED**（备选方案，见说明）

**根因**：`self._config_manager.config = dict(self._config_snapshot)` 在
ConfigManager `_file_lock` 之外整体替换 dict 对象，与并发 `set()`/
`save_config()` 竞态（丢键/撕裂保存/`_dirty_keys` 对被替换 dict 重放）。

**修复**（preferences_dialog.py，证据首选方案为在 ConfigManager 上加
`restore_snapshot()`——**config_manager.py 不在本批白名单**，故在对话框
侧以纯公开 API 实现同等语义）：
1. `_on_apply` 经 `_tracking_config_writes()` 上下文执行
   `_apply_settings`：临时在 manager 实例上包一层记录型 `set`，登记
   `_applied_config_keys`（含模块页 apply 触发的键），退出时移除实例
   覆盖恢复原绑定方法（try/finally）。
2. `_restore_config_snapshot`：只对 `_applied_config_keys ∩ snapshot`
   逐键 `mgr.set(key, snapshot_value, auto_save=False)` + 一次
   `save_config()`——全程公开写路径，不替换 config dict 身份（无撕裂
   窗口），`_dirty_keys` 由 manager 自治管理；Apply 新建且快照缺失的键
   从 config 移除。
3. 相对旧整体替换的额外收益：对话框打开期间其他组件写入的键
   （recent 列表、窗口几何等）不再被快照连带抹掉（旧实现的数据丢失面）。

**测试**：`test_cancel_restores_config_via_public_set_api`（值还原、
`id(cfg.config)` 不变、`("panel_opacity", 90, False) in set_calls`、
save_count==2）、`test_cancel_preserves_foreign_keys_added_while_open`。

## AUD-4101（Major/risk）ShortcutDialog 无 WA_DeleteOnClose 累积 widget 树

**状态：FIXED**（对证据建议做了实证补强）

**根因**：两个调用点（menu_toolbar_controller.py:732、
preferences_dialog.py 的 `_open_shortcut_editor`）均以父窗口为 parent +
`exec()`；有父 QObject 由 C++ 侧持有，Python 引用消失不销毁。

**修复**（shortcut_dialog.py）：`__init__` 中
`self.setAttribute(Qt.WidgetAttribute.WA_DeleteOnClose, True)` **并**
`self.finished.connect(self.deleteLater)`。补强原因：本机 offscreen 实测
（PyQt6/Qt6）`QDialog.accept()/reject()` 走的 `done()` 路径**不触发**
WA_DeleteOnClose 的删除（仅 `close()` 路径触发），而两个调用点都以
exec()+accept/reject 收场——只设属性对该用法无效；finished 信号两条
关闭路径都发射，deleteLater 由后续事件循环处理（exec() 返回后调用方
不再访问 dialog，两个调用点已核实无 post-exec 访问）。

**测试**：`test_dialog_attributes_set`、`test_dialog_destroyed_after_close`
（reject + 冲刷 DeferredDelete 后 `sip.isdeleted` 为 True）。
