## 1. shared/color 域（AUD-32400..32407）

### AUD-32400 — FIXED
`src/shared/color/__init__.py`：删除与实现相反的"延迟导入"顶层 import，改为模块级
`__getattr__`（PEP 562）按需加载 `CompactColorStudio`/`EyeDropperOverlay`/`get_color`，
附 `__dir__`。`import src.shared.color`（或 `from src.shared.color.types import ...`，
渲染侧调用点见 page_controller.py:1033、composite_render_output.py:384 等）不再把
QtWidgets/QtSvg 拖进进程；`from src.shared.color import get_color`（node_properties_panel
等 13 处函数内导入）语义不变。

### AUD-32401 — FIXED
`EyeDropperOverlay`：`start()` 记录截图来源屏幕的逻辑原点
`self._screen_origin`；`mousePressEvent` 把 `globalPosition()` 逻辑坐标 →
屏内逻辑坐标 → `× img.devicePixelRatio()` 物理像素后再 clamp 取样。
吸管光标 hotspot 本就精确定位在尖端（`create_dropper_cursor`），移除
`-8px` 采样偏移 hack。Retina（dpr=2）上取色点不再系统性偏左上。

### AUD-32402 — FIXED
`get_color()`：保留 `WA_DeleteOnClose=False`（closeEvent 被 monkey-patch 包裹，开
delete-on-close 会在 `_close_and_quit` 里触碰已销毁 C++ 对象），改为 `loop.exec()`
返回后显式 `studio.deleteLater()` 释放整棵选择器树，注释同步更正；
`EyeDropperOverlay` 在取色/Esc 取消后立即置 `full_screen_img = None`
（4K 屏约 33MB 的整屏 QImage 不再常驻）。

### AUD-32403 — FIXED
新增 `_is_valid_hex_color` / `_validate_swatch_rows`（行数 ≤64、每行 dict、name 非空
str、colors ≤128 且全为 `#RRGGBB`；归一化输出含 locked 键）。`_import_swatches`
重写：读取异常收窄为 `(OSError, JSONDecodeError)`；**先整体校验、后提交**——畸形数据
弹明确拒绝提示，`swatch_data` 与已构建 UI 原样保留（旧代码先整体替换再构建，
KeyError 被 QMessageBox 兜住时 UI 已半构建、数据已换血）。

### AUD-32404 — FIXED
`_write_ase_file` 按 ASE 规范重写：头部块计数 = 实际写入块数（`#333333` 占位色
既不计数也不写入）；每个色块先在内存组装 payload（名称长度含终止符 + UTF-16BE
名称 + `\x00\x00` + `RGB ` + 3×float32 + 颜色类型），再写
`uint16 块类型 + uint32 len(payload) + payload`。此前缺长度字段且计数虚高 20
（160 vs 140），Photoshop 无法解析。

### AUD-32405 — FIXED
`SwatchPage._on_rgb_changed` 不再发射 `colorSelected`（滚轮/中键拖拽的连续中间值只
更新 current_color/预览/HEX 文本）；新增 `_on_rgb_edit_committed`（挂在每个 RGB
编辑框的 `editingFinished` 上）在离散提交时一次性广播。中间值不再经
`_on_swatch_color_selected → color_history.add_color` 挤掉 12 格真实历史。

### AUD-32406 — FIXED
`rgb_to_xyz_linear`/`xyz_linear_to_rgb` 补齐正反分支：
- **Rec.709**：BT.709 OETF 逆（`_bt709_to_linear`：0.5→0.2596，与项目 Rec.709 契约
  一致，见 `tests/color/test_ocio_config_load.py`，不用 BT.1886 纯 2.4 幂）；基色
  矩阵与 sRGB 共享（BT.709）。
- **ACEScg**：场景线性（不做 OETF 解码）+ AP1→XYZ 矩阵经 **Bradford D60→D65**
  白点适配（`_bradford_adapt`，含 3×3 乘/逆/向量辅助 `_mat_mul/_mat_vec/_mat_inv`）。
  发现并修正：原 `ACESCG_TO_XYZ` 常量行和为 (1,1,1)、列不匹配 AP1 基色
  （R xy≈(0.87,0.10)≠AP1 (0.713,0.293)），属来源不明的错误矩阵（此前恰为死代码）；
  启用前更正为 ampas 发布值（行和 = D60 白点，列为标准 AP1 基色），逆矩阵
  `XYZ_D65_TO_ACESCG` 数值求逆，删除原 `XYZ_TO_ACESCG` 死常量（全仓库无引用）。
- 白点一致性：四个空间纯白 → XYZ ≈ D65 (0.9505, 1.0, 1.0888)。

### AUD-32407 — FIXED
`SwatchPage.__init__`：`config["swatches"]` 过 `_validate_swatch_rows`，非法回退
DEFAULT_SWATCHES；`last_color` 非合法 hex 回退 `#FF0000`。
`CompactColorStudio.initUI`：`picker_custom_swatches`/`color_history` 仅在为 list 时

构造抛 KeyError/TypeError 使取色功能不可用。

## 4. tangent hub_client（AUD-32800）

### AUD-32800 — FIXED
`_send`：`sendall` 抛 `OSError`（含 0.25s 超时下的部分发送）时，在 `_socket_lock`
内 `self._socket = None` + `shutdown(SHUT_RDWR)` + `close()`——出站帧流已损坏的连接

## 5. db/database（AUD-32901/32902/32903）

### AUD-32901 — FIXED
`Database` 复用单一懒创建长连接（`_connection()`：`check_same_thread=False` +
实例级 RLock 串行化所有访问——当前调用方全在 UI 线程，锁防未来跨线程使用）。

### AUD-32902 — FIXED
连接 `isolation_level=None`（显式事务控制），`init_db` 的全部建表 + layouts 迁移
（RENAME→CREATE→回填→DROP）在一个 `BEGIN IMMEDIATE … COMMIT` 事务内，注入回填
失败验证整个事务回滚（旧表原样、无孤儿 legacy）。另增恢复路径：启动时检测到
`layouts_legacy` 孤儿表（修复前版本的崩溃窗口可能已产生）先 `INSERT OR IGNORE`
合并行再 DROP——已被拆掉的预设可找回。

### AUD-32903 — FIXED
所有方法改经 `_read`（锁内游标 + finally 关闭）/`_write`（锁内 BEGIN IMMEDIATE，
成功 COMMIT、异常 ROLLBACK 后原样上抛）上下文管理器：异常路径不再泄漏连接或残留
持锁半开事务，异常后连接立即可用；`save_default_layout` 的"清旧默认 + 置新默认"
保持单事务原子。异常继续向调用方传播（不吞领域错误，遵守 .clinerules）。
