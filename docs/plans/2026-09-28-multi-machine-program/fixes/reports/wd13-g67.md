## AUD-20501 [Major/perf-opportunity] 类级预设文本在 import 期冻结

**状态：FIXED**

**根因**：`RESOLUTION_PRESETS` 以 `I18N.tr(...)` 的译文作字典键、默认项用
`findText(译文)` 定位——类属性在模块 import 期求值，语言切换菜单无需重启
即调 `I18N.load_locale` 生效，findText/字典查找随后全部失配，默认分辨率静
默落到第 0 项 4K DCI，`_on_resolution_changed` 的 Auto 判定也永假。

**修复**（quick_project_dialog.py）：
- 预设改存语言无关稳定 key（`AUTO_PRESET_KEY`/`CUSTOM_PRESET_KEY` 哨兵 +
  固定预设文本键），新增 `_resolution_preset_display_text` /
  `_fps_preset_display_text` 在实例化时按当前 locale 生成显示文本；
- combo `addItem(显示文本, 稳定key)`，默认项 `findData(AUTO_PRESET_KEY)`；
- `_on_resolution_changed` 改按 `itemData` 判定 Auto/Custom，不再比较译文。
- FPS 预设首项同机制处理（显示文本实例化期生成，默认项为稳定下标 0）。

**测试**：`test_quick_project_presets_use_stable_keys`、
`test_quick_project_display_text_follows_runtime_locale`（monkeypatch 新译文，
断言 itemText 随 locale 变化而 itemData 恒定）。

## AUD-20601 [Major/bug] 缓存命中快路径被 sender 守卫吞掉

**状态：FIXED**

**根因**：`_start_detection`（由 BottomActionBar 的 `auto_detect_clicked`
信号槽驱动）在缓存命中时直调 `_on_detection_completed`；该槽内的陈旧信号
守卫 `sender() is not self._worker` 在槽激活期间返回外层按钮（非 None 非
worker），缓存结果被整体 return 吞掉——既不显示也不再启动新探测。

**修复**（scene_cut_dialog.py）：拆出无 sender 校验的
`_apply_detection_completed(analysis)`（应用结果 + 发射
detection_completed）；信号槽 `_on_detection_completed` 保留守卫后委托，
缓存命中路径直调 `_apply_detection_completed`。

**测试**：`test_cache_hit_applies_analysis_inside_slot`（monkeypatch
`sender` 返回 BottomActionBar，断言 set_analysis/detection_completed 均生效
且不再启动新 worker）。

## AUD-20602 [Major/bug] 批量弹窗显示字面 {0}

**状态：FIXED**

**根因**：`accepted_count`/`rejected_count` 弹窗用

均为 `{0}` 位置占位符，`I18N.tr` 只在收到 kwargs 时才 `format(**kwargs)`，

`_format_cut_confirmation_message` 改为委托它；两处批量弹窗改用
`_format_count_message` + `SCENE_CUT_I18N_KEYS`。

**测试**：`test_format_count_message_positional_placeholder`（zh_CN 译文
`{0}` → "5 个候选点已接受。"）、`test_format_count_message_named_placeholder`

## AUD-20603 [Major/risk] UI 线程无超时 wait()

**状态：FIXED**

**根因**：`_start_detection` 对运行中探测线程 `cancel()` 后无参 `wait()`；
取消检查点仅在采样循环内，容器打开/探测器构造阶段（网络盘、慢速代理）不
响应取消，UI 线程被无限阻塞。

**修复**（scene_cut_dialog.py）：
- `_start_detection` 改 `wait(2000)` 有界等待，超时调用新助手
  `_abandon_detection_worker(worker)`；
- abandon 助手：断开旧 worker 全部信号（`_on_detection_progress` 无
  sender 守卫，陈旧进度会污染新一轮探测的进度条）、
  `finished.connect(worker.deleteLater)` 自回收（连接持有 bound method 引
  用，线程结束前 Python 侧不被回收——绝不销毁运行中的 QThread）、转入
  `_zombie_detection_workers` 列表、清空 `_worker` 引用；
- `__init__` 增加 `_zombie_detection_workers` 状态；
- closeEvent 的探测线程路径（原 `wait(1000)` 忽略返回值）同样接入 abandon
  助手，与 AUD-20600 预览线程 zombie 模式对齐。

**测试**：`test_start_detection_uses_bounded_wait_and_abandons`（有界超时、
cancel、zombie 转移、新 worker 替换）、
`test_abandoned_worker_signals_are_disconnected`（四信号断开 +
finished→deleteLater 连接）。

## AUD-20700 [Major/risk] MiniScrubber.set_total_frames 泄漏 frame_changed

**状态：FIXED**

**根因**：`setMaximum` 在新最大值小于当前值时钳制 value 并发出
valueChanged；`set_total_frames` 未持 `_updating` 锁，
`_on_value_changed` 把程序化钳制当用户操作泄漏为 frame_changed →
`_seek_to_frame` 意外跳帧（clear() 归位 1000、换载更短视频时必现）。

**修复**（scene_cut_graph_widget.py）：`set_total_frames` 以
`_updating` 锁 + try/finally 包住 `setMaximum`（与 `set_frame` 一致，且异常
路径不悬挂锁）。触发链（set_candidates/clear → set_total_frames）由此全部
覆盖。

**测试**：`test_scrubber_set_total_frames_does_not_leak_frame_changed`
（置 500 后缩范围到 100：value 被钳制但 frame_changed 零发射）。

## AUD-20902 [Major/bug] GL 上传/删除在 paint 回调外且无 makeCurrent

**状态：FIXED**

**根因**（以当前代码复核，AUD-20900/20901 已在前轮修复，本条仍在）：
`set_texture_from_qimage[_with_display_size]` 被 6 处 UI 槽
（_load_frame 缓存命中/图片加载/CPU 解码/解码回退/CPU fallback×2）直调，
`clear_texture`（close_source）直调 glDeleteTextures——全部在
paintGL/initializeGL/resizeGL 之外且文件内 0 处 makeCurrent；Qt 契约要求此
情形自行确保上下文 current。无当前上下文时 PyOpenGL 抛 GLError（被上层
except 吞成 cpu_decode_error → 永久黑帧）或按驱动未定义。`_pending_qimage`
虽有 paintGL 消费逻辑但从未被赋值（死机制）。

**修复**（source_viewer.py）：
- 新增 `submit_qimage(qimage, display_width=0, display_height=0)`：UI 槽
  只暂存 QImage（`_pending_qimage` 恢复为活机制，另存
  `_pending_display_size`）、清共享引用、宽高比/fit 等非 GL 计算即时完成，
  `update()` 调度重绘；
- `paintGL` 消费暂存图像（有显示尺寸走 with_display_size 变体，否则基础
  变体），实际 glGen/glTexImage/glTexSubImage 全部在上下文 current 的
  paint 回调内执行（对齐 program_viewer 的 pending 模式）；
- 6 处 UI 槽调用点全部改走 `submit_qimage`；两个上传方法 docstring 写明
  "仅在 paintGL（上下文 current）内调用"的契约；
- `clear_texture` 的删除改经 `_delete_viewer_texture`：
  makeCurrent → glDeleteTextures → doneCurrent；部件销毁中（RuntimeError）
  跳过并清理状态、GLError 记 warning，均不向 Qt 槽抛异常；同时清空
  pending 暂存；`set_shared_texture` 同步清 `_pending_display_size`。

**测试**：`test_submit_qimage_stages_without_gl_calls`（暂存 + 共享引用切
换 + 宽高比，未初始化 GL 时零 GL 调用）、
`test_paintgl_consumes_staged_image` / `..._without_display_size`
（paintGL 消费并清空暂存）、`test_clear_texture_wraps_delete_in_make_current`
（make → delete[7] → done 顺序）、`test_clear_texture_survives_destroyed_widget`
（RuntimeError 不外抛）、`test_cpu_callers_stage_via_submit`（静态断言：
模块内不再存在 `viewer.set_texture_from_qimage*` 形式的外部直调）。
