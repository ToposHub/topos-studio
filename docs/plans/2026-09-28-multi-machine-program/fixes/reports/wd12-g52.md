## 修复要点

### AUD-14811（doc-gap：commit 的 ApprovalService 直传路径）
docstring 承诺"直接传 ApprovalService 自动构造 scope 并 consume"，实现恒返回 None。
取审计建议的**文档侧**修复：`approval_service.py` 不在白名单，且该路径与 M0.1
安全模型冲突（grant_id 不透明，service 无法确定用户批准了哪一个 grant；实现
"按 expected_scope 检索消费"会弱化防重放边界）。docstring 删除该承诺 bullet，
新增 AUD-14811 注释段说明直传 service 恒拒绝及原因；错误行为不变（稳定拒绝 +
`ApprovalGrant` 提示），新增回归测试锁定"拒绝而非静默成功"。

### AUD-14812（simulate 宽泛 except 伪装 SCHEMA_INVALID）
simulate 阶段异常改为 `TaepDiagnosticCode.INTERNAL_ERROR`，detail 保留
`{type(exc).__name__}: {exc}`。注意：INTERNAL_ERROR 无消息模板，经
`make_diagnostic(detail=...)` 会把 detail 整个丢弃（message 只剩裸码），
故直接构造 `Diagnostic(message=...)` 保证失败原因进入 message。

### AUD-14813（compute_diff 单标签分类）
- `_range_payload` 增加 `track` 字段（before/after 均可见轨道）。
- 分类改为状态差驱动：track/start 变化 → "moved"；时长**同时**变化 → 双记一条
  "trimmed"（旧实现靠 `op_kinds_by_clip`（只保留最后一个 op 的 kind）把
  "跨轨移动+裁切"折叠成 trimmed，轨道变更不可见且 total_changes 少计）。
- 轨道变化时新旧两条轨道都计入 `affected_track_ids`；删除死代码
  `op_kinds_by_clip` 块（`compiled` 参数保留并向后兼容，docstring 已注明）。

### AUD-14900（diarization 帧/sample 量纲错配）
`analyze()` 调 `merge_diarization` 时传入 `media_fps_ratio=Rational.from_string(fps)`
与 `timebase_service=self._timebase`（与 `_convert_segments` 同一换算路径），
diar 段 sample 坐标与 transcript 段 frame 坐标统一后再求重叠。

### AUD-14901（惰性引擎缓存无锁）
- `__init__` 新增 `self._engine_lock = threading.Lock()`；
  `_get_asr_engine` / `_get_aligner` / `_get_diar_model` 改双检锁
  （快路径无锁返回，加载全程持锁——多 GB 模型绝不双载）。
- `_force_cpu_asr_engine` 的字段拆除进入同一临界区。
- 模块级 monkeypatch 标志（`_rope_scaling_patched`/`_processor_compat_patched`）
  的 check-then-set 用新增 `_compat_patch_lock` 保护（锁序恒为
  engine_lock → patch_lock，无死锁）。

### AUD-14902（Sortformer 运行期错误击溃整次转录）
`_run_diarization` 增加 `except Exception` 分支：warning（`exc_info=True`
保留 traceback）+ 进度消息 + 返回 `[]`，与函数声明的"可选增强降级"语义一致；
导入类异常分支保持不变。此处宽泛捕获不违反红线（领域错误即"分离失败"，
降级是文档化行为且留有可观测性）。

### AUD-14910（强制去伴奏失败静默降级不标注）
采用审计建议的"软降级但必标注"策略（保住 transcript 结果，与"可降级，必标注"
红线一致）：失败原因记入 `demucs_degradation`，随所有后续返回路径
（qwen original / whisperx fallback / best result）写入
`provenance.extra["demucs_requested_but_failed"]`；后续 Demucs 重试成功时
清除该痕迹（分离最终已生效）。未请求去伴奏时不产生标注。

### AUD-14913（失败 cue 索引错位）
`_synthesize_custom_voice` / `_synthesize_voice_clone` 对空结果 cue 不再
`continue`，改为追加 `(start_frame, 空 ndarray, _OUTPUT_SAMPLE_RATE)` 0 时长
占位并 logger.warning —— 保证 `waves`/`cue_durations` 与输入 cues 按索引
一一对位（controller `edit_controller.py` 按位置配对字幕）。
`_lay_down_waves`：全部占位（无任何实际音频）仍抛
"合成未产生任何音频波形"；0 时长占位不产生句间停顿。

### AUD-14920（locked 死参数 + 硬约束假 pass）
- `_select_segment_for_beat` 真实使用 `locked`：与锁定区间相交的候选经稳定
  sort 提到最前（组内保持 query 的 user_verified/confidence 排序）。
- `_score` 接收 `locked` 并真实计算 `hard_constraints_passed`：任一锁定区间
  未被任何 decision 的 subject 覆盖（overlaps）即 False，explanation 追加
  未覆盖计数（用户不再看到假 pass 徽章）。

### AUD-15000（装配宽泛 except 伪装"缺模型包"）
两个 backend 装配块拆为两层：`(ImportError, ModelPackNotInstalledError)` →
维持"缺模型包"归类（warning 记录）；其余 `Exception` → logger.exception 保留
traceback，且 `unavailable_reason` 携带 `init failed: {异常类型}: {摘要}`，
不再误导用户去装模型包。

### AUD-15001（关键帧全量物化内存失控）
`visual_semantics.py` 不在白名单，故在 provider 侧流式化：新增
`_NoDecodeSampler`（`sample` 恒 None），`analyze()` 用它构建 identity-only
关键帧（复用 manifest 的 shot/range 校验，零解码），推理循环内逐帧
`replace(identity, image=sampler.sample(frame))`，单帧所有 backend 完成后
在 finally 中释放引用；`observed` 只保留 identity（aggregation 只读
identity 字段，已核实）。sampler 关闭的 try/finally 覆盖整个推理循环。

### AUD-15007（word 级时间戳无外部数据校验）
word 换算前：非有限值（NaN/Inf）跳过；负值钳到 0；`end<=start` 钳制
`max(start, end)`（与段级防护同款）。一条畸形 word 不再让整次转录失败。

### AUD-15008（WhisperX `_engine` 懒加载无锁 + 并发 transcribe）
新增 `self._engine_lock = threading.RLock()`：`_get_engine` 双检锁防双载；
`analyze()` 的"引擎获取 + transcribe"段整体持锁（ctranslate2 模型对象不保证
线程安全，串行化是显式选择）；`load_audio` 留在锁外（纯解码 I/O）。

### AUD-15011（artifact 覆盖冲突以异常终止）
`_run_subtitle` / `_run_multilingual` 的 `save` 包 `try/except
ArtifactOverrideError` → 返回带可行动降级文案的 `WorkflowResult`
（"已被你手动编辑，模型不得覆盖…如需重新生成请先重置/另存新 brief"），
符合模块"失败以 degradation 表达"契约；用户版本保持不被覆盖。

### AUD-15203（跳过的设备探测被缓存为 available=True）
- `CapabilityResult` 新增 `unknown: bool = False` 三态字段；
  `probe_audio_capabilities(check_output_device=False)` 的占位改为
  `CapabilityResult(False, "跳过探测（unknown）", unknown=True)`（未知 ≠ 可用）。
- `disabled_components` 区分 unknown/unavailable（unknown 不计入"被旁路"）。
- `get_audio_capabilities(check_output_device=True)` 不再静默忽略参数：
  缓存为 unknown 时重探测并把缓存升级为真实结果（此后复用）；
  重写顺带消除 get/reset 竞态返回 None 的窗口（AUD-15204 同型，
  局部快照引用，恒返回非 None）。

### AUD-15300（Reverb 重建分支用旧 decay/damping）
采用与已修复 AUD-15301（DelayEffect）相同的"先提交后重建"顺序：
`self._decay`/`self._damping_hz` 在进入 `if sr_changed or predelay_changed`
分支**之前**提交，`_rebuild_filters → _apply_comb_params` 恒用本次新值；
尾部重复赋值删除；同值重复调用值保持。
