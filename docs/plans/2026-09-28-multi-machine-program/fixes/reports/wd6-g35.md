## 设计决策与残留说明

- **AUD-6901 的线程模型**：worker 是每节点单守护线程，只做 `decode_image_file`（纯 CPU），结果经 `threading.Lock` 保护的 `_seq_results`/`_seq_failures` 交付；GL 纹理只在渲染线程创建（测试以线程身份断言锁死）。`_load_state` 在异步解码期间保持 UPLOADED_GPU——这是有意设计：renderer 的 `_sync_image_input_nodes` 对非 ready 节点会对 pattern 路径发起注定失败的异步解码并经 `set_load_failed` 清 `_cpu_data`，保持 ready 状态可完全避开该干扰路径。
- **AUD-6901 的已知边界**（成文，非遗漏）：渲染线程命令队列纯事件驱动，节点无法主动唤醒重评估——**播放/拖动**（审计场景：每次帧变化都触发新请求）完整修复；暂停状态单步 scrub 的解码完成帧最快在下一次渲染请求时上屏（原行为是每步冻结渲染线程数百 ms，仍严格劣于现状）。与 model3d 的 `MODEL_IMPORT_READY` 唤醒通道同构的接线点在 composite_renderer（白名单外）。
- **AUD-6901 与 AUD-6900 的边界**：异步化只在**帧号变化**时接管；参数编辑触发的 `_dirty` 仍走同步路径（AUD-6900 为独立在册条目，g34 已 BLOCKED 待其所属批处理，本批不越界）。`reload()` 顺带清空序列缓存（强制重载语义下磁盘像素可能已变）。
- **AUD-7008 的粘滞键**：`(request, mtime)` 双因子——request（frozen dataclass 值相等）覆盖 path/normalize/flip_uv_v，mtime 覆盖文件内容变化（0.1s 容差与既有缓存一致）。取消（cancelled）不置键：取消只发生在被新请求取代时，该结果本就不会被轮询。
- **AUD-7101 的 BLOCKED 依据**（均已现场核实）：`node_capabilities.py` "noise" 条目 action_type="effect"；`base_evaluator._evaluate_node` 对 effect 节点 `node.evaluate(input_textures, self.ctx, …)`（行 1746），`self.ctx` 为裸 moderngl.Context（无 frame_number，全库 grep 无任何位置向其注入）；所有现存读帧节点（text/particle/deflicker/image_input/video_frame）均为 source 分类、经 CompositeEvalContext 获帧。节点侧改动已使"求值上下文携带帧号"的一切路径（含测试与未来重构）即时生效。
- **AUD-7107 的哈希决策**：原 `_hash01` 的 SplitMix64 折叠**未按位掩码**，中间值以任意精度大整数增长（第三轮折叠后 h 可达 ~192 bit），numpy uint64 无法逐位复现；`_hash01` 定义出生位置/速度/寿命身份，必须原样保留。故湍流场改用规范 64 位回绕变体（`_hash01_u64`）——字段值变化、统计性质不变、确定性保持；`_noise01` 标量入口委托批量实现保证两条路径永不分叉。
- **锁定旧行为协议（1 例翻正）**：`tests/composite/test_composite_nodes_roi_expansion.py::TestMatteCleanupROIExpansion::test_blur_operation_roi_expansion` 原以字面量锁定 `4 // 2 + 1`（docstring 明言）——恰为 AUD-7006 要求移除的欠采样 padding。按 FIXLOG 先例改为行为断言（完整高斯半径 + 分发端契约引用），全量 81 例通过。
- **并行波次隔离**：本批 10 个白名单文件开工时干净；工作区其余未提交改动（base_evaluator 的 AUD-5806/5910、scene3d 的 AUD-7301 等）属并行 agent，验证均在当前混合工作树上进行且全绿（下方"邻接失败归属"无新增）。
