## AUD-37702 — 双击切换插值信号无消费者，功能静默失效

**问题**：`AutomationLane.set_keyframe_interp` 已定义并发射
（automation_lane.py:312、429），但 `_on_mixer_show_automation` 的连接块
只接了 add/remove/clear/mode 四个信号，双击切换插值类型
（linear/bezier/hold）完全无消费端，也无对应命令类。

**修复**（按 g98 报告给出的精确方案）：

1. **新命令类** `src/features/edit/core/commands.py`
   `SetAutomationKeyframeInterpolationCommand`（置于 ClearAutomationCommand
   之后，与 Add/Remove/Clear Automation 同型）：
   - apply 基于 `EditTrack.with_automation_keyframe_updated`
     （timeline_v2.py:2659），以 `dataclasses.replace(kf, interpolation=...)`
     构造同帧新 Keyframe —— **帧号、值、bezier/handle 手柄、tangent_mode
     全部保留，仅改插值**；
   - 插值名解析 `_resolve_interp`：先按枚举 value（"linear"/"bezier"/"hold"
     …）再按成员名（大小写不敏感）匹配。注意不能
     `InterpolationType(name.upper())` —— 枚举按 value 查找，"LINEAR" 并非
     任何成员的 value（既有 AddAutomationKeyframeCommand 的
     `.upper()` 写法因此实际永远回退 LINEAR，见"遗留观察"）；
   - undo 走整个 automation dict 快照恢复（快照损坏条目按具体异常类型
     `(TypeError, ValueError, KeyError, AttributeError)` 捕获并
     `logger.warning`，不静默吞）；to_dict/from_dict 序列化往返；
   - 目标帧无关键帧时 apply 抛 `ValueError`（不制造空命令进撤销栈），
     controller 侧按具体类型捕获。

2. **消费端接线** `edit_controller.py`：
   - `_on_mixer_show_automation` 连接块补
     `dlg.set_keyframe_interp.connect(self._on_mixer_automation_set_interp)`
     （对话框为新建实例，连接恰好一次，无重复连接风险）；
   - 新增 handler `_on_mixer_automation_set_interp(track_id, param, frame,
     interp)`：仿 `_on_mixer_automation_add`，经 `tview._execute_command`
     提交命令（进撤销栈，一次 undo 恢复原插值）；关键帧缺失等
     `ValueError` 场景只 `logger.warning`，不崩溃、不入栈。

**验证**（TestAud37702InterpolationConsumer，3 用例）：
- 经 `_on_mixer_show_automation` 创建的对话框发射
  `set_keyframe_interp("t1","volume",0,"bezier")` → 恰好 1 条
  `SetAutomationKeyframeInterpolationCommand` 入栈，插值变 BEZIER、值
  0.8/帧号 0/tangent_mode "flat"/handle_left (0.5,0.25) 全保留，相邻
  关键帧不受影响；一次 undo 恢复 LINEAR 且值与手柄不变；
- 目标帧无关键帧 → 0 命令、时间线不变、不抛异常；
- 命令类独立验证：apply/undo/redo + to_dict/from_dict 快照往返。

## AUD-37810 — 环检测告警被丢弃 + 图简化漏检 Bus-Bus 环（消费端）

**问题**：`_on_mixer_show_routing`（edit_controller.py，原 3496-3505）构造
`RoutingDialog` 时不传 g98 批新加的 `routing_snapshot` 参数 → 校验退化为
仅含当前轨道的简化图（其余 Bus 的 output 一律 None），Bus↔Bus 既有环
不可见；且消费端 `_on_mixer_routing_committed` 无任何校验，收到 payload
即同时落实时听感与命令栈。

**修复**（按 g98 报告给出的精确方案）：

1. **传全量快照**（`_on_mixer_show_routing`）：从 `sequence.audio_tracks`
   构建 `{track_id: {"output_bus_id", "sends": [(target, level)…仅 enabled],
   "is_bus"}}`（与 g98 报告给出的构造式一致），作为
   `routing_snapshot=` 传入 → 对话框校验图包含其他轨道的真实路由，
   Bus↔Bus 既有环可检出；
2. **当前 Bus 轨纳入图节点**（g98 报告建议项）：正在编辑的轨道本身是
   Bus 时追加进 `bus_tracks`（其他 Bus 在前、自身最后）—— 环检测只把
   bus_tracks 中的轨道建为图节点，否则经被编辑 Bus 构成的环
   （B1→B2→B1 中编辑 B1）不可检出；
3. **消费端提交门控**（`_on_mixer_routing_committed` + 新增
   `_build_routing_validation_graph`）：提交前以当前 timeline 全量
   audio_tracks + 当前轨拟定 payload 构建完整图，调
   `validate_routing_graph` 复核（发射侧 RoutingDialog 已按同一校验门控
   发射，此处为防御纵深，保证任何发射路径都无法把非法路由写入引擎或
   命令栈）；校验失败 → `logger.warning` + 状态栏提示
   （I18N.tr("warning.audio_routing_commit_blocked", …)），
   **实时听感与命令栈都不落**，直接 return。校验不可用（导入/构造异常，
   按具体类型捕获）同样阻止提交（fail-closed）。

**验证**（TestAud37810RoutingSnapshotAndGate，6 用例）：
- 经 `_on_mixer_show_routing` 创建的对话框收到全量快照：B2 的既有
  `output_bus_id="B1"` 注入、enabled send 计入 / disabled send 不计、
  被编辑的 B1 自身进入 bus_tracks；
- `_build_routing_validation_graph`：当前轨拟定值最后写入覆盖既有状态，
  bus_ids/routing 结构与 validate_routing_graph 入参一致；
- 消费端门控：B1→B2 提交遇既有 B2→B1 成环 → 0 命令入栈、
  `set_track_routing` 未调用、时间线未变、状态栏提示发出；output 指向
  不存在 Bus 同样被阻止；
- 合法提交（vox→B1，sends 无 diff）：恰好 1 条命令 + 1 次实时听感
  （仅 enabled send 进引擎），undo 恢复 output=None；
- 端到端：带快照的对话框里把 B1 输出设为 B2 → `routing_committed`
  不发射、命令不入栈、告警区可见"环"；改回 Master（无环）后放行。
