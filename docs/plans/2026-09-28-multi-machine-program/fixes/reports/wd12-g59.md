## 逐条明细

### AUD-17233 [Major/bug] 进度百分比未除以总时长 — FIXED
- `_generate_video_proxy_pyav` 打开容器时经 `_container_duration_seconds`（流级 `duration*time_base` 优先，容器级 `duration` 兜底）取总时长；进度改为
  `_encode_progress_percent(frame.time, total)`：已知时长按 `time/total*95` 归一（95 留给 mux 收尾），未知时长退回旧的钳制估计并保持单调。>1 秒视频不再立即跳 95%。
- 回归：5 例（归一化/95 钳制/单调性/未知时长回退/None time 安全）。

### AUD-17235 [Major/bug] delete_all_proxies_in_directory 子串误删 — FIXED
- 改为精确回溯：预扫描目录内真实文件，推导"合法代理名集合"（与 `_generate_proxy_path` 完全一致的 `name+suffix+ext`），仅删除同时存在于目录与集合中的文件。文件名含 "proxy" 的用户原片（无对应源）、孤儿代理均不再删除；空 suffix 直接返回 0。
- 回归：4 例（精确删除/自定义 suffix/空 suffix 拒绝/目录不存在）。

### AUD-17251 [Major/bug] mode="all" 先于尺寸未知检查 — FIXED
- `width<=0 or height<=0 → dimensions_unknown` 检查前移到 `mode=="all"` 分支之前，"未知尺寸不盲生成"（P2-04 排序需要尺寸）对 auto/all 均成立；带尺寸的 all/topos 分支行为不变。
- 回归：4 例。

### AUD-17300 [Major/risk] 引擎状态字段加锁不一致 — FIXED
- `_set_state` 内部统一持锁（RLock 对 set_mode 等已持锁调用方可重入），`state_changed` 信号移到锁外发射；`mode/state/generation_id` 属性持锁读取；`request_present` 的 SHUTDOWN 检查并入持锁快照；presented 分支的 `_state` 读取并入计数锁窗口；`seek` 的 `was_playing` 读取与 generation 递增同锁（并改用局部 gen 传给 scheduler）；`_handle_miss` 的 miss 计数/状态读取持锁快照、`_total_holds` 持锁递增，回调在锁外。
- 回归：4 例（含 200 次 seek × 并发 set_mode/state 读取的竞争压测，断言无异常/无挂死/无状态丢失；shutdown 后 request_present 拒绝）。

### AUD-17310 [Major/bug] P010/P016 位深回退正则不命中 — FIXED
- 正则改为 `(\d+)(?:le|be)?$` 取末尾完整数字串 + 位深白名单 {8,10,12,14,16}：`p010le→10`、`p016le→16`、`yuv422p10le→10`、`gray16le→16`；`bgr24→24` 不在白名单→8。另发现并修掉审计建议算法的一个新坑：`nv12/nv21/nv16/nv24` 的末尾数字是子采样标记（8-bit），用 `nv\d{2}` 全匹配显式排除，避免被误判 12/16-bit。
- 回归：8 参数化用例。

### AUD-17315 [Major/bug] read_frame 宽泛 except 零日志 — FIXED
- `DecodeManagerMediaSource.read_frame` 捕获后首例 `logger.warning(..., exc_info=True)`（带 source/frame 与栈），同源后续失败降级 `debug` 防逐帧刷屏；miss 语义仍返回 None。`close()` 复位标记。
- 回归：2 例（warning 可见 + 不刷屏）。

### AUD-17400 [Major/doc-gap] 池缓存命中共享 handle vs 文档教调用方 release — FIXED
- 所有权语义固化为**池独占释放**：模块/类文档删除"调用方 `gpu_frame.release()`"用法，改为 `release_generation()/shutdown()`。
- 结构性防御：`ensure_gpu_frame` 对入池 handle 统一经 `_install_pool_release` 包装 release 为幂等回调——释放时同步把条目逐出 `_resident`（误调用后缓存不会再命中已释放纹理），底层释放只执行一次（调用方误释放与容量淘汰/release_generation/shutdown 并发时不会双重释放）。三条释放路径统一走包装回调；shutdown 保持持锁释放（包装按 key 逐出，锁外执行会与并发同 key 重传竞争误逐出）。
- 回归：共享单例、误释放幂等（released 恰好一次）、误释放后重新上传、release_generation 逐出。

### AUD-17401 [Major/risk] 默认/external 上传 release=None → GPU 纹理泄漏 — FIXED
- `_default_upload`：
  - planar/cpu 上传路径（`upload_frame_to_gpu`）**必须**捕获结果对象的 release 回调入池，无 release 回调时拒绝入池（warning + 返回 None）——不再产生 release=None 的池自有纹理，容量淘汰/generation 释放/shutdown 不再跳过释放。原静默 `except ImportError: pass` 改为 debug 日志（该函数当前在 video_upload.py 中并不存在，import 恒失败，属死路径——修复后语义明确且可观测）。
  - external 纹理：所有权显式登记为"外部所有者"（解码侧 IOSurface 生命周期），payload 自带 release 回调时透传给池统一调用，否则 release=None 表示池不释放（文档化，符合规格书 §12.3"external 必须有明确 release 语义"）。
- 回归：4 例（非 external 不可上传→None、external release 透传、无 release 拒绝入池、带 release 入池并释放）。

### AUD-17409 [Major/bug] render cache 快照全局语义串 clip — FIXED
- 根因（adapter）：新增按 clip 查询 `has_render_cache_ready_for(clip_id)` / `render_cache_path_for(clip_id)`；全局 `has_render_cache_ready`/`render_cache_path` 保留但降级为诊断/统计语义并在 docstring 标注。
- 误用链（SourceResolver，条目行内明列）：`resolve_layers` 不再把同一全局 adapter 传给每个 layer，改为经 `_PerClipRenderCacheState` 视图按 `q.clip_id` 限定注入 policy（policy.py 无需感知 clip 维度；外部注入的自定义快照实现若无 per-clip 方法则视为已按 layer 限定，原样透传）。
- 回归：per-clip 语义 3 断言 + 双 clip 端到端（clip-a RENDER_CACHE 指自己的缓存、clip-b 不再被误判为 RENDER_CACHE/不再拿到 clip-a 路径——旧行为正是如此）。

### AUD-17410 [Major/bug] register_manifest 硬编码 fps/默认值 + 校验缺失 — FIXED
- `register_manifest`：帧率按"显式参数 → manifest.frame_rate_num/den（int）→ manifest.fps（Fraction/float 经 limit_denominator）"解析，尺寸同理；全部不可用时抛 ValueError（缺失报错而非静默默认——否则 key 的 fps 字段形同虚设）。新增可选显式参数 `frame_rate_num/frame_rate_den/width/height` 透传真实值。
- `get_cache_entry`/`is_cache_ready`：失效校验升级为完整 key 比对（含 fps、cache_version、source_path、timeline_id、asset_id），任一字段变化即失效，满足 §8"没有 hash/version 不复用缓存"。
- 回归：6 例（缺帧率/尺寸报错、显式与 fps 属性注册、完整 key 四维失效）。

### AUD-17419 [Major/perf] configure 持锁调用工厂与 close — FIXED
- 重构为三段式：**锁内计划**（确定要关闭的流与要新建的 key，先从表中摘除）→ **锁外执行**（`stream.close()` 与 `media_source_factory()` 均为重 I/O）→ **锁内提交**（按最新 layer 集合与现有流做冲突复查：并发 configure 已移除的 clip 丢弃新流、已建同 key 流去重，过期/重复新流在锁外关闭）。`_cancel_prefetch_requests` 行为保持。
- 回归：3 例（仪器化锁断言工厂调用时锁深度恒 0、换源重建流、layer 移除后流关闭）。

### AUD-17500 [Major/risk] attach_backend 部分失败不回滚 — FIXED
- attach 前探测全部所需信号（缺 frame_ready/render_error 直接 warning 返回）；逐条连接并登记 (signal, slot) 清单，任一失败按清单回滚断开已建立连接（单条断连失败仅 warning），`_connected` 只在全量成功后置 True；`detach_backend` 改为按清单逐条断连，不再依赖单一旗标跳过。失败日志从 debug 升到 warning。
- 回归：2 例（render_error.connect 抛异常 → frame_ready/present_frame_ready 均被回滚断开且 `_connected=False`；正常 attach → detach 逐条断开）。

### AUD-17501 [Major/bug] 兜底分支构造 backend 必拒任务 — FIXED
- `_build_backend_layer` 兜底分支（非 dict payload、非 gpu、非 planar）不再为 cpu_ndarray/placeholder 构造任务，改为抛带 payload_type 的 ValueError；`submit` 捕获后发 `render_error("unsupported_payload_type:<t> (realtime GPU path accepts gpu_texture/planar_yuv only)")` 并返回 **False**（旧行为 submit 返回 True 但帧永不产出、miss 归因 misleading）。`GpuLayerInput` docstring 固化两种受支持 payload。
- 回归：3 例（cpu 拒绝且不进 backend + 语义化错误、placeholder 拒绝、gpu/planar 仍接受）。

### AUD-17601 [Major/risk] take 落盘在 UI 线程同步执行 — FIXED
- `_finalize_take` 拆分：主线程完成终止性上下文（停定时器/停设备、锁内缓冲交接、`_current_take` 归零），落盘抽为 `_write_take_payload`（不取任何管理器锁，只操作已交接的独占 pcm 引用），归档抽为 `_archive_take`（主线程：列表追加 + 状态回调）。
- 新增 `enable_background_flush` 开关（默认 False，与 `enable_live_post_roll` 同款控制器 opt-in 模式——离线/注入/既有测试保持同步落盘语义）：开启且 QCoreApplication 存在时，写盘在 `TakeFlush` 后台线程执行，状态进入新增 `STATE_FLUSHING`（期间重复 stop 返回 None、`start_recording` 被拒），主线程 15ms 轮询 QTimer 检测完成后归档并回调 `on_take_completed`（不依赖跨线程 Qt 调用）。线程/定时器启动失败回退同步（已启动的 worker 先 join，绝不二次写盘）。`cancel_recording` 对进行中的 flush 先 join。
- 生产接线说明：控制器（`src/app/controllers/edit_controller.py:2873` 处设置 `enable_live_post_roll = True` 的同一位置）需一并设置 `mgr.enable_background_flush = True`；该文件不在本批白名单，未改动。
- 回归：2 例（后台 flush：stop 返回 None + flushing 态 + flushing 中 stop/start 被拒 + 超时内完成 + 单一完成事件源 + 文件落盘；默认关闭时行为与旧完全一致）。

### AUD-17602 [Major/bug] _spool_oldest 先 pop 后预检丢块 — FIXED
- `_check_disk_space` 前移到 `pop` 之前：预检抛 `DiskSpaceExhausted` 时块仍在 `_chunks` 且计入 `_total_samples`（partial take 不缺段、时长不虚高，iter_blocks 仍能读出该块）。

- 回归：2 例（预检失败块保留在内存且 total_samples 完整、写失败丢块被扣除）。
