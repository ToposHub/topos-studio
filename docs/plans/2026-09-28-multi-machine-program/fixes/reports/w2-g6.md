## 2. AUD-6603 [Critical/risk/M] — FIXED

**问题**：deflicker 每帧输出纹理没有任何所有者且从不释放——三条子路径
（legacy CPU 上传 `_upload_result`、GPU 池路径 acquire 后无人 release、池
失败回退 `gl.texture`）全部泄漏；deflicker 注册为
`owns_color_texture=False`（node_capabilities.py:870-877）→ 不在
CACHE_OWNED_TYPES → 缓存逐出/瞬态释放都拿不到该 glo → 显存随评估帧数
无界增长。

**证据核实**：与审查一致（三段代码原样存在；moderngl 5.12 无自动回收为
审查报告本机实测结论）。问题在当前代码存在。

**修复**（`src/features/composite/nodes/deflicker_node.py`，按任务处方
"节点持有的缓存/resource_pool 管理，按 key 复用并释放旧纹理"）：

1. **有界输出注册表** `self._output_ring: OrderedDict[key → _OutputEntry]`，
   key = `(gl 对象, w, h, 绝对帧号)`（gl 用对象身份比较，`id()` 会在 ctx
   重建后复用；帧号维度保证不同帧的缓存条目各有多自纹理，不共用别名）；
   entry 记录创建时的 resource_pool/fb_manager，退休时经同一分配器归还。
2. **复用**（`_acquire_output_texture`）：同 key 再评估（缓存逐出/失效后
   重渲、或参数变更）直接渲染/写入既有纹理，不新分配；命中即 LRU 前移。
3. **有界退休**（`_register_output_texture`）：条目上限 8
   （`_OUTPUT_RING_MAX_ENTRIES`）+ 字节预算 256MiB
   （`_OUTPUT_RING_MAX_BYTES`，1080p≈33MB/张、4K≈133MB/张），至少保留最新
   两帧（当前帧 + 回退一帧，保住求值器帧缓存的一帧 scrub-back 正确性）；
   超限从最老端退休。退休路径：池获取的走 `resource_pool.release_texture`
   （回池复用；池对未跟踪纹理自行委托 fb_manager），无池则直释放并顺带
   清掉 `fb_manager._fbo_cache` 里挂着的 FBO。
4. **陈旧缓存防悬挂**：任何退休/同 key 覆写都置
   `_cache_invalidated_needed = True`，由 base_evaluator.py:988-1002 的
   self-managed source 处理在**同一求值趟**内把本节点+下游的全部旧缓存条
   目作废（Constant/Text 同款机制），杜绝"缓存条目引用已释放 glo"。
5. **ctx 重建**：注册时发现 key 的 gl 与现存条目不同 → 旧条目属已死上下
   文，仅丢弃引用**不调 release**（particle_node `_release_gpu_objects(
   release=False)` 先例），同样置失效标记。
6. **`cleanup()`（新增）**：渲染线程删除节点/关停时（base_evaluator
   `_sync_render_nodes` 的 `hasattr(old_node,'cleanup')` 路径 +
   composite_renderer 关停路径）退休整个注册表，并释放 `_luma_tex`/
   `_luma_prog`/`_composite_prog`/`_gpu_vbo`——顺带补上 AUD-6604 的
   removal 路径泄漏（AUD-6604 的 ctx 切换半边未动，仍开放）。
7. `_upload_result` / `_composite_gpu` 改为经注册表取纹理（新增 `frame`
   形参；`_evaluate_legacy` 增加 `resource_pool` 形参由 `_do_evaluate`
   透传），GPU 路径维持"优先池获取"，失败回退 `gl.texture`（回退纹理同样
   入注册表，退休时经 fb_manager 池回收）。

**行为保持**：帧缓存语义不变（逐帧独立纹理 + `params_require_frame_cache`
不动）；既有 33 例 deflicker 测试（含真实 standalone GL 上下文的 GPU/CPU
等价、warming、确定性用例）全部通过。

**测试证据**（`TestAud6603OutputRing`，7 例全过）：
- 同帧再评估复用同一纹理（`gl.texture` 仅 1 次）且置失效标记；
- 10 帧仅存 3 条（monkeypatch 条目上限 3），7 张旧纹理各恰好 release 一次；
- 池路径超限经 `release_texture` 归还池（无裸分配）；
- ctx 切换旧条目只丢引用不 release、置失效标记；
- `cleanup()` 释放全部注册纹理 + luma/program/VBO；
- GPU composite 路径（假 GL 全链路）注册输出且同帧复用。

UnboundLocalError → 被 L267 宽 except 吞成 error 日志并 return None →

整体不可用。

moderngl 引用）。问题在当前代码存在。

1. `import moderngl` 提升至模块顶部（与 cv2/numpy 并列）——按审查建议的
   首选方案；
2. 删除函数内 `import moderngl`（AUD-6713 顺带：未使用的
   `import traceback` 一并移除）；
3. **附带 AUD-6709**（审查明确指出"一旦修复 6708 即暴露此泄漏面"）：

  全部释放；
- render 抛错时 VAO/VBO/纹理/FBO 仍被 finally 释放（AUD-6709）且返回
  None 降级。
