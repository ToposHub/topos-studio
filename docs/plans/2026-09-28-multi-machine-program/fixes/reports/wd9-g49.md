## 逐条明细

### AUD-13903 — FIXED（宿主侧加锁）
jobs.py P4 契约声明"多 worker 由宿主加锁"，GenerationService 正是宿主却未加锁。在 media_generation_service.py 内新增两个宿主侧锁包装并全部接线：

1. `_LockedJobRegistry(JobRegistry)`：`_record_event`（`_event_sequence += 1` 自增 + 事件表追加）、`submit`、`events_since`、`metrics`、`get`、`cancel`、`list_active`、`list_all`、`cleanup_terminal`、`prune_events`、`to_dict`、`restore_dict` 全部持 RLock（RLock 兼容父类内部嵌套调用）。service 自建 registry（`jobs=None`）时默认使用。
2. `_LockedGenerationBin(GenerationBin)`：全部 15 个公开读写方法（`add_candidates`/`by_request`/`all_assets`/`mark_previewed`/`import_to_media_pool`/`provenance_report` 等）持锁；宿主传入的 bin 通过状态嫁接（`_assets`/`_import_events` 两个容器，无回调绑定）共享同一容器，service 对外 `generation_bin` 属性恒返回带锁视图。
3. `worker_pool` 属性改为在 `self._pool_lock`（RLock）下懒建——修掉并发首调重复构建 executor、输家线程池泄漏的 check-then-act；外部注入的（无法事后加锁的）registry 时池退回 `max_workers=1`（证据给出的备选方案），自建锁式 registry 保留池默认并发。
4. 外部注入的 JobRegistry 无法加锁（已提交 JobHandle 的 `_event_sink` 绑定原对象），已在 docstring 标注该限制。

新代码全部带类型注解（`# type: ignore[override]` 仅用于标注父类签名透传）。

### AUD-13904 — FIXED（close() 清扫僵尸 Job）
- `close()`：先在 `_pool_lock` 内摘除 worker 引用，`shutdown(wait=False)`（其内部 `cancel_futures=True` 会取消未启动 future），随后遍历 `list_active()` 将所有非终态 Job 显式 `fail("JOB_SHUTDOWN", ...)`——未启动的 Job 不再永久 QUEUED，`list_active()`/`metrics().active` 不再虚高。
- `_execute_generation` 在 provider 调用返回后新增终态守卫：`if job.status.is_terminal: return []`——close() 判死的运行中 Job，迟到的 provider 结果不再把 FAILED 改写回 SUCCEEDED，也不再把候选写入素材箱（§11.1 红线"取消/失败不污染工程"）。
- 已知残余（jobs.py 不在白名单）：`JobHandle.complete/fail` 自身不校验终态，宿主线程在 worker"终态检查之后、complete 之前"的窗口仍可能交错；本守卫覆盖了主窗口（长 provider 调用期间），彻底封死需 jobs.py 内置状态机校验（与 AUD-13701 同域）。

### AUD-14003 — FIXED（写入门 fail-closed）
`scene_is_stale` 重写：

- 提供任一依据（`current_scene_revision`，或 `approved_scene_hash`+`context_fingerprint` 可对比对）→ 按依据判定（revision 一致时若指纹也可对比则双依据都要过——比旧实现更严）；
- **确认已发生**（`writable=True` 或盖了 `approved_scene_hash` 戳）但拿不到任何依据 → True（fail-closed）——这是审计指出的放行路径：空 fingerprint 的请求确认后，`can_write_artifact` 不再无条件放行；
- 未确认 artifact 不做无依据的有罪推定（stale 对其尚无语义，写入本就被 staged/evidence/writable 门拦截）——该收敛保住了宿主 `ai_edit_controller.check_motion_graphic_write_gate`（先查 stale 后查 evidence，白名单外）对"未验证"原因文案的既有语义（tests/app/test_ai_controller_agent_runtime_v2.py::test_write_gate_blocks_without_verification 锁定"验证"文案，曾因初版无条件 fail-closed 失败，按锁定旧行为协议细化后通过）。
- `can_write_artifact` 区分拒绝原因：有依据但不一致 → "场景在确认后已变更"；确认后无任何依据 → "缺少场景版本依据……fail-closed 拒绝"。
