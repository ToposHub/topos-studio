## 1. AUD-5300 [Critical/bug/M] — FIXED

**问题核实**：审查描述属实，且实读代码发现比报告更严重的一层：
除 padding 覆盖漏洞（`local_id.x == (k-1)%16` 守卫使每线程只写
{kernel-1, kernel-17, ...} 少数槽位）之外，`s_row`/`s_column` 是 **一维**
数组却被 16×16 的 work group 按 `local_id.x`（H）/`local_id.y`（V）索引——
tile 的 16 行/列线程彼此践踏同一数组（数据竞争），该变体在任何输入下
输出都是错的，不只是 padding 未初始化。

**修复**（`shaders.py` `_BLUR_H_COMPUTE_SHARED` / `_BLUR_V_COMPUTE_SHARED`
整体重写，现位于 3752-3906 行区间）：
1. 共享内存改为 **2D tile**：H 为 `s_tile[16][16 + 2*MAX_KERNEL]`（每 tile
   行一条 padded 行），V 为 `s_tile[16 + 2*MAX_KERNEL][16]`（每 tile 列一条
   padded 列），消除跨行/列践踏；
2. 装载改为任务要求的**常量边界跨步协作装载**：
   `for (int i = local_id.x; i < 16 + 2 * MAX_KERNEL; i += 16)`——槽位 s
   由线程 `s % 16` 恰好写一次，[0, 128) 全区间被写，卷积读窗
   `[kernel+lx-kernel, kernel+lx+kernel] = [lx, 2*kernel+lx]` 完全落在已
   初始化区间（测试对全部 kernel ∈ [0,56] × lx ∈ [0,15] 枚举验证）；
3. 边界策略保持原语义（policy 0 → u 钳到 0.0/1.0，否则 fract wrap）；
4. 越界线程不再提前 `return`，改为 `bool active` 只跳过 imageStore
   （见下"AUD-5303 重叠"说明）；
5. **MAX_KERNEL 64 → 56**：2D tile 使共享内存变为 16×(16+2K)×16B，32KB
   上限（GL 保证值）要求 K ≤ 56。`16×128×16B = 32768B` 恰好等于保证
   上限（不超）。该变体仅在 radius > 32 时被选中（sigma ≥ 16.05 →
   kernel ≥ 49），radius ≤ 37.3 时 3σ 截断不受影响；更大 radius 的截断
   由 `weight_sum` 归一化补偿（与原 cap=64 的截断性质相同，只是阈值
   略提前），远优于读取未初始化共享内存。

## 2. AUD-5301 [Critical/bug/M] — FIXED

**问题核实**：属实。四个角块 `if (local_id.x < padding && ...)` 守卫只
初始化角区，上下左右四条边条从未写入即被 `s_block[sy+dy][sx+dx]` 读取。

**修复**（`_ERODE_DILATE_COMPUTE_SHARED` 重写，现位于 3908-4011 行）：
改为**分块滚动窗（tiled rolling window）**：
- 采样窗 `[base-​half, base+15+half]²` 按 16×16 chunk 网格（chunk (ci,cj)
  覆盖窗内偏移 `[ci*16, ci*16+15]²`）多趟覆盖：`for cj/ci ∈ [0, MAX_CHUNKS)`
  （常量边界），每趟 256 线程整块协作装载 → `barrier()` → 各线程对落在
  自己 `[-half,half]²` 结构元内的子矩形做 min/max → `barrier()`（防止
  下一趟覆写仍在读的 chunk）；
- 每个窗口纹素被装载**恰好一次**；每线程归约到的偏移集合经测试对
  half ∈ {0,1,2,8,13,50} × 全部 256 线程枚举验证 **== [-half,half]²**
  （无缺失、无重复）——计算语义（extend 边 + min/max）不变；
- `chunk_used` 守卫只跳过装载与归约，两个 `barrier()` 无条件执行，
  所有 invocation 屏障数一致。

## 3. AUD-5302 [Critical/bug/M] — FIXED

**问题核实**：属实。`shared vec4 s_block[16+100][16+100]` =
116×116×16B = 215,296B，远超 GL 保证的 32KB 与常见硬件 48–128KB 实际
上限，程序在多数硬件无法链接。

**修复**：与 AUD-5301 同一重写——共享内存只剩一个 `s_chunk[16][16]`
（4,096B ≤ 32KB，仅为保证上限的 1/8），大半径通过 8×8 chunk 多趟覆盖
（"多趟覆盖/每 workgroup 处理子块 + 循环滑窗"方案）。fetch 代价：
每 workgroup 纹理采样次数从 (2h+1)²×256（理论无共享）降为
`ceil((16+2h)/16)² × 256`（half=50 时 49 次/线程），shared 版本的加速
目的保留。

## 4. AUD-5304 [Critical/bug/M] — FIXED

**问题核实**：属实。`abs(mod(uv,2)-1)` 对 uv∈[0,1] 给出 1-uv（整幅画面
绕 (0.5,0.5) 翻转），越界值绕 0.5 反射（-0.1→0.9）。本文件 6623 行
（`_MESH_WARP_FRAGMENT` 的 `sample_edges`）已有正确形式并注释了同一
坑。

**修复**（`shaders.py:2491`）：`sample_uv = 1.0 - abs(mod(sample_uv, 2.0) - 1.0);`
四象限验证（测试枚举 + 代数）：
- uv ∈ [0,1]：恒等（修复前为 1-uv）；
- uv ∈ (1,2)：2-uv，绕边 1 镜像（1.1→0.9，1.75→0.25）；
- uv ∈ (-1,0)：-uv，绕边 0 镜像（-0.1→0.1，-0.9→0.9）；
- 第二周期（±2 之外）继续正确折叠（-1.5→0.5，2.25→0.25，-2.1→0.1）；
输出恒在 [0,1]。与 6623 行参考实现形式一致。

## AUD-5303 重叠说明（重要，供对应批次核对）

三个 SHARED 计算着色器原本的"越界线程提前 return + 后续 barrier()"
分叉屏障 UB（AUD-5303，Major，另一批次）与本批修复不可分割：
跨步/分块协作装载要求 **256 线程全部参与装载并到达屏障**，否则越界
work group 的 padding 覆盖再次出现空洞。因此本次把三个着色器的提前
return 统一改为 `bool active` 模式（只跳过 imageStore）。处理 AUD-5303
的批次对这三处可直接标 INVALID（已在本批修复）；其清单中如仍有其他
着色器的提前 return，不在本批范围。

## 设计约束核对

- 浮点字面量均带 `.0`（0.0/1.0/2.0/0.5）；
- 装载/chunk 循环上限为编译期常量表达式（`16 + 2 * MAX_KERNEL`、
  `MAX_CHUNKS`）；归约内层循环沿用本文件既有惯例（GL 4.30 允许的
  动态边界，同 T-P1-21 模式，如原 `for (int dy = -half_size; ...)`）；
- 共享内存：blur H/V 各 8,192 float（=32KB 保证上限，恰好不超），
  erode 1,024 float；
- dispatch 契约不变：local_size 16×16、`gx/gy = ceil(dim/16)`、
  uniform 名集合不变（u_input/u_resolution/u_radius/u_edge_policy/
  u_output；u_operation/u_size/u_channels），`compute_shader_manager.py`
  零改动；
- 未引入任何对 HDR 数据的 clamp（形态学装载的 clamp 是坐标钳制，
  与原实现一致）。
