### AUD-28005 [Major/risk] 确认路径与同步兜底在 UI 线程执行全尺寸真实浏览器验证 — FIXED

- **复核缺陷仍在（承接 wd16-g77 的同类定位）**：`_validate_motion_graphic_scene` 传入 64×36，但 `render/html_validation.py` 按层视口把渲染上下文替换为设计尺寸（1920×1080），`validate_html_scene` 随后在**调用线程**上同步跑多候选帧 + 每页多探针 + 透明/对比背景两轮捕获。三处在 UI 线程执行：
  1. `_confirm_html_generate_request`（用户点确认卡/自动应用）写前复验；
  2. `_confirm_motion_graphic_request` 对未走后台验证的旧/JSON 场景的确认复验；
  3. `_handle_model_motion_graphic_html_response` 无 `start_motion_graphic_postprocess` 通道时的 staging 兜底。
- **修复（module.py）**：
  - 新增模块级 `_BrowserValidationJob(QThread)`（仿 `_PreviewRenderJob`/既有后台 postprocess 线程模式；PyQt6 顶部 try-import 保护，Qt-less 轻宿主回落 `QThread=object`，由 `_start_browser_validation_job` 返回 False 走原同步路径——无事件循环可阻塞）。`run()` 在工作线程执行同一 `_validate_motion_graphic_scene` 门（含空捕获检查），经 `succeeded(object)`/`failed(str)` **队列信号**回 UI 线程；`_finish_browser_validation_job` 统一 `wait()`+`deleteLater()` 并按 scope 清引用。同 scope 二次确认直接忽略（不重复拉起浏览器会话）。
  - **确认路径 1（html_generate）**：`_confirm_html_generate_request` 增加 `completion: Callable[[bool], None] | None`，生产模式（`TOPOS_TEST_MODE != "1"`）验证转 Job，方法返回 `None`（=已受理、后台复验中）并置 waiting 状态"正在后台复验浏览器渲染…期间可继续操作"。排队成功回调里**重放 revision 守卫**（后台捕获期间场景可能变更，对齐 AUD-28002 语义；plan 被取消则丢弃结果）后进入新提取的 `_apply_confirmed_html_generate`（原写入段原样迁移 + 重取 service/场景）；失败回调 `_html_generate_confirm_failed` 输出原诊断消息。同步路径（测试模式/无 Qt）行为逐字节保留，`completion` 恰好回调一次。
  - **确认路径 2（motion JSON/旧场景）**：同法拆出 `_apply_confirmed_motion_graphic_scene`（时间线句柄在续体内**重新解析**，覆盖后台期间时间线可能变化的情况）+ 共享失败面 `_motion_graphic_execution_failed`（原外层 except 的等价消息）。
  - **staging 兜底（路径 3）**：无控制器通道时验证同样转 Job，卡片展示提取为 `_present_staged_motion_graphic_html`，由排队完成回调触发；取消守卫同上。
  - **调用点适配**：直接应用流（`_handle_model_html_generate_response` 的 auto_apply 段）改为 completion 驱动，成功/失败续体提取为 `_complete_direct_html_edit_apply` / `_fail_direct_html_edit_apply`（内容与原内联代码一致）；卡片/文本确认两处路由把 `None` 归一为 `True`（确认已受理）。
  - **`render/html_validation.py`：未改动**（白名单允许最小改动，但非必需）。按审计建议的备选"小视口复验"会改变门语义（小视口下 media-query 页面可能假阴性），故选择保留全尺寸门、整体移出 UI 线程；该文件在交叉点的职责（视口归一）本身正确，且此门在生产本就已在控制器 QThread 内运行（`_prepare_motion_graphic_html_response`），线程安全性有既有先例。
  - **约束对账**：同步兜底仅剩两类——测试模式（确定性测试需要，沿用仓库既有惯例）与 Qt-less 宿主（无 UI 事件循环可阻塞）；常规确认路径在任何有 Qt 的环境下都不会再自动跑同步验证。异步期间均有 waiting 状态繁忙指示。
- **回归（8 例）**：Job 在非主线程执行且**期间 UI 事件循环持续运转**（预挂 30ms QTimer 在捕获运行中触发）；失败经队列信号在 UI 线程回报；空捕获判失败；确认路径返回 `None` 期间场景未被写入、完成后在 UI 线程写入并清卡；验证失败诊断上屏且场景保持原文档；测试模式仍同步返回 bool；motion JSON 确认 gate 在后台、通过后才恰好插入 1 条时间线命令；无控制器 staging 兜底走后台门、卡片仅在验证通过后出现。

### AUD-30640 [Major/bug] 数值行对 `parameter_ui` 元数据 `float()`/`int()` 强转 — FIXED

- **修复（html_inspector.py）**：新增 `_ui_number` / `_ui_int`（仿同文件 `_token_specs` 的逐项 isinstance 校验）：拒绝 `bool`（int 子类但非真界）、非 `(int, float)`、非有限值（NaN/Inf）→ 回退调用方声明的默认值；`_ui_int` 另要求整数值并钳到 ≥0。`_add_numeric_row` 的 min/max/step/decimals 四处强转全部改经守卫读取；`step <= 0` 回退默认步长（否则两行后的除法抛 ZeroDivisionError，同属畸形元数据崩溃类）。`_add_choice_row` 对 `enum` 做 `(list, tuple)` 过滤，非序列（如普通字符串，原实现按字符迭代）降级为纯文本行。`_parameter_ui` 保持 Mapping 形状校验（数值字段在读点校验，docstring 注明分工）。
- **回归（5 例）**：畸形 min/max/step/decimals（`"abc"`/None/list/字符串/0/NaN）下 `set_layer` 不抛异常且数值行正常构建；`_ui_number`/`_ui_int` 逐类拒绝与接受；字符串 enum 降级为 QLineEdit 而非按字符的组合框。

### AUD-30702 [Major/doc-gap] 重排序号按"可见行"而非全文档元组索引 — FIXED

- **修复（layer_tree_panel.py）**：新增 `_full_display_element_ids()`——与 `build_layer_rows` 完全一致的 `(z_index, tuple_index)` 降序、按页面时间线顺序分组的**全量**元素序列（即"全部展开时的显示序列"）；`_elements_before_page()` 给出页面块在全量序列中的前置元素数。
  - **footer 移动**（`_move_current`）：`全量位置 = 前置页面全量元素数 + 页内目标位置`，发射 `N-1-全量位置`（N=全文档元素数）。旧公式 `len(可见元素行)-1-页内位置` 在两种情形下写错元组位：折叠了当前页**之后**的页面（M<N），以及当前页非首页时把页内位置当全局位置。
  - **拖拽**（`_rows_moved` 同页重排分支）：`全量位置 = 可见位置 + 下方折叠页不贡献、上方折叠页整块补回`（遍历页面到当前页为止，折叠页的全部元素都排在全量序列的上方），发射 `N-1-全量位置`。跨页拖拽仍走 `pageMoveRequested`，多行拖拽回滚（AUD-30703）不动。
  - 全部展开时的数值与旧实现逐例一致（`tests/ui/test_mg_scene_pages_ui.py` 的 footer/拖拽期望值原样通过佐证），仅在折叠/跨页场景改变为正确值。
- **回归（6 例）**：全量序列与全展开行一致；折叠后页时 footer 上移发射全量索引（旧代码发可见索引）；全展开下第二页元素 footer 移动计入首页块偏移；折叠后页时同页拖拽发射全量索引；折叠前页时拖拽把隐藏块补回计数；发射索引经真实消费者 `with_elements_reordered` round-trip 落在预期元组位。
