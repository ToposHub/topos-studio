### AUD-33400（journal 写失败被吞 → 两阶段提交静默失效）— FIXED
根因：`_write_sequence_journal` 对 OSError 仅告警。(1) 创建态（state=writing）写失败后活暂存无 journal，并发实例按"无 journal=死亡"rmtree **活**目录；(2) prepared 写失败后仍逐帧 os.replace 覆盖用户旧帧，进程中断后恢复流程读到无 journal → 连 .backup 一起 rmtree，旧帧永久丢失。
修复：journal 写失败改为致命——`_write_sequence_journal` 清理 .tmp 后 re-raise OSError；`_create_image_sequence_staging` 对创建态写失败释放活性锁、rmtree 刚建暂存并中止（不留"无 journal 的活目录"）；commit 内 prepared/committed 写失败走既有 except → 回滚（备份还原）→ re-raise 路径，收尾态（rolled_back 等）调用方已有 try/except 保护不变。
验证：patch os.replace 模拟 ENOSPC——journal 写抛 OSError；staging 创建中止且目录清理、活性锁释放。

### AUD-33401（PID 判活 + 恢复扫描不持提交锁）— FIXED
根因：`_staging_owner_alive` 依赖 os.kill(pid, 0)（PID 复用误判活 → 陈旧暂存永不恢复；网络盘跨主机 pid 与真实属主无关 → 活暂存被 rmtree、提交中实例备份被删）；恢复入口 `_create_image_sequence_staging` 先于 `_sequence_commit_lock`，不与在途提交互斥。
修复（两层）：
1. flock 心跳活性锁：暂存目录新增 `.alive.lock`（`_SEQ_ALIVE_NAME`），`_acquire_staging_alive_lock` 在创建暂存时持有排它 flock（实例终结/进程死亡自动释放），`_release_staging_alive_lock` 在 `_remove_image_sequence_tmp_dir` 顶部统一释放（含 rollback_incomplete 保目录场景——属主已不在，恢复流程须能判死接管）。`_staging_owner_alive` 优先 `_probe_staging_alive_lock`（拿得到锁=死、BlockingIOError=活；无锁文件=旧版暂存回退 PID 判活；打不开=保守判活，宁漏恢复不误删）。平台无 fcntl（Windows）时回退既有 PID 逻辑。
2. 恢复扫描纳入提交锁：输出目录已存在时 `_recover_stale_image_staging` 在 `_sequence_commit_lock` 临界区内执行（不存在时不加锁扫描——提交锁会 makedirs，不得为扫描提前创建输出目录；该窗口内任何在途提交的暂存由活性锁保护）。
验证：持有/释放生命周期、同进程另一 fd flock 冲突判活、伪造无关 PID 仍判活、无 journal 判死；恢复执行时提交锁确被持有（探测锁冲突）。

### AUD-33402（基类 image_sequence 模式引用未定义 `_image_tier`）— FIXED
根因：基类构造显式接受 `container_mode="image_sequence"`，但 `_image_tier` 仅子类 `ToposImageSequenceEncoder` 在 `super().__init__()` 之前赋值；`_write_image_packet`（L1763）直接 `self._image_tier` → 首帧 AttributeError（被包装成不可读的 "Topos encode error"）。
