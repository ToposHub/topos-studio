## AUD-11904 — FIXED

**位置（修复前）**：`export_queue.py` `resume()`（原行 335-341）；成因为 `_process_next` 暂停排空路径置 `_running = False`（原行 421-425）。

**根因**：队列在作业间暂停时调度器把 `_running` 清 False 停车；`resume()` 的守卫 `if self._running and not self._is_currently_executing()` 因此恒假，剩余 PENDING 作业永远不会被调度。`retry()`（原行 365-368）有正确的对照实现：先 `self._running = True` 再 `_process_next()`。

**修复**：`resume()` 去掉对 `_running` 的依赖，改为与 retry 对称——`_is_currently_executing()` 为假时重置 `_running = True` 并继续调度（正在执行时由内层事件循环驱动，无需干预）。

## AUD-11905 — FIXED

**位置（修复前）**：`export_queue.py` `load_export_queue`（原行 188-195）及 `ExportJob.from_dict` 的裸强转（原行 113-119）。

**根因**：捕获范围只有 `(OSError, json.JSONDecodeError)`。合法 JSON 但形状错误（顶层非对象 → `data.get` AttributeError；jobs 项非 dict → `from_dict` 内 AttributeError；progress 等为非数字字符串 → `float()` ValueError）全部逃逸，`has_restorable_jobs()`/启动恢复直接崩溃。

**修复**：① `load_export_queue` 逐层形状校验：顶层非 dict / `jobs` 非 list → 告警返回 `[]`；逐条目 `isinstance(entry, dict)` 预检 + `from_dict` 包裹 `(TypeError, ValueError, AttributeError, KeyError)`，坏条目跳过并记日志。② `from_dict` 本体安全化：新增 `_safe_float/_safe_int` 强制回退默认值；`config` 非 dict 降级 `{}`；`job_id` 为空时生成新 uuid（构造器对空 id 的 ValueError 拒绝契约不变，仅持久化读取路径兜底）；str 字段统一 `str(... or "")`。

## AUD-11906 — FIXED

**位置（修复前）**：`export_queue.py` `_process_next` 尾部自递归（原行 421-425）。

**根因**：每完成一个作业递归深一层。`NamingConfig.RenderMode.INDIVIDUAL_CLIPS` 千级作业逼近默认 1000 层递归上限抛 RecursionError，且原 try 只包 runner 调用不含该递归，异常从 `start()` 冒泡到 UI 槽中断队列。

**修复**：调度改为 `while True` 循环（暂停/排空时 return），栈深恒定；单作业执行、信号次序、取消标志消费语义逐行保留。测试以 1200 作业（`_persist` 打桩）验证不再 RecursionError。

## AUD-11909 — FIXED

**位置（修复前）**：`video_batch_export_controller.py` `restore_from_disk`（原行 229-247）无异常防护，配合 `export_queue.enqueue` 对重复 job_id 的 `raise ValueError`（原行 290-291）与 `deliver_workspace.set_project` 的无捕获调用（477 行）。

**根因**：导出运行期间切换工程（runner 嵌套事件循环使 set_project 可达）时，运行中作业无法 remove，队列文件已持久化同一 id；restore 再次 enqueue 同 id → ValueError 冒泡至 `set_project` 崩溃主流程。持久文件含坏快照（如 `from_legacy_job → from_flat_config` 的 `int("abc")` ValueError）时启动恢复同样崩溃。`add_jobs` 有防护而 restore 没有。

**修复**：restore 循环体整体包 `try/except (ValueError, TypeError, KeyError, AttributeError)`，坏/重复条目 `logger.warning` 记 job_id 后跳过，其余条目与 `jobs_changed` 正常完成。NEEDS_RELINK 归档语义不变（有测试锁定）。

## AUD-11914 — FIXED

## AUD-12010 — FIXED

**位置（修复前）**：`video_job_runner.py` `_create_worker`（原行 353）以 runner 为父创建 `VideoExporter`，`run_job` finally（原行 263-272）只 `cleanup()`；`video_export_worker.py` 的 cleanup 仅 `quit()+wait(3000)` 不 deleteLater（该文件不在白名单，未改动）。

**根因**：QObject 父子关系使每个作业的 exporter（连同 VideoExportWorker、QThread 包装、闭包及捕获引用）在作业结束后仍挂在 runner 上直到 runner 销毁；批队列控制器常驻，连续 N 个作业累积 N 组对象/线程句柄，属资源泄漏。

**修复**：在 `run_job` 的 finally 中 cleanup 后追加 `exporter.deleteLater()`（保留 parent=self 作为 runner 先死的兜底）；同时对 `_create_worker` 返回的 thread 做 `isFinished()` 检查，`wait(3000)` 超时未停时 `logger.warning`（补上 worker 侧被忽略的超时信号）。

## AUD-12011 — FIXED

**位置（修复前）**：`video_job_runner.py` `run_job`（原行 251-282）：`loop.exec()` 返回而 `_result_success/_result_error/_cancelled` 全空时裸 `return False`；`export_queue._process_next` 继续递归下一作业。

**根因**：嵌套事件循环会处理所有主线程事件；应用退出/`QApplication.exit()` 中断所有事件循环（含嵌套），`exec()` 立即返回而 worker 未发任何信号 → 当前作业误标 FAILED，随后调度器连锁为每个剩余 PENDING 作业再创建一个 VideoExporter+OS 线程再立刻 teardown；已核对 main_window closeEvent 无队列停止接线，解释器退出阶段有线程崩溃风险。

**修复**：结果分类处新增分支——非取消、非成功、无错误（即无任何回调）时发射新信号 `aborted(job_id)` 并 `return False`；controller 侧接线 `_on_runner_aborted`：`logger.warning` + `queue.pause()`，使调度循环在当前作业结束后停车（可 resume 恢复），不再关机路径上连锁空跑整个队列。

**根因**：docstring 宣称任意线程可调，但该窗口内 `exporter is None` 时取消被静默丢弃（pause 有 pending 机制，cancel 没有）：跨线程/重入调用时导出跑完整段编码，而队列侧 `_cancelled_current=True` 使作业最终标 CANCELLED——状态与"文件已完整写出"不符。

## AUD-12205 — FIXED

**位置（修复前）**：`deliver_page.py` `ExportWorker(QThread)`（原行 89-135）与 `self._worker`（原行 173）；类中无 closeEvent/析构钩子。

## AUD-12209 — FIXED
