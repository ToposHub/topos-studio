## 1. AUD-4905 — FIXED

**位置**：`src/features/composite/core/layer_stack_controller.py` `_recompile_stack_recursive`（原 1684-1704）

**根因**：递归编译子栈后只聚合了 `warnings`，`child_result.changes` 从未并入 `aggregate.changes`（与注释"Child changes are appended below"矛盾，漏掉一行 extend）。而每一层递归都会把 `stack.generated_merge_node_ids` 覆盖为编译结果，导致子栈持有"从未创建的节点 id"并被持久化。

**修复**：在子栈递归返回处（conflict 短路之后、父栈编译之前）按序 `aggregate.changes.extend(child_result.changes)`（子先父后，与注释及 `_apply_changes` 的 create/remove → connect → set_parameter 应用顺序一致），整个嵌套编译仍是一次 undoable 图变更。

**说明**：审查建议中"`sync_from_node_graph(repair=True)` 也走递归路径"未一并实施——该方法直接 `compiler.compile(main)`，从不编译子栈，因此不存在"改写子栈标志但不应用变更"的损坏路径（属功能覆盖范围问题而非本 Critical 的数据损坏），留作后续独立改进。

## 2. AUD-5408 — FIXED

**位置**：`src/features/composite/core/undo_stack.py` `UndoTree.compress`（原 629 起）

**根因**：合并删除 `next_node` 时只把它从父节点 children 里摘除，不重接其子节点；且 `for i in range(...)` 遍历预计算的 path，删除后 `path[i+1]` 已不存在，游标更深处（线性历史常态）时历史链在洞口断裂：`_get_path_to_root` 截断、undo 走进 ghost、redo 永久失效、被合并动作不可达。

**修复**（两处配合）：
1. 删除 `next_node` 前把其 children 全部重挂到 `node`（`child.parent_id = node_id`），并将它们按原顺序拼接到 `node.children` 中 `next_node_id` 原来的位置（保序，redo 的"最近子节点"回退语义不受扰动）；防御性处理 `next_node_id` 不在 `node.children` 的病态情况。
2. 遍历改为索引 while：合并后 `del path[i+1]` 并停留在当前 `i`，使幸存节点（其 merged action `is_compressed=True` 可继续吸收后续同 key 动作）能继续与下一个后继合并——修复后一条 run 合并到底，合并语义（最早 old + 最新 new）保持。

**未动**：第二段"按最旧淘汰剪枝"未改（属 AUD-5409，Major，不在本批范围）。

## 3. AUD-11600 — FIXED

**位置**：`src/features/composite/utils/serialization_formats.py` `IncrementalSaver.compute_delta`/`_compute_graph_delta`/`apply_delta`（原 256-263、271-363）

**根因**：delta 只追踪 nodes/connections/backdrops/sticky_notes/groups/viewport_state/viewer_state 白名单键；`NodeGraph.to_dict()` 输出的 fps、duration_frames、layers、layer_stacks、composite_schema_version 等顶层字段及任何未来新增键的修改被静默丢弃；且 "no_changes" 判定也只看 4 个节点类键——只改这些字段时保存被判定为无变化。

**修复**（采用"显式键集扩展 + 全顶层键比较"，而非全量回退，保持增量格式与旧 delta 兼容）：
- 新增模块常量 `_STRUCTURAL_TOP_LEVEL_KEYS = {"nodes", "connections"}`（有专用 id-diff 逻辑的键）与 `_DEDICATED_DELTA_KEYS = {"nodes_added", "nodes_removed", "nodes_modified", "connections_changed"}`（apply 侧专用键）。
- `_compute_graph_delta`：除两个结构性键外，对全部顶层键（含未知的/新增的）做 `base.get(k) != new.get(k)` 的全量替换式比较（取代原先 5 个硬编码块，语义等同且覆盖任意键）；迭代用 `sorted(...)` 保证 delta 键序确定（顺带缓解 AUD-11608 的字节不可复现面，但 nodes_added 排序本身未动）。
- `compute_delta`：no_changes 判定改为 `if not delta:`——覆盖全部顶层键。
- `apply_delta`：除 4 个专用 delta 键外，其余 delta 键一律按顶层全量替换写回（取代原 5 个硬编码块；旧格式 delta 只含已知键，向后兼容）。

**行为差异说明**：旧代码对被删除的 backdrops 等键在 delta 中写 `{}` 默认值，新代码写实际值（键被删除时为 `None`）——仅影响"基线有、新数据无"的边角场景，语义更准确，本仓库无该模块的既有测试断言（tests/ 无任何文件 import 本模块，已 grep 验证）。
