## 实现说明（关键决策）

1. **AUD-0201 与 full_res PBO**：全分辨率路径在尺寸切换前已有
   `_synchronize_full_res_pbo_for_resize`（finish + poll + 失败兜底），
   因此旧 full_res 纹理入 garbage 队列是纯安全边际；外部目标
   （monitor/composite）的跨上下文消费者持有已发布 glo，延迟释放消除了
   "消费者 blit 中纹理名被删/复用"的单帧花屏窗口。
2. **AUD-0203 采用"先生成后归还"而非 try/except+pop**：两条路径
   （源分辨率/视口）统一重排后，异常路径上缓存条目从未离开渲染器所有权，
   无需依赖异常处理器；副作用仅为生成期间池内少一张可复用纹理（稳态
   池尺寸不变）。
3. **AUD-0204 快照成本**：`_snapshot_scope_params` 每次成功 front 发布
   执行一次（播放 60fps 亦然），递归拷贝的是 layers/raw_preview 等小型
   嵌套结构 + curves LUT（(256,1,3)）等小数组，微秒级，远低于渲染 pass
   本身。
4. **AUD-0303 的技术边界**：证据报告首选"uint16 中转/高位深 LCMS"在本
   环境（Pillow 12.1.1）不可行（实测：`Image.fromarray` 不接受 3 通道
   uint16；`I;16` 无法 build transform）。按报告兜底方案落地：uint16
   显式支持（转换确实发生而非静默失败）+ HDR 截断告警 + rint 量化；
   完整 float/GPU 导出路径留待 OCIO 接入。
5. **AUD-0313/0314 顺序依赖**：字节上限以正确统计为前提，两者在同一
   `LRUCache` 重构中落地；`DecodeFrameCache.get` 的无尺寸搜索直接遍历
   `cache._cache`，故值存储格式保持原样（平行映射而非 tuple 包装），
   该调用点零改动。
6. **AUD-0310 的 join 语义**：`start_warmup` 重启时旧线程锁外有界
   join（2s），超时仍强启新线程（与旧版容忍度一致）；每运行独立
   stop event 使旧循环退出不依赖共享 event 状态。
