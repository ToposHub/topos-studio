## 设计决策与残留说明

- **AUD-5803 采用"立即归还"而非"并入 owned_texture_ids"**：转换纹理只服务于单次 merge 绘制，出 draw 即无人引用；并入缓存条目所有权会不必要地延长其占用（缓存条目被 pin 期间纹理不能复用）。`release_texture` 归还池时打当前帧围栏（`_current_fence`），acquire 侧不会在 GPU 仍读取时复用——与 `_blur_separable` 的 temp 纹理完全同型。若 merge 后续（geometry 计算/acquire）自身抛错，转换纹理由 AUD-5806 的差集回滚兜底，两条修复互补。
- **AUD-5804/5801 的 revision 语义统一为"透传上游"**：文件内已有两个先例（`_convert_to_linear` 传播 `tex.revision` 并注释冻结画面缺陷、AI upstream_key 含 `image.revision`）。单调会话计数器虽也能防混叠，但会让内容未变的帧逐次换 key、摧毁下游缓存命中（性能回归），故未采用。
- **AUD-5805 的 clamp 位置**：审计建议"仅在张量送入模型前 clamp"。`request_compute` 的负载是 CPU 侧独立副本（`np.clip` 产生新数组），每 key 仅在 miss 时提交一次（P2-9 已确保 in-flight/命中零读回），无逐帧开销；`_read_ai_cache_result` 保留模型域 clamp 的理由成文在注释（写读两侧同域，掩码另一侧为未 clamp 线性 HDR）。
- **AUD-5806 的差集回滚边界**：异常点位于 `cache_mgr.put` 之后的概率几乎为零（put 后仅剩磁盘写（内部自护）与 dict 赋值），即便发生，重复 release 走 `release_texture` 的 not-in-active 早退/fb_manager 委托，无双重池化风险。源节点纹理（image_input 等自建 GL 对象）与 external 追踪纹理均被排除，不会误删非本次求值的资源。单渲染线程契约（GraphEvaluatorMixin）保证差集无并发污染。
- **AUD-5607 的 plan 内组模拟**：`groups_added/groups_removed` 镜像节点的 added/removed 语义，避免把合法的 [group, ungroup] 同 plan 序列误判为不存在（apply 本可顺序执行成功——validate 不得比 apply 更严）。跨 plan 状态由图自身（get_all_groups）提供。
- **错误路径纪律**：所有新增 except 分支均为 `except Exception:` + 归还/解绑 + `raise`（或带日志的显式回退），无裸 except、无吞错；共享助手 `_release_effect_textures_on_error` 的二级异常仅 logger.warning 不遮蔽原异常。
- **类型注解**：新增方法/助手（`_validate_static_param_value`、`_validate_position`、`_effective_group_ids`、`_graph_group_ids`、`_snapshot_active_texture_ids`、`_release_failed_node_textures`、`_release_effect_textures_on_error`）全部带类型注解。
