## 设计决策与残留说明

- **AUD-7304/7305 的签名兼容**：新参数全部为带默认值的 keyword 尾参（near/far 默认 0.1/1000，anim 三参默认 False/0/1=旧采样结果 `{}`），既有测试对五个 pass 方法的旧式位置调用（`test_scene3d_node_coverage.py::TestRenderPassEarlyReturns` 等）零改动通过。
- **AUD-7306 的实例化展开**：id-write 无 instanced program 变体，Geo3D 实例用 CPU `instance_offsets` 循环合成矩阵逐实例 draw（与 `_build_component_pick_meshes` 同一数据源，GeometryPayload 字段注释明确该数组就是给辅助拾取 pass 用的）；实例数通常为网格布局量级，拾取 pass 每帧一次、成本可接受，正确性优先。
- **AUD-7407 的上抛边界**：求值器（base_evaluator.py:1034-1039，白名单外）对节点异常的兜底是 warning + 空输出——节点侧 re-raise 已把"静默"变为"有完整 traceback 的显式节点错误"（perf/日志/错误消息三处可见）；要让导出任务整体 fail-fast 需改 export renderer（白名单外），留待后续批次。
- **AUD-7505 的 GPU 侧不动**：`_effect_params["pivot"]` 与 `_apply_transform` 的 rebase 数学同居纹理像素空间（pivot_mode="center" 的文档语义即"图像中心"）；若改用 bbox 参考会同时破坏 GPU 锚定语义与锁定测试，故选择"共享参考 + 契约成文 + 等价性测试"的收敛方式。
- **AUD-7602~7604 的测试策略**：VideoFrameNode 用真实 `__init__`（headless 安全）+ MagicMock GL 对象驱动 `_clear_cache`/`_ensure_gpu_target`/`_upload_frame_gpu_vt`；VT 上传测试中 `node._vt_bridge_ctx` 与传入 ctx 必须同一对象，否则会走真实 `IOSurfaceGLBridge()` 初始化（native 崩溃）——首跑即踩，已修正并留注释。
