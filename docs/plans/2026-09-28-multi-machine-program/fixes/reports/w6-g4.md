## 1. BUG-A4-06 — EyeDropperOverlay 未成功 start() 时点击 AttributeError（低危）

## 3. AUD-R2-004 — test_prores_cast_corrected pristine HEAD 即失败（Major/bug/M）

**失败现象**（本机复现）：`assert s.temp > 5.0` 得 `temp=2.533, tint=-37.245`；
且第二条断言 spread 比 0.317（阈值 0.3）同样不过。

**溯源**：

1. src 侧 `auto_balance` 数学正确：灰世界增益 `k_c = m_avg/m_c`，temp 由
   (k_r−k_b) 驱动。实测新素材通道均值 BGR = (89.85, 89.71, 113.20)——**素材本身
   R 高 26%（暖偏）**；注入 B×1.3 后 B=116.8 ≈ R=113.2（差 3%），"蓝偏主导"
   前提不成立，temp≈0 而 G 缺口 23% 由 tint=−37（提 G）补偿——对实际像素这是
   正确解，不是数值漂移。
2. 素材是 gitignored 本地文件（`.gitignore:32 tests/test_videos/**`），4K 素材
   mtime 显示 09-27 04:09 被整体替换（2K 系列为 09-11）；失败发现于 09-28/29
   的 pristine HEAD 验证——时间线吻合"素材替换"而非代码回归。
3. git 历史：`src/features/color/core/auto_color.py` 自特性提交 990e6326 后仅有
   docstring 提交（2df58ced），数值路径零改动；测试同期写入，当时素材近似中性。

**判据与修法**（属"测试期望/方法过时（有正当理由）"路径）：保留真实素材解码
路径，注入前先把各通道均值归一到灰世界中性（对任意素材成立的前提），再 B×1.3。
实测：temp=25.45（>5 ✓）、校正后 spread 比 0.116（<0.3 ✓）。

**回归测试**：`test_fix_w6g4_aud6.py::TestAutoBalanceWarmSourceBlueInjection`
（合成版不依赖 1.8GB gitignored 素材：暖偏素材归一后注入蓝偏 temp>5；对照用例
锁定"不归一时 B≈R → 小 temp 是正确解"，防止后人把素材前提误当算法缺陷回滚）。

## 4. AUD-R2-006 — test_f16_saturation_no_inf（Major/bug/M）

**失败现象**：restore 侧全 inf（`np.isfinite(back).all()` 失败），伴随
`src/shared/export/topos_encoder.py:359 RuntimeWarning: overflow encountered in cast`。

**溯源**（以溯源结果为准的域修正）：

- 任务描述指向的 `src/shared/export/disk_cache_store.py` 不存在；store 实际在
  `src/features/composite/render/disk_cache_store.py`。
- npz 路径（`_write_payload`）**本就有** `np.clip(image, -_F16_MAX, _F16_MAX)`
  （disk_cache_store.py:49-51 还有专门注释说明 inf 毒化风险）。
- 实际漏点：G6 改造后 HDR 载荷走 HALF .toos——
  `store → _payload_format（payload_is_ldr=False → FORMAT_ID_FLOAT）→
  encode_toos_payload_float → ToposImageSequenceEncoder.encode_frame →
  topos_encoder._half_plane` 的 `np.ascontiguousarray(arr, dtype=np.float16)`
  对 >65504 的值溢出为 inf，经冻结单调映射原样存取，恢复侧拿到 inf。

**修复**：在缓存存储边界 `encode_toos_payload_float` 写前
`np.clip(rgba[:, :, :4], -_F16_MAX, _F16_MAX)`（新增 `_F16_MAX = 65504.0`
常量）。**有意不动** `topos_encoder._half_plane`：它是 spec §15 冻结的 HALF
样本域"无裁剪直通"契约（与 native `tc_image_half_to_codes` 逐位一致），为视频
导出共用路径；饱和属于缓存存储契约（与 npz 路径对齐），应做在 store 侧。
alpha 由编码侧恒 [0,1]（topos_encoder.py:3351），clip 对其无影响。

**回归测试**：既有 `TestDiskCacheStoreHardening::test_f16_saturation_no_inf`
转绿；新增正/负双向超界 round-trip 饱和用例（native codec 缺失时 skip）。
变异验证：去掉 clip → 2 failed（±inf 复现）。

**邻接回归**：`tests/composite/test_disk_cache.py` + `test_topos_cache_payload.py`
+ `test_advanced_plan_audit.py` 全绿（35 用例）。

## 5. AUD-R2-008 — 目录插件元数据未送达 AddEffectCommand（Major/bug/M）

**失败现象**：`assert ... ["capabilities"] == ["gpu_preview"]` 得
`['gpu_preview', 'export_opengl']`——其余 3 条断言（plugin_id / content_hash /
to_dict↔from_dict 往返）全部通过。

**溯源**（链路逐环检查，结论：无断点）：

```
effect_catalog._specs_from_plugins（plugin_capabilities 依 @export_support 声明，:571-577）
  → AddEffectCommand.create（commands.py:13100-13108：get_spec → build_plugin_identity(spec).to_dict()）
  → apply（:12974-12977 with_plugin_identity(dict(...))）
  → EffectInstance.plugin_identity / to_dict / from_dict 往返 ✓
```

失败的真实原因：测试写于 2026-07-30（a757c578/2af67766），当时首个插件无
export 声明；**2026-09-29 提交 045cf562 新增 Fake_Infrared.tglsl
（`@export_support all`）**，按 catalog 规则合法获得 `export_opengl` 能力，且成为
`plugins[0]`（扫描序第一）。硬编码期望过时，且 `plugins[0]` 的选取本身对插件
增删脆弱。

**修法**（保留原测试意图"目录元数据如实送达"）：断言改为
`attached.plugin_identity["capabilities"] == list(spec.plugin_capabilities)` +
`"gpu_preview" in capabilities` 不变式——对任意被选中的 spec 成立，插件增删/
声明变化不再误报。src 侧无改动。
