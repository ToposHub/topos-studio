## 逐条结论

### AUD-5901 [Critical/bug/M] — FIXED

- 结论：**FIXED**（问题确认存在）
- 根因：`_apply_color_correct` 设置 `u_brightness`，而 `_COLOR_CORRECT_FRAGMENT`
  （core/shaders.py:1811-1825）声明的 uniform 集为
  u_texture/u_mask/u_exposure/u_contrast/u_saturation/u_hue_shift/u_temperature/u_tint/u_shadows_lifting/u_midtones_gamma/u_highlights_gain/u_channel_selector/u_mix——
  无 `u_brightness`。moderngl `prog['u_brightness']` 抛 KeyError，上游兜底后节点输出为空。
  另核实 `ColorCorrectNode.PARAM_DEFS`（color_correct_node.py:36-62）也没有 `brightness`
  参数，因此“shader 补 uniform”方向无节点契约支撑。
- 修复（最小方案，删多余参数）：删除 `color_evaluator.py` 中的
  `prog['u_brightness'].value = params.get("brightness", 0.0)` 一行，保留 saturation /
  contrast / mix（均为 shader 实际声明且节点实际提供的参数），并加注释说明。
- 备注：AUD-5902（13 个真实参数未完整映射）不在本批范围，未处理；本修复只消除
  100% 崩溃路径。

### AUD-6001 [Critical/bug/M] — FIXED

- 结论：**FIXED**（问题确认存在）
- 根因：erode/dilate fragment 路径第 2 次及以后迭代执行
  `self._resource_pool._texture_by_id.get(...)`；`GPUResourcePool`
  （render/gpu_resource_pool.py）只有 `_active_textures`，全仓无 `_texture_by_id`
  赋值 → AttributeError → 节点及其下游输出为空。触发条件：iterations≥2 且走
  fragment 路径（macOS GL 4.1 下 compute 基本不可用，即常态触发）。
- 修复：改用公开 API `release_texture_by_id(current_tex.texture_id)`
  （gpu_resource_pool.py:980；与 base_evaluator.py:1240 用法一致）。该 API 对未知
  glo 静默返回，安全。中间纹理现在按 id 恰好归还一次（有回归测试断言）。

### AUD-6105 [Critical/bug/M] — FIXED

- 结论：**FIXED**（问题确认存在）
- 根因：`self.ctx.clear(color=1.0)`——moderngl 5.12 的 `Context.clear` 对 `color`
  执行 `tuple(color)`，标量 float 抛 `TypeError: 'float' object is not iterable`
  （已核对 venv 内 moderngl 5.12.0 源码）。DeepMerge 在任一输入带深度时必经此行。
- 修复：`self.ctx.clear(1.0, 1.0, 1.0, 1.0)`。依据：深度输出是 R32F 纹理且经
  `FramebufferManager.get_fbo` 以 **color attachment** 挂载（gl_backend.py:158），
  `_DEPTH_OUTPUT_FRAGMENT` 输出 `out float fragDepth`（红通道），故红=1.0 即
  “最远深度”初始化，与 shader 越界返回 1.0 的约定一致。与本文件既有
  `clear(0.0, 0.0, 0.0, 0.0)` 风格统一。
