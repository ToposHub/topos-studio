## 1. AUD-25420 [Critical/risk/M] — FIXED

**问题**：`LayerPanel._toggle_current_visibility` 读取 `widget._is_visible`，
但 `LayerItemWidget` 从未定义该属性（构造参数 `visible` 只进入
`self.visible_btn.setChecked(visible)`，见 `__init__`）。从图层设置菜单点击
"切换图层可见性"即 `AttributeError`，Qt 槽内未捕获异常可致进程中止。

**根因修复**：可见性的唯一真值是 `visible_btn` 的 check 态，改为
`new_state = not widget.visible_btn.isChecked()`。

- 文件：`src/features/color/ui/layer_panel.py`
- 行号：578-580（`_toggle_current_visibility`）

**测试证据**（`tests/color/test_fix_layer_qualifier_panels_aud.py`）：
- `test_toggle_current_visibility_does_not_crash`：两层列表 + 选中行，直接调用
  `_toggle_current_visibility` 不再抛 AttributeError。
- `test_toggle_current_visibility_emits_inverted_state`：bottom 可见 →
  `layer_visibility_changed` 精确 emit `(0, False)`（UI 倒序索引换算正确）。
- `test_toggle_current_visibility_roundtrip`：引擎回写不可见后再切换 → `(0, True)`。
- `test_toggle_visibility_without_selection_is_noop`：空列表安全 no-op。
- 修复前反证：`grep -n "_is_visible" layer_panel.py` 仅此一处引用、无任何赋值
  （`LayerItemWidget` 内 `self._is_baked`/`self._is_offline_mode` 有赋值，
  `_is_visible` 没有），触发即 AttributeError。

## 2. AUD-25421 [Critical/bug/M] — FIXED

**问题**：混合模式下拉的填充项是 `I18N.tr(f"layer.{key}", ...)` 的本地化显示名，
`currentTextChanged` 直连 `layer_blend_mode_changed.emit`，把显示名原样发给引擎
（main_window.py:1605 → `engine.set_layer_blend_mode` → `layer.blend_mode = mode`）。
下游 `composition_uniforms.py:371` 用 `Layer.BLEND_MODES.index(name)` 反查：
- 现状即可复现：`saturation_blend` 的标题化兜底 "Saturation Blend" 不在
  BLEND_MODES（规范名是 "Saturation"）→ ValueError → `bm_idx = 0` 静默回退
  Normal（渲染错误）；`layer.py:1088-1089` from_dict 同样把未知名改写为
  "Normal"（持久化状态丢失）。
- 一旦任何 locale 补上 `layer.<mode>` 翻译（该 I18N.tr 调用的本意），全部 16
  个模式都会走上同一条回退路径。

**根因修复**（显示/数据契约分离，按要求用 item data 绑规范名）：
1. 模块级新增 `_BLEND_MODE_KEY_TO_CANONICAL`（UI key → Layer.BLEND_MODES
   规范显示名，`saturation_blend` 显式映射为 `"Saturation"`）。
2. 填充改为 `addItem(display, canonical)`：显示用 `I18N.tr(f"layer.{key}", canonical)`
   （兜底也用规范名，显示与规范一致），UserRole data 存规范名。
3. `currentTextChanged` 直发改为 `currentIndexChanged → _on_blend_mode_changed`：
   只 emit `currentData()` 的规范名（str 校验，非空才发）。
4. `update_layers` 同步改 `setCurrentText(规范名)`（本地化显示名下永远匹配失败）
   为 `findData(blend_mode)` 定位；面板未收录的模式（如 "Addition"）回退
   index 0（Normal），与引擎 [R3-1] 未知模式回退语义一致。程序化同步仍在
   `blend_combo.blockSignals(True/False)` 状态锁内，不 emit。

- 文件：`src/features/color/ui/layer_panel.py`
- 行号：16-39（映射表）、391-395（填充+接线）、564-568（`_on_blend_mode_changed`）、
  798-803（update_layers 同步）

**测试证据**：
- `test_blend_combo_data_are_canonical_names`：16 项 data 逐一断言
  `in Layer.BLEND_MODES`（引擎反查可命中，不回退）。
- `test_saturation_blend_maps_to_canonical`：data == "Saturation"，且没有任何
  项的 data 是 "Saturation Blend"（修复前的实际回退点）。
- `test_blend_mode_signal_emits_canonical_even_when_localized`：monkeypatch
  I18N.tr 返回 `LOC[...]` 完全本地化显示名后，逐项切换断言 emit 的始终是
  currentData 规范名、在 BLEND_MODES 内、绝不以 "LOC[" 开头。
- `test_update_layers_syncs_combo_from_canonical`："Soft Light" 正确选中；
  未收录的 "Addition" 回退 Normal。
- `test_update_layers_does_not_emit_blend_signal`：update_layers 期间 0 次 emit。

## 3. AUD-25600 [Critical/risk/M] — FIXED

**问题**：`invert_check.toggled` 直连 `on_param_changed`（原 :167/:454），该槽
不检查 `_updating_flag` 状态锁。程序化 `set_params`（:706-711）虽在
`setChecked(invert)` 前后设置了锁并 `self.blockSignals(True)`，但 blockSignals
只封锁面板自身信号的发出，拦不住子控件 invert_check 的 toggled → 槽照常执行：
强制 `params["enabled"] = True` + 在 set_params 内部重复 emit `params_changed`
（:742 结尾还会再 emit 一次）→ 限定器被意外激活、引擎重复提交。
`reset_all`（内部委托 set_params）同路径。

**根因修复**（按 .clinerules 状态锁模式）：
- `on_param_changed` 槽首行检查 `if self._updating_flag: return`。程序化路径
  （set_params :715 置位 → :718 `invert_check.setChecked` → 锁内完成 → :749
  复位后 :750 emit；reset_all :672 置位后委托 set_params）在 setChecked 前后
  均已持锁，信号为同步直连，故锁必然覆盖 toggled 触发窗口。
- 用户交互路径不变：手动勾选 invert 仍自动激活限定器并提交一次。

- 文件：`src/features/color/ui/qualifier_panel.py`
- 行号：454-466（`on_param_changed` 状态锁守卫 + 类型注解 + docstring）

**测试证据**：
- `test_set_params_invert_does_not_force_enable`：`set_params({"invert": True,
  "enabled": False})` 后 `enabled is False`、复选框已同步勾选（修复前被强制
  True）。
- `test_set_params_invert_emits_params_changed_once`：全程仅 1 次 emit
  （修复前 toggled 槽叠加 emit 共 2 次）。
- `test_reset_all_does_not_force_enable_via_invert`：invert=True 状态下
  `reset_all()` 后 `invert is False` 且 `enabled is False`（修复前被强制 True）。
- `test_reset_all_emits_params_changed_once`：reset 全程仅 1 次 emit。
- `test_user_invert_toggle_still_auto_activates`：用户路径仍自动激活 + 单次提交。
- `test_updating_flag_cleared_after_programmatic_paths`：程序化路径结束后锁
  释放，用户交互恢复生效。
