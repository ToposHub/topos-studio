## 关键决策说明

1. **AUD-7903 的根因已被前置批次修掉**：证据引用的"非原子落盘"在 AUD-7900/7901 修复中已是 tmp+`os.replace` 原子写。剩余的真实问题是损坏清单被静默清空（孤儿 .exr 无从对账）——备份 `.corrupt` + 双处 warning 是最小可验证修复；不尝试从坏 JSON 抢救条目（不可靠且越权）。
2. **AUD-8303 选择"manifest 提交后"清理兄弟格式**：审计建议"写 manifest 前 unlink"。若在 manifest 写前删除旧格式 payload 而 manifest 写失败，旧 manifest 仍指向旧格式 → has() 因新 payload 存在误报 True → load() 按旧 manifest 尺寸解码新 payload，属正确性隐患。提交后清理同样达成"无孤儿"目标且零风险（新增反例测试 `test_same_format_rewrite_keeps_payload` 锁死该语义）。
3. **AUD-7920 保持驱逐序列逐位一致**：原算法每轮从最高优先级类目重扫 = "全部 PREFETCH（旧→新）→ 全部 PREVIEW（旧→新）→…"的扁平序；单趟候选快照按类目优先级 × 插入序生成完全相同的序列，并用 `self._cache.get(key) is not entry` 防御性跳过已失效候选，行为等价仅复杂度下降。
4. **AUD-8313 取审计首选的"线程契约"方案并加了运行时护栏**：纯 docstring 无法回退敏感测试，故以"属主线程采样、他线程读缓存"的运行时守卫为主 + docstring 契约为辅。macOS 上无 NVX/ATI 扩展（`_supported=False` 直接返回 0），生产行为零变化；属性主线程首次查询前缓存为 0，也严格优于原"无上下文发 GL 调用"的未定义行为。
5. **AUD-8419 的 json.dumps+md5 部分为 DUPLICATE（已修，不计）**：计划行 576-577 指向的 params_hash 现位于 plan() 614-628，已被 AUD-7502 备忘录（param_revision + parameters 同一性/相等守卫）覆盖；本次只补齐剩余的临时 Node 双重实例化，用同一判定模式建 `_roi_node_cache`。
6. **红线自查**：UI 线程无新增 GL 调用（8313 反而拦掉了非渲染线程 GL；8403/8404 的 fence 删除发生在既有渲染线程 enqueue/enqueue_sync 节拍内）；无裸 `except:`/新增吞错（新增 except 均为具体类型 + logger 留痕或明确 fallback，8203 的 release 兜底 warning 不吞原异常）；新函数（`_eviction_candidates`/`_rank_cost_candidates`/`latest_request_id` property/`fake_toos_encode`）均带类型注解；无 HDR 值域钳制、无矩阵混用。
