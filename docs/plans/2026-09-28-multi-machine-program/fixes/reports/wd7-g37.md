## AUD-7605 [Major/perf-opportunity] GC 后备释放机制是死代码

**状态：FIXED**

**根因**：`_gc_resources` 自 `__init__` 后从未被 append，`weakref.finalize` 在每次 GC 时空转；注释宣称的"GC 时确保 GPU 纹理和 MediaSource 释放"完全不成立。且按项目 GPU 纪律（deferred-release / 渲染线程释放），GL 对象本就不应从 GC 线程释放——把机制"接通"反而是错误方向。

**修复**（`video_frame_node.py`）：移除 `_gc_resources` 列表、`_finalizer` 注册与 `import weakref`，原位注释说明为何移除及资源释放的正确归属（`composite_renderer._handle_cleanup_node` 渲染线程分发的显式 `cleanup()` + 上下文管理器协议）。`_cleanup_on_gc` 静态方法保留为工具函数（正确 release/close 传入资源），因 `tests/video/test_resource_cleanup_on_exception.py::test_context_manager_protocol_exists` 锁定 `hasattr(VideoFrameNode, "_cleanup_on_gc")`——锁定旧行为协议处理，详见下文；其吞异常的 `except` 升级为带 `logger.debug` 的诊断。

**锁定旧行为协议处理**：既有用例锁定的是"方法存在"这一契约，本修复完整保留该方法及其行为（对传入资源逐个 release/close），仅删除死注册与误导注释，用例无需翻转、保持绿色。

## AUD-7700 [Major/risk] volume3d 每次求值新建无主 GL 纹理

**状态：FIXED**

**根因**：`_do_evaluate` 内 `tex = gl.texture(...)` 后仅把 `tex.glo` 放进 TextureResult，包装对象随即失去引用；volume3d 不在 `CACHE_OWNED_TYPES`（`owns_color_texture=False`），缓存逐出时 `_collect_owned_texture_ids` 不回收 → 每次缓存未命中求值泄漏一张 RGBA32F 纹理（480×360 ≈ 2.7MB，8192² ≈ 1GB），擦洗/调参无上限累积。

**修复**（`volume3d_node.py`，按证据报告建议采用 constant_node 自管模式）：

1. `__init__` 增加 `self._gpu_texture` / `self._gpu_content_sig` / `self._cache_invalidated_needed`；
2. 求值入口先算内容签名（解析路径、帧号、render_mode、输出尺寸、有效步数、density、absorption）；签名命中且持纹有效 → 直接复用，跳过 CPU raymarch 与上传；
3. 重建路径：先 `release()` 旧纹理并置 `_cache_invalidated_needed = True`（渲染线程直接释放安全；evaluator 在 base_evaluator.py:993 消费该标志做含下游的缓存失效），再建新纹理、记录签名、`bump_output_revision("result")`；
4. 新增 `cleanup()` 释放持有纹理（接入 `composite_renderer._handle_cleanup_node` 的节点清理分发）。

## AUD-7710 [Major/bug] grid_size 变更按扁平索引截断/补零 offsets

**状态：FIXED**

**根因**：`set_parameter("grid_size", ...)` 在 `super()` 已写入新 grid_size 后才 `self.set_offsets(self.get_offsets())`——旧 JSON 被按新格点数解析，点索引 `row*(g+1)+col` 在新格上整体错位（旧索引 7 原是 (1,2)，新 9×9 格上变 (0,7)），用户格点位移跳到错误位置且不可恢复。

**修复**（`warp_node.py`）：`set_parameter` 在 `super()` 写入前捕获旧格与旧格点表；grid 变更时经新增 `_resample_lattice()` 按 (row,col) 归一化坐标做双线性重采样（四角精确映射），位移场形状跨分辨率保持；grid 未变（被拒/钳制写入）时退回原"重编码清洗陈旧点"行为。通道镜像经既有 `_sync_point_parameters` 自动刷新。

## AUD-7900 [Major/risk] put() 持锁做 EXR 写盘/manifest 落盘/驱逐删文件

**状态：FIXED**

**根因**：实例锁内执行数百 ms 级 EXR 编码、全量 manifest `json.dump`、驱逐 `os.remove`；渲染线程的 `has_cache`/`get_cache_path` 同锁，AI 结果落盘期间交互被阻塞。

**修复**（`ai_cache_manager.py`）：锁内只做内存簿记（manifest 字典更新 + 变更日志登记）；EXR 改为锁外写 **唯一临时文件名 + `os.replace` 原子落位**（临时名保留 `.exr` 后缀——cv2 按扩展名选编码器）；manifest 落盘与驱逐删文件全部移出实例锁；`_evict_if_needed` 改为"锁内定计划、锁外删文件、经日志机制持久化"。

## AUD-7901 [Major/bug] manifest 整文件覆写 + 多实例并发丢更新

**状态：FIXED**

**根因**：`_save_manifest` 以本实例内存快照整体覆写磁盘，实例锁只护单实例；`module.py` 每次回调新建 `AICacheManager()`（composite_page/composite_renderer 另持长寿命实例），后写者抹掉先写者条目 → EXR 成孤儿、重启后缓存 miss；`IOError` 被静默吞。

**修复**：模块级 `_MANIFEST_FILE_LOCK`（进程级）串行化全部 manifest 读改写；实例持 `_pending_adds`/`_pending_removals` 变更日志，`_sync_manifest_to_disk()` 在文件锁内 **重读磁盘 → 重放本实例增量 → 临时文件 + `os.replace` 原子写**（读端不再见撕裂 manifest）；写失败保留日志下次重试并记 warning（不再静默）；`clear_all` 在文件锁内重读磁盘拿到兄弟实例条目一并删除（日志机制表达不了"删除未知键"，故专用路径写 `{}`）。8 线程 × 4 实例 × 10 键并发 put 压测 80/80 条目零丢失。

## AUD-7908 [Major/bug] 自定义生成模型失败无终态信号，cache_key 永久卡死

**状态：FIXED**

**根因**：`_run_generate_inference` 中 `result is None` 直接 `return`，error/finished/stale 均不发；`_workers[cache_key]` 永不清理，`is_processing()` 恒 True、`request_compute()` 恒 False。

**修复**（`ai_compute_manager.py`）：`result is None` 且非取消时 emit `error("Custom model inference failed: <path>")` → `_on_worker_error` 弹出并 `deleteLater`；取消路径（`self._cancelled`）保持静默返回。

## AUD-7909 [Major/bug] 并发上限驱逐的 worker 被静默丢弃

**状态：FIXED**

**根因**：`request_compute` 的并发上限循环 `pop + cancel` 后无任何信号，UI 对被驱逐 cache_key 永远等不到回音。

**修复**：锁内收集被驱逐 (key, worker)，锁外 `cancel()` + `compute_stale.emit(key)`（对齐 `set_latest_request_id` 的锁外 cancel 模式），消费方可复位/重试。

## AUD-7910 [Major/bug] 取消以 RuntimeError 进入通用异常分支被误报失败

**状态：FIXED**

**根因**：两处 `raise RuntimeError("Cancelled")` 被 `run()` 末尾通用 `except Exception` 捕获，取消以 `"... inference error: Cancelled"` 报给 UI 并向 stderr 刷堆栈。

**修复**：新增内部专用异常 `_ComputeCancelled`；两处 raise 改用它；`run()` 的 except 链前置 `except _ComputeCancelled: return`（静默返回），真实异常仍走 error 路径。`_run_custom_generate_model` 内部宽 `except Exception` 吞掉取消异常的情况由 AUD-7908 修复的 `if self._cancelled: return` 前置检查覆盖。

## AUD-7911 [Major/risk] _on_worker_stale 弹出 worker 后未 deleteLater

**状态：FIXED**

**根因**：`stale_detected` 从 worker 线程 emit，槽在管理器线程排队执行时 run() 可能尚未返回；pop 丢掉最后引用后 QThread 包装器被立即析构，线程仍在运行则触发 Qt 崩溃；与 `_on_worker_finished/_on_worker_error` 的清理方式不一致。

**修复**：对齐其他终态处理器——pop 后在持引用状态下 `worker.deleteLater()`，再 emit `compute_stale`。

## AUD-7912 [Major/risk] cancel/cancel_all/cancel_stale_requests 持锁同步 wait

**状态：FIXED**

**根因**：锁内对每个 worker `cancel() + wait(1000–3000ms)`，ONNX 推理不可中断，最坏 ~6s 持锁；渲染线程的 `request_compute`/`is_processing`/`is_request_stale` 全部阻塞。

**修复**：三个方法统一改为"锁内 pop、锁外 cancel/wait"（`set_latest_request_id` 既有模式）；cancel 路径补 `deleteLater()`（旧流程 pop 发生在 wait 后、终态处理器 pop 不到 → 从不走 deleteLater，与 AUD-7911 同源的销毁竞态）。

## AUD-7913 [Major/risk] ONNX session 缓存无上限、无失效

**状态：FIXED**

**根因**：`_session_cache` 类属性只增不减，自定义模型路径任意切换时每个 InferenceSession 常驻数百 MB 显存直至 OOM。

**修复**：session 缓存声明提升为类级常量并加上限 `MAX_SESSION_CACHE = 4`；新增 `_cached_session()`（命中刷新 LRU 位）与 `_store_session()`（超限驱逐最久未用，逐出仅解除缓存引用——onnxruntime 在 session 析构时释放资源，在用 worker 自持引用不受影响）；淘汰记 info 日志。QMutex 临界区只做字典操作，驱逐后的资源释放不在锁内发生。

## AUD-7914 [Major/bug] tile/overlap 边界无输入验证

**状态：FIXED**

**根因**：`overlap >= tile_size` → stride 0 → `range()` ValueError（功能失败）；`overlap == 1` → `0/(1-1)` NaN Hanning 权重 → `_postprocess` 归零成黑缝；`_prepare_outpaint_input` 接受负 expand_* → `copyMakeBorder` 报错。

**修复**：新增 `_sanitize_tiling_params()`（非法值回退最近安全值 + warning 日志：tile_size<1/非数值 → 512，overlap 非法 → 64，负数 → 0，overlap==1 → 0，overlap>=tile_size → tile_size//2；保证 `0 == overlap or 2 <= overlap < tile_size`，stride 恒 ≥1）；`run()` 取参处接入；`_prepare_outpaint_input` 的 expand_*/blend_radius 钳非负。

## AUD-80002 [Major/risk] render_gpu_handle 缺一次性模式 cleanup 纪律

**状态：FIXED**

**根因**：其余全部公开入口（`render_and_readback`、`render_and_readback_passes`、`_render_full_frame`、两条瓦片路径）finally 均按 `not self._persistent` 收尾；`render_gpu_handle` 成败皆不 cleanup，一次性（默认非持久）调用泄漏 fb_manager/resource pool/cache manager/shader 库/全部 render node。

**修复**（`composite_export_renderer.py`）：`render_gpu_handle` 增加 `finally: if not self._persistent: self.cleanup()`，与其它入口对齐。

## AUD-80003 [Major/doc-gap] render_passes=None 且 srgb_u8 时 AOV 走 sRGB 读回

**状态：FIXED**

**根因**：`_readback_output` 的判定 `requested_names in (None, ("beauty",))` 在 None 展开前执行；`render_passes=None` 实际读 beauty + 全部 AOV，AOV（depth/object_id/motion 数值通道）被 sRGB OETF 编码损坏，违反 docstring "Mixed beauty/AOV reads are forced to linear_f32"。

**修复**：按证据报告方案一——None 在求值后展开为实际 pass 集合时，若集合 ⊄ {beauty} 且当前为 `srgb_u8` 则强制 `linear_f32`（无 AOV 时 srgb 请求保留；显式混合列表的既有强制路径不变）。

## AUD-81001 [Major/bug] 串行与并行导出的"中途取消"语义相反

**状态：FIXED**

**根因**：串行路径（render_video 573–589、render_image_sequence 729–749）对 written>0 的中途取消保留产物并报 success；并行视频 stage（ok=False 时走到删除+`"Render failed"`）与并行序列 stage 同病——同一用户动作 N=1 与 N≥2 结果相反，且并行侧误导性错误文案。

**修复**（`composite_render_output.py`）：以串行契约为准统一（证据报告建议方向）：两个并行 stage 均增加 mid-cancel 分支（`is_cancelled() and written > 0`）——关闭 encoder、保留部分产物、报 `success=True / error=""`；零帧取消仍为 `"EXPORT_CANCELLED"` + 删产物；worker 错误（无取消）仍为失败 + 删产物。同时以测试锁定串行视频中途取消的契约作为对齐基准。

## AUD-81002 [Major/bug] render_image_sequence 无异常路径清理

**状态：FIXED**

**根因**：串行循环（632–692）无 try/except，渲染/保存抛异常时已写帧残留磁盘；并行 stage 的 finally 只清 GL renderer 不清已写文件；与 render_video 的失败清理不对称。

**修复**：串行循环整体包 try/except——异常时 `logger.exception` + 清理 written_paths + 移除空目录 + 返回失败结果；并行 stage 增加 `except Exception`（在既有 GL finally 之外）同构清理并返回失败结果（证据报告明确"返回失败结果"）。清理逻辑抽为 `_remove_written_frames()` 共享，序列取消/失败路径复用。
