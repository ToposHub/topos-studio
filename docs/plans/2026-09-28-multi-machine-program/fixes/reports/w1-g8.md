## 1. AUD-10300 [Critical/risk/M] — FIXED

**问题**：`KeyframesTreeView.mouseReleaseEvent` 中 `target_node`/`target_param` 只在
`if active and 0 <= idx < len(rows):`（拖拽）分支内赋值；单击 Bind 列后未移动 ≥4px
即释放时走 `elif not active:` 分支，二者未定义 → `UnboundLocalError`。PyQt6 事件
处理器内未捕获异常会经 qFatal 中止进程（用户单击绑定图标即崩溃）。

**根因修复**：把 `target_node = str(drag["node_id"])` / `target_param =
str(drag["param_name"])` 提取到分支之前——按压起点本身就是绑定目标，与是否
进入 pick-whip 拖拽无关，两个路径共用同一解析结果。

- 文件：`src/features/composite/ui/keyframes_tree_view.py`
- 行号：1391-1399（`mouseReleaseEvent`，赋值提前至 `unsetCursor()` 之后、
  `if active ...` 之前，原分支内的两行赋值删除）

**测试证据**（`tests/composite/test_fix_ui_crashes_aud.py::TestAud10300BindClick`）：
- `test_click_without_move_emits_binding_requested`：真实 press→release（无 move）
  走完整事件处理器，断言 `binding_requested` 以 `(node_id, param_name)` 发出、
  `_binding_drag` 清空。
- `test_drag_to_another_param_still_binds`：press→move(≥4px)→release 断言
  `parameter_binding_dragged` 仍按原契约发出（防回归）。
- 修复前反证：临时还原 HEAD 版本运行，前者因 `UnboundLocalError` FAILED；
  修复后 9/9 PASSED。

## 2. AUD-10400 [Critical/risk/M] — FIXED

**问题**：`node_editor_actions.py` 全文件无 `import logging`、无 `logger =`，
而 `paste_nodes` 的 topos_color 剪贴板分支（clip 上下文）调用 `logger.info(...)` →
`NameError`。该方法是 Ctrl+V 主路径，异常发生在节点已入图、内部连接未建之时，
Qt 槽内未捕获异常可致进程中止且图状态不一致。

**根因修复**：模块顶部新增 `import logging` 与 `logger = logging.getLogger(__name__)`
（标准库日志设施，沿用项目其他模块的模式）。

- 文件：`src/features/composite/ui/node_editor_actions.py`
- 行号：28（import logging）、38（logger 定义）

**测试证据**（`TestAud10400PasteLogger`）：
- `test_module_logger_defined`：断言模块级 `logger` 为 `logging.Logger` 且 name
  为模块 `__name__`。
- `test_paste_topos_color_completes`：用 MagicMock editor + 假 CompositePage
  （`_runtime_context.clip_id` 等走 clip 上下文分支）+ monkeypatch
  `NODE_REGISTRY`，真实调用 `NodeEditorActions.paste_nodes()`，断言粘贴完成、
  返回 1 个新节点、参数改写正确（`stack_source="preset_copy"`、
  `color_stack_id` 前缀 `clip-1_grade_`、`role="preset_copy"`）。
- 修复前反证：两个用例分别以 `AttributeError`（无 logger 属性）与
  `NameError: name 'logger' is not defined` FAILED；修复后 PASSED。

## 3. AUD-10601 [Critical/risk/M] — FIXED

**问题**：`DeleteNodeCommand.undo` 第一段为移除自动重连链路，直接遍历并
`self.graph.connections.remove(conn)`——锁外裸改共享列表（数据竞争），且绕过
`NodeGraph.disconnect` 内的 `_mark_dirty_downstream` / `_generation` /
`_topology_revision` 通知，增量渲染可基于脏拓扑缓存继续出图。

**根因修复**：改为调用 `self.graph.disconnect(from_node, from_port, to_node,
to_port)`——与同文件 `ConnectCommand.undo`/`PasteNodesCommand.undo`/`DisconnectCommand`
一致的正确写法。`disconnect` 在 `graph._lock`（RLock）内过滤移除匹配连接、
`_mark_dirty_downstream(dst)`、`_generation += 1`、`_topology_revision += 1`；
连接不存在时为安全 no-op 返回 False。保留 `except Exception` + 注释的既有风格
（非裸 except，符合 .clinerules）。

- 文件：`src/features/composite/ui/node_graph_commands.py`
- 行号：155-170（`DeleteNodeCommand.undo` 第一段）

**测试证据**（`TestAud10601DeleteUndoLocking`，链路 color→transform→output，
TransformNode 单 image 输入口使命令真正记录重连链路）：
- `test_undo_restores_topology_and_removes_reconnect_link`：redo 后仅存
  color→out 桥接；undo 后精确恢复原始两条连接、节点回归。
- `test_undo_routes_link_removal_through_disconnect`：`patch(wraps=chain.disconnect)`
  间谍断言移除调用 `("color-1","result","out-1","image")` 且桥接链路消失——
  修复前 `spy.call_count == 0` FAILED。
- `test_undo_bumps_topology_revision_and_marks_dirty`：undo 后
  `_topology_revision` 严格递增、下游节点 `_dirty is True`（锁定了绕过
  revision/dirty 的回归）。
- `test_undo_tolerates_missing_reconnect_link`：桥接已被手动断开时 undo 不抛
  异常且拓扑正确（no-op 路径）。
- `test_undo_redo_cycle_is_repeatable`：两轮 redo/undo 循环拓扑一致。
