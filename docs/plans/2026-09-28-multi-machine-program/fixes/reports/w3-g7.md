## 1. AUD-20508 — FIXED

**位置**：`src/features/edit/ui/relink_media_dialog.py`（原 :347、:381、:416、:499）

**根因**：四处读取 asset_id 时把枚举类本身 `Qt.ItemDataRole` 当角色值传给 `item.data()`（PyQt6 抛 `TypeError: data(self, role: int): argument 1 has unexpected type 'EnumType'`），而写入侧 :288 是正确的 `setData(Qt.ItemDataRole.UserRole, asset_id)`。`_on_relink_selected`、`_on_relink_by_directory`、`_on_auto_search`、`_update_relink_path` 四个入口在取 asset_id 的第一行即抛未捕获 TypeError，`_relink_map` 永远为空，重链接整体不可用且表现为静默无效果。

**修复**：四处统一改为 `self._table.item(row, 0).data(Qt.ItemDataRole.UserRole)`，与写入侧对称。纯一行式根因修复，无行为面变化。

## 2. AUD-20600 — FIXED

**位置**：`src/features/edit/ui/scene_cut_dialog.py` `closeEvent`（原 :2663-2667，配合 `_on_preview_worker_finished` :1984-1995 与 `__init__` :1472-1474）

**根因**：closeEvent 循环中对运行中的预览线程 `requestInterruption()` 后 `worker.wait(1000)` 忽略返回值，随即无条件调用 `_on_preview_worker_finished(worker)` → `worker.deleteLater()`。`PreviewLoadWorker.run` 只在解码前后检查中断标志，长 GOP/4K/网络媒体的单帧解码可远超 1 秒且无法中断——超时后对仍在运行的 QThread 执行 deleteLater，事件循环处理 DeferredDelete 时析构运行中的线程（"QThread: Destroyed while thread is still running"），属未定义行为，典型表现为进程崩溃。

**修复**（zombie 模式，审计建议的第一方案）：
1. `__init__` 新增成员 `self._zombie_preview_workers: list[PreviewLoadWorker] = []`（带注释说明用途）。
2. `closeEvent` 检查 `wait(1000)` 返回值：已退出 → 照旧 `_on_preview_worker_finished`（含 deleteLater，安全）；超时未退出 → **不清理、不销毁**，仅把引用转入 `_zombie_preview_workers` 并 `logger.warning`，`continue`。线程自然退出时其自身 `finished` 信号（`_start_preview_request` 中已连接的 lambda）回调 `_on_preview_worker_finished` 完成最终清理——此时线程已结束，deleteLater 安全。
3. `_on_preview_worker_finished` 同步从 `_zombie_preview_workers` 移除 worker，避免引用滞留（该方法本身对 closeEvent 与 finished 信号的双重调用幂等，注释已在）。

**说明**：worker 同时保留在 `_preview_workers`（finished 回调据此摘除）与 zombie 列表（保引用防 Python 包装被回收）；未采用"延迟重试"分支——单帧解码不可中断，重试只是拉长关对话框的阻塞时间，zombie 模式即刻返回且无崩溃窗口。

## 3. AUD-21100 — FIXED

**位置**：`src/features/edit/ui/timeline_items.py` `_show_retime_segment_speed_menu`（原 :5205-5248，方法体 :5234 引用 `I18N`；调用点 :4469）

**根因**：方法内（及模块级导入 22-76 行）均无 `I18N` 导入，构建菜单到 `I18N.tr("edit.clip.smooth_ramp", ...)` 即抛 `NameError`。PyQt6 对事件处理器内未处理异常默认 qFatal，最坏情况应用直接崩溃；至少 Smooth Ramp / 段速度编辑完全不可用。

**修复**：在方法内 `from PyQt6.QtWidgets import QMenu` 之后补 `from src.shared.i18n.i18n import I18N`，与同文件其它菜单的函数内导入惯例一致（:4589、:6367、:7998、:8124、:8968 均此写法）。未提为模块级导入以维持文件既有风格（模块级不导入 I18N，各用点函数内导入）。

## 4. AUD-12200 — FIXED

**位置**：`src/features/deliver/ui/deliver_page.py`（原 :257-260、:691）

**根因**：`_end_frame_spin.setRange(0, 1000000)` 后 `setValue(-1)` 被 QSpinBox 钳位到 minimum=0；值为 minimum 时恰好显示 specialValueText "To End"，用户看到的是哨兵文案、拿到的却是 `end_frame=0` → Custom 范围导出区间 [0, 0)，流程走完返回 success 但产出 0 帧（`TimelineExportConfig` 约定 `end_frame < 0` 才表示到末尾，timeline_export.py `_calculate_frame_range` 将其解析为 duration）。

**修复**（specialValueText 哨兵模式，即"哨兵值不得被 QSpinBox 钳位破坏"约束的规范做法）：
1. `setRange(-1, 1000000)`：`setValue(-1)` 不再被钳位，值 -1（== minimum）时显示 "To End"；用户可从 0 下调回 -1 恢复哨兵语义，也可输入显式终止帧。
2. `get_export_config` 增加防御性归一：Custom 范围下 spin 值为负时统一传 -1（当前只可能是 -1，该映射为未来范围调整锁定哨兵语义，防钳位回归）。
3. `TimelineExportConfig`/导出侧未动——`end_frame=-1` 本就是其既定哨兵约定，UI 侧修复即恢复完整链路：默认 Custom 范围导出完整尾部。
