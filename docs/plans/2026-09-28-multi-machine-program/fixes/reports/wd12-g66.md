## AUD-20103 [Major/bug] 诊断消息未转义即拼入富文本 QLabel

**状态：FIXED**

**根因**：诊断 `message` 直接携带适配器捕获的异常文本
（fcpxml_adapter `f"FCPXML parse failed: {exc}"`、otio_adapter
`f"OTIO read failed: {exc}"`），路径中合法的 `&`/`<` 在 QLabel AutoText
检测到 `<span>` 后按 HTML 解析，渲染残缺/被吞。

**修复**（interchange_dialog.py）：诊断行改为 `html.escape()` 后再拼富文本
（severity/msg/code 三个字段均转义，非 str 先 `str()`），并显式
`setTextFormat(RichText)`。计数行（label 为 I18N 内部文本、count 为 int）不需要转义，
维持原样。

**测试**：`test_interchange_diagnostics_escaped`——消息含 `<bad & tag>` 时标签文本
包含 `&lt;bad &amp; tag&gt;` 且无裸 `<bad`。

## AUD-20200 [Major/risk] Quick Look 的 Space 切换永远找不到已打开的对话框

**状态：FIXED**

**根因**：`findChild(QuickLookDialog)` 只搜索面板自身子树，而对话框的 QObject
父对象是 `_get_top_level_widget()`（主窗口）；面板嵌在 dock 中，对话框不是面板
后代 → toggle 永远走"新开"分支，旧对话框（`WA_DeleteOnClose=False`）泄漏。

**修复**（media_pool_panel.py `_show_quick_look`）：面板以成员变量
`self._quick_look_dialog` 跟踪当前实例（`__init__` 初始化，`destroyed` 信号回调
清引用）。toggle 逻辑：存在实例 → 记录 `isVisible()` → `close()`+`deleteLater()`
（`RuntimeError` 防御 C++ 对象已被销毁的情形）；此前可见则 return（关），
此前已隐藏（Esc 关过）则继续走开新分支（一次 Space 重开，Finder 语义）。

**测试**：`test_quick_look_space_presses_do_not_leak`（连按两次只存在一个实例、
第一个被 close+deleteLater）、`test_quick_look_reopens_after_hidden_close`。

## AUD-20202 [Major/risk] 5 秒定时器在 UI 线程对全部素材同步 `os.path.exists`

**状态：FIXED**

**根因**：`_refresh_offline_status`（5s QTimer 槽）同步调用
`update_offline_status`（project.py:5094 逐素材 `os.path.exists`）。网络卷/
断开移动盘上单次 stat 可阻塞数百 ms～秒级，周期性冻结 UI。

**修复**（media_pool_panel.py，均在白名单内）：
- 新增 `OfflineScanSignals`/`OfflineScanWorker(QRunnable)`：worker 线程对
  frozen `EditProject` 快照执行 `update_offline_status`（复用核心函数，语义与
  原同步路径一致，含 is_virtual 跳过）；无变化/异常时 emit `(source, None)`；
- `_refresh_offline_status` 只投递 worker（`_offline_scan_in_flight` 防重入：
  慢卷上不会堆积扫描），不再在 UI 线程 stat；
- `_on_offline_scan_finished`（UI 线程槽）：`source is not self._project`
  身份校验（扫描期间工程被 import/undo/切换则丢弃旧结果，下个 tick 重扫），
  仅在确有变化时沿用原路径 `set_project` + `project_changed.emit`。

**线程安全**：worker 只读 frozen dataclass 快照（项目侧不变式：所有更新经
`with_*`/replace 重建），结果经 queued 信号回 UI 线程应用。

**测试**：`test_offline_refresh_does_not_scan_on_ui_thread`（UI 线程不再同步
调用 update_offline_status；in-flight 防重入）、`test_offline_scan_result_
applied_when_source_current`、`test_offline_scan_result_discarded_when_project_
swapped`、`test_offline_scan_worker_emits_only_on_change`。

**锁定旧行为更新**：`tests/edit/test_media_pool_panel_refresh.py::
test_panel_refresh_detects_source_removed_while_project_is_open` 原断言
`_refresh_offline_status()` 返回后工程同步更新（锁定旧的同步扫描行为）。按协议
更新：测试内以"内联线程池"（start → run 同步执行）驱动同一
worker→signal→slot 链路，端到端语义（扫描结果发布新工程）不变，生产行为异步。

## AUD-20203 [Major/risk] `_update_disk_proxy_services` 直接锁其它服务的私有锁并改写私有缓存

**状态：BLOCKED（半侧已修，半侧因白名单受阻）**

**根因复核**（现状比审计描述更糟）：面板 `with frame_service._lock:` 内调用
`frame_service.update_disk_proxy_info(...)`，而 `VideoFrameProviderService._lock`
是**非重入** `threading.Lock`（frame_provider_service.py:656），该方法自身
`with self._lock:` ——源素材存在打开 clip 时该路径**必然死锁 UI 线程**
（不止封装问题）。

**已修半侧（FrameProviderService）**：改走公共 API——
`get_shared_clips_info().get(source_path, [])`（公共，返回 `_path_to_clips`
拷贝）+ `get_clip_session(clip_id)`（公共）+ `update_disk_proxy_info(clip_id, info)`
（公共，原已使用）。面板不再触碰该服务的 `_lock`/`_path_to_clips`/`_clips`，
死锁路径消除。

**受阻半侧（DiskProxyService）**：审计建议"在服务上提供公共方法（如
`disk_proxy_service.mark_ready(...)`）"，即需在
`src/shared/media/disk_proxy_service.py` 新增公共 cache 写入 API（核验：现有公共
方法 get_proxy_status/get_disk_proxy_info/has_ready_proxy/generate_proxy/
cancel_*/cleanup_*/get_proxy_stats 均不能外部播种 READY 信息；其内部
ProxyManager 亦为私有实例、无公共访问器；`ProxyManager.update_proxy_for_asset`
存在于另一单例树，与本服务的 `_manager` 不是同一实例）。该文件不在本批白名单
（属 shared/media 批次），并行修复波次的文件集互斥。**在服务侧 API 就位前移除
直写会回归**（`_maybe_auto_ensure_disk_proxy` 等依赖 `_info_cache` 命中判断
ready，MISSING 误判会触发重复入队生成）。处置：保留该半侧带锁直写并在代码内
注明 AUD-20203（半侧遗留），待服务侧提供 `mark_ready(source_path, info)` 类
公共方法后一行替换。已在代码中留注释指引。

**测试**：`test_update_disk_proxy_services_uses_public_frame_api`——fake frame
服务**只暴露公共方法**（无 `_lock`/`_path_to_clips`/`_clips` 属性），旧代码路径
若运行会 AttributeError 被吞、update 不被调用 → 断言 update 恰好一次且携带
proxy_path，证明私有访问已消除。

## AUD-20403 [Major/bug] present-frame ack 只在 blit 成功路径触发

## AUD-20500 [Major/bug] 图片素材的 Auto 分辨率恒为 1920x1080

**状态：FIXED**

**根因**：`FileIO.get_metadata` 从不返回 "width"/"height" 键；像素尺寸在
"Resolution" 字符串（exiftool 与 Pillow 两条路径均产出 `"W x H"`，失败为
"-"）。按不存在的键取值使任何图片回退 1920x1080。

**修复**（quick_project_dialog.py `_probe_media_metadata` 图片分支）：正则
解析 `Resolution`（容忍空格/大小写 x/全角 ×/小数），成功且 >0 才写
width/height；不可解析时显式 `logger.warning`（含路径与原始值）后维持
1920x1080 回退。视频分支与默认值不变。

**测试**：`test_image_resolution_parsed_from_resolution_string`
（"6000 x 4000" → 6000x4000）、`test_image_resolution_missing_falls_back_
with_warning`（"-" → 1920x1080 回退）。
