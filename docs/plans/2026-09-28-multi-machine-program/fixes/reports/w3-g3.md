## 1. AUD-17100 — FIXED（Critical/bug/M）

**位置**：`src/features/edit/core/project.py` `update_comp_clip`（原 4183-4243，现 4197-4245）。

**根因**：`nodes = list(comp_dict.get("nodes", []))` 只新建了列表容器，列表内的
node dict 对象仍与旧工程快照（undo 栈 / revision 历史）共享；循环里
`node["parameters"] = params`（constant 与 output 两处）原地改写这些共享 dict。
旧 EditProject 实例会"看到"新的 width/height/背景色——撤销后图数据不回滚。

**修复**（copy-on-write，与文件内其他 update_ 路径对齐）：

```python
new_nodes: list[Any] = []
for node in nodes:
    if node.get("type") == "constant":
        params = dict(node.get("parameters", {}))
        ...
        node = {**node, "parameters": params}
    elif node.get("type") == "output":
        if width is not None or height is not None:
            params = dict(node.get("parameters", {}))
            ...
            node = {**node, "parameters": params}
    new_nodes.append(node)
comp_dict["nodes"] = new_nodes
```

要点：
- 被修改的节点重建为新 dict（`{**node, "parameters": params}`），
  `parameters` 仍为浅拷贝 dict——所有写入都是键赋值（`params["width"]=...`），
  不改嵌套值，浅拷贝足够且与项目隔离模式一致；
- output 分支仅在 width/height 实际变化时重建，未触及的节点对象保持共享
  （只读共享与 `update_composition` 等现有路径语义一致，不做无谓深拷贝）；
- `background_nodes`/`background_node_ids` 只读旧节点，判定逻辑不变。

## 2. AUD-17600 — FIXED（Critical/risk/M）

**位置**：`src/features/edit/core/recording_manager.py` `_on_audio_ready`
（原 1079-1090，触发点 1089）与 `_finalize_take`（原 1211，死锁点）。

**根因**：`threading.Lock`（785 行，非重入）。磁盘剩余空间低于
`_DISK_FAIL_BYTES` 时 `append` 抛 `DiskSpaceExhausted`，except 处理器位于
`with self._buffer_lock:` 块内部，直接调用 `_finalize_take(save_partial=True)`
→ 后者在 1211 行再次 `acquire` 同一把锁 → 同线程（readyRead 交付的主线程）
永久阻塞，"安全终止并保留已录数据"完全无法发生。

**修复**（重构为"锁内捕获、锁外处理"）：

```python
disk_error: Optional[DiskSpaceExhausted] = None
with self._buffer_lock:
    if self._pcm_buffer is None:
        self._pcm_buffer = _ChunkedPcmBuffer(channels=channels)
    try:
        self._pcm_buffer.append(raw)
    except DiskSpaceExhausted as e:
        disk_error = e            # 锁内只捕获
if disk_error is not None:
    self._set_state(self.STATE_FAILED)
    if self.on_error:
        self.on_error(str(disk_error))
    self._finalize_take(save_partial=True)   # 锁外执行
    return
```

同时修复审查"另注"的同源风险——`on_error` 回调持锁执行（若回调再入
`stop_recording`→`_finalize_take` 同样死锁在 1211）：
- 缓冲注册的 `on_disk_warning` 改为向 `_pending_disk_warnings` 队列入队
  （`__init__` 新增该字段），不再直接调 `self.on_error`；
- 新增 `_drain_disk_warnings()`（完整类型注解）：在 `_buffer_lock` 之外把
  队列中的预警转发给 `on_error`；`_on_audio_ready`（正常路径与终止路径）和
  `inject_pcm` 的锁块之后调用；
- `_ChunkedPcmBuffer.on_disk_warning` 契约不变（仍同步回调），既有测试
  `test_disk_warning_callback` 不受影响——改变的是 manager 侧注册的回调。

## 3. AUD-18400 — FIXED（Critical/bug/M）

**位置**：`src/features/edit/core/timeline_export.py` `_cpu_sharpen`（原
1212/1232）、`_cpu_edge_detect`（原 1373-1376/1491）、`_cpu_denoise`（原
1530-1532/1590-1600）。

**根因**：三个处理器硬编码 `/255.0` 归一 + `*255.0 → uint8` 量化。
`_apply_clip_effects_cpu`（8903）在 `_use_high_precision_export=True` 时直接
处理 `_convert_yuv_planes_to_bgr16` 产出的 uint16 层帧：中灰 32768/255 ≈
128.5 → clip[0,1] → 1.0 → 输出 255（整帧全白、dtype 退化 uint8）。对照组
`_cpu_blur`/`_cpu_glow`/`_cpu_defocus` 均按 `np.iinfo(dtype).max` 缩放并保留
输入 dtype，仅这三处不感知位深。

**修复**（新增两个共享辅助 + 三处处理器接入，对照 `_cpu_glow` 范式）：

```python
def _effect_full_scale(frame: "np.ndarray") -> float:
    """uint8→255、uint16→65535；float 输入不额外缩放（返回 1.0）。"""
    if np.issubdtype(frame.dtype, np.integer):
        return float(np.iinfo(frame.dtype).max)
    return 1.0

def _effect_quantize(normalized, dtype, full_scale) -> "np.ndarray":
    """整数目标 clip[0,1]×满刻度 rint 后回输入 dtype；float 目标不钳位
    （保留 HDR 浮点范围），只做 dtype 转换。"""
```

- `_cpu_sharpen`：`source = frame / full_scale`，输出
  `_effect_quantize(result, frame.dtype, full_scale)`；
- `_cpu_edge_detect`：`source` 一次按满刻度归一，5 个 channel 分支删去各自的
  `/ 255.0`；输出 `gray = _effect_quantize(output, ...)`——uint16 时边缘为
  65535（原 255），BGRA16 的 alpha 赋值 `result[:, :, 3] = frame[:, :, 3]`
  不再发生 uint16→uint8 截断；
- `_cpu_denoise`：`center`/`alpha` 按满刻度归一（权重/σ 均在归一化域，
  数学不变），BGR 与 alpha 输出走 `_effect_quantize`；
- **uint8 路径逐位不变**：`full_scale=255.0` 时归一/量化表达式与旧代码
  等价（`np.float32(255.0)` 精确表示，除法语义同旧 `/255.0`），既有
  uint8 测试全部原样通过。
