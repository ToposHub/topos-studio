## 1. AUD-25900 [Critical/bug/M] — FIXED

**问题**：`_interpolate_curve_255` 把控制点 y 直接当输出（`y/255`），而 UI 侧
`CurvesWidget._compute_lut`（src/shared/ui/widgets/curves_widget.py:457-458）与
`layer.curves_data` 持久化约定是 `(255.0 - y) / 255.0`（y=0 为顶部/白）。
`set_curves` 写入 `curves_data` 的默认通道值 `[(0.0, 255.0), (255.0, 0.0)]`
（UI 约定恒等线）恰证明存储侧用的是 UI 约定。脚本设置的曲线立即渲染方向正确，
但 `layer_controller.update_from_layer`（layer_controller.py:86-87）把同一组点
载入 CurvesWidget 后，用户拖动任一控制点即按 `(255-y)/255` 重算 → 整体反相。

**根因修复**：`_interpolate_curve_255` 与 UI 统一为 `(255.0 - y) / 255.0`，
覆盖全部 4 条计算路径（单点、2 点线性、scipy 缺失 fallback、PCHIP+外推），
并同步修订 docstring（模块内 `_interpolate_curve_255` 与 `ToposAPI.set_curves`），
明示倒置 Y 轴：y=0 为顶部（提亮）、y=255 为底部（压暗）、恒等线
`[(0, 255), (255, 0)]`，示例改为提亮中间调的
`topos.set_curves(master=[(0, 255), (128, 100), (255, 0)])`。

- 文件：`src/features/scripting/api.py`
- 行号：98-166（`_interpolate_curve_255`：docstring 98-116，单点 126，
  2 点 133，fallback 141，PCHIP 收尾 166）；664-687（`set_curves` docstring）

**测试证据**（`tests/scripting/test_fix_api_engine_aud.py::TestCurveYAxisConvention`）：
- `test_ui_identity_curve_is_identity_lut`：UI 默认恒等线 `[(0,255),(255,0)]`
  → 恒等 LUT（修复前会得到反向 LUT）。
- `test_inverted_ys_produce_inverted_lut`：旧约定的 `[(0,0),(255,255)]`
  现在正确产出反相 LUT（方向锁定）。
- `test_single_point_follows_inverted_y`：单点路径 `(255-100)/255`。
- `test_script_to_ui_roundtrip_matches_curves_widget`：审计建议的脚本→UI
  往返回归——真实实例化 `CurvesWidget`，`set_curves_data` 载入与脚本相同的
  M/R/G/B 四组控制点，逐通道断言 `_interpolate_curve_255(points) ≈
  widget._lut_cache[ch]`（allclose atol=1e-5）。修复前两套公式方向相反，
  该测试必然失败。

**既有测试更新**（锁定旧错误行为，按任务授权更新断言并说明）：
`tests/color/test_color_tools_scripting_api.py` 中 4 处——
`test_interpolate_two_points_linear`（输入改为 UI 恒等线 `[(0,255),(255,0)]`，

## 2. AUD-25901 [Critical/bug/M] — FIXED

**问题**：`batch()` 在 `output_dir=None` 时 `out_path = file_path`，随后
`self.save(out_path, ...)` 直接覆写原始文件（对 `.jpg` 输入 + 默认
`format="JPEG"` 路径不变），8-bit JPEG q95 结果无确认、无备份地覆盖源素材，
且 docstring 完全未提示。

**根因修复**：选择"默认写入不覆盖源的子目录"方案（与 docstring 既有语义
"Returns a list of output file paths" 兼容，且不破坏无参调用方）：
`output_dir=None` 时输出到源文件旁的 `graded/` 子目录（按每个源文件各自的
目录计算，目录由 `save()` 的 `os.makedirs` 自动创建）；显式传入 `output_dir`
行为不变。docstring 新增说明："If *output_dir* is omitted (None), results
are written to a ``graded`` subdirectory next to each source file (created
automatically) — source files are never overwritten."

- 文件：`src/features/scripting/api.py`
- 行号：1095-1165（`batch`：docstring 1126-1129，输出路径计算 1148-1162）

**测试证据**（`tests/scripting/test_fix_api_engine_aud.py::TestBatchOutputDirDefault`，
以 `_FakeBridge` + 实例级 stub 的 `open`/`save` 隔离引擎）：
- `test_default_writes_to_graded_subdir_not_source`：
  `/tmp/.../shoot_001.jpg` → save 收到 `/tmp/.../graded/shoot_001.jpg`，
  断言不等于源路径。
- `test_default_graded_subdir_next_to_each_source`（tmp_path）：两个不同
  目录的源文件分别落到各自的 `graded/` 子目录，且 `format="PNG"` 扩展名正确。
- `test_explicit_output_dir_is_used_unchanged`：显式 `output_dir` +
  `format="TIFF"` → `/out/shoot_001.tif`（原行为回归保护）。

## 3. AUD-25909 [Critical/risk/M] — FIXED

**问题**：`_run_script`/`_run_action` 只捕 `ScriptAbortError`/`Exception`；
用户脚本的 `sys.exit()` / `raise SystemExit` / `KeyboardInterrupt` 属
BaseException，会逃出被重写的 `QThread.run`（engine.py:283
`self._thread.run = lambda: ...`）。PyQt6 中逃出虚方法重实现的未处理异常按
qFatal 处理 → abort 整进程；且 `script_finished` 永不发射，UI 停留"运行中"。

**根因修复**：
1. 新增模块级辅助 `_error_line_number(exc_tb, script_name)`（带完整类型
   注解），统一抽取"优先用户脚本帧、回退最内层帧"的行号逻辑（原
   `_run_script` 内联逻辑与 `_run_action` 的最内层逻辑合并，行为等价）。
2. `_run_script` 与 `_run_action` 在 `except Exception` 之后各增加
   `except BaseException as e:` 分支：
   - `SystemExit` 且 `e.code is None or e.code == 0` → 视为正常完成，
     发射 `script_finished(True, "Script exited via sys.exit(0).")`；
   - 其余（`SystemExit(非0)`、`KeyboardInterrupt`、其他 BaseException）→
     traceback 输出到 stderr 流（`error_output_ready`）、`script_error`
     携带行号、`script_finished(False, "<类型>: <信息>")`；
   - 记录后吞掉，绝不让异常逃出 run() 重写（不重抛）；既有 `finally`
     继续 flush 输出流。正常退出路径（无异常）不经过该分支。

- 文件：`src/features/scripting/engine.py`
- 行号：23-50（`_error_line_number`）；324-366（`_run_action`，BaseException
  分支 344-358）；369-417（`_run_script`，BaseException 分支 398-412）

**测试证据**（`tests/scripting/test_fix_api_engine_aud.py::TestRunScriptBaseException`，
直接调用 `_run_script`/`_run_action`（即 run 重写的函数体），信号槽记录发射）：
- `test_system_exit_zero_reports_success`：`sys.exit(0)` → 恰一次
  `(True, "Script exited via sys.exit(0).")`，无异常逃出（逃出则测试失败）。
- `test_system_exit_nonzero_reports_failure_with_line`：`sys.exit('boom')`
  → `(False, "SystemExit: boom")`，`script_error` 行号 == sys.exit 所在行（3）。
- `test_keyboard_interrupt_does_not_escape`：`raise KeyboardInterrupt` →
  `(False, ...)` 含 "KeyboardInterrupt"，无逃出。
- `test_regular_exception_path_unchanged`：`1/0` →
  `(False, "division by zero")`，行号取用户脚本帧（回归保护）。
- `test_run_action_system_exit_does_not_escape` /
  `test_run_action_exit_zero_reports_success`：注册动作回调抛
  `SystemExit(2)` / `SystemExit(0)` 的对应行为。
