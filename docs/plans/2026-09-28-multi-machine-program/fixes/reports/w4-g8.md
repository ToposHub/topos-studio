## 1. AUD-38000 — import_preset 外部预设 per-value 类型零验证（Critical/bug/M）

**验证属实**。原代码（399-411 行）把 `entries.items()` 的值直接送进
`by_sequence.setdefault(seq, ...)`：list/dict 值不可哈希 → `TypeError: unhashable
type`；int 等可哈希非字符串值会经 `set_shortcut` 存入 config，之后
`QKeySequence(seq)` 再抛 TypeError。调用方 `src/app/ui/shortcut_dialog.py:304-342`
的 `_on_import_preset` 是 Qt 槽且无 try 包裹 → PyQt6 槽内未处理异常默认 qFatal
终止进程。另外非字符串 key 落进 `unknown` 后 `sorted(unknown)` 对混合类型同样
抛 TypeError。

**修复**（根因：入口逐值校验，失败项跳过 + 报告）：

- 构建 `known` 的循环改为逐项三段校验：
  1. `not isinstance(aid, str)` → `errors`（"invalid action id ...: expected
     string, got ..."），不再进入 unknown（避免 sorted/join 对混合类型崩溃）；
  2. 未知 id → `unknown`（语义不变，现有测试 `unknown == ("ghost.action",)`
     继续通过）；
  3. 已知 id 但 `not isinstance(seq, str)` → `errors`（"invalid shortcut for
     ...: expected string, got list/int/NoneType/..."），绝不进入冲突检测、
     `set_shortcut` 或 config。
- 末尾报告从写死 `errors=()` 改为 `errors=tuple(errors)`——非法项随报告返回；
  `ShortcutPresetReport.ok` 因 errors 非空为 False，调用方
  `parts.extend(report.errors)` + `QMessageBox.information` 使用户可见。
- docstring 校验规则同步补一条 bullet。合法条目仍正常应用、预设内冲突检测
  （`conflicts`）行为不变（回归测试锁定）。

## 2. AUD-38205 — 吸管覆盖层在自身事件处理栈内析构（Critical/risk/M）

**验证属实**。`EyeDropperOverlay`（`src/shared/color/color_picker.py:410-461`）
是无父 QWidget、未设 `WA_DeleteOnClose`；其 `mousePressEvent` 先 `close()` 再
`colorPicked.emit(color)`，`keyPressEvent`(Esc) 先 `close()` 再
`cancelled.emit()`。直连槽 `_commit_color`/`_clear_dropper` 在覆盖层自己的事件
分发栈上同步执行，`self._active_dropper = None` 使最后一个 Python 引用归零 →
sip 立即析构仍在事件栈上的 C++ 对象（等价于事件处理器内 `delete this`，
Qt 明示 UB）。

**修复前的行为实验**（本仓库 `.venv`，offscreen）：
- 仅置 None（旧代码）→ `destroyed` 信号在 gc 后立即触发（确凿复现原缺陷）；
- `deleteLater()` 后再丢引用 → gc 后不析构，`sendPostedEvents(None,
  DeferredDelete)` 才析构（sip 对挂起延迟删除的对象不会因引用归零立即析构）。

**修复**（审查建议原样落地）：

```python
dropper, self._active_dropper = self._active_dropper, None
if dropper is not None:
    dropper.deleteLater()
```

成员引用仍在事件栈内释放（下次 `_start_eyedropper` 不会复用旧覆盖层），但
析构被移到事件循环安全点。None 守卫保证 `_pick_color`（拾色器路径）进入
`_commit_color` → `_clear_dropper` 时无 dropper 也不抛错。

## 3. AUD-38404 — HistogramWidget 对 NaN 无防护（Critical/bug/M）

**验证属实**。`np.clip` 对 NaN 不生效，`astype(np.int32)` 得 INT_MIN（审查方在
本仓库 venv 实测复现 `ValueError: 'list' argument must have no negative
elements`），调用链 `scope_panel._process_pending_image`（QTimer 槽）无人捕获；
仓库无自定义 excepthook → qFatal。HDR float 管线产生 NaN 是真实风险，同文件
CIE 路径（`linear_rgb_to_xy`）已有 `nan_to_num` 防护，直方图路径缺失。

**修复**（入口清洗，与 CIE 路径对齐）：

```python
values = np.nan_to_num(
    small[:, :, ch].astype(np.float32),
    nan=0.0, posinf=1.0, neginf=0.0,
)
codes = np.clip(values * 255.0, 0, 255).astype(np.int32)
```

- NaN 无语义 → 0（bin 0/黑）；±inf 先映射到 0..1 域边界再由既有 clip 钳到
  [0,255]（超白 → 顶 bin 255，-inf → bin 0）。
- 不用 `nan_to_num` 默认 posinf/neginf：默认会用 float32 极大有限数替换，
  `* 255.0` 会溢出并产生 RuntimeWarning（测试开发中发现并规避）。

## 4. AUD-38501 — 0°/90° 分支宽高约束互换（Critical/bug/M）

**验证属实**。0° 正确解为 `w_c = min(w, h*ar)`：ar ≥ w/h（预设比图更宽）时
受宽度限制应返回 `(w, w/ar)`，ar < w/h 时受高度限制应返回 `(h*ar, h)`——原
代码两分支恰好写反。反例复现（修复前）：`(1000, 1000, 0, 2.0) → (2000,
1000)`（宽超原图一倍）、`(1920, 1080, 0, 1.0) → (1920, 1920)`（高超 77%）。
90° 分支同源错误。下游 `canvas.py:439` `_apply_crop_constraints` 用被膨胀的
safe 尺寸计算 `max_offset = (safe - final)/2`，裁切框中心可越出图像。

**修复**（删除特判、统一通用公式）：

- 通用投影公式在退化角极限正确：`sin_a==0 → w_c = min(w, h*ar)`（恰好 0°
  正确解，两个约束退化为 `w_c<=w, h_c<=h`）；`cos_a==0 → w_c = min(h, w*ar)`
  （90° 正确解，交换约束）。全程数值扫描验证（角度 ×{0, 0.0001, 5, 15, 30,
  45, 60, 75, 89.9, 89.999999, 90, 180, 270, 359.9999, -15, -90} × 比例
  ×{0.25, 0.5, 1.0, 1.3333, 16/9, 2.0, 4.0} × 尺寸 ×{1920×1080, 1080×1920,
  1000×1000, 640×480}）：投影约束全部成立、比例严格保持、结果最大化（至少
  一约束取等）、0° 时两维均不超原图。
- 注：审查建议中的断言「任意角度 w_c<=w 且 h_c<=h」数学上过强——非 0° 时
  旋转图像的轴对齐包围更大，h_c 合法可超过 h（如 1920×1080 转 30° 的竖长
  裁切）。测试采用正确的投影判据 `w_c·cos+h_c·sin<=w ∧ w_c·sin+h_c·cos<=h`，
  0° 下退化为审查所述的简单断言。
- 顺带（同函数、零行为变更）：docstring 三个示例改为真实运行输出
  （15°+16/9 → (1346.38, 757.34)；45° 默认比例 → (977.50, 549.85)，原文
  (792.0, 792.0) 与任何参数组合都对不上，即 AUD-38503 所指）；签名改
  `aspect_ratio: Optional[float] = None, ... -> tuple[float, float]`
  （AUD-38502 所指，满足强类型约束）。
