## 1. AUD-0200 [Critical/bug/M] — FIXED

**问题**：`_do_bake_layer` 在调用 `build_composition_shader(..., request_id=render_request_id)`
时引用了方法体内未绑定的 `render_request_id`（全文件仅 `_do_render_impl` 内有绑定），
首个未冻结前缀层走到该分支即 `NameError`，异常被 `run()` 主循环吞掉，
`layer_baked_ready` 永不发射，AI Bake 100% 失效。

**证据核实**：审查报告行号 6428 已漂移至当前代码 **6628**（方法体 6455 起）。
grep 确认 `render_request_id` 在该方法内无绑定，问题在当前代码存在。
`shader_compiler.py:219/232` 确认 `request_id` 仅是诊断关联上下文、
不参与 shader 缓存键，传 `None` 安全。BAKE_LAYER 提交侧
（`image_engine.py:4614`）的负载不含该键。

**修复**（`src/features/color/core/async_renderer.py:6482-6485`）：
在 `_do_bake_layer` 头部数据提取段补 `render_request_id = data.get('render_request_id')`，
与 `_do_render_impl`（2439 行 `params.get('render_request_id')`）口径一致；
负载不携带时为 `None`，未来负载带上即自动生效。

**测试证据**（`tests/color/test_fix_aud02xx.py::TestAud0200BakeLayerRequestId`，3 例）：
- `test_bake_completes_and_emits_without_name_error`：GL 全 mock 走完前缀渲染 +
  回读 + 信号发射（修复前该路径抛 NameError，信号永不发射）；
- `test_request_id_defaults_to_none`：负载缺省 → `build_composition_shader`
  收到 `request_id=None`；
- `test_request_id_taken_from_payload`：负载带 `render_request_id="bake-42"`
  → 原样透传。

## 2. AUD-0501 [Critical/bug/M] — FIXED

**问题**：`HistoryManager._serialize_layers` 直接存 `layer.to_dict(assets_dir=None)`
的返回 dict。`Layer.to_dict`（layer.py:1011/1040）与 `MaskShape.to_dict`
（layer.py:189-193/199）对 `grading_params`、`plugins`、`points`、`center`、
`brush_strokes` 等可变容器**按引用**返回 → 栈内快照与活动图层共享可变对象，
压栈后的任何就地编辑（`apply_grade_patch`、canvas 拖点、plugin 开关）都改写
历史，undo/redo 静默失效。

**证据核实**：history.py 已从审查时的 155 行演化为 210 行（`_serialize_layers`
现位于 179 行起），但 `to_dict` 引用语义未变，问题存在。

**修复**（`src/features/color/core/history.py:189-196`）：
`_serialize_layers` 对每层 `to_dict` 产物做 `copy.deepcopy` 后入栈
（`copy` 模块原本已 import 未用）。`push_state` / `undo()` / `redo()` 三条
入栈路径共用该函数，一处修复全覆盖。同时把模块 docstring 中
"to_dict 内部对可变容器做 copy"的错误契约描述更正为实际机制
（`history.py:17-20`）。图像快照（`copy_image=True/False`）行为不变，
`test_non_destructive_snapshot_keeps_source_reference` 继续通过。

**测试证据**（`TestAud0501HistorySnapshotIsolation`，4 例）：
压栈后就地改 `grading_params["exposure"]` / 拖 `mask_shapes[0].points` /
翻 `plugins[0]["enabled"]` / undo 后继续编辑再 redo——栈内快照与
反序列化恢复值均回到压栈时刻（修复前全部被污染）。

## 3. AUD-0600 [Critical/bug/M] — FIXED

**问题**：`ImageEngine._restore_state` 恢复图像后仅写 CPU 侧
`img_full_original/img_low/img_high` 就调 `render_pipeline()`：
- 渲染线程只消费此前 `UPLOAD_IMAGE` 上传的纹理 → 视口继续显示撤销前
  旧图/旧尺寸；
- `img_low/img_high` 直接赋 `_resize_to_fit` 的 uint8 结果，破坏
  "img_high 为 float32 [0,1]" 的文件不变量（对照 `set_image:847-848`）；
- 无任何层置 `mask_dirty` → `_update_mask_textures`（2811-2813 按脏标志
  跳过）不重栅格化；
- split 参考纹理未同步（尺寸/内容过期）。

**证据核实**：审查行号 4194-4225 已漂移至当前 **4379-4410**，问题存在。

**修复**（`src/features/color/core/image_engine.py:4390-4431`，均在 UI 线程
执行、经 `renderer.submit` 命令队列投递渲染线程，符合线程约束）：
1. 与 `set_image` 同口径的 `normalize_to_float32`（uint8/uint16 → float32
   0..1，float 直接保留，无 clamp，不破坏 HDR）写入 `img_high/img_low`；
2. `renderer.submit(RenderCommand.UPLOAD_IMAGE, {'image': float32 连续数组,
   'original_size': (w,h), 'is_video': self._is_video_mode})`；`renderer=None`
   时走 legacy no-op（`_upload_to_gpu`/`_generate_pyramid`），与 `set_image`
   的降级分支一致；
3. `self._source_epoch += 1`：恢复的源像素与 bake 前缀摘要基准不同，
   递增 epoch 使所有 baked 前缀过期（`set_image:750` 同款语义，关闭
   "撤销 crop 后视口继续消费旧 bake"的漏洞）；
4. `self.set_reference_image(self.img_high)`：split/wipe 参考纹理与主纹理
   同尺寸同内容；
5. 图层恢复后对所有层 `layer.mask_dirty = True`（deserialize 新建 Layer
   默认置脏，此循环显式锁定该不变量并覆盖 layers_data 为空、图层列表
   未被替换的路径）。

未动 `flip_h/flip_v` 恢复（AUD-0502，非本批范围）。

**测试证据**（`TestAud0600RestoreStateGpuResync`，6 例）：
undo 后恰有一次 `UPLOAD_IMAGE`，payload 为 float32、值 =200/255、
`original_size=(6,4)`；恰一次 `UPLOAD_REFERENCE`；layers 未替换 /
反序列化两条路径全层 `mask_dirty=True`；`_source_epoch` 递增；
`renderer=None` 路径不抛错且 `img_high` 为 float32[0,1]。
