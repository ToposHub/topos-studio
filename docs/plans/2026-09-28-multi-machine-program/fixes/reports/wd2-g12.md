## 1. AUD-22201 — FIXED

**位置**：`src/features/ai_harness/plugin_runtime.py` `PluginCapability.__post_init__` / `PluginManifest.__post_init__`（原 193-195、241、246-271）

**根因**：frozen dataclass 只冻结字段绑定，`metadata` 与 capability 的 `input_schema/output_schema/metadata` 保留调用方传入对象引用；注册后原地修改会使 `content_hash`/`declared_hash`/签名校验结果随时间漂移。

**修复**：新增 `_freeze_mapping(value, *, field_name)` 辅助（deepcopy → `types.MappingProxyType` 包装；非 Mapping 输入抛 `TypeError`，deepcopy 失败降级为浅拷贝快照），在两个 `__post_init__` 内对全部 Mapping 字段做防御性快照。`to_dict()`/`content_hash` 原有消费路径（`dict(self.metadata)`）不变。

## 2. AUD-22202 — FIXED

**位置**：`src/features/ai_harness/plugin_runtime.py` `PluginRegistry.activate`（原 511-558）

**根因**：`plugin.activate()` 在锁外执行（必要），但收尾临界区不校验条目身份——激活窗口内 `register(replace_existing=True)` 替换条目后，新条目被标 ACTIVE（从未执行其 activate）、写入基于旧 policy 构建的 broker/host_io，旧实例孤儿化不 deactivate；异常路径 `_mark_failed` 同样会把新条目误标 FAILED。

**修复**：
- 激活前在首个临界区内快照 `activation_policy`，broker/host_io/context 一律基于快照构建（不再引用旧 entry 对象）。
- 收尾临界区校验 `entry.plugin is plugin`（含 manifest-only 分支的 `entry.plugin is not None` 校验）：不一致时不落 ACTIVE、不挂 host_io，调用新增 `_deactivate_orphan()` 对已 activate 的旧实例做 try/except 包裹的 best-effort teardown（异常记 `_LOG.exception`，不发 `plugin.activated`，改发 `plugin.activation_abandoned`）并返回 False。
- 异常分支同样先做身份校验，仅当条目未被替换时才 `_mark_failed`。

## 3. AUD-22205 — FIXED

## 5. AUD-22309 — FIXED

**位置**：`src/features/ai_harness/runtime.py` `HarnessRuntime.finish`（原 538-562）

**根因**：`finished_at` 在迁移校验前写入——对 DRAFT run 调 finish 返回 False 但留下"活跃却带 finished_at"的脏状态（rollout_metrics 只看 finished_at 非空即计入延迟）；对已终态 run 再次 finish 会覆盖 error 字段并发出一条状态实际未变的伪 RUN_STATE_CHANGED 事件。

## 7. AUD-22311 — FIXED

## 15. AUD-22414 — FIXED

**位置**：`src/features/ai_harness/subagent_runtime.py` `SubagentSupervisor`（原 131-134、176-178、221-223）

**根因**：`_children_by_parent`/`_rounds`/`_requests` 三个记账 dict 只增不删（`SubagentRequest` 含完整 prompt 字符串），Supervisor 为长生命周期对象，长会话无界内存增长且 prompt 文本永久驻留可被枚举。

**修复**：
- `_requests` + `_rounds` 合并为单一 `OrderedDict[str, _ChildContinuation]`：**不含 prompt**（continue_child 从不读取旧 prompt，事件走 `to_trace_dict` 只带长度/hash），round 并入记录充当权威轮次。
- 记录 LRU 有界：`_MAX_TRACKED_CHILDREN = 512`，超限淘汰最旧（淘汰后的 continue 以 "unknown child run" fail-closed）。
- `_children_by_parent` 改 `OrderedDict` LRU，`_MAX_TRACKED_PARENTS = 1024`（淘汰极端大量 parent 时每 parent 计数可能重置，换取有界内存，注释明示取舍）。
- **锁定旧行为保留**：终态/one-shot/达轮次上限的子代理记录不立即删除（仅去 prompt + LRU 淘汰），使后续 continue 仍得到原领域错误（"subagent is one-shot and cannot continue" / "subagent maximum rounds exceeded"）而非 "unknown child run"——`tests/ai/test_agent_presets_subagents_and_fork.py` 锁定该语义，首版"终态即删"实现被该测试捕获后按锁定协议修正。

## 16. AUD-22415 — FIXED

**位置**：`src/features/ai_harness/subagent_runtime.py` `SubagentSupervisor.continue_child`（原 208-223）

**根因**：轮次"读 `_rounds`+1 并检查上限"与"回写 round_number"分属两次加锁，中间窗口两个并发 follow-up 读到同一旧值、双双通过 `max_rounds` 检查，runner 对同一 child 并发执行两次，轮次权威被并发绕过。

**修复**：准入（读记录 → 校验 definition/continuable/prompt → 轮次 +1 → 上限检查 → 构造 request → **回写推进后的轮次**）合并进单次 `with self._lock:` 临界区；runner 与事件仍在锁外执行。并发 follow-up 第二个会读到已推进的轮次，各自消耗互异轮次（不串行化执行，只保证轮次权威）。验证测试用 `threading.Barrier(2)` 强制两个 follow-up 同时进入 runner，断言轮次集合为 {2, 3}（旧缺陷下为 {2, 2}）。
