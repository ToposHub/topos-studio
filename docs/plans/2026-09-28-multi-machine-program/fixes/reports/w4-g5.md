## 1. AUD-33100 [Critical/process/M] — FIXED

**问题**：`generate_export_filename` 的 Custom Pattern 分支只捕获
`(KeyError, IndexError)`；`'{}'.format(name=..., n=..., ext=...)` 对非法
format 串（单个 `{`、`{n:0dd}` 等）抛 **ValueError**。`custom_pattern_input.
textChanged`（export_panel.py:896）每敲一键同步调用
`update_naming_preview`（:1444-1469）→ 异常逃逸出 Qt 槽 → PyQt6 默认
qFatal 中止进程；导出路径（get_settings/_start_batch_export）同样崩溃。

**证据核实**：审查报告位置 49-53 与当前代码一致，问题存在。实测
`'{}'.format(name='a', n=1, ext='.jpg')` 抛
`ValueError: Single '{' encountered in format string`，复现确认。

**修复**（`src/shared/export/export_panel.py`）：
1. `generate_export_filename`（:49-57）捕获列表扩为
   `(KeyError, IndexError, ValueError)`，非法时回退默认命名
   `{original_name}_{index:0{seq_digits}d}{output_ext}`——对全部调用方
   （预览 + 实际导出）生效，locale 无关。
2. `update_naming_preview`（:1459-1472）新增 pattern 预检：custom pattern
   非空时先 `custom_pattern.format(name=sample_name, n=1, ext=sample_ext)`
   试算，抛 `(KeyError, IndexError, ValueError)` 即把预览标签置为占位
   错误文案 `I18N.tr('export.invalid_pattern', '(无效的命名模式)')` 并
   提前返回——用户在 Pattern 框获得即时反馈而不是静默回退。
   未新增 locale 键（白名单不含 locale JSON，I18N.tr 的 default 参数
   在键缺失时返回默认文案，行为确定性已核）。

**测试**：`tests/shared/test_fix_export_aud4.py::TestAud33100InvalidPattern`
（10 例：6 个参数化非法 pattern 回退、合法 pattern 格式化、UI 路径键入
`{`/`{n:0dd}` 不崩且显示占位文案、恢复合法后占位消失）。

## 2. AUD-33320 [Critical/bug/M] — FIXED

**问题**：`_extract_frame_data` 的 packed 分支对整数 dtype 原样返回：
uint8 帧经 `_apply_color_policy`（假定 [0,1] float 域）与 `_export_png`
的 `np.clip(data, 0.0, 1.0)` 后近乎全白；EXR(SCENE_LINEAR) 路径把 0-255
码值当线性亮度写入——255 倍过曝。违反硬约束"整数帧数据必须按位深归一化
（uint8/255、uint16/65535）"。

**证据核实**：审查报告位置 332 与当前代码一致，问题存在（DecodedFrame
契约 packed dtype 可为 uint8/uint16，frame.py:331/344-350）。

**修复**（`src/shared/export/sequence_exporter.py:322-345`）：
- `uint8 → astype(np.float32) / 255.0`，`uint16 → / 65535.0`（与项目
  硬约束及 file_io 预览缓存同一定标）；float dtype 原样透传（HDR >1.0
  不破坏）；其他整数 dtype 防御性按 `np.iinfo(dtype).max` 归一化。
- 归一化**先于**补 alpha：3 通道输入在 float 域补 `alpha=1.0`。
  （原实现整数域 `np.ones(dtype)` 的 alpha=1，若先补后归一化会得到
  alpha=1/255 的错误透明度——顺带修正。）

**测试**：`TestAud33320PackedNormalization`（3 例：uint8 RGB 补 alpha 且
值域/alpha 断言、uint16 RGBA 定标、float32 原样含 >1.0 值）。

## 3. AUD-33504 [Critical/bug/M] — FIXED

**问题**：`_configure_encoder` 的 GOP 分支条件
`codec_lower in ("h264", "hevc", "av1")` 不含 vp9，而 `_is_gop_codec`
与 GOP 默认值把 vp9 当 GOP codec——crf/bitrate/preset/gop_size 一个都
不下发，libvpx-vp9 落到 FFmpeg 默认目标码率 256 kb/s（无报错的严重
画质劣化）。违反硬约束"编码器参数必须真正下发给后端"。

**证据核实**：审查报告位置 1286-1287 与当前代码一致；触发链可达
（composite_render_output.py:388-402 带 crf 构造 FFmpegEncoderConfig）。
另核 `hwaccel_engaged`（:593 `codec_lower not in ("h264","hevc","av1")`）
确认 vp9 永远走 CPU 路径，无需考虑硬编映射。

**修复**（`src/shared/export/video_encoder.py`，对齐 H.264 CPU 路径写法）：
1. `_configure_encoder`（:1300）GOP 元组扩为
   `("h264", "hevc", "vp9", "av1")`。
2. crf：`{'crf': str(...)}`（与 H.264 同写法），vp9 侧 clamp 到
   libvpx 域 0-63（x264/x265 是 0-51，与 AMF/NVENC 路径的 clamp 风格
   一致）。
3. bitrate：`_build_rate_control_options` 的标准 AVOption 分支由
   `av1` 扩为 `("av1", "vp9")`——libvpx 不认 x264-params/x265-params
   私有串，走 `b`/`maxrate`/`bufsize`（与 av1 分支同款；`b` 键名是
   AVOption 正名，b:v 会被 avcodec_open2 静默忽略——文件内 1235-1238
   已实证的教训）。
4. preset：libvpx **没有** 'preset' AVOption（直接下发会 open 失败，
   同 libaom-av1 跳过 preset 的原因），新增模块级映射表
   `VP9_PRESET_CPU_USED`（ultrafast→8 … medium→4 … veryslow→0），
   以 `cpu-used` 选项承载 preset 语义，未知 preset 名回退 medium 档。
5. gop_size：共享既有 `self._stream.gop_size = self._config.gop_size`
   语句（`_is_gop_codec` 含 vp9，None 时默认 fps*2 现在真正生效）。

**测试**：`TestAud33504Vp9ParameterDelivery`（6 例：crf/preset/gop 全量
下发、crf clamp 63、bitrate 走 b/maxrate/bufsize 且无私有串、映射表
端点、GOP 默认 fps*2、H.264 路径回归护栏）。

## 4. AUD-33901 [Critical/doc-gap/M] — FIXED

**问题**：`_cache_preview` 的 EXR 编码参数仍用 ZIP(3)——T-P1-71 已
文档化（docs/ai_executable_optimization_upgrade_plan_2026-09-17.md
T-P1-71 批次三条：opencv 5.0.0 轮子的 libOpenEXR 走 ZIP/PIZ 时经
libdeflate 派发间歇 SIGILL，.ips 栈 `libdeflate_zlib_compress ←
cv2.imwrite`；复现循环 ZIP 6 跑 2 崩 → RLE 6 跑 0 崩）的安全压缩策略
是 **RLE(1)**（无损、不经 deflate）。`save_image` 已改（file_io.py:849-854
注释），预览缓存路径漏同步——所有 16 位/浮点源首次加载即走该崩溃路径。

**证据核实**：file_io.py:477（当前代码）确为
`[cv2.IMWRITE_EXR_TYPE, 1, cv2.IMWRITE_EXR_COMPRESSION, 3]`，问题存在。

**修复**（`src/shared/io/file_io.py:473-482`）：压缩值 3 → 1（RLE），
并同步 T-P1-71 注释说明与 save_image 一致。未动 `save_baked_layer`
的 DWAB(9)——审查建议中"确认不受 libdeflate 派发影响后统一"属后续
独立验证项，超出本条最小根因修复范围（且该路径为 Topos 自有编码器
参数，非 libOpenEXR ZIP/PIZ 家族）。

**测试**：`TestAud33901PreviewCacheExrCompression`（3 例：monkeypatch
cv2.imencode 捕获 uint16 预览的 EXR 参数断言 `IMWRITE_EXR_COMPRESSION==1`、
uint8 无 alpha 仍走 JPEG 路径、cv2 EXR 常量存在性护栏）。
