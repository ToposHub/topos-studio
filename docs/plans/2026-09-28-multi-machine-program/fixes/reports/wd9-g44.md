## AUD-12214 — FIXED

**位置（修复前）**：`detachable_panel_host.py:135-140`（`float_panel` 已浮动分支）。

**根因**：`self._dock.setFloating(floating and area is None or area is None)` 在 Python 运算符优先级下等价于 `(floating and area is None) or (area is None)`——area 非 None 时恒为 False，`floating` 参数被完全忽略，docstring 承诺的 "with an area, True keeps floating / False docks" 被破坏。

**修复**：改为 `self._dock.setFloating(bool(floating) or area is None)` 并加注释说明三种语义分支：无 area → 恒浮动；有 area + floating=True → 保持浮动锚定该区；有 area + floating=False → 停靠。

**测试**：`test_floating_argument_honoured_with_area`（floating=True 保持浮动 / floating=False 停靠）、`test_floating_without_area_is_always_floating`。

## AUD-12215 — FIXED

**位置（修复前）**：`detachable_panel_host.py:262-266`（`_build_dock` 内注释）。

**根因**：注释声称 "关闭浮动 dock = 回到 splitter，由 workspace 监听 visibilityChanged 处理"，但该连接全仓库不存在——用户关闭浮动队列窗口后面板被留在已隐藏的 QDockWidget 里，只能靠主窗口 dock 菜单找回。

**修复**：行为落地在 host 自身（证据报告两个可选方案中的等效实现，不越白名单改 workspace）：
- `_build_dock` 对 dock `installEventFilter(self)`；host 覆写 `eventFilter` 捕获 `QEvent.Type.Close`。
- 回嵌经 host 拥有的 0ms 单发 `QTimer`（`_dock_close_return`）延迟一拍执行——等 dock 自身 close 处理完成后才 reparent+teardown，且 timer 以 host 为父，host 销毁即自动失效。
- `_on_dock_close_return` 带 mode/dock 前置检查与 `except RuntimeError`（teardown 期 C++ 对象已亡）留痕兜底，槽内不抛异常。
- `return_to_splitter` 在拆除前 `removeEventFilter(self)`。
- **实现备注**：第一版按证据报告字面建议连 `visibilityChanged`，实测（offscreen 复现）Qt 在 `addDockWidget`/`setFloating` 过渡期会发瞬态 False，导致既有测试 `test_double_float_is_idempotent` 失败（dock 在区域迁移中被误拆）。改用 Close 事件（精确的用户关闭手势）后语义正确且既有测试全过。注释同步更正为描述真实机制。

**测试**：`test_dock_close_returns_panel_to_splitter`（close → embedded、面板回到 splitter）、`test_manual_return_to_splitter_is_not_disturbed_by_signal`。

## AUD-12404 — FIXED

**根因**：①编辑已有任务时（load_job 不清 `_selected_preset_ids`）若同时勾选多个预设，循环内每个 job 都被赋予同一 `_editing_job_id` → 入队后同 id 互相覆盖/错乱；②成功发出 add/add_and_start 后 `_editing_job_id` 不清理、`set_project` 换项目也不重置，后续新增持续顶替旧任务，完全依赖控制器记得调 `clear_editing()`。

## AUD-12405 — FIXED

**位置（修复前）**：`video_export_settings_panel.py:2855-2859`（预览 `except Exception` 静默清空标签）、`:2309-2316`（Add 路径对同一构造逻辑完全不设防）；另按证据建议收窄 `:2826-2829`（frame_count）。

**根因**：草稿构造阶段的领域错误在预检预览中被 `except Exception` 静默吞掉（状态行仅清空、`preflight_updated` 消费者拿过期结果）；点 Add 时同一异常在 Qt 槽内未捕获——PyQt6 对槽内未处理异常默认 qFatal 中止进程。

**修复**：
- 模块级显式领域异常元组 `_DRAFT_BUILD_ERRORS = (ValueError, TypeError, KeyError, ArithmeticError)`（草稿取值强转/模板字典查找/分辨率运算的实际逃逸面），非裸/宽捕获。
- `_refresh_preflight`：捕获该元组，`logger.warning` 留痕并把错误写入状态行（`⚠ <msg>`，红色样式），不再静默清空。
- 新增 `_build_jobs_for_add()`：两个 Add 槽统一经其调用 build_jobs，同域异常 → `logger.error` + `QMessageBox.warning` 弹窗反馈 + 刷新预检 + 返回 None（不发射信号、不入队）。
- `_build_preflight_context` 的 frame_count `except Exception` 收窄为 `except (TypeError, ValueError)`（int 强转的真实失败面）。
- 证据中另提的 `:2490`（auto_detect_stem_groups，可选插件导入+调用防护，带注释的显式回退）不在本条引用位置内，保留原状。

**测试**：`test_preflight_preview_shows_domain_error`、`test_add_clicked_reports_domain_error`、`test_add_and_start_clicked_reports_domain_error`（QMessageBox 打桩，验证弹窗一次、零发射、槽不抛）、`test_error_tuple_is_explicit_and_not_broad`。
