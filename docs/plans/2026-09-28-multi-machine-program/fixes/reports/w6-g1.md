## BUG-A2-01（medium）undo/redo 不恢复翻转状态

**状态：FIXED**

**根因**（当前代码核实，位置较证据文档有漂移）：`flip_image` 经
`push_state(..., flip_h=, flip_v=)` 把翻转标志存入快照，但：
1. `ImageEngine._restore_state`（image_engine.py，原 ~L4379）只消费
   `image`/`layers`/`active_layer_index`；
2. `HistoryManager.undo/redo` 的"当前状态换历史状态"对称交换构造
   redo_state/undo_state 时**不记录** flip 字段——即使修了 1，redo
   回来的快照也没有翻转信息。

**修复**（两文件三处）：
- `history.py`：
  - `push_state` 的 `flip_h/flip_v` 缺省从 `False` 改为 `None`（未跟踪
    语义）。这是刻意设计：全仓 ~15 处 `push_state` 调用（crop/resize/
    rotate/apply_changes 及各 controller）不带 flip 参数，它们压栈时的
    图像像素已含现行翻转；若缺省记 False 并在恢复时无条件回写，会把
    "翻转→裁切→撤销裁切"错误重置为未翻转（标志/像素错位），引入新
    回归。None 表示"本快照不跟踪翻转，恢复时保持引擎现行标志"，
    与这些调用方的旧行为完全一致。
  - `undo`/`redo` 新增 `current_flip_h/current_flip_v` 关键字参数，
    写入对称交换到对侧栈的快照（含类型注解与 docstring）。
- `image_engine.py`：
  - `undo()`/`redo()` 调用时传 `current_flip_h=self._flip_h,
    current_flip_v=self._flip_v`；
  - `_restore_state` 在恢复活动图层索引后消费 flip 字段：值非 None
    才回写 `self._flip_h/_flip_v`（None 保持现行）。

**效果**：翻转→撤销后 `get_flip_state()` 回到撤销前（项目保存不再写入
错误翻转态）；再次翻转/`reset_flip` 以正确标志为基准，不再双重翻转；
redo 同样完整恢复。

**测试影响**：
- `TestUndoRestoreFlipState::test_undo_restores_flip_flags` 去掉
  `xfail`（翻正），新增 `test_redo_restores_flip_flags`、
  `test_flip_get_flip_state_after_undo`；
- 新文件 `TestFixA201FlipUndoRedo`（undo/redo/双翻转/序列化态/未跟踪
  快照保持标志 共 5 例）与 `TestFixA201HistoryManager`（HistoryManager
  层对称交换 3 例），其中 `test_non_flip_snapshot_keeps_current_flags`
  专门锁定 None 语义防回归。

## BUG-A2-04（low）_render_mask_items_recursive 未知类型防御分支不可达

**状态：FIXED**（选择"使可达"，并删除因此新产生的死分支）

**根因**（当前代码 image_engine.py ~L2735）：循环第一行
`if not item.visible:` 在 `isinstance(MaskGroup/MaskShape)` 判定之前
执行，无 `visible` 属性的杂项对象（旧序列化数据/编程错误）先抛
`AttributeError`，永远到不了 `else: continue`。

**修复**：类型过滤前移——

```python
if not isinstance(item, (MaskGroup, MaskShape)):
    continue
if not item.visible:
    continue
```

已知类型（均有 `visible`）行为完全不变；未知条目无论有无 `visible`
属性都被跳过。同时把后续 `elif isinstance(item, MaskShape): ... else:
continue` 中因守卫而不可达的 `else` 删除（守卫已保证二选一），避免
留下新的死代码。

**测试影响**：新文件 `TestFixA204UnknownMaskItem` 4 例——无 `visible`
属性的杂项对象不再 AttributeError（旧现状是崩溃）、带 `visible` 的
未知对象跳过、杂项不阻断同列表合法形状、已知类型行为不变。既有
`test_unknown_item_type_skipped` 继续通过。

## BUG-A1-02（轻微/仅影响测试替身）RESET_VIDEO_DENOISE_HISTORY 分支的 getattr 不符 __new__ 桩惯例

**状态：FIXED**

**根因**（当前代码 async_renderer.py ~L1042）：该分支用普通
`getattr(self, 'video_denoise_pipeline', None)`；未跑 `QObject.__init__`
的 `__new__` 测试桩上缺失属性时 PyQt6 抛 `RuntimeError`（getattr 默认值
兜不住），与文件自身在 `run()`/`_do_render`（L527 注释）及 L6130/L6184
的 `self.__dict__.get(...)` 守卫惯例不一致。

**修复**：改为 `pipeline = self.__dict__.get('video_denoise_pipeline',
None)`，附注释说明惯例与 PyQt6 RuntimeError 语义。生产路径行为不变
（真实实例总是跑过 `__init__`）。

**测试影响**：新文件 `TestFixA102StubFriendlyDispatch` 2 例——不带该
属性的裸 `__new__` 桩直接分发该命令不再抛 RuntimeError；带 pipeline 的
桩仍调用 `reset_temporal_history()`。既有
`test_reset_denoise_history_without_pipeline_is_safe` 继续通过。

**备注（未改，超出证据范围）**：`_do_set_video_denoise`（~L1057）与
`_ensure_video_denoise_pipeline`（~L5103）还有两处同模式
`getattr(self, 'video_denoise_pipeline', None)`，证据文档未列，未动，
留待后续批次判断。

## BUG-A3-02（medium）perform_quick_export 缺 uint16→uint8 降位

**状态：FIXED**

**根因**（当前代码 deliver_controller.py ~L243-249）：dtype 安全转换
只有 `np.float32` 分支；uint16 源（16-bit TIFF）对
`.jpg/.jpeg/.png/.bmp` 直传 `FileIO.save_image`。`perform_panel_export`
（~L197-199）与 `_batch_export_single_file` 均有
`(img / 256).astype(np.uint8)` 分支，唯 quick export 漏了。

**修复**：照抄 panel export 分支，在 float32 分支后补：

```python
elif export_img.dtype == np.uint16:
    if ext in ['.jpg', '.jpeg', '.png', '.bmp']:
        export_img = (export_img / 256).astype(np.uint8)
```

`/256` 与另两条路径同口径（符合"uint16→uint8 降位必须正确缩放"约束）；
`.tif/.tiff` 等 16 位格式不做降位。

**测试影响**：既有锁定用例翻正并更名
`test_uint16_passthrough_documents_missing_conversion` →
`test_uint16_downconverted_to_uint8`（断言 uint8 且值 = 原值/256，512→2）；
新文件 `TestFixA302QuickExportUint16` 2 例（.png 降位、.tif 保持 uint16）。

## BUG-A3-03（low）sRGB 回退编码对负值像素放大而非钳制

**状态：FIXED**

**根因**（当前代码 deliver_controller.py `_encode_composite_linear_to_srgb`
回退分支 ~L99-108）：`mask = rgb <= 0.0031308` 把负值归入线性段，
`12.92 * rgb` 不钳制（-0.5 → -6.46 越界），而幂律分支内侧才
`np.maximum(rgb, 0.0)`。

**修复**：分段前统一 `rgb = np.maximum(rgb, 0.0)`——负值先钳 0 再
OETF；正值高光不钳（2.0 → 1.353256 保持 HDR 上滚，回归用例显式锁定），
alpha 通道照旧直通。原幂律分支内的 max 因此冗余，一并移除。

**测试影响**：既有锁定用例翻正并更名
`test_fallback_negative_handling_documents_amplification_bug` →
`test_fallback_negative_pixels_clamped_to_zero`（-0.5 → 0.0，1.0/2.0/alpha
期望不变）；新文件 `TestFixA303SrgbFallbackNegatives` 3 例（负值钳 0、
正高光不封顶且单调、alpha 直通不改动输入 buffer）。
