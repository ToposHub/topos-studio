## AUD-1207 [Major/bug] wait_fence 的 timeout_ns 语义错误

**状态：FIXED**

**根因**：`glWaitSync` 的 timeout 形参按 GL 规范必须传 `GL_TIMEOUT_IGNORED`；
原实现把调用方传入的非零 timeout_ns 原样透传，产生 `GL_INVALID_VALUE` 且
等待依然无限——限时语义完全是假的。

**修复**（composite_gpu_frame_handle.py `wait_fence`）：`timeout_ns == 0`
走 `glWaitSync(sync, 0, GL_TIMEOUT_IGNORED)`（无限服务器端等待，语义不变）；
`timeout_ns > 0` 改走 `glClientWaitSync(sync, 0, timeout_ns)`——唯一支持
超时的 fence 等待。返回值契约不变（False 仅表示句柄无效）；docstring 写明
两条路径。唯一调用方 `edit_gpu_preview_renderer.py:3515` 不传 timeout，
行为不变。

## AUD-1211 [Major/bug] create_shared_context 不产生共享上下文

**状态：FIXED**

**根因**：`moderngl.create_context()` 只会拿回已附着的（默认）上下文，
返回对象与 `self.ctx` 之间没有共享对象命名空间。审查建议的
`self.ctx.create_shared_context()` 在本环境 moderngl 5.12 中**不存在**
（已实证 `hasattr(moderngl.Context, 'create_shared_context') == False`）；
moderngl 5.12 的受支持路径是 `create_context(share=True)`（glcontext
"share" 模式）。

**修复**（gl_backend.py `create_shared_context`）：未初始化时显式
`RuntimeError`；否则 `moderngl.create_context(share=True)`，docstring 注明
moderngl 官方对 context sharing 稳定性的警告，并要求调用方以
GLContextHub 探测验证后再依赖跨上下文呈现。无既有调用方（休眠缺陷），
零行为风险。

## AUD-1214 [Major/risk] _do_pixel_probe 从未在 ctx_b 上验证

**状态：FIXED**（探测去 GL 化）

**根因**：原 2x2 像素探测中 `ctx_b` 除判空外从未参与任何 GL 调用——
PyOpenGL 调用作用于**调用线程的当前上下文**：探测结果是同义反复（假阳性
→ 直接纹理呈现开在非共享上下文上），且 `tex.release()` 会在当前上下文
删除纹理（不共享时误删无关纹理，数据破坏）。真正的跨上下文探测需要各
上下文的拥有线程（ctx_a 建纹理 → ctx_b 查询 → 回 ctx_a 删除），hub 无法
从任意调用线程做到。

**修复**（gl_context_hub.py `_probe_sharing`，替代 `_do_pixel_probe`）：
探测不再发出任何 GL 调用，按三级判定——
1. 同一上下文对象 → 直接 True（单上下文呈现路径）；
2. 两个 `QOpenGLContext` → `QOpenGLContext.areSharing(a, b)`（share group
   比较，无线程亲和要求、无 GL 调用；当前唯一真实注册方
   composite_viewport.py:11431 注册的正是 QOpenGLContext）；
3. 其它类型（moderngl 等）→ fail-closed False + warning——直接纹理呈现
   绝不建立在未证明的共享对上。
消除全部"隐含当前上下文"的 GL 调用与错误上下文删除路径。当前生产路径
（"composite_renderer" 从未注册）原本就恒 False，行为不变。

## AUD-1300 [Major/risk] release_fn 抛异常时台账条目已被 pop

**状态：FIXED**

**根因**：`release_group` 先整组 `pop` 再逐条回调；回调抛异常意味着资源
在 GL 层并未真正释放，但其登记已消失——deferred-release 同时失去重试与

`release_all` docstring 注明失败条目保留、可重试。既有锁定旧行为测试

## AUD-1401 [Major/risk] dispatch 异常静默丢弃整条累积 command buffer

**状态：FIXED**

**根因**：`dispatch` 编码异常时丢弃 `_current_cb`（设计正确：半编码
buffer 无法再挂 encoder），但已成功编码进该 buffer 的前序 kernel 调用
一并丢失且无任何信号；随后 `submit()` 返回 None 冒充"没有 pending 工作"，
调用方若只重试失败的那个 kernel，输出缺前序计算。

**修复**（metal/context.py）：
- `__init__` 增加 `_dropped_work` 标记；dispatch 丢弃路径置位并 re-raise
  （丢弃发生时调用方必然知情——异常来自 dispatch 本身）；
- `submit()`：无 cb 且 `_dropped_work` → 抛 `MetalComputeError`（"必须
  重新编码整条链"），**一次即清**——异常本身即信号，避免把 context 永久
  毒化（现有调用方 metal_compute_bridge 每次效果调用都是整链重编，bridge
  的"捕获 → 上层回退"流不受影响）；有 cb 的成功提交同样清位（调用方在
  drop 异常后已重编整条链，新链取代旧链）；
- 新增 `has_dropped_work` 属性供诊断（审计建议的区分"无工作"/"工作被
  丢弃"）。
- 锁定旧行为的既有测试 `test_dispatch_failure_drops_poisoned_command_buffer`
  更新为断言"drop 后 finish 显式报错 + 一次即清 + 全链重编后恢复"。

## AUD-1402 [Major/risk] PyObjC 路径全程无 autoreleasepool

**状态：FIXED**

**根因实证**：基线 docstring 声称"PyObjC 在每次 Python→ObjC 调用边界
自动清池"——该声明是**错误的**。本机实证（pyobjc 12.1）：pool-less 线程
上 2000 个 1MB autoreleased `NSData.dataWithData_` 使 RSS 线性增长约
2.1GB（553MB@500 → 2125MB@2000），无任何回收；对照显式
`objc.autorelease_pool()` 包裹的运行无此增长。工作线程（QThread）上
dispatch/submit/read_texture 每帧泄漏 autoreleased Metal 对象成立。

**修复**（metal/context.py）：
- 模块级 guarded `import objc` + `_autoreleasepool()` contextmanager（无
  objc 的 fake 测试宿主退化为空操作）；
- 包裹全部产生 PyObjC 对象的公共入口：`dispatch` / `submit` /
  `read_texture` / `compile_kernel` / `create_buffer_from_numpy` /
  `create_buffer` / `create_private_buffer` / `create_texture_from_numpy` /
  `create_texture_2d`。对象存活性仍由 Python 强引用锚定
  （`_current_cb`/`_kernels`/`_libraries`/调用方变量），池只清那些唯一
  所有者是 autorelease 机制的对象；
- 模块 docstring 的 autoreleasepool 约定段改写为实证结论（含实验数据与
  日期），防止回归到错误假设。真机层测试（本机有 Metal）全部通过。

## AUD-1520 [Major/risk] drain() 可快照到 None 预留槽并解引用 .command_buffer

**状态：FIXED**

**根因**：`submit` 锁内放 `None` 预留槽、锁外调 `context.submit`；此窗口
内 shutdown 线程的 `drain()` 对 None 取 `.command_buffer` → AttributeError
打断关机序列。

**修复**（submission_scheduler.py `drain`）：
- 跳过 None 预留槽（不解引用），对其余 buffer 逐个等待（单个等待失败仅

- 有预留槽且未到 `timeout_s`（默认 5s，新增关键字参数）时 sleep 10ms 重

  已注册的 completion handler 收尾；
- 回归测试：submit 阻塞在 context 层（模拟 commit 在途）时 drain 不抛
  AttributeError 且有界返回；正常路径单次等待行为与旧测试兼容。

## AUD-1601 [Major/risk] TextureLease 状态转移未统一纳入 pool 锁

**状态：FIXED**

**根因**：协议图要求渲染线程在 pool 锁外直接调
`lease.mark_ready()/make_present_frame`，而 shutdown 线程经 pool 锁内
`release_all/acquire_for_writing` 读写同一批字段——check-then-act 竞态：
release_all 置 FREE 后 mark_ready 可把 slot"复活"为 READY（纹理已被销毁、
新 fence 无人清理 → GLsync 泄漏），或 acquire 出现双写者。

**修复**（present_frame.py）：
- `TextureLease` 增加自身 `_lock`（dataclass field，compare=False）；全部
  状态转移（begin_writing/mark_ready/begin_viewer_use/ack/release）与
  `make_present_frame` 的状态/fence 读取原子化；fence_cleanup 回调移到
  slot 锁外执行（锁序恒为 pool → slot，无死锁；pool 锁为 RLock 允许
  回调重入）；
- release_all 先行回收后，迟到的 mark_ready 得到 RuntimeError"拒绝复活"
  ——唯一直接调用方 edit_gpu_preview_renderer.py:5138-5140 本就捕获
  RuntimeError 并降级为无 slot fallback descriptor，无缝衔接；
- 回归测试：200 次并发 mark_ready vs release_all，终态恒 FREE、fence 清理
  至多一次（修复前可出现僵尸 READY）。

## AUD-1603 [Major/bug] 消费端消失/迟到帧无 slot 回收路径

**状态：FIXED**（协议侧：discard API + 文档契约；Viewer 侧接入见"遗留"）

**根因**：不变量"未 ack 永不复用"的另一面——帧 emit 后 Viewer 队列溢出
丢帧或 Viewer 消失未补 ack，slot 永久滞留 READY；池容量典型为 3，数次后

**修复**（present_frame.py）：
- 新增 `OutputSlotPool.discard(slot_id) -> bool`：READY/IN_VIEWER →
  RELEASABLE（含 fence 清理），不可回收状态返回 False；
- 模块协议图与交接契约补"丢帧纪律"：任何被丢弃的 present **必须**
  `ack` 或 `discard` 二选一；顺带把协议图中与本实现不符的调用顺序/签名
  更正（make_present_frame 无 fence 形参、属性名 fence_ns、先 mark_ready
  后 make_present_frame——与 327 行起的正确示例一致）。
- 回归测试：discard 回收 READY slot + fence 清理 + 可再次 acquire；
  FREE/不存在 slot 返回 False。

  `ValueError/TypeError/AttributeError` 兜底；
- 回归测试：list 根的 locale 文件返回 False 且词典安全；模块目录带 list
  根 JSON 时激活路径不抛异常、既有词典不受影响；合法根正常深合并。
