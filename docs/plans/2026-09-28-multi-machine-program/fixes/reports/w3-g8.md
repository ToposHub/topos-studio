## 1. AUD-20900 — paintGL 别名池纹理，clear_texture 误删（Critical/risk/M）

**验证属实**。`paintGL`（原 698-703 行）在共享纹理在显示时执行
`self._current_tex_id = tex_id`（tex_id 即 `_shared_tex_id`），使 `_current_tex_id`
别名渲染线程 OutputSlotPool 的纹理；`close_source()`（1387 行）→ `clear_texture()`
（原 983-986 行）无条件 `glDeleteTextures([self._current_tex_id])`，随后 1395 行把该
slot ack 回池——池把已销毁的纹理名重新派发，后续渲染写入已删除纹理，且名字被
viewer 之后 `glGenTextures` 复用时发生跨模块别名写入。注释"do NOT delete — owned
by render thread"的意图确被别名击穿。

**修复**（独立字段方案——任务处方"flag 或独立字段"）：
- **paintGL 移除别名写入**：共享纹理在显示时只更新显示尺寸
  （`_tex_width/_tex_height`，供 display-rect/缩放计算），不再触碰 `_current_tex_id`；
  `_current_tex_id` 从此严格只存 viewer 自建纹理（`_shared_tex_id` 只存外部池纹理，
  两个字段各自专责，即"独立字段"的所有权区分）。
- **新增 `_display_tex_id()` 解析器**：渲染期按"共享优先、自有兜底"只读解析实际要
  绘制的纹理 ID；`paintGL` 的渲染条件与 `_render_texture` 的绑定/校验均改用它。
- **`_render_texture` 无效纹理分支重写**：只解除匹配的那个引用字段（共享或自有），
  不再一刀切双清（旧写法在新模型下会把仍有效的自有纹理引用丢掉造成泄漏）。
- **`clear_texture` 只删自有**：`_current_tex_id != _shared_tex_id` 才调
  `glDeleteTextures`（防回归守卫——即使未来别名回归也不会删除池纹理），共享引用仅
  置 None，池释放继续走既有 slot-ack 协议。
- `set_texture()` docstring 补所有权合同（传入即转移所有权；池纹理必须走
  `set_shared_texture`）。该方法全库无调用方（composite/program viewer 的同名方法属
  其他类），语义无行为变更。

**附带的内存修复**：旧代码在"CPU 上传自有纹理 A → GPU 恢复共享显示"时，paintGL
直接用池 ID 覆盖 `_current_tex_id`，A 从此失联泄漏；新模型中 A 始终留在
`_current_tex_id`，CPU 回退时可继续复用（尺寸匹配时 glTexSubImage2D），
`clear_texture` 时正确删除。

## 2. AUD-20901 — CPU 回退按尺寸匹配复用/重定义池纹理（Critical/risk/M）

**验证属实**。`set_texture_from_qimage_with_display_size`（原 929-943 行）的
`size_matches` 只看 `_current_tex_id is not None` + 尺寸相等；别名建立后
`_tex_width/_tex_height` 来自池纹理，代理解码尺寸与池尺寸同源（同为媒体显示尺寸
封顶 1920），大概率相等 → `glTexSubImage2D` 原地写入被 ack 协议钉住的池槽纹理。
`set_texture_from_qimage`（原 872-885 行）同状态下用 `glTexImage2D` 重定义池纹理。
974 行只切断共享引用、保留别名，无法自救。

**修复**（任务处方"CPU 回退路径使用 viewer 自建纹理，不复用外部 ID"）：
- `set_texture_from_qimage_with_display_size`：
  - `size_matches` 增加 `self._current_tex_id != self._shared_tex_id` 条件——复用
    目标必须是 viewer 自有纹理；
  - else 分支的分配条件改为 `self._current_tex_id is None or
    self._current_tex_id == self._shared_tex_id`——别名状态（防回归）下强制
    `glGenTextures` 新建。
- `set_texture_from_qimage`：分配条件同样加 `== self._shared_tex_id` 守卫。
- 根因层面与 AUD-20900 同一处修复闭环：paintGL 不再建立别名后，这两条路径的
  `_current_tex_id` 本来就只会是 None 或 viewer 自有纹理；不等式守卫是对未来回归的
  二道防线（GL share group 内活跃纹理名唯一，相等仅可能来自别名）。
- 合法复用路径不受影响：无共享纹理时同尺寸连续上传仍走 glTexSubImage2D 原地更新
  viewer 自有纹理（新增测试锁定）。

## 3. AUD-13500 — `complete_host_export` 未定义名（Critical/bug/M）

**验证属实**。`export_service.py` 原 765 行
`brand_timeline_duration_frames=subtitle_duration_frames`——`subtitle_duration_frames`
在 `complete_host_export`（697-768 行）内既非参数（参数名为
`subtitle_timeline_duration_frames` / `brand_timeline_duration_frames`）、非局部变量、
非模块级名字；763-767 行续行多缩 8 格为拼接编辑残迹。生产调用方
`src/app/controllers/ai_edit_host_bridge_impl.py:1259` 在编码 worker 的 `_post_export`
回调中调用本方法，求值关键字实参即抛 NameError，probe / 交付质量门 / manifest 物化
全部不执行。

**来源推断**（非盲目置 0）：全库唯一同名局部变量在调用方
`ai_edit_host_bridge_impl.py:1239`：
`subtitle_duration_frames = int(getattr(sequence, "duration_frames", 0) or 0) or None`，
且调用方 1274/1280 行把同一值同时传给 `subtitle_timeline_duration_frames` 与
`brand_timeline_duration_frames`。可见本方法内该实参的应有来源就是自身的
`brand_timeline_duration_frames` 参数（调用方已把序列时长传入；默认 None 语义保留）。

**修复**：改为 `brand_timeline_duration_frames=brand_timeline_duration_frames`，并修复
五行的缩进残迹使其与上下文对齐。
