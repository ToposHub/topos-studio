## 修复明细

### AUD-26600 — `__all__` 含 40 个未定义名称（FIXED）

- `ai/__init__.py`：`from .context_provider import` 补入 `TeachingAIContextProvider`
  （公开 API 别名存在于 context_provider.py:19，此前只是漏导入）；删除 `__all__`
  中 39 个 job_dag / lane_scheduler 残留导出（`MotionGraphicJobDAG`、`KIND_*`、
  `NODE_*`、`LANE_*`、`MotionGraphicLaneScheduler` 等，491–504 行整块）。
- 结果：`__all__` 398 → 359 项，全部有定义、无重复（`import *` 与逐名 import 均可用）。
- 全库 grep 确认无任何调用方引用被删名称。

### AUD-26603 — codec 白名单条件失效（FIXED）

- `advanced_capabilities.py:227`：`codec not in export_backends and not
  supports_codec(codec)` → **`or`**。白名单（如 CAP_CHARACTER_LIPSYNC /
  CAP_3D_CAMERA 的 `export_backends=("mp4",)`）现在对未列入的导出格式真实拒绝；
  黑名单（`incompatible_codecs`）继续叠加生效，与 preview 后端的严格检查对称。
- 语义依据：本模块种子数据与既有调用（测试传 `codec="mp4"`）中 `export_backends`
  与 codec 参数共用同一格式词汇表（svg/html/mp4），不属跨词汇表混比。

### AUD-26608 — 音频许可口径不一致（FIXED）

- `audio_plan.py`：新增 `BLOCKING_LICENSE_STATES = {missing, restricted}`（复用
  `asset_provenance.LICENSE_*` 常量，与 quality_gate.py:204 口径一致）；
  `issues()` 阻断条件由 `== "missing"` 改为 `in BLOCKING_LICENSE_STATES`；
  `AudioTrack.__post_init__` 增加 `license_state ∈ ALL_LICENSE_STATES` 闭集校验
  （拼写错误如 `"Missing"` 在构造期即拒绝）。`BLOCKING_LICENSE_STATES` 入 `__all__`。

### AUD-26702 — 能力清单与编译器参数漂移（FIXED）

以编译器实际读取键为唯一事实源重写 `capability_context.DEFAULT_COMMANDS`：
- `apply_motion_preset`：`target`/`property` → **`element_id`/`param_name`**，补
  `start_frame`/`end_frame`，`params` 类型 string → object（编译器要求 Mapping）。
- `stagger_elements`：`targets` → **`element_ids`**，补必填 `param_name`（缺它必然
  编译失败）与 `interval`/`duration`/`delay`/`anchor_frame`/`params`。
- `set_brand_theme`：顶层 `theme_id`/`palette` → **`theme` 对象**（编译器读取
  `args["theme"]`，内含 theme_id/palette/type_scale/spacing/motion/safe_area/source）。
- `replace_asset_slot`：`asset_id` → **`asset` 对象**（SceneAssetRef 字段）。
- `set_beat_timing` / `set_transition` / `set_stagger_interval`：全仓库无 AI 编译器
  （`set_stagger_interval` 有核心 SceneCommand 但从未接入 EXTENDED_COMMAND_NAMES），
  按审计建议**从清单删除**，并在注释中写明"先补编译器再上清单"。
  - 说明：曾实现 `_compile_set_stagger_interval` 并加入 EXTENDED_COMMAND_NAMES，
    但 `tests/ai/test_wiring_mg09_mg12_os05.py::test_total_command_count` 以
    "25 条命令"锁定旧词汇表且该测试文件不在本批白名单，故按锁定旧行为协议收敛为
    "从清单删除"方案（同为审计认可的修复路径）。
- `add_element`/`update_element` 的 `element`/`updates` 类型 string → object
  （编译器要求 Mapping），`CommandParam.type` 词汇表注释补 `object`。
- 新增交叉核对测试：清单名 ⊆（基础 4 ∪ EXTENDED）且 required 参数与编译器必填键
  一一对应；对 4 条曾漂移命令用清单自己的参数名实际编译通过。

### AUD-26703 — stagger `or` 默认值吞掉显式 0（FIXED）

- `command_catalog.py` `_compile_stagger_elements`：`int(args.get("interval", 12) or 12)`
  改为显式判 None（`raw is None` → 12）。`interval=0`（全部同时动画）不再被静默改成
  12；`duration=0` 不再被洗成 18 而是命中 "must be positive" 报错；省略时默认值不变。

### AUD-26704 — insert_keyframe 同帧替换的 undo 数据丢失（FIXED）

- `_InsertKeyframeCommand.undo`：改为"跳过该帧现有关键帧 + 回填 apply 时记录的
  `_existed`"。原实现只跳过新关键帧、从不回填，导致该帧关键帧被彻底删除。
  现 apply→undo 后轨道精确回到提案前基线（含被替换的原值）；无原关键帧时行为不变。

### AUD-26705 — set_color_token / set_typo_token 死约定（FIXED）

- 匹配约定从全仓库无生产者的 `var(token)` / `font_token` 改为真实设计令牌约定
  （core/design_tokens `_TOKEN_REF = "$"`，如 `$palette.primary`、`$type_scale.display`）：
  - `set_color_token`：style 的 `color`/`fill` 等于 `$token` 原始引用 **或** 经
    `read_scene_tokens(scene.metadata).resolve_value` 解析出的当前值（模板产出的
    场景通常已解析为具体 hex，按值反查命中）；大小写不敏感。
  - `set_typo_token`：style 的 `font_size` 等于 `$token` 引用或解析后的数值
    （数值比较，字符串引用精确比较）。
  - 无命中仍 fail-closed 抛 `TeachingAIProposalError`，错误信息带上两种查找形态。

### AUD-26713 — 第一方注册表构建异常被静默吞掉（FIXED）

- `context_provider.py`：两处 `except Exception: pass` 拆分为
  `except ImportError`（可选能力缺失，合法降级，静默）+ `except Exception`
  （第一方代码 bug，`logger.exception` 记录完整堆栈，不再掩盖）。
- 返回结构新增 `degraded: tuple` 标记（"templates" / "motion_presets"），供宿主观测
  上下文退化。测试验证注入坏注册表时日志产生且 catalog 标记降级、健康构建时为空。

### AUD-26800 — `supports_4k` 声明永远无法触发（FIXED）

- `creative_templates.py`：`compatibility_issues` 新增可选 `width`/`height` 参数；
  同时给出时，长边 > `NON_4K_MAX_EDGE_PIXELS`（1920）且 `supports_4k=False` →
  拒绝并给出可读理由。`social_card_9x16`（supports_4k=False）对 3840×2160 现在会被
  前置拒绝；1080p 请求与 supports_4k=True 模板不受影响。参数可选，既有调用兼容。

### AUD-26805 — 素材校验复用画布越界错误码（FIXED）

- `design_validator.py` `_check_assets` 两处（未引用素材 warning、未声明素材 error）
  改用专用的 `MOTION_GRAPHIC_ASSET_UNRESOLVED`（error_codes.py:89 已定义，
  `_SUGGESTED_NEXT_STEPS` 有对应恢复建议，与 quality_gate L199 口径一致）。
  用户不再看到"将元素移回安全区"这类无关建议。

### AUD-26806 — 对比度只看场景背景（FIXED）

- 新增 `_backing_color()`：对每个文本元素，取**完全包含其 bbox 的最上层不透明非文本
  元素**（z_index 高者优先、同 z 后出现者优先；`style.opacity < 1` 跳过）的
  fill/color/background 作为对比背景；无包含者回退场景背景色。复用 `_bbox` 与
  容差（`options.overlap_tolerance`），只认"包含"不认"相切/部分相交"，避免装饰性
  交叉形状造成误判。模块文档"contrast between text fill and the element behind it"
  的承诺现在成立：浅色卡片上的白字被正确阻断，深色卡片上的合规文字不再被误判。

### AUD-26814 — 非 success 路径不清理 .tmp（FIXED）

- `export_job.py`：新增 `_remove_temp_file()`（best-effort `os.unlink`，仅吞
  OSError——被锁/权限问题不得掩盖任务自身的终态迁移）；`finish()` 的取消、质量
  阻断、覆盖被拒、落盘失败四条路径与 `fail()` 全部清理临时文件；新增公开
  `cleanup_temp()` 供宿主在取消时显式调用（幂等）。success 路径仍由 `os.replace`
  消费临时文件，行为不变。

### AUD-26815 — `finish()` 内 OSError 逃逸（FIXED）

- `os.makedirs`/`os.replace` 包入 `try/except OSError`：失败即
  `EXPORT_FAILED` + `diagnostic_code=EXPORT_FINALIZE_FAILED`（新增常量，入
  `__all__`）+ 中文诊断信息 + 临时文件清理，不再出现 "running 但已结束" 的矛盾
  快照。状态写入顺序保持（finished_at/postflight 先行，status 终态化）。

### AUD-26902 — 增/删页正则双向误判（FIXED）

- `_ADD_PAGE_RE` / `_REMOVE_PAGE_RE` 重写为两个分支：
  1) 动词 + **必填**数量词 + 页（`加一页`/`删除两页`/`插入3页`），数量词后加
     `(?!码|面)` 排除复合词；
  2) 动词 + 第 N 页序数形（`删除第2页`/`增加第 4 页`），尾部排除"的内容/底部/
     标题…"等页内容名词（`_PAGE_ORDINAL_TAIL`），但允许"增加第 4 页总结"这类
     新页标签。
- 修复后：`为每一页添加页码`、`删除页面底部的版权信息`、`减少页面之间的留白`、
  `删除第2页的内容`、`在第3页添加标题` 不再误判为增删页；`删除第2页`、
  `增加第 4 页`、`加一页总结` 正确设防。28 组正则用例全部通过。

### AUD-26903 — `_REMOVE_QUOTED_RE` 误判否定/改写目标（FIXED）

- 去掉 `不要` 否定动词分支，并对动词前加负向后行断言
  （`(?<!不要)(?<!不需要)(?<!无需)(?<!别)`），"不要删除「X」"不再把 X 列为待删；
- 动词与引号之间的跨度字符集排除从句标点（，。、；：,.;:!?！？）与全部引号字符，
  "删掉旧数据，把文案改成「B」"中的 B 不再同时进入"要求包含"与"要求删除"集合
  （任何修订必被否决的死锁消除）；
- 真删除（`删除「旧文案」`、`去掉顶部横幅「X」`）仍正常设防。
