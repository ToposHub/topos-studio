## 逐条处置

### 1. AUD-16200（Critical）InsertLinkedAssetCommand.undo 手工重建 TimelineSequence 丢弃 subtitle/master 等全部新字段 — FIXED

- 位置核实：`src/features/edit/core/commands.py` 原 9839-9849（undo 的 `_created_audio_track_id` 清理分支）确为手工 `TimelineSequence(...)` 构造，仅传 9 个原始字段。`TimelineSequence`（`timeline_v2.py:2933`）现共有 20 个字段：`format_settings / subtitle_tracks / caption_graphic_bindings / caption_track_graphic_styles / caption_graphics_extra / range_start / range_end / master_volume / master_muted / master_automation / master_automation_mode / revision` 均未传递——因都有默认值不会 TypeError，而是被静默重置（undo 即数据丢失）。问题存在。
- 修复（根因）：改用不可变重建器 `timeline._rebuild(audio_tracks=new_audio)`（`timeline_v2.py:3248`，集中传递全部字段且保留 revision），与 Wave3 修复转场命令的 `track._rebuild` / 本文件 `AddTrackCommand` 的 `timeline._rebuild` 模式一致。保留原判定逻辑（仅删除我们创建的空轨）不变。
- 验证：
  - 新增 `TestInsertLinkedAssetUndoPreservesFields` 3 用例：构造富字段时间线（subtitle 轨+字幕片段、master_volume=1.75、master_muted=True、master_automation（KeyframeTrack）、master_automation_mode="read"、format_settings、caption_graphics_extra、range、revision=41），apply（触发自动建 A2 轨）→ undo 后：
    a) **动态守卫**：遍历 `dataclasses.fields(TimelineSequence)` 逐字段与原时间线相等（未来新增字段自动纳入守卫）；
    b) `to_dict()` 序列化快照与原时间线完全一致；
    c) 无自动建轨路径同样无损。
  - 反向验证（证明测试有效）：以旧 undo 实现逐字替换后重跑，用例 a/b 如期失败（`undo dropped TimelineSequence.format_settings`、快照 diff 显示 `revision 0≠41`、`master_muted False≠True`、`subtitle_tracks []≠[...]` 等）。

### 2. AUD-2701（Critical）Solid 生成器参数修改用手工构造函数重建 EditProject，静默丢弃 smart_bins 并将 revision 归零 — FIXED

- 位置核实：`edit_controller.py` 原 3736-3753（`_on_edit_generator_color_changed`）与原 3809-3826（`_on_edit_generator_params_changed`）两处 `project.__class__(...)` 手工罗列 15 个字段，均未传 `smart_bins`（P1-12 用户自建 Smart Bin）与 `revision`（TAEP P0 乐观锁）——两者默认值 `{}` / `0`，静默丢弃。问题存在（证据报告两处行号均覆盖）。
- 修复（根因）：两处统一改为 `replace(project, assets=new_assets, modified_at=_time.time())`（`from dataclasses import replace` 已在文件头部 41 行导入，与本文件 658/728/910 等处既有模式一致），其余全部字段由 dataclass 机制原样携带。
- 验证：新增用例构造 `smart_bins={"sb-rated": SmartBin(...)}`、`revision=17` 的工程，经 stub controller 调用两个 handler 后：动态守卫遍历 `dataclasses.fields(EditProject)`（仅允许 assets/modified_at 变化）+ 显式断言 `smart_bins`/`revision` 保持。反向验证：以旧实现逐字替换后重跑，如期失败 `project rebuild dropped EditProject.smart_bins`。

### 3. AUD-2702（Critical）生成器重建 MediaAsset 时丢弃 keywords/rating/flag/color_label/comment 日志字段 — FIXED

- 位置核实：两个 handler 内原 3716-3732 / 3789-3805 的 `MediaAsset(...)` 手工构造仅传 15 个字段，`keywords/rating/flag/color_label/comment`（P1-12 素材日志，`project.py:120-126`）全部落在构造之外被重置默认；注释自称 "rebuild via dataclass replace" 但实为手工构造。问题存在。
- 修复（根因）：两处统一改为 `replace(asset, metadata=new_meta)`——仅更新目标字段（metadata），日志字段与未来新增字段全部携带。
- 验证：同一组用例构造 `keywords=("intro","bg") / rating=4 / flag="reject" / color_label="orange" / comment="..."` 的 solid 资产，断言 handler 后全部保留、`metadata["color"]`/`metadata["generator_params"]` 正确更新、且新旧 metadata 不共享对象（旧资产快照不被污染）。动态守卫遍历 `dataclasses.fields(MediaAsset)`（仅允许 metadata 变化）。

## 防回归设计（"新增字段不丢"）

- 三组动态守卫分别遍历 `dataclasses.fields(TimelineSequence)` / `fields(EditProject)` / `fields(MediaAsset)` 的**当前**类定义做逐字段对照（各自排除唯一合法变更字段：undo 场景无一排除、project 排除 `assets`/`modified_at`、asset 排除 `metadata`）。未来给这三个领域对象新增任何字段，只要任一重建路径退回手工构造而漏传该字段，无需修改测试即失败。
- 另附 `to_dict()` 序列化快照对照（undo 场景），覆盖"字段存在但 to_dict 语义变化"的第二层防线。
