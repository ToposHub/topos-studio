## AUD-9920 — FIXED

**位置（修复前）**：`node_editor_actions.py:1193-1195`（`create_group_from_selection` 内部 redo）、`1220/1241/1259`（Ungroup/Add/Remove 直接 `cmd.redo()` 后丢弃）；`group_commands.py:315-317`（helper 自行应用并只返回 id）。

**根因**：模块 docstring 声称的 undo 集成（`undo_stack.push(cmd)`）从未发生——四处调用方应用命令后即丢弃命令对象，页面真实的 `UndoStack`（composite_page.py:319）对组操作一无所知，Ctrl+Z 跳过组变更，且后续无关撤销可能得到图/组状态不一致的快照。

**修复**（沿用 backdrop_created/sticky_note_created 的"页面拥有 undo 记录"架构契约）：

1. `group_commands.py`：新增 `build_group_command_from_selection()` —— 计算 bbox/group_data 后返回**未应用**的 `CreateGroupCommand`；`create_group_from_selection()` 变为薄封装（build → redo → 返回 id），旧契约（返回 str、立即生效）不变（tests/composite/test_group_enter_publish.py 等既有依赖不受影响）。模块 docstring 同步说明 undo 集成归属。
2. `node_editor_widget.py`：新信号 `group_commands_applied = pyqtSignal(str, list)`（描述 + 已应用命令对象列表）。
3. `node_editor_actions.py`：四个组操作改为 build → `redo()` → emit `group_commands_applied` → emit `graph_changed`；`ungroup_selected` 把一次交互解散的多个组合成**一个批次**（单步撤销，先例：`backdrops_deleted`）。
4. `composite_page.py`：连接信号至新槽 `_on_group_commands_applied`——把命令对象包进单个 `UndoAction("group_change", …)`（闭包持有命令对象存活于历史条目；action_type 避开持久化特判的 `"group"` 内部批量类型）；`_apply_group_commands` 逐命令 undo/redo（`except Exception` + `logger.exception` 槽防护）后 emit `graph_changed` 再同步（组为 UI 元数据，不触发渲染 dirty）。

**回归验证**（tests/composite/test_fix_wd10g42_aud.py）：
- 命令层：builder 未应用/应用/撤销三态、旧 helper 契约、bbox 位置推导（含 padding 与空节点回退）。
- actions 层：四操作各自 emit（含载荷可 undo/redo）；<2 选中/无选中/未知组三处守卫。
- 页面层：`page.undo()` 撤销分组 → `page.redo()` 恢复；解组撤销恢复组成员；add_to_group 撤销/重做；撤销后 `graph_changed` 再同步计数；空命令列表不产生历史条目。
