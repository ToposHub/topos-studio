## AUD-30008 — FIXED [Critical/doc-gap]

**文件**：`src/features/teaching_animation/render/html_layer/html_patch_apply.py`

**根因**（与证据一致，确认存在）：`_locate_element` 的 `_TAG_RE` 把自闭合写法（尾随 `/`）当普通开标签；SVG 几何标签（`rect`/`path`/…）不在 `_VOID_ELEMENTS` 里，而 sanitizer（sanitizer.py:303-314）恰恰把这些标签重发为自闭合 `<rect/>`（不产生闭合标签）。深度行走找不到匹配闭合 → 落入"malformed 回退"把 inner 取为 `len(html)` → `_op_replace_text` 用一段文本替换目标开标签之后的整段文档（其余节点 + 闭合标签全部丢失，且 revision+1 落库）。

**修复**（定位器根因修复，三层）：
1. 新增 `_is_self_closing_syntax()`：开标签属性尾 `rstrip().endswith("/")` 判定自闭合写法（只看尾部，引号值 `href="a/"` 不会误判；sanitizer 输出的属性一律带引号）。
2. 新增 `_SELF_CLOSING_SVG_ELEMENTS`（与 sanitizer 重发清单一致：path/rect/circle/ellipse/line/polyline/polygon/stop/use/fegaussianblur/fedropshadow），与 `_VOID_ELEMENTS` 并为 `_EMPTY_INNER_ELEMENTS`：这些标签无论书写形态都按"立即闭合、inner 为空"定位（`inner_start == inner_end == open_end`）。任意标签的自闭合写法（`<div … />`）同样返回空 inner 的新 `self_closed` span——不是文档剩余部分。
3. 深度行走中，同名的自闭合/空内容后代不再消耗父级的闭合标签（修复嵌套定位正确性）。
4. 删除"malformed 回退 = 文档剩余"分支：未终结的标签现在返回 `None`（未定位），`replace_text` 等操作抛可诊断的 `UNKNOWN_NODE` HtmlPatchError 而不是静默吞文档。此分支正是审计指出的擦除机制本身（审计建议第 3 条）。
5. `_op_replace_text` 对自闭合非空内容元素（`<div … />`）扩展为显式配对标签 `<div …>text</div>`——新文本成为该节点内容而非尾随兄弟节点；SVG 几何/void 目标保持既有 `EDIT_MODE_FORBIDS` 干净拒绝。

**受益的额外调用方**（未改动）：`template_promote._replace_inner_text` 复用 `_locate_element`，其"整段文档被替换"的同源风险随定位器修复一并消除（自闭合节点现在得到空 inner，不再是 rest-of-doc）。

**新测试**：`tests/teaching_animation/test_fix_render_ui_aud4.py` — 7 条（空 inner / SVG 几何按 void 定位 / 未终结返回 None / 自闭合后代不吃父级闭合 / replace_text 展开且后续节点存活 / SVG 几何 replace_text 干净拒绝 / 未终结节点抛 UNKNOWN_NODE）。

## AUD-30309 — FIXED [Critical/risk]

**文件**：`src/features/teaching_animation/render/render_worker.py`

**根因**（确认存在）：`submit()` 把每个 job 的 `RenderHandle` 放进 `self._handles[job_id]`，仅在 `shutdown()` 清除；job_id 每次唯一。完成的 `Future` 持有 `RenderResult.frames`（整个 job 的全部 RGBA 帧），应用级单例 `TeachingSceneCacheCoordinator`（scene_cache.py:16）每次 `schedule()` 都全量 submit → 完成帧数据永久钉住，无界增长至 OOM。

**修复**：`submit()` 注册 handle 后挂 `future.add_done_callback`，future 进入终态（完成/取消/异常）即 `self._handles.pop(job_id, None)`——按完成信号逐出（任务给定方案之一）。`_handles` 语义收窄为"运行中 job 注册表"（已加注释）。调用方持有的 `RenderHandle` 不受影响（`result()`/`cancel()`/`done` 均经由 handle 自身持有的 future/token）；`shutdown()` 的取消循环只对未完成 job 有意义，行为不变。

**边界说明**（不在白名单内、未改动）：`scene_cache.py` 自身按 `scene_id` 只保留最新一个 handle（有界，是其取消/替换语义所需）；`host_adapters.py` 由调用方持有 handle。worker 侧逐出已消除"每次 submit 累积"的无界部分。

**新测试**：2 条 — 完成 job 逐出后 `worker._handles == {}` 且调用方 handle 仍可用；取消 job 同样逐出（回调可能晚于 waiter 唤醒，测试用 deadline 轮询等待逐出）。

## AUD-30900 — FIXED [Critical/bug]

**文件**：`src/features/teaching_animation/ui/motion_graphic_editor_window.py`（`_remove_page_requested`，原 :1169）

**根因**（确认存在）：`core/model.py` `with_page_removed` 对 `len(pages) == 1` 抛 `ValueError("a scene must keep at least one page")`；`layer_tree_panel.py:577-581` 页头右键菜单无条件提供 "Remove Page"；槽内直接 `execute(RemovePageCommand(...))` 无防护 → PyQt6 槽内未处理异常 → qFatal 进程中止。同文件 `_move_elements_to_page`(:1141) 已有同型防护，唯独此处缺失。

**修复**：删除前检查 `len(scene.pages) <= 1` → 状态栏显示用户可见提示（`I18N.tr("motion_graphic.pages.keep_last_page", "A scene must keep at least one page.")`，5s）并拒绝删除；另对 `execute` 包 `except ValueError` 转 `statusBar().showMessage`（与 `_move_elements_to_page` 一致，防场景并发变更的竞态），成功路径不变。layer_tree 菜单禁用项不在白名单（`layer_tree_panel.py`），未改动——窗口侧防护已消除崩溃路径。

**新测试**：2 条（真实 `MotionGraphicEditorWindow`，offscreen + qapp）— 单页场景 `_remove_page_requested` 不抛异常、页仍在、状态栏有消息；双页场景删除仍正常生效。
