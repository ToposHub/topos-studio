## 逐条明细

### AUD-1100 [Major/bug] 播放降级系统从未激活（全库无 `set_playback_state(True)`） — BLOCKED

- **复核仍成立**：全库 grep 确认，管理器级 `set_playback_state` 唯一调用点是 `src/shared/video/video_playback.py:2123`（v2 桩引擎 `stop_playback`，仅传 False）；v3 引擎 `EnhancedVideoPlaybackEngine.start_playback`（video_playback.py:3614）、`PlaybackCoordinator.start_playback`（src/shared/video/playback_state.py:481）均不触碰该管理器。`_state.is_playing` 仍无任何 True 写入路径。指示器 `effect_degradation_indicator.py:183` 的"PlaybackCoordinator 已经设置了状态"注释仍与事实不符（该文件亦在白名单外）。
- **为何 BLOCKED**：根因是缺接线，修复必须修改 `src/shared/video/video_playback.py`（v3 start/stop 或 `play_state_changed` 信号处）和/或 `src/shared/video/playback_state.py`——均不在本批白名单（`src/shared/effects/preview_quality.py` 行内）。preview_quality 模块自身无法感知播放开始（拉取式依赖会造成 shared/effects → shared/video 反向耦合，且 video_playback 已 import 本模块，必成环）。
- **建议后续批次**：在 `EnhancedVideoPlaybackEngine.start_playback` 成功启动后调用 `get_effect_preview_quality_manager().set_playback_state(True)`，`stop_playback`（v3 分支）对应传 False（v2 的 :2123 已有）；端到端断言播放中 `is_playback_degradation_active() is True`。
- **本批已消除的次生风险**：AUD-1102 的导出保护落地后，一旦后续接线 `set_playback_state(True)`，导出期间降级参数也不会再泄漏进导出帧（原审计指出"一旦接线修复即暴露"）。

### AUD-1101 [Major/risk] 无锁共享可变状态 + 非线程安全懒汉式单例 — FIXED

- 单例 `get_effect_preview_quality_manager` 改双重检查加锁（模块级 `threading.Lock`），并发首次访问不再可能产生两个实例。
- 管理器新增 `self._lock: threading.RLock`，全部公共方法（播放状态、降级决策、注册/注销、配置阈值、UI 摘要、导出保护）在锁内读写；`_apply_playback_degradation` 收敛为"调用方持锁"的私有方法。并发 `register/unregister` 与遍历 `degraded_effects`/`_heavy_effects` 不再可能抛 `RuntimeError: changed size during iteration`。
- `get_degradation_state` 返回快照拷贝（新 `PlaybackDegradationState` + 列表拷贝），修改返回值不影响管理器；`get_all_heavy_effects` 原有拷贝语义保留。类文档 Threading 节同步改写。
- 回归：单例并发初始化（8 线程屏障竞速 → 同一实例）、注册/开关并发 vs 查询遍历锤击无异常、快照独立性，3 例。

### AUD-1102 [Major/bug] 导出路径无保护，preview/export 语义仅靠调用方约定 — FIXED

- 新增导出保护 API：`begin_export()` / `end_export()` / `is_export_active()` 及异常安全的上下文管理器 `export_full_quality()`。导出期间：`get_degraded_params`/`should_skip_effect` 强制返回"不降级"，降级列表清空（UI 摘要 0 项），`set_playback_state`/`set_degradation_enabled` 只记录标志、状态重建冻结至 `end_export` 按最新状态统一重算（不抛异常、不破坏现有 stop 流程）。
- 模块级 `is_playback_degradation_active()` 增加 `not manager.is_export_active()` 门控。
- 修正自相矛盾文档：`PlaybackDegradationState.degradation_reason` 注释由 "(playback, seek_recovery, export)" 改为 `("playback" / "paused" / "none"；导出不是降级原因——导出期间强制完整质量)`；模块头"导出时：不受影响"补注由本 API 强制保证。`.clinerules` 的"预览质量降级链一致"约束自此在模块层可执行，而非依赖调用方约定。
- 导出管线接入方式（白名单外，供后续批次）：`with get_effect_preview_quality_manager().export_full_quality(): export_frames(...)`。
- 回归：导出作用域强制完整质量/退出恢复、导出中状态切换冻结、异常安全、`end_export` 幂等无操作、模块级激活标志，5 例。

### AUD-1103 [Major/bug] 播放中重新启用降级后 `degraded_effects` 不重建，状态追踪与决策路径脱钩 — FIXED

- `set_degradation_enabled(True)` 且播放中 → 调用 `_apply_playback_degradation()` 重建列表（原代码只有关闭分支）；关闭分支行为不变。导出模式下按 AUD-1102 冻结。
- 决策路径统一以降级列表为单一判定来源：`get_degraded_params`/`should_skip_effect` 增加 `is_degraded(effect_type)` 检查，与 `is_effect_degraded`/UI 摘要同源，消除"同帧内策略分裂"（消费端 `video_playback.py:2016` 的 `is_effect_degraded("blur_high_radius")` 与 film_grain/AI skip 路径不再分歧）。
- 补齐一致性缺口：`register_heavy_effect` 在播放中注册时同步纳入降级列表（`needs_degradation` 且开关开启），`unregister_heavy_effect` 同步移除，晚注册插件立即生效。
- 回归：重新启用重建/参数限流恢复/三条决策路径一致/播放中注册即时降级，4 例。

### AUD-1104 [Major/bug] 降级参数覆盖式合并而非钳制，可能反向增大计算量/改变画面 — FIXED

- `HeavyEffectDefinition` 新增 `degradation_caps: Dict[str, float]` 字段：合并后逐键取 `min(当前值, 上限)`（仅数值键，bool 开关语义不参与），保证降级"只减不增"。
- 注册表迁移：`blur_high_radius` 的 `blur_radius/blur_iterations` 与 `full_res_mask` 的 `mask_scale` 由 `degradation_params`（覆盖）移入 `degradation_caps`（钳制）——`blur_radius=10` 不再被抬到 20，`mask_scale=0.25` 不再被抬到 0.5；越上限值仍分别收到 20/0.5。
- 新增模块级单一来源常量 `BLUR_HIGH_RADIUS_PLAYBACK_CAP = 20.0`（注册表引用）。**遗留**：`video_playback.py:2016` 仍硬编码 `> 20.0`（白名单外未改），建议后续批次改为引用本常量消除双源。
- 回归：低值不抬升/高值钳制/mask_scale 双向/caps 不注入缺失键/bool 不钳制/HIGH 覆盖语义不变/管理器 API 与消费端语义一致，7 例。

### AUD-1105 [Major/bug] SKIP 路径硬编码 `{"enabled": False}` 丢弃全部原始参数、`degradation_params` 成死配置 — FIXED

- 删除 SKIP 硬编码分支；SKIP/HIGH/MEDIUM/LOW 统一为 `{**original_params, **degradation_params}`（+ AUD-1104 的 caps 钳制）：原始参数不再被丢弃，注册的降级参数真正生效——`ai_matte` 的 `ai_matte_enabled`、`ai_matte_update` 的 `update_enabled` 由死配置变为活配置；`denoise/ai_denoise/deblur/ai_plugin` 的 `{"enabled": False}` 与 `plugin_manager._register_plugin_preview_quality` 的注册约定（`{"enabled": False}`）语义一致，且不再注入未知键、不再丢参数。
- 三个重复的 HIGH/MEDIUM/LOW 分支随之合并为单一路径（顺带消除原 :148 不可达 return）。
- 回归：ai_matte/ai_matte_update/denoise/plugin 约定/管理器级 SKIP 合并，5 例。
