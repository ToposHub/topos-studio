## 1. AUD-18800 [Critical/perf-opportunity/L] — FIXED

**问题**：slip/slide/roll/ripple trim（左/右）/overwrite 六个活路径纯操作
用手工构造 `ClipInstance(...)` 重建实例，只传入 9 个基础字段，
`animated_params / label_color / waveform_show_channels /
fade_in_duration / fade_out_duration / color_stack_id / color_shared /
composite_id / composite_bypassed / render_cache_id / freeze_source_frame /
blend_mode / audio_gain_db / raw / _source_fps_num/_den /
_timeline_fps_num/_den / _source_pts_index` 全部回落默认值——调色联动、
关键帧动画、淡入淡出、混音增益、冻结帧、FPS 元数据静默丢失。

**证据核实**：逐行核对当前工作区代码（Wave3 已修 AUD-18801 的 slide
原子重建，其对齐模式保留）：审查报告所列六处（slip 2317 / slide
2031-2046 / roll 1812-1844 / ripple left 2451-2466 / ripple right
2536-2551 / overwrite 1452-1540）逐字段构造属实，且 slide 的前/后邻居
（2072-2087 / 2121-2136）与 overwrite 的 else 分支半片（1556-1595）为
同型缺陷。问题在当前代码存在。

**修复**（`src/features/edit/core/timeline_ops.py`）：

1. 新增公共 helper `copy_clip_with(clip, **field_updates)`
   （timeline_ops.py:55-96）：
   - 语义 = `dataclasses.replace(clip, **field_updates)`——全部
     dataclass 字段（含未来新增字段）自动保留，调用方只覆写操作语义
     要求的字段；
   - **动态属性回拷**：replace 重建实例会丢非字段动态属性，helper 显式
     回拷（`vars(clip)` 中不属于 dataclass 字段的键），保证"未知新字段
     不丢"；
   - **淡入出钳制**：duration 缩短时原 fade 可能超过新时长而触发
     `__post_init__` ValueError（把"静默丢字段"换成"操作失败"是回归），
     helper 按 `__post_init__` 自身边界将未显式覆写的 fade 钳到新时长
     （sum 溢出仍交由模型既有归一化处理）。
2. 六操作 14 处重建点统一改用（均为"copy + 指定字段覆写"）：
   - slip_clip:2286（仅覆写 source_start）；
   - slide_clip:2023（slid，仅 timeline_start）、2050（prev）、2088（next）；
   - roll_trim_clips:1822/1829（left/right）；
   - ripple_trim_clip_left:2406、ripple_trim_clip_right:2483；
   - overwrite_clip_at_playhead:1497/1510（中间切分半片）、1533/1554
     （残片，保留原 clip_id）、1576/1592（else 分支半片）。
   半片语义决策：右半段 `fade_in_duration=0`（与 split_clip 既有先例
   一致）、新 id + linked_clip_id=None 沿原代码；残片保留原 clip_id 与
   全部扩展字段。Wave3 的 slide 原子 `_rebuild`（AUD-18801）应用段
   未动，仅替换其上的实例构造。
3. 与 TrimClipCommand 的 `clip.with_trim_left/right`（replace 路径）
   及 commands.py 修复方式同构；与 `.clinerules` "重建 ClipInstance
   不得丢扩展字段——统一用不可变更新"约束对齐。

**测试证据**（`tests/edit/test_fix_w6g8_aud6.py`，纯函数 13 例全过）：
- `TestCopyClipWith` 3 例：仅指定字段变化 / 未知动态属性存活 /
  duration 缩短的淡入出钳制（50/60 → duration 30 时 fade_in=30、
  fade_out 经模型归一化为 0，不抛错）；
- 六操作字段保留各 1-3 例：富片段（AUD-18800 点名全部 22 个扩展字段
  + `object.__setattr__` 动态探针）执行 slip/slide（含前/后邻居）/
  roll（双片段）/ripple 左/右/overwrite（中间切分双半片 + 左切残片 +
  右切残片）后逐字段断言保留，并断言几何最终态不回退；
- `TestFaultInjection` 1 例：monkeypatch `copy_clip_with` 为旧式

  恢复 helper 后通过——证明回归测试对丢字段敏感。

## 2. BENCH-0004 [Critical/risk/L] — FIXED（按交付物闭环口径）

**问题**：codec 98% 体积帽不满足（六档体积比 1.03-3.79×）+ QP63 地板
三档超支 1.40-1.67×；对照决策文档 §1/§6，98% 帽验收线未判定/不满足。
本机无法跑真实编码对比，按任务书以"门禁脚本 + 报告注记"闭环，
不改编码器默认参数（需产品决策）。

**证据核实**：`bench_out/real_codec_bitrate_20260907/result.json` 逐档
核对（proxy 23107368/6092550 B、pro444 143405293/139408890 B 等），
体积比与 QP 钉死档（proxy/pro444/extreme 的 topos_qp_min==max==63）
与 codec.md §1.1 表一致；决策文档 §1 V10-422 行"每档同码率非劣和默认档
容量≤对应 ProRes 的既定 98% 帽须同时验证"原文核实。问题存在。

**交付物 (a)**：`tools/check_codec_budget.py`（新建门禁脚本）：

- 读 `bench_out/real_codec_bitrate_20260907/result.json`，逐档判定：
  1. **98% 体积帽**：`topos_mov.bytes ≤ cap_ratio × prores_mov.bytes`
     （默认 0.98，决策文档 §1/§6）；
  2. **QP 地板预算**：`qp_min == qp_max == qp_floor`（默认 63）判为
     地板钉死（码控无余量），要求实际 bpp ≤ 容差 × target_bpp；
     实际 bpp 由 bytes 复算（`bytes*8/(w*h*frames)`），不信任存档字段；
  3. 完整性自检：bpp 复算 vs 存档偏差 >2% 违规；六档缺失任何一档违规；
     Pro444 位深不对齐（12-bit vs 10-bit）以注记提示不豁免判定。
- CLI：`--result/--cap-ratio/--qp-floor/--floor-overspend-tolerance/
  --exclude/--list/--json`；违规 exit 1，全过 exit 0。

exit 1）：
