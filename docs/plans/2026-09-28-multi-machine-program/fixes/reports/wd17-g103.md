## 逐条明细

### AUD-39505 [Major/risk] 构造函数对主 GL 上下文做 doneCurrent/makeCurrent 干预 — FIXED

- `VideoAsyncRenderer.__init__` 移除 `main_context.doneCurrent()` → `create()` → `makeCurrent()` 的窃取序列（审计建议方案一：彻底消除干预，而非用 GLContextManager 互斥锁串行化）。`QOpenGLContext.create()` 与 share context 建立共享不要求对方处于非 current 状态，该干预是 file_controller.py 规避注释记载的崩溃源。
- 构造函数现在完全不触碰任何上下文的 current 状态；共享上下文创建 + `moveToThread` 保留。
- 测试：AST 级断言 `__init__` 调用集合不含 `doneCurrent`/`makeCurrent`（防注释文字误报）；真实 `QOpenGLContext` 无 GL 构造成功。

### AUD-39506 [Major/risk] 线程退出不做 doneCurrent，moderngl ctx 不 release 仅置 None — FIXED

- 新增 `_release_gl_context_on_exit(moderngl_ctx)`（仅 `run()` 尾部调用，渲染线程）：先 `ctx.release()`（GL 对象已在 `_cleanup_gl_resources` 于本线程、上下文 current 时释放完毕），再 `shared_context.doneCurrent()`，最后 `surface.deleteLater()`（QOffscreenSurface 归属主线程，投递回主线程事件循环销毁）。
- `run()` 尾部先捕获 `self.ctx` 引用再调用 `_cleanup_gl_resources`（后者末尾置 None，否则引用丢失正是一直无法显式 release 的根因）。
- 异常全部窄化：`moderngl.Error`（ctx.release）/ `RuntimeError`（Qt doneCurrent/deleteLater）。
- 测试：释放三件套各 exactly-once、缺件容忍、`run()` 退出路径确实调用（无 GL 环境 monkeypatch 后直接跑 `run()`）。

### AUD-39507 [Major/bug] GC 后备释放机制是空操作（_gc_resources 从未被填充）— FIXED

- 按 AUD-7605/video_frame_node 先例移除死 finalizer 注册与 `_gc_resources`（同时删除 `import weakref`）。审计原文认可两条路线之一："要么登记+投递渲染线程 deferred 队列，要么删除该机制避免虚假安全感"——选后者：GC 线程没有 current 上下文，塞 ModernGL 对象进该列表同样违反「GL 仅渲染线程」铁律；显式销毁路径（`run()` 退出 / `stop_thread()`）经 AUD-39506 修复后已完备。
- `_cleanup_on_gc` 静态助手保留为工具函数（文档注明真实归属路径），非 GL 资源的清理语义不变。
- 测试：`_finalizer`/`_gc_resources` 不再注册、模块 AST 无 `finalize` 调用、助手函数对 release/close 资源仍然有效。

### AUD-39508 [Major/bug] frame_ready 发出的 glo 在视口变化重建 FBO 时被释放 — FIXED

- `_ensure_fbos` 换尺寸时旧 FBO/纹理不再立即 release，改为挂入 `_retired_fbo_resources` 延迟释放队列（宽限期 2.0s，与主渲染器 `garbage` 队列同量级；容量上限 8 防长时间无渲染时无限增长，超限最旧立即释放）。
- 排水点：命令循环每轮 `_drain_retired_fbo_resources()`（渲染线程）+ `_cleanup_gl_resources(force=True)` 收尾。释放异常窄化为 `moderngl.Error`。
- 测试：resize 后旧纹理未释放且进入队列、宽限期内不释放/过期后释放、force 排水、容量上限触发最旧释放，共 4 例。

### AUD-39509 [Major/bug] 着色器加载失败被静默吞掉（清屏空白帧仍按成功 emit）— FIXED

- `_load_shaders` 失败不再吞掉：捕获 `moderngl.Error` 后 `raise RuntimeError` 上抛，由 `run()` 初始化 except 统一 `emit error_occurred` 并终止渲染线程（审计建议的"与 ModernGL 初始化失败同路径"）。
- `_do_render_frame` 在 `passthrough` 着色器缺失时：`emit error_occurred` + 直接 return，不再清屏翻转缓冲后把灰屏纹理当成功结果 `emit frame_ready`（消除"僵尸正常"状态）。
- 测试：编译失败抛 RuntimeError；无着色器渲染 → error_occurred 1 次、frame_ready 0 次。

### AUD-39510 [Major/bug] 命令循环宽泛 except 吞掉命令级异常（既不上报也不重试）— FIXED

- 命令循环 except 保持线程存活（边界宽捕获是线程设计的正确形态），但新增 `error_occurred.emit(f"Render command failed [{cmd_type}]: {e}")` 携带命令类型上报；`cmd_type` 预初始化为 None 防解包失败时 except 内 NameError。
- 消费方从此对丢帧有感知（要么 frame_ready 要么 error_occurred，审计验收口径）。
- 测试：monkeypatch `_handle_command` 抛 ValueError，真实 `run()` 循环（线程内）收到含命令名与错误文本的 error_occurred。

### AUD-39511 [Major/perf] _render_quad 每帧创建并销毁 VBO/IBO/VAO — FIXED

- 四边形几何（常量顶点/索引，类级 `_QUAD_VERTICES`/`_QUAD_INDICES`）随 `_load_shaders` 一次性创建并缓存到 `_quad_vbo/_quad_ibo/_quad_vao`；`_render_quad` 直接 `vao.render(...)`，缓存缺失时懒构建兜底；`_cleanup_gl_resources` 统一释放。60fps 下消除每秒 180 次 GL 对象创建+释放 churn，与 P4.1 纹理池化理念对齐。
- 测试：6 帧渲染只创建 1 次 buffer、cleanup 释放三件套。

### AUD-39601 [Major/bug] 基类公共方法引用从未在基类初始化的 _playback_clock/_proxy_prefetch_worker — FIXED

- 基类 `VideoPlaybackEngine.__init__` 补 `self._playback_clock = None` 与 `self._proxy_prefetch_worker = None`（与 `_video_renderer` 等属性一致的初始化方式）。`seek_to_time`/`last_frame`/`set_playback_speed`/`get_current_time`/`get_time_string`/`_check_proxy_ladder` 对纯基类实例不再 AttributeError。
- 连带更新 `tests/video/test_video_playback_coverage.py` 的 BUG-C2-03 characterization 测试：原测试断言旧缺陷（`pytest.raises(AttributeError)`），修复后翻转为断言基类实例可安全调用。
- 测试：基类实例 6 个方法无异常 + 属性为 None（2 例）。

### AUD-39602 [Major/bug] set_playback_speed 未验证 speed（0 → ZeroDivisionError，负值 → 8ms 高频定时器）— FIXED

- 新增模块级 `_validated_playback_speed(speed) -> Optional[float]`：非数值/0/负/NaN 一律返回 None（有限正值才通过）。
- 基类 `set_playback_speed`：非法值 warning + return（保持原速、定时器不被改写）；合法值照旧计算 interval。
- Enhanced 覆写：非法值不得透传给 `PlaybackClock.set_speed`（其对非正值行为未定义）；合法值同步时钟与定时器。
- 测试：7 种非法输入（0/0.0/-1.0/-0.5/NaN/"abc"/None）拒绝且时钟未收到、合法 2.0 时 interval==16 且 set_speed(2.0)、负值不改写定时器、校验器单元。

### AUD-39606 [Major/risk] UI 线程置空 renderer.current_video_texture/planes 可能成为 ModernGL 纹理的最后引用 — FIXED

- 新增 `_clear_renderer_video_texture_state()`（unload_video 调用）：属性清空必须同步发生（残留 RENDER_FRAME 闪旧片段的契约保留），但不再让 UI 线程的置空成为潜在的 GL 释放点——同时向渲染线程提交既有命令 `RenderCommand.RELEASE_VIDEO_TEXTURE_POOL`，让旧片段的池内纹理在渲染线程统一释放（审计建议的"调用渲染器既有 deferred release 通道"）。
- 所有权不变量在代码中显式成文：`current_video_texture` 恒来自渲染线程 `_video_texture_pool`（池持强引用，UI 置空永不触发释放）；`current_video_planes` 恒来自 `_yuv_gpu_uploader` 池（同样被持有）或非占有的 `ExternalGLTexture` 描述符（dataclass，无 release/GL 调用）——经本轮全量溯源确认审计置信度低的"最后引用"场景在现行代码不可达，本修复把"恰好安全"升级为"由构造保证"。
- 渲染器已销毁/Qt 包装失效（RuntimeError）容忍跳过。`async_renderer.py` 不在白名单故未改（无需改：既有 RELEASE_VIDEO_TEXTURE_POOL 命令即可闭环）。
- 测试：unload 后属性为 None 且 submit 收到 `(RELEASE_VIDEO_TEXTURE_POOL, None)`；engine 为 None / Qt 已删除渲染器两种退化场景不抛。

### AUD-39700 [Major/bug] 池满换尺寸时新建纹理失败留下「已释放纹理 + 旧元数据」损坏槽位 — FIXED

- 第 4 步（池满换尺寸）重排为"先创建新纹理，成功后再释放旧纹理并更新槽位字段"（审计建议方案二）。create 失败（窄化 `moderngl.Error`，如 GPU OOM）直接返回 None：旧纹理保持有效、槽位元数据未动，后续同尺寸 acquire 仍能命中有效纹理，损坏状态不再存续到 release_all。
- 成功路径顺序断言：create 先于 release-old。
- 测试：创建失败后旧纹理未释放且同尺寸复用返回原对象；成功路径释放顺序 create→release-old、槽位字段更新。

### AUD-39701 [Major/risk] weakref.finalize 在任意触发 GC 的线程直接调用 GL release — FIXED

- `_cleanup_on_gc` 不再调用 `slot.texture.release()`（GC 线程无 current 上下文，glDeleteTextures 属未定义行为且异常被静默吞掉，实际效果是"泄漏 + 潜在驱动层错误"）。finalizer 保留但职责改为可观测性：记录泄漏警告（slot 数量）并置空引用（纯 Python 操作，任意线程安全）；GPU 内存随所属 GL 上下文销毁统一回收。常规释放仍由渲染线程的 `release_all`/槽位替换/renderer 退出路径负责。
- 保留 `_finalizer` 注册（既有 `tests/video/test_video_upload_command.py::test_weakref_finalizer_present` 依赖该属性）。
- 测试：`_cleanup_on_gc` 不调用 release 且置空引用、finalizer 仍注册、真实 `gc.collect()` 不触发 release。

### AUD-39710 [Major/bug] upload_planes 8-bit 路径向 f1(R8) 纹理写入 float32 数据 — FIXED

- 8-bit 分支改为直接上传原始 uint8 平面（`np.ascontiguousarray(plane, dtype=np.uint8)`）：R8 纹理每像素 1 字节，字节与像素格式严格匹配；归一化交给硬件采样（R8 采样即得 [0,1]）。旧实现写 float32（4 字节/像素），write() 只消费前 1/4 像素的位模式碎片，8-bit planar 上传必然乱码。
- >8-bit 的 f2/f4 路径字节匹配本就正确，未动。
- 测试：8-bit 三个平面 dtype=='f1'、write 字节数==像素数、字节内容==原始 uint8 位模式；10-bit f2 路径 2 字节/像素回归。
