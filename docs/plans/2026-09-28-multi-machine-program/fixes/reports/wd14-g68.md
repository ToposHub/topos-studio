## FIXED 明细

### AUD-20903 — Source Viewer CPU 回退为 UI 线程同步解码（source_viewer.py:2161-2169 / 2220-2233 / 2255-2261）
- 根因：`_load_video_frame` 的 CPU 回退分支、`_on_gpu_timeout`（watchdog）、`request_cpu_fallback`（解码 worker 的 queued 通道）三条路径都在 UI 线程同步执行 `_open_cpu_video_decoder()` + `read_frame()`（关键帧 seek + 前向解码），长 GOP 大分辨率素材单帧可达数百毫秒，直接阻塞播放 tick / scrub / 事件循环。
- 修复：
  - 新增模块级 `_CpuFallbackDecodeWorker`（daemon `threading.Thread` + 无父对象 QObject 信号，线程模型与 `file_controller._SourceViewerDecodeWorker` 一致）：worker 独占解码器（按 `(path, target_size)` 失效重建），latest-wins 合并请求，解码出的 QImage 经 `frame_ready(frame, image, decode_ms, generation)` 排队回 UI 线程；失败走 `decode_failed(frame, error, generation)`。
  - 三条入口（`_load_video_frame` CPU 分支 / `_on_gpu_timeout` / `request_cpu_fallback`）统一改为 `_submit_cpu_fallback(frame)`，UI 线程零解码；`_cpu_fallback_decode`（同步版）删除。
  - UI 侧新增 `_on_cpu_frame_ready` / `_on_cpu_decode_failed`：复用 GPU 协议的 generation + trailing-window（`_GPU_STALE_WINDOW`）守卫，上传走 AUD-20902 的 `submit_qimage`（paintGL 延迟通道），并维护 LRU 缓存 / last-good / `_error_message`；`_gpu_pending_frame` 兼作 CPU 解码在途标记，播放背压（`_should_defer_playback_tick`）语义保持。
  - 生命周期：`close_source()` → `close_decoder()`（解码器只在 worker 线程内关闭，FFmpeg 句柄线程亲和）；`widget.destroyed` → `worker.stop()`（避免悬挂线程在已删除对象上 emit——AUD-20910 同型教训）；signals QObject 不挂 widget 父对象（接收方销毁时 Qt 自动断连，emit 变 no-op）。
  - `request_cpu_fallback` 信号签名不变，`file_controller` 连接无需改动。

### AUD-20910 — Stem 导出 join 超时后对话框销毁时的 QThread destroyed-while-running（stem_export_dialog.py:392-408）
- 根因：取消只在 stem 边界生效（长 Master 混音常超 3 秒），`wait(3000)` 超时返回 False 后 `reject()/closeEvent()` 照常关闭对话框；worker（parent=对话框）继续后台写文件、信号发往已隐藏 UI，对话框销毁时触发 Qt fatal "QThread: Destroyed while thread is still running"。
- 修复（按证据建议的"等待后台完成"状态方案）：
  - `_cancel_and_join_worker` 返回 worker 是否在超时内退出（`QThread.wait()` 返回值，此前被丢弃）。
  - 超时未退出时：`reject()` 不调用 `super().reject()`，`closeEvent` `event.ignore()`，进入 `_enter_wait_worker_exit_state()`——禁用 Close/导出/取消与输入控件，状态栏显示"后台收尾"提示；`finished_ok/failed` 回调经 `_switch_running(False)` 恢复 Close，此后才可关闭。
  - `_start_export` 原有 `isRunning()` 双保险保持，杜绝新旧 worker 并发写同一输出目录。

### AUD-21008 — 字幕 end_drag 的 final/original 取值空间不一致（subtitle_handle_controller.py:333-342, 421-435）
- 根因：`start_drag` 的 `original` 取自 resolved style（轨道默认 ⊕ cue 覆盖），`end_drag` 的 `final` 只读 cue 扁平字段；轨道 default_style 覆盖某变换字段时，零位移的"按下-释放"也产出非空 delta，把 cue 扁平基线值当作"变化"提交，静默抵消轨道默认并可能压入无操作 undo 项。
- 修复：`_apply_preview_delta` 记录本次 drag 已应用的增量（同字段 last-write-wins，`_applied_delta`），`end_drag` 的 `final = original ⊕ applied_delta` —— 与 original 严格同空间；拖回原值自然产出空 delta。`start_drag`/`_reset_drag` 维护增量记录生命周期。快速移动-释放手势（原注释强调的场景）由 applied 记录保证不丢失。

### AUD-21101 — Audio Gain 菜单项在 menu.exec() 之后才 addAction（timeline_items.py:5064）
- 根因：`menu.exec()` 是模态阻塞调用，菜单关闭后才向已销毁菜单 addAction，"Audio Gain…" 永不显示，C3 片段级增益对话框入口整条失效。
- 修复：addAction 移到 `menu.exec()` 之前（与 Waveform Display 音频分组同块的 `if self._media_type == "audio"` 内），保留 `setEnabled(not self._is_track_locked)`；exec 后只保留 `selected(audio_gain_action)` 分发。

### AUD-21102 — TransitionItem 无轨道锁状态（timeline_items.py:6315；view 侧 10762 起）
- 根因：`TransitionItem` 全类无 `_is_track_locked`/`set_track_locked`，锁定轨道上的转场仍可修剪/移动/右键删除，与 ClipItem 锁语义不一致。
- 修复：
  - item 侧：构造参数 `is_track_locked` + `set_track_locked()`；`mousePressEvent` 锁定时只允许选中（emit `transition_clicked`）并 accept 返回（左右键同），不进入 trim/move drag、不弹上下文菜单；`hoverMoveEvent` 锁定时显示 ForbiddenCursor。
  - view 侧：两处 `TransitionItem` 创建点（load_timeline / `_create_transition_item`）传入 `track.is_locked`；`_on_track_lock_changed`、`_update_track_clip_states`、增量更新 `track_changes['is_locked']` 三条路径同步 `set_track_locked`；三个 finished-handler（trim_left/trim_right/move）补 `_is_track_locked(track_id)` 兜底守卫。

### AUD-21103 — ClipItem.hoverMoveEvent 每次鼠标移动无条件 update()（timeline_items.py:4410）
- 根因：构造开启 `DeviceCoordinateCache`，hoverMoveEvent 各分支先置状态再无条件 `update()`，鼠标划过片段时以事件频率（≥60Hz）整卡重建设备像素缓存（filmstrip/波形/徽章全量重绘）。
- 修复：整个 handler 重构为"先算后写"——新 hover 状态（edge/fade/tooltip/cursor）先入局部变量，仅当 `new_edge != old_edge or new_fade != old_fade` 才写回并 `update()`（全函数唯一一次 update）；tooltip 与 cursor（含 `_trim_cursor` 自定义位标）同样差异检测后设置。写法对照 `TrackHeaderItem.hoverMoveEvent`。

### AUD-21104 — 轨道头 target/sync 菜单动作先改本地状态再发信号（timeline_items.py:8210-8217）
- 根因：`target_action`/`sync_action` 分支在 emit 前先写 `self._is_target`/`self._is_sync_locked`，命令失败或被撤销时表头视觉与模型脱节，违反 P4 提交一致性约定（对照 `_toggle_mute` 注释）。
- 修复：两分支只 emit 请求（`target_track_changed(track_id)`；`sync_lock_changed(track_id, checked)`），本地状态由宿主回写——target 由 `TimelineView._on_target_track_changed` 写新旧表头，sync-lock 由 `SetTrackSyncLockCommand` 成功后的增量更新经（本批修复的 AUD-21401 分支）`set_sync_locked()` 回写。

### AUD-21105 — DragPreviewItem._draw_thumbnail 对零尺寸 QPixmap 无防护（timeline_items.py:9962-9965）
- 根因：`pixmap.width()/height()` 直接做除数；拖拽预览缩略图来自外部媒体池，提取失败时可能是 null/0 尺寸 QPixmap，paint 内 `ZeroDivisionError` 中断绘制。
- 修复：入口守卫 `pixmap.width() <= 0 or pixmap.height() <= 0` 与 `avail_h = height - ITEM_MARGIN*2 - LABEL_HEIGHT <= 0` 直接返回（只画标签），对照 `ClipItem._draw_single_thumbnail_at` 的防护。

### AUD-21200 — 存在字幕轨道时 video_scroll_offset 被完全忽略（timeline_layout.py:338-348）
- 根因：`_compute_track_rects` 的字幕分支固定 `y = subtitle_splitter_rect.bottom()`，`video_scroll_offset`（含 -1 底部对齐语义与滚动条写入值）完全不参与；而 `scroll_range_for_area("video")` 仍按 `stack - video_area.height()` 报告非零 max_scroll——溢出场景下视频滚动条变死条；`_compute_areas` 的 `subtitle_top = va_splitter_top - video_group_h` 无钳制，组高超面板上限时字幕/最上方视频轨画进标尺区。
- 修复（三处一致化）：
  - `_compute_areas`：`subtitle_top = max(TRACK_AREA_TOP, va_splitter_top - video_group_h)`，溢出不再进标尺区。
  - `_compute_track_rects`：字幕在场时视频栈可用区间为 `[S/V 分隔条底, V/A 分隔条顶]`，栈高超出时套用与无字幕分支完全相同的 offset 钳制滚动（-1 保持底部对齐、V1 贴 V/A 分隔条；默认行为不变）。
  - `scroll_range_for_area("video")`：字幕在场时 max_scroll 按同一可用区间计算，滚动条范围与布局钳制口径一致，拖动即生效。

### AUD-21201 — TimelineLayoutState.from_dict 不校验外部持久化数据（timeline_layout.py:113-124）
- 根因：数据源是工程持久化 JSON（外部输入），字段类型损坏时 `float()/int()` 直接抛 ValueError/TypeError 打断工程加载；`video_area_ratio=7.5` 等越界值不钳制（对照 `set_splitter_ratio` 的 0.1..0.9）；`track_heights` 值为 str 时在 `_height_for` 的 min/max 比较处 TypeError。
- 修复：`from_dict` 逐字段容错——`isinstance(data, dict)` 入口守卫；比率 try/except (TypeError, ValueError) 回退默认并钳制到 [0.1, 0.9] / [0.05, 0.6]（与运行时 setter 口径一致）；`track_heights` 逐值 `int()` 转换、非法项丢弃（该轨回退默认高度）；三个 scroll offset `int()` 容错回退默认。

### AUD-21301 — 键盘切换工具时 Rate Stretch 按钮互斥选中状态不同步（timeline_panel.py:1545）
- 根因：`_on_view_tool_changed` 手写 9 个按钮同步、唯独漏掉 `btn_rate_stretch`（`_set_tool` 里有），Shift+R 激活后工具栏与实际工具不一致。
- 修复：改为遍历 `_get_tool_button_map()` 驱动 checked 状态（单一来源，与 `_set_tool` 共用映射），杜绝两份手写清单漂移。

### AUD-21302 — `_on_timer_frame_ready` 缺少隐藏视图守卫（timeline_panel.py:1376）
- 根因：共享 `EditPlaybackController` 也被 Color 页驱动；本面板 timer tick 无条件执行 `_update_timecode_display`（→ 隐藏视图 `set_corner_timecode`）与 `_set_view_playhead_from_controller`（→ 隐藏视图 `set_playhead`），绕过 `_on_controller_frame_changed` 专为规避 macOS 隐藏 GL viewport 初始化 abort 的守卫；背压分支还会用隐藏 Edit 视图的旧 playhead reanchor 共享控制器，令 Color 页播放回跳。
- 修复：函数开头加与 `_on_controller_frame_changed` 相同的 `timeline_view.isVisible()` 早退（防御式 `getattr` 取视图），隐藏期间既不驱动视图也不触发背压 reanchor。

### AUD-21303 — TimecodeInputDialog 在 fps∈(0, 0.5) 时整除零（timeline_panel.py:2609）
- 根因：`round(fps)==0` 而 `fps > 0` 守卫不生效，`// fps_int` / `% fps_int` 除零；fps 来自工程文件等外部数据，构造路径无捕获。
- 修复：新增 `_safe_fps_int()`——round 后 <1（含 0/负/NaN/Inf，NaN/Inf 的 round 抛 TypeError/OverflowError 一并捕获）回退 `round(DEFAULT_FPS)`；`_setup_ui` 与 `_parse_input` 两处统一取用。

### AUD-21400 — 间隙指示器在全部生产调用点被 `_updating` 锁短路（timeline_view.py:2020、6064、15556）
- 根因：`load_timeline` 与 `update_timeline_incremental` 都在 `self._updating = True` 锁内调用 `_update_gap_indicators()`，而后者入口守卫复用同一把锁（恒真返回）、内部又自己置 `_updating` —— GapIndicatorItem 永不创建，功能整体失效。
- 修复：`_update_gap_indicators` / `_update_gap_indicators_for_track` 改用专用防重入锁 `self._updating_gaps`（__init__ 中初始化），可在 `_updating` 锁内执行且保持自身不可重入；两个生产调用点保持原位不动（加载 + 每次增量更新后刷新）。

### AUD-21401 — 增量更新中 set_sync_locked 嵌套在 is_locked 分支内（timeline_view.py:6033-6037）
- 根因：变更检测器把 sync-lock 作为独立键写入 `track_changes['is_sync_locked']`，但表头同步代码把它嵌套在 `if 'is_locked' in track_changes:` 体内——仅改 sync-lock 的命令（如撤销 SetTrackSyncLockCommand）永不刷新表头，恰是该"审计修复"注释声称要解决的问题。
- 修复：`if 'is_sync_locked' in track_changes:` 提升为与 is_muted/is_solo/is_locked 平级的独立分支。

### AUD-21402 — 常规片段拖拽/修剪的"排除自身"吸附从未传给 SnapManager（timeline_view.py 9 处调用点）
- 根因：`_snap_frame` 走 SnapManager 路径时只透传 `exclude_source_ids` 参数，而 8 个片段拖拽/修剪调用点全部未传——移动中的片段把自身原始入/出点当吸附点（微小拖拽被吸回原位、修剪时边缘吸附到本片段另一边缘），`_get_snap_points(exclude_clip_id=...)` 的结果被整体旁路；字幕路径（3150 起）传参正确，行为不一致。
- 修复：`_on_clip_moved_impl`（拖拽预览）、`_on_drag_finished_impl`、trim left/right 预览与 finished、ripple left/right 共 8 处 `_snap_frame(...)` 调用全部显式传 `exclude_source_ids={clip_id}`（legacy tuple 路径本就排除自身，SnapManager 与 legacy 语义重新对齐）。
