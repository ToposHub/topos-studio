## 逐条结论

### AUD-19740 — FIXED

**问题确认**：fps 下拉的 Custom 项 userData 为 `"__custom__"`，`get_settings()` 里
`float(self._fps_combo.currentData() or 24.0)` 对其抛 ValueError；编辑模式下非预设
fps（`_sync_fps_combo` 自动落 Custom）+ Apply 也可触发。异常发生在
edit_controller `_on_finished` 槽（try/finally 无 except）内，可致进程中止。

**修复**（`comp_clip_settings_dialog.py`）：
1. `_build_timing_group` 在 fps 下拉旁新增 Custom 帧率 `DragValue`
   （范围 [1, 240]、decimals=3、suffix=" fps"、初值取 `_init_fps` clamp）。
   DragValue 保证数值恒在合法域内，杜绝解析失败。
2. 新增 `_is_custom_fps_selected` / `_on_fps_combo_changed` /
   `_update_custom_fps_visibility`：仅选中 Custom 时显示输入框（程序化同步无回环，
   信号在 `_sync_fps_combo` 之后才连接，构建期无触发窗口）。
3. 新增 `_current_fps()`：currentData 为数值时直接用；否则读 Custom 输入；
   非正数/NaN 防御回退 24.0。`get_settings()` 改用它，永不返回无效值。
4. 新增底部 `_hint_label`（红色、默认隐藏）；`_on_accept` 校验空名称与 Custom fps，
   失败时给出可见提示并拒绝 accept（顺带消除了原空名称静默拒绝的问题）。

### AUD-19800 — FIXED

**问题确认**：`_on_motion_graphic_generator_double_clicked_by_id`
（edit_effects_panel.py:1534）引用 `template_display_name`，该名字仅存在于
`_append_motion_graphic_generators` 函数内局部导入，双击卡片即在 Qt 槽内抛
NameError。

**修复**：`template_description` / `template_display_name` 提升为模块级导入
（`content_localization` 仅依赖 `src.shared.i18n.i18n`，无循环导入风险，该文件顶部
本就模块级导入了同包的 `motion_graphic_generator_registry`）；删除函数内局部导入。
新增回归测试直接调用双击处理器验证。

### AUD-20000 — FIXED

**问题确认**：`EditPropertiesPanel._current_frame` 仅 `set_current_frame` 会写，
而全库无调用者；◆ 按钮点击永远发射 frame=0、value=0.0（构造默认缓存），控制器
`_on_edit_effect_keyframe_toggled` 据此在第 0 帧写/删关键帧；按钮菱形状态也恒为
初始灰态。

**修复**（均在 `edit_properties_panel.py` 内，未触碰白名单外文件）：
1. **帧来源解析** `_resolve_current_frame()`：优先 `set_frame_provider()` 注入的
   回调 → 沿父链 `_find_timeline_panel()` 找主窗口的 `timeline_panel.get_current_frame()`
   → 回退缓存值。全部异常防御 + 日志。
2. **信号订阅** `_ensure_frame_source_connected()`：幂等连接 timeline panel 的
   playback controller `frame_changed` → `set_current_frame`，播放/scrub 期间菱形
   状态实时刷新；在 `showEvent` 与 `_update_keyframe_buttons` 中重试连接。
3. **点击路径**：`_on_keyframe_button_toggled` 与新增
   `_on_effect_keyframe_button_toggled`（替换 4093 处裸 lambda）在发射前重新解析
   播放头帧，并从 clip/EffectInstance 的 `get_param_at_frame` 重读当前值，不再使用
   按钮缓存。
4. **刷新路径**：`_update_keyframe_buttons` 每次先同步解析帧；`set_clip` 末尾补调
   `_update_keyframe_buttons()`（原先选中片段后按钮恒为初始灰态）。
5. `set_current_frame` 保留为公开推送 API（加同值早退）。

验证：provider 注入、timeline_panel 拉取 + frame_changed 订阅、set_clip 刷新三条
路径均有测试覆盖（tests/edit/test_fix_ui_aud3.py）。

### AUD-20400 — FIXED

**问题确认**：`_set_frame_from_qimage`（program_viewer.py）对 RGB888 QImage 用
`bits.setsize(width*height*3)` + `reshape(height, width, 3)`，忽略
`bytesPerLine()` 的 4 字节对齐填充；`width*3 % 4 != 0`（如宽 1366/854）时整幅
画面逐行错位（CPU 预览主路径）。

**修复**：抽取模块级 `_rgb888_qimage_to_rgba(qimage)`：`stride != width*3` 时按
行切片（`reshape(height, stride)[:, :row_bytes]`）+ `ascontiguousarray` 去填充，
再拼 alpha=255；紧凑路径保持原实现。`_set_frame_from_qimage` 改调该助手，返回
None（非法尺寸）时告警返回。抽取为独立函数同时使行跨距逻辑可脱离 GL 上下文单测。
