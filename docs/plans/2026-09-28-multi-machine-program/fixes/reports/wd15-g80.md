### AUD-31502 — INVALID（已随 AUD-31500 修复）
证据（当前代码）：`_check_cancelled()` 已存在于 `_process_tiled` 与 `_process_upscale` 的每个 tile 迭代（src/shared/ai_models/ai_plugin_engine.py，两处 `# Cancel checkpoint at every tile boundary (AUD-31500)` 注释处）、provider 尝试循环、以及 session 加载后。类已有 `_abort`/`request_cancel`/`_InferenceCancelled` 完整协作取消机制，`cancel()`/`process_plugin()` 均不再 terminate/wait。原审计所述"循环内无 abort 检查；类中不存在 abort 标志"已不成立。新测试 `TestAud31502InvalidVerification` 以 AST 断言钉住该状态。

### AUD-31510 — FIXED
`src/shared/ai_models/ai_mask_engine.py`
- worker 新增 `_sam_decode_cache`：记录 `{embedding(按身份), shape, 已处理点/标签前缀, pos/neg 累加器}`。
- `process_sam_decode`：若传入点表以缓存前缀开头且 embedding 未变（`is` 身份比较，re-encode 自动失效），累加器从缓存副本续算，仅推理 `points[prefix_len:]`；撤销/删点（前缀不匹配）自动回退全量。N 点会话从 N(N+1)/2 次解码器推理降为 N 次。
- 缓存仅在完整、未取消的解码成功后提交；中途取消的部分累加绝不成为下次起点。
- 测试验证：扩展点表只跑新增点且结果与全量重算逐像素一致；撤销、换 embedding 均触发全量重算。

### AUD-31511 — FIXED

### AUD-31520 — FIXED
`src/shared/ai_models/denoise_worker.py` `AIDenoiseThreadController`
- 引用清理由新增 `_on_thread_finished`（连至 `thread.finished`）统一完成：`sender.wait()` 保证 OS 线程完全退出后再 `sender.deleteLater()`——**不能**直接 `finished.connect(thread.deleteLater)`：QThread 在清理 `running` 标志**之前**发射 finished，紧随的 deleteLater 会撞上 "QThread: Destroyed while thread is still running" 原生 abort（本批测试实测复现并修复）。
- 清理后 `self._thread/self._worker` 置 None，`is_running()/wait()/start_processing()` 不再触碰已销毁 wrapper。
- worker 自清理改为 `worker.finished/error/cancelled → worker.deleteLater`（经 worker 自己的线程队列投递并在线程收尾时冲刷，三条退出路径一致；控制器线程不得对已死线程的对象调 deleteLater——实测同样原生 abort）。此机制顺带覆盖了 AUD-31525（Suggestion，不在本批）的 error 路径泄漏。
