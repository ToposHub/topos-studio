## 设计决策与残留说明

- **AUD-64001 的完整激活需要 base_evaluator 的回写（白名单外，跨批依赖）**：`base_evaluator.py:635-636` 的 `evaluated_port_revisions/evaluated_upstream_revisions` 是**死变量**——求值后修订只写入临时快照副本（:1046-1059），从未回写节点对象（`Node.set_upstream_revision` 全库零调用方），而下一帧快照从节点对象重建（node_engine.py:1815-1816）。因此调度器第 6 层的比较（render_scheduler.py:1164-1184：上游当前修订 vs 消费者缓存修订）在"上游发生过 bump"后永远不等——**下游消费者会在其后的每个 plan 重复求值（过度失效，方向安全：宁重算不出陈旧）**，直到图重载。本批选 0 基登记把该效应限制在"确有内容变更信号（set_parameter/关键帧/表达式）之后"；彻底消除需要 base_evaluator 批次把死变量接回 `self._render_nodes[node_id]._port_revisions/_upstream_port_revisions`（约 10 行，建议移交该批次责任人，与 AUD-5801~5806 同文件）。
- **AUD-6009 的调用方透传（一行）在 color_evaluator.py（白名单外）**：生产路径 `_compute_percentile_range` 持有 `input_tex.revision`（TextureResult）但传入的是解析后的原生纹理；manager 侧已支持 `texture_revision=` 权威参数并在无权威值时自动走内容指纹（本批主修复）。color_evaluator 批次补 `texture_revision=input_tex.revision` 一行即可跳过指纹探测的 512B 回读（纯优化，非正确性依赖）。
- **AUD-6002 的渲染器销毁接线**：`release_lut_cache()` 已就绪；composite_renderer.py `_cleanup` / composite_export_renderer.py `cleanup`（白名单外）各加一行 `safe_call("3D LUT cache", self.release_lut_cache)` 即可整体释放。LRU 逐出+立即 release 已使无界增长与"零释放"在本文件内闭环（复合与导出渲染器各自实例缓存的"双份"由 8 条/64MB 上限定界）。
- **AUD-6307 的完整异步**：AIComputeManager 异步分支（cache miss 先直通、结果落地触发重评估）需在 base_evaluator 注册本节点（`_AI_NODE_TYPES`，:246）并走 `_evaluate_ai_node` 模式（:1372）——同文件白名单外；且导出路径必须同步等待结果，预览/导出分叉的接线也在求值器侧。本批交付的有界超时 + worker 线程已把"网络往返/挂死连接无限期阻塞渲染队列"这一条目的核心危害关闭，并把 cost_confirm 移出渲染线程。
- **AUD-6306 的 provider 侧根治**（把输入图纳入请求体）在 `src/shared/ai_models/generation/image_gen_job.py:202-209`（白名单外）；节点侧合成已独立保证遮罩外像素正确，不依赖该改动。注意 job.run 内部仍会把 provider 原始输出缓存进 `gen{key}` 条目——节点侧的 `gencomp{key}` 合成条目与形状校验保证坏形状结果表现为 FAILED（可见）而非错像素。
- **AUD-64002 与未知字段的边界**：审计建议的"非法键归入 `_unknown_fields`"未采纳——大量节点在运行时向 `parameters` 写入无 ParamDef 的动态键（roto_point_*、内部 `_effect_*` 约定等），按键名移除会破坏它们；类型规范化只作用于**有定义**的参数，未定义键原样保留（to_dict 的 `_unknown_fields` 机制继续负责顶层未知字段）。
- **AUD-6009 指纹的 GL 状态**：`_downsample` 复用既有路径，与 `compute_histogram` 内部下采样一样会切换 FBO/viewport 且不恢复（既有行为，AUD-6303 记录的契约："后续 pass 自行 fbo.use()+viewport"）；指纹持有 manager 的 RLock，与 compute 路径互斥。
