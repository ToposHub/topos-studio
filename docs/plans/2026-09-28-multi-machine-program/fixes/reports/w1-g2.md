## 1. AUD-2209 — `_write_png` 缺 sRGB/显示变换 → **FIXED**

**位置**：`src/app/controllers/ai_workflow_composite_render.py:263-287`（`_write_png`；调用点 `_render_headless` 内 237-241）。

**做法**：

- `_write_png(frame, path)` → `_write_png(frame, path, config_manager)`，`_render_headless` 把已有的 `config_manager` 透传（provider 据此选择色彩引擎，尊重 OCIO）。
- 写 PNG 前复用主导出路径同一编码函数 `composite_render_output._encode_linear_to_srgb`（即 FileOutput png/jpg 导出与视频路径 `transform_color` 的同源实现；provider 不可用时自动回退内置 sRGB OETF），随后 `np.clip(encoded, 0, 1) * 255 + 0.5` 量化为 uint8——与 `composite_render_output._convert_for_image_ext` 的 png 分支行为一致。

**0-1 外高光的处理**：scene-linear >1.0 经 OETF 后 >1，量化时 clip 到显示白（255）。SDR 8bit PNG 无 HDR 余量，这是标准且与主导出路径（`composite_render_output.py:1201`）完全一致的处理；未对输入数据本身做无理由 clamp（违反 HDR 红线的是"先 clip 再编码"，本修复是编码后再量化 clip）。

**测试证据**（`tests/app/test_fix_controllers_aud.py`，强制 provider 回退内置数学以获得确定性期望值）：

- `test_write_png_encodes_srgb_not_linear`：linear 0.5 灰 → 188/255（旧错误行为为 128，断言差值 >20）。
- `test_write_png_dark_range_uses_linear_knee`：0.001（≤0.0031308 阈值）→ 走 12.92 线性段 → 3（旧行为为 0）。
- `test_write_png_hdr_highlights_clip_to_display_white`：linear 4.0 → 255。
