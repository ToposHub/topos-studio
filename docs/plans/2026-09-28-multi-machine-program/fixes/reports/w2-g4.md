## 逐条结论

### AUD-5400 [Critical/bug/M] — FIXED

- 结论：**FIXED**（问题确认存在）
- 根因：`TilePaddingComputer._SOURCE_TYPES` 是手写集合
  `{color_input, constant, image_input, timeline_clip_input, scene3d,
  camera3d, light3d, geo3d, model3d}`，与 `node_capabilities.py` 的
  `_NODE_CAPABILITY_TABLE` 严重脱节：`video_frame`/`text`/`particle`/
  `deformer3d` 等 action_type="source" 类型，以及 `ramp`/`noise`（能力表中为
  effect 型生成器，roi_policy="full_frame"）全部不在集合内。Step 3 只对集合内
  节点取 accumulated 最大值 → 这些图根的 total_padding 恒 0 → 分块渲染接缝。
- 修复（数据驱动，删除类型清单）：彻底移除 `_SOURCE_TYPES`。Step 3 改为
  `total = max(accumulated.values())`。正确性依据：accumulated 沿链向根单调
  不减（`accumulated[n] = own(n) + max(downstream) >= max(downstream)`），
  其全局最大值必在颜色数据根（source 或生成器）处取得，故与"在 source 层取
  最大"等价，且不可能漏掉任何节点类型——新增源/生成器节点无需改本模块。
  `padding_chain` 诊断改为在取得最大值的节点处取链（根节点无自有 padding 时
  继承下游链，与旧实现输出一致）。
- 防遗漏测试：`test_rooted_blur_chain_has_padding` 参数化覆盖
  video_frame/text/ramp/noise/particle/image_input/color_input 七种图根；
  `test_generator_root_with_downstream_effects_exact`（ramp→blur→erode 精确
  13px）、`test_mixed_media_and_generator_graphs_take_max`（混合图取最深链）、
  `test_legacy_source_chain_value_unchanged`（锁定旧行为正确的部分：13px）。

### AUD-48007 [Critical/risk/M] — FIXED

- 结论：**FIXED**（问题确认存在）
- 根因：`ImageLoader.cancel_all` 在 2s 有界等待后无条件
  `self._cancelled_workers.clear()`——超时仍在运行的解码 QThread 失去全部强
  引用，循环 GC 可在运行中析构 QThread 导致进程 Abort。且 clear() 无条件执行，
  连等待期间（mutex 释放时）新加入 `_cancelled_workers` 的运行中 worker 也被
  一并丢弃。
- 修复（参考 tracking_service `_zombie_workers` 模式，未改动该参考文件）：
  1. 新增 `self._zombie_workers: List[ImageDecodeWorker]` 强引用保活列表；
  2. `cancel_all` 等待后仅将**已退出**的 worker 从 `_cancelled_workers` 过滤
     掉；仍在运行的移入 `_zombie_workers`（含 warning 日志），等待期间新
     cancel 的 worker 保留在 `_cancelled_workers` 中不丢引用；
  3. 周期剪枝：`_prune_zombie_workers_unlocked()` 挂到
     `_cleanup_finished_workers_unlocked()`（每次 decode 完成/失败回调触发）
     及每次 cancel_all，已退出的 zombie 释放引用；永不退出的 worker 刻意
     泄漏到进程退出（与 image_engine `_TERMINATED_THREADS` 的销毁责任移交
     语义一致），绝不 terminate。
- 测试：5 个用例——卡死 worker 保持强引用、正常完成 worker 被释放、
  zombie 退出后被剪枝、等待期间新 cancel 的 worker 不丢引用且下轮
  cancel_all 正确转僵尸、重复 cancel_all 不产生重复僵尸。
