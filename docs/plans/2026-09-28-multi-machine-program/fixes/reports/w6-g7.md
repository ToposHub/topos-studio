## AUD-18206 [Critical/bug] v4→v5 迁移把 `project["timelines"]`（TimelineSequenceRef 字典）当序列列表迭代

**状态：FIXED**

**根因**：`_dict_to_project` 只收到 project 子字典，而 `_migrate_v4_to_v5`
在其中迭代 `data.get("timelines")`——该键实为 `{timeline_id: TimelineSequenceRef}`
元数据字典（`_project_to_dict` L260-263 写出；git `a5b38cc1^` 已核实 v4 时代同
为 ref 字典）。迭代 ref 字典得到字符串 key，`tl.get("clips")` 抛
`AttributeError`，被 load API 的宽泛 except 吞成 "Failed to load project"
返回 None——旧版工程经 `from_json`/`load_from_file` 加载必败。clip 数据实际
存放在 wrapper 顶层 `timeline_sequences.{seq_id}` 的
`video_tracks/audio_tracks/subtitle_tracks`（旧布局 `tracks`）→ `clips`。

**修复**（结构先验，参照 `captions/schema.upgrade_captions_in_project` 的遍历方式）：

1. `from_json` / `from_json_with_ui_state` 在提取 project 子字典**之前**对完整
   wrapper 执行 `_migrate_data(data, version)`（迁移须作用于 wrapper 全量数据），
   之后以 `SERIALIZATION_VERSION` 调 `_dict_to_project` 避免重复迁移。
2. `_migrate_v4_to_v5` 重写遍历逻辑：序列来源仅两个——wrapper 级
   `timeline_sequences`（dict）与 `timelines` **作为列表**的极旧布局回退
   （`isinstance(timelines, list)` 防御）；`timelines` 为 dict 时是 ref 映射，
   **绝不迭代**。每个 seq_dict 按
   `video_tracks/audio_tracks/subtitle_tracks/tracks` → `clips` 下钻，各层
   isinstance 防御。兼容传入 wrapper 或 project 子字典两种调用位置（scopes
   含 `data["project"]` 嵌套层）。
3. 关键帧缩放修正（迁移功能修复）：原实现对 `entry["keyframes"]` 做
   `isinstance(list)` 检查，而 `AnimatableParam.to_dict`（v4 时代
   `a5b38cc1` 同款）把 `keyframes` 序列化为 **KeyframeTrack 字典**（内层
   `"keyframes"` 才是列表）——原检查在真实数据上永不命中，值缩放是死代码。
   现两种形状均处理（dict 先下钻一层再取列表）。

**测试**：`tests/edit/test_fix_w6g7_aud6.py::TestV4ToV5Migration`——按真实
v4 布局（project.timelines 为 ref 字典 + wrapper.timeline_sequences 含
animated_params 的 clip）构造样例：
- `from_json` 加载成功、ref 解析进 `project.timelines`（旧代码在此抛
  AttributeError）；
- `from_json_with_ui_state` 全链迁移：key 改名
  `transform.position_x → transform.translate_x`、关键帧值 ×1920
  （0.5→960.0、-0.25→-480.0）；
- 迁移幂等；project.timelines 的 ref 字典内容原样保留（不被迭代/篡改）。

## AUD-4701 [Critical/bug] migrate_v6_to_v7 借用 v9 的 `_SCENE3D_KEEP` 删参，场景环境参数静默丢弃

**状态：FIXED**

**根因**：v6→v7 的删参循环用 `k not in _SCENE3D_KEEP`（只留
width/height/format_name，v9"纯渲染器"语义）删除全部非保留键，而
`migrated_keys`（_SCENE3D_PARAM_SPLIT 并集）求并集后从未使用（死变量）——
实现从"删已迁移键"漂移为"删全部非保留键"。结果：`bg_*`、`show_grid/axes`、
`grid_*`、`output_*`、`msaa`、`active_camera_id`、`light_color_*`、`hdri_preset`
等场景环境键不在 split 也不在 keep，v6→v7 即被删；随后 `migrate_v8_to_v9`
（设计为把这些键提升到 `viewer_state["default_3d_scene"]`）已无键可迁——v6
旧工程升级后场景背景/网格/MSAA/HDRI/活动相机静默回默认并随重存固化。

**修复**（铁律"迁移删参必须按版本核对"）：v6→v7 只删除

v8→v9 的全局迁移。`migrated_keys` 恢复用途（不再是死变量）。v8→v9 本体

**测试**：`TestScene3DEnvParamsSurviveMigrationChain`——

  （bg_r/msaa/hdri_preset/active_camera_id/light_color_g）且从节点删除。

既有测试核对：`test_scene_payload.py::test_scene3d_keeps_only_canvas_params`
断言全链末端只剩画幅参数——环境键经 v8→v9 移除后仍然满足，无需改测试。

## AUD-30017 [Critical/bug] 参数值仅剥 `<script>` 块；自由 profile 重建后 `on*` 事件处理器等活动内容注入存活

**状态：FIXED**

**根因**：`apply_html_template` 的参数值防御只有 `_SCRIPT_BLOCK_RE` 剥 script
块；值代入后经 `build_html_layer_from_source` 重建，该路径默认自由 Motion
Graphic profile（`allow_event_handlers=True` 等——为模板**作者**的 HTML 设计），
sanitizer `_clean_attrs` 对 `on*` 前缀属性放行（sanitizer.py:372-374）——参数
值里的 `<svg onload=alert(1)>`、属性逃逸 `x" onerror="...`、style 块逃逸
`</style><img onerror=...>` 均以活动内容存活，击穿"参数值绝不能注入"承诺
（外部输入入口：ai/service.py:270、timeline_view.py:14106）。

**修复**（铁律"HTML 模板参数值绝不能注入"；按替换上下文归类，纯文本/数据语义）：

`template_promote.py` 新增 `_prepare_param_value(kind, value)`，`_sub` 按
marker 种类（`{{slot:…}}`/`{{asset:…}}`/`{{token:…}}`）分别净化：

- **slot（内容节点内文）**：`html.escape(value, quote=True)`——payload 成为
  字面文本（`&lt;svg onload=alert(1)&gt;`），不再解析为带事件处理器的元素；
  经 sanitizer 文本往返（unescape→re-escape）后形态不变。
- **asset（`topos-asset://` 引号属性内的 id）**：同款引号转义——`x&quot;
  onerror=&quot;…` 无法闭合属性开新属性；替换点的 scheme 前缀固定，不可能
  引入 `javascript:` scheme。
- **token（`--NAME` CSS 自定义属性值）**：剥 `<>{};\` 五类结构元字符（含
  反斜杠防 CSS 转义重组）——值恒为单一声明，不能闭合规则、不能以 `</style>`
  终止 style 块注入标记。

既有 `_SCRIPT_BLOCK_RE` 全值剥离保留（纵深防御）。

**sanitizer.py 未改的理由**：`allow_event_handlers=True` 下放行 `on*` 是自由
profile 的**设计契约**（模板作者的浏览器级 HTML 保留内联 JS/事件），改它会
破坏作者侧功能；注入问题的根源在"参数值以标记形态进入重建管线"，在替换点
按数据语义净化即根治。审计证据中 sanitizer.py:372-374 是存活路径描述而非
要求改动的位置。

**测试**：`tests/teaching_animation/test_fix_w6g7_aud30017.py`（14 例）——
按审计 payload 清单：`<svg onload=alert(1)>`、`<img src=x onerror="alert(1)">`、
`<a onclick=…>`、`javascript:alert(1)`（文本/asset 两上下文）、
`x" onerror="alert(1)`（属性逃逸）、`red}</style><img src=x onerror=…>`
（style 逃逸）、`red} *{position:fixed;inset:0`（规则重组）；断言真实标签
边界（转义文本/属性值内的 `on*=` 子串是惰性的，不误报）+ 合法 token 值
（#00e676/1.5em/rgba(...)/dark-blue）原样通过 + script 剥离回归。

## AUD-R2-010 [Major/bug] color 模块 3 个 .glsl 仍含 BT.601 PAL 模拟系数

**状态：FIXED**

**根因**：AUD-39800（Wave5 已修 Python 侧 yuv_gpu_upload.py）同族——三个
shader 库文件的 bt601 常量为 `mat3(1,1,1, 0,-0.3945,2.032, 1.140,-0.581,0)`
（PAL 模拟 YUV：U/V 按 0.493/0.877 缩放推导），而三者的色度归一化均为数字
YCbCr 的 `(C-128/255)×(255/224)`（limited ±0.5）约定，该约定下标准系数应为
R:+1.402 / G:-0.3441·U-0.7141·V / B:+1.772（Kr=0.299、Kb=0.114 推导）。

**修复**（铁律"BT.601 用数字 601 系数"；列布局与既有 BT.709/2020 行及
yuv_gpu_upload.py 修正一致）：

```glsl
const mat3 bt601 = mat3(
    1.0, 1.0, 1.0,
    0.0, -0.3441, 1.7720,
    1.4020, -0.7141, 0.0
);
```

- `video_yuv.glsl`（1 处；唯一被 Python 实际加载的——video_upload.py:411）
- `video_color_decode.glsl`（1 处）
- `yuv_gpu_convert.glsl`（3 处：3-plane / nv12 r16ui / nv12 float 三 shader）
- **同族顺带修正（白名单 glob `shaders/*.glsl` 内）**：`color_convert.glsl`
  的 `BT601_YUV_TO_RGB` 与 `BT601_PAL_YUV_TO_RGB`（2 处）携带同样错误的
  PAL 值（"NTSC"条目注释与数值本就不符）。该文件无任何 Python/测试引用
  （纯库/参考文件），与三份点名文件同批订正以免遗留错误参考；数字域
  PAL/NTSC 同为 BT.601 Kr/Kb，两矩阵数字系数一致。

**测试常量订正**：

- `tests/video/test_yuv_upload_api.py`：本地 `BT601_MATRIX`（L51-55）与
  `test_bt601_matrix_values` 自引用断言（L342-350）改为数字 601。该断言为
  文件内自引用（不读源码），修正前后测试均通过（w5-g2 已注明），属误导性
  旧值订正。
- `tests/benchmark/quality_reference_frames.py`：CPU 参考
  `_MATRIX_COEFFS['bt601']` 由 `(1.1400, -0.3945, -0.5810, 2.0320)` 改为
  `(1.4020, -0.3441, -0.7141, 1.7720)`，注释同步（旧注释自述"镜像 shader
  旧变体，非教科书值"——现已与修正后的 GPU 矩阵一致）。

**golden 重录（有基线文件，按工具流程重新生成）**：

- 修正后先跑对比模式（未动 golden）：CPU↔GPU 6 用例全 PASS（bt601 用例
  max 0.25/255，数字↔数字一致），但 GPU↔旧 golden 对比中
  `sdr_8bit_601_full_444` 差 **33.62/255**（旧基线 2026-09-11 以 Wave5 之前
  的 PAL GPU 矩阵录得），其余 5 个非 601 用例 golden 差 0.0（跨 6800→6900
  GPU 位精确复现，证明重录环境确定性）。
- 按 `--update-golden` 全量重录（工具文档既定流程；5 个非 601 用例内容
  不变）并复验：6 用例全 PASS、GPU↔golden 差全部 0.0/255；
  `reference_meta.json` 环境（git bc120ecd、AMD Radeon RX 6900 XT）如实
  记录新基线。
