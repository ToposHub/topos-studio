## 设计决策与残留说明

- **AUD-16006 的"阻塞调用线程"项**：首次 apply 的网络调用是"翻译此轨"操作本身的语义（用户动作），无法在命令层消除；本修复消除的是 redo 重复触网与非确定性（审计核心危害），并使网络故障即便在 redo 阶段发生也不再丢历史（AUD-16204 回填）。AiAssistantTranslationProvider 侧的超时/重试策略属 llm_client 域（不在白名单）。
- **AUD-16209 的映射入口一致性**：无 fps 元数据时 `timeline_to_source_frame` 的回退公式仍是 `int(relative * speed)`，但**段时长改为两边界帧差**后截断误差不再逐段累加（首边界共享），有理 fps 元数据路径则完全精确。反转（SpeedParams.reverse）下行映射经 min/max 窗口归一后配合原 speed 字段重放，方向正确。
- **AUD-16211 的契约选择**：审计建议"返回 updated 命令（本文件已有大量先例）"，但 AddEffectCommand 的既有直接调用方（tests 与 controller 经 CommandStack 的两条路径外，`test_plugin_identity.py` 等直接 `result = cmd.apply(seq)` 后当 timeline 用）锁定 bare-timeline 返回契约；改返回形状会连坐 5+ 个测试文件。`object.__setattr__` 回写与本文件 DeleteBinCommand/SplitClipCommand（`_original_clip`）为同一既定机制，语义等价（栈存的实例即携带快照），零契约破坏。
- **AUD-16213 的证据核实差异**：审计自述"remove_bin 对子 bin 的处理（实现在 project.py，本批未审）"——本次核实 remove_bin **无**级联/reparent 语义，按审计给出的两条路线中"快照后代并还原"实现（防御未来语义变化），而非仅在注释固化契约。
- **AUD-16210 的三个例外**：`MoveClipsOverwriteCommand`/`RetimeMotionGraphicClipCommand`/`ProjectMacroCommand` 有 command_type 但无 from_dict，本就无法反序列化；其余 24 个 EditProject 级命令刻意排除（见上表）。注册表为显式静态清单 + 完备性测试双保险。
- **锁定旧行为协议处理**：仅 `tests/edit/test_channel_layout.py::TestBS1770Weights` 锁定了 AUD-16100 判定为错误的 0.59/0.41 权重（`test_51_weights`/`test_71_weights`/`test_surround_weighted` 3 处断言），按协议翻转为 BS.1770-4 的 1.41 并在用例内注明翻转原因；`test_stereo_weights`/`test_lfe_excluded` 不涉改动、未动。其余邻接套件无任何用例锁定被修改行为（全量 tests/edit 392 文件跑通，见验证记录）。
