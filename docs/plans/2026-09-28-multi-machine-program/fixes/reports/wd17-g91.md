## AUD-35200 [Major/bug] IOSurface 以 kIOSurfaceIsGlobal=True 创建

**状态：FIXED**

**根因**：`ToposIOSurfacePool` 创建字典带 `kIOSurfaceIsGlobal: True`，表面
IOSurface ID 进入全系统命名空间，任意进程可 `IOSurfaceLookup` 命中并读写
像素数据。全仓 grep 确认无任何 `IOSurfaceLookup`/global ID 消费方——池只按
PyObjC 对象引用在进程内传递，全局可见性纯属攻击面。

**修复**（topos_surface.py `__init__`）：创建字典移除该键，注释写明安全
理由。测试断言 `kIOSurfaceIsGlobal not in create_options`。

## AUD-35201 [Major/bug] 行距未回查 IOSurfaceGetBytesPerRowOfPlane

**状态：FIXED**

**根因**：请求的 `kIOSurfacePlaneBytesPerRow` 只是建议，IOSurface 按自身对
齐规则可能分配更大行距；slot 直接采用请求值建立 CPU 映射（stride 与
`as_buffer` 长度都基于请求值），实际分配更大时逐行读取错位、实际更小时
越界读写。

**修复**（topos_surface.py `__init__`）：每个 surface 创建后逐平面回查
`IOSurfaceGetBytesPerRowOfPlane`，实际值写入 slot.row_bytes；回查失败
（TypeError/ValueError）或实际值小于请求 stride 时 `close()` 后抛
`ToposSurfaceUnavailable` fail-loud。映射闭包因此自动使用实际行距。

## AUD-35206 [Major/risk] submit/complete 锁外调原生 API，与 close() TOCTOU

**状态：FIXED**

**根因**：`submit`/`complete` 在 `_lock` 内检查会话指针、锁外调用
`EncodeFrame`/`CompleteFrames`；`close()` 并发 Invalidate 并清空
`self._session`，原生调用随即作用于已失效句柄（未定义行为/崩溃）。

**修复**（vt_compression.py）：引入第二把 `_session_lock` 专责原生会话
指针的"检查—使用—Invalidate"生命周期：
- `submit`：状态登记（`_pending`/id 分配）仍在 `_lock`；EncodeFrame 的
  会话快照 + 原生调用整体在 `_session_lock` 临界区内。
- `complete`：CompleteFrames 同样收进 `_session_lock`。
- `close`：先在 `_lock` 内置 `_closed=True` 关门（此后 submit 登记阶段即
  拒绝，消除"complete 排空后又有新帧挤入"窗口），排空 pending 后在
  `_session_lock` 内 Invalidate + 清空会话。
- `_close_session`（HEVC profile 拒绝路径）同样在 `_session_lock` 内。

锁序恒为 `_lock` → `_session_lock`；VT 回调线程只碰 `_lock`，持
`_session_lock` 做原生调用不会与回调互锁（同步回调场景由 RLock 同线程
重入覆盖）。并发测试（200 次 submit 对 1 次 close）断言每次 EncodeFrame
收到的会话指针均有效。

## AUD-35207 [Major/risk] Muxer 先 av.open/add_stream 后校验 pixel_format

**状态：FIXED**

**根因**：`VideoToolboxPacketMuxer.__init__` 先 `av.open`（创建输出文件）
+ `add_stream`，之后才校验 pixel_format；非法值抛出时容器未关、输出文件
句柄泄漏。

**修复**（vt_compression.py）：pixel_format 校验前移到 `av.open` 之前
（非法值时容器从未打开，零泄漏）；容器打开后的 `add_stream`/尺寸/pix_fmt
配置包进 try/except，任何失败先 `container.close()` 再抛。

## AUD-35208 [Major/bug] 回调丢包仅记 last_error，导出静默缺帧

**状态：FIXED**

**根因**：VT 回调里 status!=0 或 sample buffer 缺失只写 `_last_error`，
而该字段无任何消费者——导出缺帧完全不可观测。

**修复**（vt_compression.py）：新增 `_dropped_packets` 计数器与
`dropped_packets` 属性；两类丢包路径均计数 + `logger.warning` 留痕
（回调内仅计数与一次日志，不做重活，符合回调约束）。导出侧可对比
`packet_count`/提交数与 `dropped_packets` 发现缺帧。

## AUD-35301 [Major/risk] VTDecompressionSession 只 Invalidate 不 CFRelease

**状态：FIXED**

**根因**：`VTDecompressionSessionCreate` 返回 +1 引用（CF Create Rule），
`destroy()` 只 Invalidate，从不 CFRelease——每个 session 泄漏一个原生
解码器实例。

**修复**（vt_session.py）：模块加载时补配 `_CF_LIB.CFRelease` 签名；
`destroy()` Step 2 在 `VTDecompressionSessionInvalidate` 之后、
`WaitForAsynchronousFrames` 已完成的前提下调用 `CFRelease(self._ctypes_session)`
再清空指针。

## AUD-35302 [Major/bug] create() 从不复位 _destroyed

**状态：FIXED**

**根因**：`destroy()` 置 `_destroyed=True` 后，同一实例再 `create()` 会
重建原生会话并返回 True，但 `is_created` 因 `_destroyed` 恒为 False，
`decode_packet` 永久返回 None——会话看似重建、实际不可用。

**修复**（vt_session.py `create`）：codec 校验通过后（1）若旧会话仍存活
（未 destroy 且指针非空）先 `destroy()` 释放旧资源（重新配置时旧资源先
释放）；（2）无条件 `self._destroyed = False`。测试覆盖 destroy→create
重建、存活期重复 create 先释放、全新实例无多余 destroy 三个场景。

## AUD-35303 [Major/bug] 异步 submit_packet 的 pts 被完全忽略

**状态：FIXED**

**根因**：同步路径靠取帧后回填 `decoded.pts = pts`；异步
`submit_packet(packet_data, pts, ...)` 调 `_submit_packet_raw(packet_data)`
丢弃 pts，而提交的 sample buffer `numSampleTimingEntries=0`、回调 CMTime
无效——异步取帧路径所有帧都没有时间戳，seek 后无法映射回时间线。

**修复**（vt_session.py）：
- `_submit_packet_raw` 增加 `pts` 参数；非负且 ≤ 2^63-1 时经
  `sourceFrameRefCon`（`VTDecompressionSessionDecodeFrame` 第 4 参）透传。
- `_on_ctypes_decoded` 优先取 frameRefCon 还原 pts（VT 对每帧原样返回其
  提交时的 refCon，重排序也不串帧），为空再回退回调 CMTime value。
- `submit_packet`/`_decode_packet_impl` 均传入 pts（同步路径回填保留作
  双保险）。

## AUD-35304 [Major/bug] avcC 长度字段宽度被丢弃，格式描述硬编码 4

**状态：FIXED**

**根因**：`_parse_avcc_extradata` 解析出 `nalu_length_size`
（lengthSizeMinusOne+1）但返回值丢弃；两处
`CMVideoFormatDescriptionCreateFromH264ParameterSets` 硬编码 4。遇到 3
字节前缀的流时格式描述与实际 packet 表示不一致，解码边界解析错位。

**修复**（vt_session.py）：`_parse_avcc_extradata` 返回
`(sps_list, pps_list, nalu_length_size)`（短数据时缺省 4）；avcC 分支用解
析值创建格式描述。Annex B 分支无长度字段可解析，保持声明 4 并注释说明
其与提交侧约定的一致性来源。测试以 lengthSizeMinusOne=2（3 字节前缀）
的 avcC 断言格式描述收到 3。

## AUD-35312 [Major/risk] decode-only 阶段解码帧从不 release

**状态：FIXED**

**根因**：probe 主循环只在 `stage in ("bridge-only","full") and bridge`
分支内调用 `session.release_decoded_frame(pb)`；decode-only 阶段（以及
bridge 为 None 时）每个解码帧泄漏一个 retain 的 CVPixelBuffer/IOSurface。

**修复**（vt_zero_copy_probe.py）：外层 if 补 else 分支——非 bridge 路径
统一 `session.release_decoded_frame(pb)`。fake-session 测试断言 4 帧全部
释放（修复前 0）。

## AUD-35313 [Major/bug] VT 会话创建失败早退不清理 bridge 与 GL context

**状态：FIXED**

**根因**：`if not created: ... return result` 路径上，bridge-only/full
阶段已创建的 `IOSurfaceGLBridge` 与 standalone ModernGL context 无人释放

**修复**（vt_zero_copy_probe.py）：早退前 `bridge.destroy()` +

## AUD-35314 [Major/bug] --output-json 纯文件名触发 os.makedirs('')

## AUD-35315 [Major/bug] 循环内硬编码绝对导入 + 裸 except 吞掉

**状态：FIXED**

**根因**：循环内 IOSurface 检测写死 `from src.shared...`（相对导入运行环
境必然 ImportError），且被 `except Exception: pass` 静默吞掉——probe 把
真零拷贝误判为非零拷贝且无任何日志。

**修复**（vt_zero_copy_probe.py）：抽出模块级 `_pixel_buffer_has_iosurface`
助手：相对导入优先、失败退绝对导入、双失败 warning 留痕；原生调用异常
窄化为 `(ImportError, AttributeError, TypeError, ctypes.ArgumentError)` 并
debug 记录。主循环改调该助手。顺手将外层错误清理路径的两处裸
`except: pass` 改为具体 `except Exception` + warning（违反「不得宽泛
except」铁律的紧邻代码，同文件同段）。

## AUD-35400 [Major/bug] Rational.from_string 不校验外部字符串

**状态：FIXED**

**根因**：`"24/1/1".split('/')` 取前两段、静默丢弃第三段；畸形输入抛
`int()` 的裸 ValueError（无上下文）；非字符串输入抛 AttributeError。

**修复**（metadata.py `Rational.from_string`）：分段数必须为 2，否则抛
带原文的 `ValueError`；分子/分母/浮点解析失败统一转成带原文的
ValueError；非字符串输入同样 ValueError。异常类型保持 ValueError（与
既有调用方的 except 兼容），仅增加校验与上下文。

## AUD-35401 [Major/risk] VideoMetadata 未验证 fps/SAR 为正

**状态：FIXED**

**根因**：`fps.num==0` 时 `duration_seconds` 的
`total_frames / self.fps.to_fps()` 抛 ZeroDivisionError；`SAR==0` 时
`display_size` 的 `height / sar` 抛 ZeroDivisionError——崩溃点远离数据
来源，难定位。

**修复**（metadata.py `__post_init__`）：构造时校验 `fps.num > 0` 与
`sample_aspect_ratio.num > 0`（后者仅非 None 时），非法即抛带值上下文的
ValueError——在契约点 fail-loud。已核查全部 10 处生产构造点
（ffmpeg_source/factory/topos_source/topos_image_source/macos_vt source/
video_upload/video_frame_node）：各 `_extract_*`/守卫均已保证正值
（`if sar:`、`if s.sar_num and s.sar_den`、`fps>0 else FPS_24` 等），
无行为回归；测试确认合法构造与除法路径无恙。

## AUD-35404 [Major/risk] 会话内统计列表无界增长 + 聚合排序在 RLock 内

**状态：FIXED**

**根因**：14 个时间序列列表（tick/process/render_submit/queue/seek/read/
cache_hits/renderer_queue/held/coalesced/plane_prepare/texture_write/
yuv_render/frame_paths）每次 track_* 无界 append，长播放会话内存持续膨
胀（对照 `_total_frame_times` 是唯一有 120 条上限的）；且
`track_tick_time`/`record_playback_stats` 在持有 RLock 时调用
`_check_aggregate_log` → 每秒一次的全量聚合排序在锁内执行，阻塞所有
track_* 记录路径。

**修复**（performance_monitor.py）：
1. 新增类常量 `_MAX_TRACKED_SAMPLES = 600`（≈10s @60fps 滚动窗口）与
   `_append_bounded` 助手（摊还 O(1)：超窗口两倍时一次性裁剪到最近 600
   条），14 个 track_* 全部改用；
2. `track_tick_time`/`record_playback_stats` 的聚合检查移到锁外；
   `_check_aggregate_log` 的时间判定在锁内原子推进，重活
   `_output_aggregate_log` 在锁外执行（内部经 `get_aggregate_stats` 短暂
   加锁取快照）；
3. `_output_aggregate_log` 改从 stats 快照取 last_decode/last_render，
   不再无锁直读 `self._decode_path_counts`。

语义说明：聚合统计（avg/p50/p95/cache_hit_rate 等）从"全会话累积"变为
"最近 ~10 秒滚动窗口"（这是有界化的必然结果，对实时监控语义更贴切）；
`frames_processed`/丢帧计数/零拷贝计数等累计量不受影响。
`_playback_stats` 与 `_decode_times/_upload_times`（dict）不在审计引用
范围内，未改动——dict 按帧号增长同样无界，建议后续批次评估。
