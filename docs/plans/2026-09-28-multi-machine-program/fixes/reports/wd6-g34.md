## 设计决策与残留说明

- **AUD-64003 的副本语义**：`_inject_payload_node_id` 优先 `dataclasses.replace`（frozen dataclass 亦可用），非 dataclass 走 `copy.copy` + setattr，两级失败（只读属性，FrozenInstanceError 是 AttributeError 子类）才回落原对象 + warning。Scene3D 侧以 payload 字段值计算 `signature()`，副本不改变字段值故缓存签名不受影响；`_collect_scene_payload`（按端口取回，本就不注入 node_id）维持原语义未动。
- **AUD-6605 的预算值**：256MB 为审计建议值。窗口帧永不逐出是有意决策——逐出窗口帧会把 4K RGB 全分辨率 legacy 模式翻成永久 warming 直通（可见功能回归）；该模式的窗口本身（最坏 9×132MB）是算法固有工作集，已作为地板成文在 `_prune_buffers` docstring。需要更紧峰值时调 `_BUFFER_MAX_BYTES` 一处即可。
- **AUD-6609 的求值器半边**：`_apply_denoise`（filter_evaluator.py，白名单外）无需改动即消费有效半径；未来若求值器想直接读 `quality`，marker 已显式携带该键（多余键对其 `.get` 模式无害，且使 effect 缓存键天然含档位）。
- **AUD-6705 的 undo 边界**：静默写与原 `set_parameter` 直调一样不经 undo 系统（render 线程本就不能走 undo command）；docstring 成文"普通用户编辑仍走 set_parameter"。引擎主线程统一提交/求值期旁路容器属 node_engine/base_evaluator 域（白名单外），本批按审计的"至少提供跳过副作用的内部写入通道"落地。
- **锁定旧行为协议（1 例翻正）**：`tests/composite/test_p7_object_interaction.py::TestPayloadNodeId::test_collect_payloads_injects_node_id` 原以 `inspect.getsource` 锁定旧实现文本 `payload.node_id = upstream_id`——恰是 AUD-64003 要求移除的原地改写。按 FIXLOG Wave1/2/3 的"锁翻正"先例改为行为断言：对 Model/Geometry payload 注入生效（P7 原意保留）+ 共享原对象不被改写（AUD-64003 新契约），44/44 通过。
- **邻接失败归属（非本批引入）**：`test_scene3d_node_coverage.py::TestRenderPassEarlyReturns` 5 例因 `Scene3DNode._render_shadow_catchers/_render_shadow_map/_render_outline_pass` 签名增加必选参数而 TypeError——scene3d_node.py 由并行 agent 修改中（git diff +111 行，不在本批白名单、本批未触碰），登记为并行波次在途变更；本批邻接集合（18 文件）稳定复跑 500/500 通过。曾出现一次 `test_p5_5_lod_deflicker` 单例与 deflicker/batch3 组合运行偶发失败，单独与同组合复跑均全绿（多 pytest 进程共享 __pycache__ 的环境抖动，Wave1 FIXLOG 有同类记录）。
