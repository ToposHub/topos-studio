## 逐条明细

### AUD-33902 — FIXED
`src/shared/io/file_io.py` `save_image`
- 审计建议两案：`except ValueError: raise` 或 `logger.exception` 后返回 False。**选择日志案**：核实全部调用方（`composite_controller.py:1201`、`deliver_controller.py:236/293/1990`、`composite_render_output.py:721/1209`、`scripting/api.py:506`）均只消费 bool 且无 try 包裹——raise 会把设计性错误变成导出槽里的未处理异常（更糟的 UX 回归）。
- 实现：`except Exception: logger.exception("save_image failed: %s", path); return False`。设计性文案（"RAW 档 … 请选择整数/浮点档"、"浮点档 … 请去除 alpha 或选整数档"）随异常消息+堆栈进入 ERROR 日志，公共 API 消费方与运维均可读到（IO 异常边界铁律）。
- 测试：真实档位路径（`toos_tier="raw12-2"`）断言返回 False 且日志含 "RAW 档"/"raw12-2"；monkeypatch 泛化异常路径断言日志含原始错误。

### AUD-33903 — FIXED
`src/shared/io/file_io.py` 两处 RAW 单例缓存
- `_read_full_image`（原 340-345 行）：旧实现无锁内 try，`rawpy.imread` 抛错经外层 except 返回 None 后，`_current_raw_obj` 仍是已 close 旧对象、`_current_raw_path` 仍是旧路径。改为 close 旧对象后**先置 `_current_raw_obj/_current_raw_path = None` 再 imread**——失败时状态干净，旧路径下次请求因路径不等强制重开。
- `update_raw_decoding`（原 799-804 行）：同型修复 + 失败分支补 `logger.exception("RAW reopen failed: …")`（对齐 AUD-33914 指出的无日志风格缺口，此处为顺带，非本条主责）。
- 测试：旧路径成功 → 新路径 imread 失败 → 断言单例状态为 None、旧对象已 close；随后旧路径请求断言 imread 被重新调用且成功解码（此前必失败）。

### AUD-33904 — FIXED
`src/shared/io/file_io.py` `_save_toos_image`
- 原实现仅在正常路径调 `enc.close()`；`open()`/`encode_frame()` 抛错时违反编码器 C13 "close 覆盖全部退出路径"契约（`_restore_slice_threads` 进程级偏好注销、pipeline、GOP ctx 释放，见 topos_encoder.py:1593-1701）。
- 实现：`enc`/`finalized` 追踪 + `except Exception` 分支调用 `enc.abort()`（编码器设计的取消路径：discard pipeline、释放 GOP ctx、清暂存目录；close() 幂等由 `_is_open` 守卫，abort 在 close 失败后的重复调用亦安全——`_restore_slice_threads` 有 `_threads_registered` 标志幂等）。abort 抛错仅 `logger.warning`，随后 `raise` 透传主错误（由 save_image 统一记日志）。`finally` 维持 rmtree 暂存目录。
- 测试：FakeEncoder encode_frame 抛错 → 断言 abort 被调用且顺序在 encode 之后；abort 自身抛错 → save_image 仍返回 False（不掩盖主错误）。

### AUD-33905 — FIXED
`src/shared/io/file_io.py`
- 新增 `_imwrite_unicode(path, image, params=None) -> bool`（类型注解齐全）：imencode + `tofile`，失败返回 False。
- `save_image` 的 EXR（T-P1-71 参数不变，锁定测试 `test_save_image_default_exr_compression_is_rle` 验证未破坏）、TIFF、通用 8-bit 三个分支全部改走该助手，与 `_cache_preview`/`save_baked_layer` 的既有 Unicode 策略统一。
- 测试：monkeypatch `cv2.imwrite` 为禁止调用（AssertionError）→ 三种格式保存均成功且不触发 imwrite；中文文件名实际写盘 + `np.fromfile`+`imdecode` 读回形状一致。

### AUD-33906 — FIXED（方案取舍见下）
`src/shared/io/file_io.py` TIFF 分支
- **实测否决 float32 TIFF 直写案**：本机验证 opencv（项目轮子）TIFF float 编码往返有 ±5% 精度损失（1.0→1.0396、0.0→-0.0531）、Pillow 当前版本无 `RGB;F` float 模式（`Image.frombuffer('RGB;F', …)` ValueError）——依赖栈无法无损落盘 float TIFF，直写反而以静默精度损坏替换静默裁剪。
- 采审计建议的下限案：保留 uint16 量化路径，但 float 输入越界（max>1.0 或 min<0.0）时 `logger.warning`（含 min/max 实测值与 "use EXR to preserve HDR highlights" 指引）。数据丢失不再静默；主要调用方（composite/deliver 控制器、composite_render_output）本就先自行完成 float→uint16 显示量化，不受影响。
- 测试：[0.25, 1.0, 4.5] → True + 告警含 4.5 + 读回 uint16 且 4.5→65535；值域内 float 与 uint16 透传均无告警。

### AUD-34201 — FIXED
`src/shared/logging/log_manager.py` `_add_file_handler`
- 根因：`log_file_path` 为用户可配置外部输入（ConfigManager 默认 `""`），裸相对文件名使 `os.path.dirname` 得 `""`、`os.makedirs("", exist_ok=True)` 确定性抛 FileNotFoundError；路径不可写/盘满时 makedirs 或 `RotatingFileHandler` 构造的 OSError 同样无防护，沿 `_add_file_handler → _setup → initialize/reconfigure` 上抛——启动崩溃或偏好变更崩溃（root logger 已 clear 的半初始化态）。

- 测试：裸文件名 chdir tmp 后 `_setup` 不抛且文件落在 tmp/topos.log；路径含文件段（NotADirectoryError）与路径为目录（IsADirectoryError）均降级（`_file_handler` None、控制台 handler 在位）不抛；`get_log_file_path` 与实际写入文件 samefile。
