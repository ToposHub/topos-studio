## 逐条修复摘要

### AUD-36805 — read_project_meta 的 float() 转换位于受保护 try 之外
- 新增 `_archive_float(value, fallback)`：捕获 `(TypeError, ValueError)` 并降级到 fallback。
- `read_project_meta` 的 `created_at`/`modified_at` 改用该助手，单个畸形档案（时间戳为字符串/dict/None）不再让整库扫描抛 ValueError。
- 附带：畸形档案仍会出现在扫描结果中（时间戳为 0.0/mtime），只是不再拖垮整批——符合"损坏单条降级不拖垮整批"。

### AUD-36806 — get_project_backup_dir 的 mkdir 无 OSError 防护
- `get_project_backup_dir` 的 `mkdir` 包裹 `except OSError` + warning 日志（与 `get_project_library_dir` 同构），扫描/列表/重命名路径不再直接抛异常。
- 附加发现并修复同类隐患：`list_project_backups` 中 `entries = backup_dir.iterdir()` 是惰性生成器，原 `except OSError` 护不住后续 `for entry in entries` 的实际 listdir（backup 路径被普通文件占用时抛 NotADirectoryError）——改为 `tuple(backup_dir.iterdir())` 在 try 内物化。

### AUD-36807 — rename_project 失败回滚丢失"部分搬移"状态
- `_move_related_project_files` 与 `_move_project_backups` 现在自带回滚：循环体抛 OSError 时先 `_rollback_moves(已完成搬移)` 再 re-raise，部分搬移的 .bak/.autosave/缓存目录/备份文件不再滞留新名称下。
- `rename_project` 外层回滚逻辑不变（target 重写档案照常 unlink，source 完整保留）。

### AUD-36814 — update_offline_status 重建 ToposProject 遗漏 revision
- 重建时显式传 `revision=project.revision`，乐观锁计数不再归零。

### AUD-36815 — get_offline_asset_list / update_offline_status 缺 is_virtual_asset_path 防护
- 两处离线判定统一为 `not is_virtual_asset_path(asset.path) and not os.path.exists(asset.path)`（与 check_offline_assets 的 216-219 行对齐），`topos://` 虚拟素材不再被误判离线。

### AUD-36816 — check_offline_assets 对未知工程类型静默返回空报告
- else 分支改为 `raise ValueError(f"Unsupported project type: {type(project)}")`，与 relink_asset/batch_relink 的显式报错一致。

### AUD-36901 — assets/ 大二进制全量读入内存并逐次全量重压缩
- `ProjectArchivePayload` 新增 `preserved_members: dict[str, _PreservedMember]` 字段。
- `load_from_file(filepath, defer_assets=True)`（默认）：`assets/` 成员不再读入内存，仅记录 (source_path, filename, date_time, file_size) 引用；`write_to_zip` 时以 1MB 块从源档案流式 `copyfileobj` 直拷到目标 zip。
- 流式成员以 `ZIP_STORED`（`PRESERVED_ASSET_COMPRESS_TYPE`）写回，消除每保存一次就对全部媒体数据重新 deflate 的 CPU 成本；代价是这些成员在包内不再压缩（EXR/PNG/JPEG 本身压缩收益极小）。
- 源档案在写回时不可读 → 抛 `ProjectArchiveReadError`（宁可使保存失败也不静默丢资产）；ToposProjectIO.save 写临时文件后 os.replace，流式期间源文件始终完好。
- `read_from_zip(zf)` 默认行为不变（eager bytes 进 `unknown_files`）——受 tests/project/test_project_module_preservation.py 的既有契约锁定；`defer_assets=True` 但源不可重开（BytesIO）时自动回退 eager。
- 顺带修复：manifest/project/known-JSON 解析失败路径原先对同一成员 `zf.read` 两次，现在读一次复用。
- 尚存边界：topos_project_io.py:503 注入的 cache 资产仍为 eager bytes（受 `max_cache_size_mb` 约束，属该文件职责，本次白名单外不动）。

### AUD-36902 — load_from_file 把"读取失败"同化为空 payload
- 文件不存在 → 仍返回空 payload（新工程语义不变）。
- 文件存在但打不开/非 zip（`zipfile.BadZipFile, OSError`）→ error 日志 + 抛 `ProjectArchiveReadError`；ToposProjectIO.save 捕获后返回 False，原文件字节保持不变——后续保存不再静默丢弃其他产品的模块数据。

### AUD-36910 — save_project/save_project_to_path 非原子覆写 + 宽泛 except + 无返回值
- 两个写路径均改为：在目标同目录 `tempfile.mkstemp` 建档 → 写 zip → `os.replace` 原子换入 → finally 清理临时文件。
- `except Exception`（吞一切且无日志栈）改为 `except (OSError, zipfile.BadZipFile, TypeError, ValueError)`，`logger.error(..., exc_info=True)` 全栈记录，返回 `bool`；空参早退也返回 False。
- 注：审计标注"全仓库当前无调用方"，返回值由 None→bool 向后兼容（唯一内部调用方 backup_project 忽略返回值）。

### AUD-36911 — schedule_autosave 后台线程遍历 engine.layers 并改写 plugin dict
- 新增 `_main_thread_autosave_timer()`：当在主线程且存在 QCoreApplication（生产路径）时，用单发 QTimer 做防抖，`_perform_autosave`（含 engine.layers 遍历与 plugin dict 写入）改在 UI 线程执行，消除数据竞争。
- 无 Qt 事件循环的 headless 场景回退到原 threading.Timer（设为 daemon，并在切换到 QTimer 时取消遗留 timer）；回退路径在 docstring 中注明局限。
- 模块常量 `AUTOSAVE_DEBOUNCE_SECONDS = 2.0` 保持原防抖时长。

### AUD-36921 — 自动新建调色栈后未同步 stack_id，孤儿栈堆积
- `_save_color_to_edit_project` 在 stack_id 缺失时先调用新助手 `_find_existing_color_stack_id(edit_project, asset_id, clip_id)`：优先按 clip_id 匹配既有栈，其次匹配 asset 的默认栈（clip_id 为 None），命中则复用并走 update 分支——无 stack_id 的重复保存不再每次铸造新栈，孤儿栈堆积从根上消除（确定性修复，不依赖 UI 接线）。
- 仅在确实无匹配时才生成新 UUID，并通过可选回调 `on_color_stack_id_created` 通知宿主（镜像 composite 路径的 `on_composite_id_created`；用 `_get_callback` 探测，未注册不产生警告噪音）。file_controller.py:1242 起的回调注册表在白名单外，建议后续在那里补注册该回调以便 ColorSession 即时拿到 stack_id（非必需，复用查找已闭环）。

### AUD-37001 — validate_json 在 jsonschema 缺失时静默放行
- fail-open 改 fail-closed：`import jsonschema` 失败时抛 `RuntimeError`（消息含 AUD-37001 fail-closed 说明），外部数据验证不再被无声绕过。
- schema 存在校验逻辑不变（未知 schema_name → False；ValidationError → False）。
- 环境注记：当前 venv 未安装 jsonschema（requirements.txt 也未声明），建议主会话决定是否将 jsonschema 加入依赖；加入前任何 validate_json 调用会显式 RuntimeError 而非假通过。

### AUD-37003 — 7 个 with_* 工厂丢失 revision
- `with_name / with_asset_added / with_color_stack_added / with_timeline_added / with_composition_added / with_active_timeline / with_ui_state` 全部补 `revision=self.revision`（已 grep 验证 7 处）。

### AUD-37004 — frozen 数据类 dict 字段跨实例共享引用
- `ToposProject.__post_init__` 对 8 个 dict 字段（assets/bins/timelines/color_stacks/compositions/deliver_presets/ui_state/settings）用 `object.__setattr__` 做防御性浅拷贝，切断构造来源与派生实例间的共享引用；"frozen 确保线程安全"的承诺在容器层成立。
- `to_dict()` 对 `ui_state`/`settings` 返回副本，序列化结果不再回写实例状态。
- 边界（已在代码注释声明）：浅拷贝只隔离容器本身，ui_state/settings 内部嵌套值仍可能可变——按只读快照对待。

### AUD-37005 — DeliverPresetRef.from_dict 对畸形 resolution 抛 IndexError
- resolution 校验：`list/tuple 且 len>=2` 时取前两元素并 `int()` 强转（失败回退），否则一律回退 `(1920, 1080)`；单个坏预设字段不再让整个工程加载失败。

### AUD-37008 — 毫秒→分钟整除截断可产生 0 间隔定时器
- 新增常量 `MIN_AUTO_SAVE_INTERVAL_MINUTES = 1`、`DEFAULT_AUTO_SAVE_INTERVAL_MINUTES = 5` 与两个助手：
  - `_validate_auto_save_interval_minutes`：`start_auto_save`/`set_auto_save_interval` 对显式入参做下界与非整数校验，非法抛 `ValueError`（显式契约）。
  - `_clamp_auto_save_interval_ms`：`from_dict` 对持久化数据（不可信外部输入）做 int 强转 + 钳制到 ≥60000ms，杜绝 `QTimer.start(0)` 保存风暴。
