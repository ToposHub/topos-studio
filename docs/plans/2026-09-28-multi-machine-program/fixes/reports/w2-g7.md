### AUD-7504 [Critical/bug/M] — FIXED

- 结论：**FIXED**（问题确认存在，数学复核成立）
- 根因核实：前向线性部分 A = [[sx·c, −sy·s],[sx·s, sy·c]]，真逆为
  [[c/sx, s/sy],[−s/sx, c/sy]]；代码取 `sin_r = sin(−rot) = −s` 后写成
  m01 = −s/sy、m10 = +s/sx，两项符号恰与真逆相反——"逆"矩阵的线性部分 = 前向矩阵
  本身（旋转被应用两次而非撤销）。审计数值案例复算确认：rot=90°、pivot(2,3)、tx=10
  时 (5,7) → 前向 (8,6) → 旧"逆" (−1,−1)（本机独立复算一致）。
- 修复：不再手推导，`_build_inverse_matrix` 直接从 `_build_transform_matrix` 的精确
  前向矩阵做解析 2×3 仿射逆（det = m00·m11 − m01·m10；伴随矩阵 + 平移项
  i02/i12 = −(i·t)），结构上保证 forward∘inverse = identity 对任意
  rotation/scale/pivot/translate 组合成立；`|det| < 1e-12` 时退化为单位阵（参数
  scale≥0.01 下不可达，纯数值防御）。pivot 解析与尺寸参考保持原语义（与
  `_build_transform_matrix` 同一 image_width/height）。
- 测试：8 组参数化往返测试（rot≠0、非零 pivot、非零 translate、非均匀缩放、负角、
  审计数值案例）+ ROI 包含性属性测试（`compute_input_roi` 逆向恢复的区域必须覆盖
  输入 bbox 四角）。回归力验证：以旧公式独立复算，往返测试必然失败（(−1,−1) ≠
  (5,7)）。
- 备注：`|det|` 守卫使原 `sx==0 → inv_sx=1` 的行为不可达，语义无回归（旧行为本身
  即错误矩阵）。

### AUD-7601 [Critical/bug/M] — FIXED

- 结论：**FIXED**（问题确认存在）
- 根因核实：`_convert_decoded_frame` 的 packed（1037-1046 + 1095）与 CPU-YUV
  （1164-1171）两条路径复用预分配 scratch（`_rgba_buffer` / `_bg_rgba_buffer`），
  `np.ascontiguousarray(result)` 对 C 连续数组原样返回同一对象；`_decode_and_store`
  （worker，background=True → `_bg_rgba_buffer`）与 `upload_frame` 同步兜底
  （background=False → `_rgba_buffer`）把该对象按帧号写入 `_frame_cache`，同尺寸下
  多帧号别名同一缓冲；`upload_frame` 精确命中（1837-1838）与 present-latest 扫描
  （1862-1874）取出上屏。
- 修复：新增 `_own_cache_frame_data`——入缓存前对与 scratch **身份相同（is）**的
  ndarray 做 `copy()` 解别名（身份比较，不做元素级 `==`，避免 ndarray 广播语义）；
  两处 `_frame_cache[...] =` 写入点均接入。planar/VT 条目持有独立数组原样通过。
  缓存条目自此不可变，三重后果一并消除：(a) 邻域/present-latest 上屏邻居帧；
  (b) 短循环导出第二遍输出循环末帧；(c) 渲染线程 flipud 读取期间 worker 复写
  scratch 的撕裂窗口。线程间双缓冲隔离（background 标志）核实保持原状：worker 仅用
  `_bg_rgba_buffer`，渲染线程仅用 `_rgba_buffer`。
- 代价：每个入缓存帧一次 `copy()`（一帧 4K RGBA float32 ≈132MB memcpy）。这是帧数据
  私有化的必要代价，与"按帧分配新缓冲"等价；scratch 复用对写入路径仍省去重复
  清零分配。同步路径本地上传继续用原缓冲（渲染线程独占，安全）。

### AUD-7701 [Critical/bug/M] — FIXED

- 结论：**FIXED**（问题确认存在）
- 根因核实：`frame_img[..., :3] = absorption × alpha`、`frame_img[..., 3] = alpha`
  ——存储的是预乘形式，却返回 `alpha_premultiplied=False`；下游 Merge 对直通输入再
  预乘一次（merge_evaluator `u_a_straight` → shaders `a.rgb *= a.a`），合成结果为
  absorption × alpha²，体积层系统性压暗。
- 修复：保留预乘数据，按证据报告"二选一"中的方案一：`alpha_premultiplied=True` +
  注释。已核对下游链路（merge_evaluator/shaders 的 premultiplied 语义），预乘声明
  即免除二次乘法。
- 测试：真实 npz 体数据 + 纹理追踪 fake GL 走完整 `_do_evaluate`，断言
  (a) `alpha_premultiplied is True`；(b) 上传像素 RGB == alpha（白色吸收色的预乘
  形式，数据与标记一致）。
