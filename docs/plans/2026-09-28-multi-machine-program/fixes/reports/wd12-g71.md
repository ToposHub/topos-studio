## AUD-27006 [Major/bug] has_transparency 输入被静默忽略

**状态：FIXED**

**根因**：`run()` 通篇不引用 `RenderFrameResult.has_transparency`，
`CHECK_TRANSPARENCY` 在 ALL_CHECKS 中却从未运行——宿主传入的透明度信号
既不报错也不产出 finding。

**修复**（quality_gate.py `run()`）：帧检查后新增 transparency 段——只要有
帧结果即把 `CHECK_TRANSPARENCY` 计入 checks_run；`succeeded and
has_transparency` 的帧产出 warning 级 finding（门禁不知道场景是否*有意*
透明底，故不阻断 deliverability，只提示"请确认交付编码是否需要透明通道"），
details 携带帧索引。

## AUD-27010 [Major/bug] accept() 仅拦截 REJECTED，终态可被接受

**状态：FIXED**（按锁定行为收敛为 REJECTED/FAILED 拦截）

**根因**：`accept()` 只挡 `STATUS_REJECTED`，FAILED（生成失败）版本可被
确认为采纳版本；docstring 不变量与实现不符。

**锁定行为**：`tests/ai/test_motion_graphic_b1_proposals.py::
test_revision_log_accept_replaces_previous_accept` 锁定了"接受已被新版本
取代（SUPERSEDED）的旧版本"是显式的产品回退路径，不得破坏。且类不变量
原文是 "terminal revisions cannot transition back **to pending**"，回退接受
到 ACCEPTED 并不违反该不变量。

**修复**（revision.py `accept()`）：守卫改为 `status in (REJECTED, FAILED)`
（终态*结果*版本永不接受，FAILED 亦然），SUPERSEDED 回退接受保留；方法
docstring 显式写明该语义区分。

## AUD-27014 [Major/risk] kill switch 原地篡改冻结的 RolloutPolicy

**状态：FIXED**

**根因**：`activate/deactivate_kill_switch` 用 `object.__setattr__` 改冻结
dataclass，破坏不可变契约且共享 policy 时波及无关控制器；deactivate 无审计。

**修复**（rollout.py）：kill switch 迁移为控制器本地可变状态
`self._kill_switch_active`（RLock 保护，新增 `kill_switch_active` property）；
`may_use_*` 检查 `policy.kill_switch_active or 本地开关`（policy 级配置仍生效）；
deactivate 同样记录 incident（severity=info，details 带 deactivated/reason）。

## AUD-27019 [Major/doc-gap] SetHtmlLayerCommand 直接 apply 后丢弃，撤销状态丢失

**状态：FIXED**

**根因**：`apply_html_layer`/`apply_html_template` 直接 `apply` 后丢弃命令
实例——`_previous_layer/_previous_pages/_previous_elements` 撤销快照随之丢失，
与 "undoable and recorded" 的 docstring 承诺不符（对比 insert_into_timeline/
replace_clip 均有 command_stack 参数）。

**修复**（service.py）：两方法新增 `command_stack: Any = None` 关键字参数；
新增 `_apply_layer_command` 辅助——有栈时走 `command_stack.execute(command,
self.scene)`（命令连同撤销快照入栈，可撤销、有记录），无栈时保持直接 apply
并在 docstring 明示"该路径不记录撤销"。

## AUD-27100 [Major/risk] 全局会话注册表无锁，get_or_create check-then-act 竞态

**状态：FIXED**

**根因**：`TeachingAssistantSessionRegistry` 的 `_sessions` 无锁，两个线程
同时判空会各建会话、后写覆盖前者；`attached_surfaces.add/discard` 也是无锁
跨线程集合修改。

**修复**（session.py）：注册表全部方法（get_or_create/get/close_project）
走 `threading.RLock`；`TeachingAssistantSession` 增加 `_surface_lock` 字段
（repr=False, compare=False），attach/detach 加锁并提供线程安全快照
`attached_surface_ids()`。

## AUD-27103 [Major/bug] upsert 更新分支 status 静默重置 + 具名参数被忽略

**状态：FIXED**

**根因**：更新分支 `status=updates.get("status", status)` 回落到签名默认
`"draft"`（与上一行 note 回落 existing 不一致），`timeline_id/brief_id/
brief_revision` 具名参数在更新分支被完全丢弃。

**修复**（session_store.py `upsert_request`）：status/note 默认值改为
`_UNSET` 哨兵；具名参数与 `**updates` 合并为单一 merged 视图（updates 内
同名字段优先，保持既有重叠语义），创建分支回落文档默认值（draft/""），更新
分支一律回落 `existing.*`（status 不再被静默重置，具名参数生效）。

## AUD-27104 [Major/bug] 磁盘写失败时内存已提交，内存/磁盘分叉无回滚

**状态：FIXED**

**根因**：所有变更路径先改 `self._requests` 再 `_write_locked()`，open/
json.dump/os.replace 抛 OSError 时内存已变更且异常上抛——调用方以为失败、
实际内存已分叉，后续 reload 复活旧记录。

**修复**（session_store.py）：新增 `_commit_or_rollback(previous_state)`——
写盘失败（OSError）时恢复变更前的完整请求映射再重新抛出；upsert/discard/
clear/invalidate_stale_grants/restore 全部改为"捕获变更前快照 → 变更 →
提交或回滚"。异常仍上抛（fail-closed），但内存与磁盘不再分叉。

## AUD-27105 [Major/risk] reload 对外部 JSON 无防御

**状态：FIXED**

**根因**：`MotionGraphicApprovalScope(**scope_data)` 遇未知键抛 TypeError、
`int()/float()` 遇非数值抛 ValueError，`reload()` 无包裹直接炸到宿主，违背
模块 "unknown-payload passthrough" 承诺。

**修复**（session_store.py）：三层防御——(1) `_scope_from_mapping` 只转发
声明的 scope 键；(2) `MotionGraphicSessionSnapshot.from_dict` 逐条记录捕获
(TypeError, ValueError)，坏记录丢弃并记 warning，好记录保留；(3) `reload()`
对快照级解析（如 schema_version 非数值）整体拒绝加载（记 warning、保持
内存现状）。

## AUD-27106 [Major/bug] grant_scope 反序列化不还原类型

**状态：FIXED**

**根因**：写侧 to_dict 输出 list/str，读侧 `**scope_data` 直灌 dataclass，
round-trip 后 asset_ids 变 list、allowed_actions 变纯 str——`diff_from`
（`action.value`）抛 AttributeError、frozen `==` 永不相等。

**修复**（session_store.py `_scope_from_mapping`）：`asset_ids` →
`tuple[str, ...]`；`allowed_actions` 逐项转 `MotionGraphicAction`（非法值丢弃
并 warning）；构造失败返回 None 而非抛异常。round-trip 后 scope 与原对象
`==` 相等、diff_from 可用。

## AUD-27110 [Major/bug] 空报告 all_meet_targets 恒为 True（空真）

**状态：FIXED**

**根因**：`all(空序列)` 空真——采样失败/样本 slo_id 全错/空输入时基准
"全达标"，正是模块要防的 "degradation slips in unnoticed"。

**修复**（slo_benchmark.py）：`all_meet_targets` 在 `summaries` 为空时显式

## AUD-27201 [Major/risk] 默认场景永不注销，跨保存-加载周期无界累积

**状态：FIXED**（累积根因；删除路径保守保留，见下）

**根因**：`__init__` 每次实例化都注册新默认场景；`from_dict` 加载时被序列化
scene_id 覆盖成孤儿；保存时 `scenes()` 全量持久化——每周期净增 N 个孤儿。

**修复**（composite_node.py）：
- `__init__` 记录 `_owned_default_scene`；
- 重写 `from_dict`：`super().from_dict` 恢复 scene_id 后调用
  `_release_owned_default_scene()`，加载/undo-redo 重建不再遗留孤儿（这是
  无界累积的驱动路径）；
- 重写 `set_parameter`：用户把节点重指向已有场景时同样回收未编辑的默认场景；
- `_release_owned_default_scene` 只回收**未被编辑过**（store 中文档与创建时
  逐字段相等）的默认场景——用户在 MG 编辑器改过的场景保留。

**保守决策（节点删除路径不回收）**：时间线 clip 按场景 id 引用场景，而本
Qt-free 节点看不到时间线，删除时无法安全判定"无其他宿主引用"，误删会挂起
clip；证据报告也认可"被 clip 引用的场景不随节点删除是正确的保守行为"。
累积问题已由加载/重指向路径的回收根除。

## AUD-27202 [Major/bug] 宽泛 except Exception 静默吞掉渲染错误

**状态：FIXED**

**根因**：`except Exception: return {}` 无日志——域错误（SVG 帧无效、维度
不匹配、渲染器 bug）与预期失败（Playwright 缺失）一同无声消失。

**修复**（composite_node.py）：收窄为 `except (ImportError, RuntimeError,
ValueError, OSError)`（HtmlRenderError 是 RuntimeError 子类；FrameAdapter
维度/SVG 校验抛 ValueError；资源读取抛 OSError；Playwright 缺失 ImportError），
命中时 `LOGGER.warning(..., exc_info=True)` 记录节点/场景/帧与异常后保持
fail-soft 返回 `{}`；真正意外的异常（如 TypeError）上抛给求值器自身的
warning 兜底——与 prepare() 路径的失败边界一致。

## AUD-27203 [Major/perf] 每帧重建渲染器 prepare/cleanup，无帧级缓存

**状态：FIXED**（帧级缓存；HTML 会话池化见"遗留"）

**根因**：motion_graphic 属 DYNAMIC_SOURCE_NODE_TYPES，求值器每个显示帧完整
执行一次 `_do_evaluate`——每帧 select→prepare→render→cleanup，HTML 场景
每帧一次浏览器建立-截图-关闭、SVG 每帧 CPU 重栅格化。

**修复**（composite_node.py）：新增帧级缓存，键为
`(scene_id, store revision, 帧号, 宽, 高)`（store revision 随每次 register
递增，场景任何变更即失效）；命中时跳过整个 prepare/render/cleanup 循环与
纹理写入。`TextureResult.revision` 语义对齐 base_node 文档"内容变化才递增"
——同帧重复求值不再空转 bump，下游缓存得以生效。

## AUD-27204 [Major/bug] HDR 场景输出 8bit 数据却按声明管线上报

**状态：FIXED**

**根因**：u1 纹理（tonemap 后 8bit 显示域数据）对外声明
`color_pipeline.working_space/bit_depth`（如 acescg/32），下游按其做 HDR/
显示变换会对已 tonemap 数据二次变换。

**修复**（composite_node.py）：仅 GPU effects 桥路径（f2/f4 scratch，接近
声明精度）上报声明管线；u1 直通路径如实上报 `bit_depth=8, color_space="srgb"`
（SVG/HTML 后端实际交付的显示域数据）；声明的管线与 hdr_fallback 降级仍完整
保留在 render_diagnostics 中可观测。SDR 场景两路径数值不变。

## AUD-27301 [Major/bug] resolve 每次未命中缓存即全量 read_bytes 计算 sha256

**状态：FIXED**

**根因**：`hashlib.sha256(path.read_bytes())` 整读 GB 级资产，内存峰值=
文件大小、调用线程阻塞数秒；无 (path, mtime, size) 级缓存。

**修复**（asset_provider.py）：`_file_sha256` 分块流式读取（1 MiB chunk），
按 `(路径, st_mtime_ns, st_size)` 缓存摘要（上限 256 条、FIFO 淘汰）——同
一文件重复 resolve 不再读盘，内容变更（mtime/size 变）自动失效重算。

## AUD-27302 [Major/bug] read_bytes 的 OSError 未处理，单文件 IO 错误击穿 preflight

**状态：FIXED**

**根因**：`is_file()` 判存在后 `read_bytes()` 无保护，权限不足/TOCTOU 删除
沿 resolve → registry.resolve → preflight 一路上抛，preflight（返回值是
问题元组）整体崩溃，违背"可诊断错误而非坏渲染"的模块自述。

**修复**（asset_provider.py）：哈希读取包 OSError → 返回
`license=AssetLicenseStatus.MISSING` 的描述符（与缺文件路径一致，保留
source_uri/metadata），preflight 产出结构化 issue 而非异常；`_path` 的
resolve 亦同防护。
