## 1. AUD-23200 [Major/bug/M] — FIXED

**问题**：`NodeSpecRegistry.register` 注释宣称"保留较新"，实际只做同版本幂等判断，
注册顺序决定最终版本——后注册的 v1.0.0 可覆盖已注册的 v2.0.0。

**修复**（`src/features/ai_workflow/core/node_specs.py`）：
- 新增 `_version_key()`：语义化版本字符串 → 整数元组（`"1.2.3"→(1,2,3)`，
  非法段按 0），元组比较即版本序。
- `register()` 重写：同版本幂等 no-op；新版本更高 → 覆盖（info 日志）；
  不高于已注册版本（降级/乱序）→ **保留较新并 warning 日志**
  （`ignoring node spec downgrade: <id> registered=<v> incoming=<v>`）。

**测试**（`tests/test_node_specs.py::TestRegistryVersioning`，4 例）：幂等、
升级替换、降级拒绝、乱序装配最终版本取最高。

## 2. AUD-23201 [Major/doc-gap/M] — FIXED

**问题**：`register_official_specs` 两个 `except Exception: pass` 捕获范围远超
ImportError，适配器内部 TypeError/AttributeError 等真实缺陷被静默吞掉，且
docstring 承诺的"只记日志"一行日志都没有。

**修复**：改为 `try: import ... except ImportError as exc: _LOG.warning(...)`
`else: register_xxx(registry)` 结构——只豁免包缺失（adapters 可选依赖），
适配器注册函数自身的真实异常照常抛出；确实吞掉的分支记录 warning
（含模块与异常原因），与 docstring 对齐。

## 11. AUD-23404 [Major/bug/M] — FIXED

**问题**：`_current_run_id` run 终态后从不清空——第二次 run 起，panel 已进入
running 但新 run_id 尚未由 run.created 回填的窗口期内点 Cancel，会把取消发往
**已终态的旧 run**（runtime.cancel 不检查终态，无效），`_cancel_pending` 不置位，
取消被静默吞掉。

**修复**（`workflow_run_controller.py`，三层）：
1. `_start_worker` 启动前清空 `_current_run_id`（旧 run 的 final 刷新已在
   worker finished 时完成），窗口期取消必然走 pending 通道。
2. `cancel()` 改用 `_current_run_is_active()`（run_id 非空 + runtime 可见 +
   非终态）判定：非 active（含终态旧 run / 未知 run / 空）→ 置 pending。
3. **竞态收口**：主线程读空 run_id 与置 pending 之间，worker 线程的
   run.created 订阅者可能已完成回填并消费过 pending（当时仍为 False）→
   取消丢失；置位后复查一次，run 已创建则直接 cancel（runtime.cancel 幂等）。
   （此竞态窗口在修复过程中被既有 `tests/ui/test_workflow_run_controller.py::
   test_cancel_marks_remaining_nodes_cancelled` 在 4 文件批次组合下确定性复现，
   pristine HEAD 同组合通过——修复后连续 5 轮通过。）

**测试**（新建 `src/features/ai_workflow/tests/test_workflow_run_controller.py`，
8 例）：active run 直发取消、终态旧 run 转 pending、未知 run_id 转 pending、
空 run_id 转 pending、`_start_worker` 清空旧 run_id。

## 12. AUD-23405 [Major/risk/M] — FIXED

**问题**：`run()`/`_start_worker` 无在跑防护——前一 worker 仍在运行时再次进入，

旧 worker 已结束则放行、拒绝时诊断含 RUN_ALREADY_ACTIVE。
