## 1. `src/shared/export/video_encoder.py`（AUD-33505..33509）

### AUD-33505 — FIXED（原 :2234-2235 → 现 :2355-2360）
`add_audio_stream` 的 `self._audio_stream.options = {'b:a': f'{bitrate}k'}`
改为 `{'b': f'{bitrate}k'}`。`'b:a'` 是 ffmpeg CLI 流指定符语法，经
stream.options → avcodec_open2 被静默忽略（本文件视频侧 `_configure_video_bitrate`
注释已实证同一机制）；AAC 用户指定音频码率此前完全不生效。与视频侧
`:1187/:1228/:1277/:1387/:1429` 的 `"b"` 键用法一致。

### AUD-33506 — FIXED（原 :2339-2347 → 现 close() :2441-2543）
close() 异常路径补齐三件事（对照 open() 失败路径 :991-1001 的既有清理）：
1. **容器 best-effort 显式关闭**：`container_closed` 标志记录 try 内是否已
   close；异常路径对未关闭容器补 `close()`（失败仅 warning，不掩盖原始异常）——
   trailer/句柄释放不再依赖 PyAV dealloc 兜底；
2. **半成品清理**：异常路径 `os.path.exists → os.remove` 删除半成品输出并留
   warning（删除或显式标记二选一，取与 open() 对齐的删除）；导出 outcome 以
   上抛的原始异常统一裁决；
3. finally 复位全部状态（container/stream/audio_stream/_audio_layout_name/
   _is_open），编码器可安全丢弃重开。

### AUD-33507 — FIXED（原 :1914-1918 → 现 :2007-2019）
`_convert_packed_frame` RGB 序（非 bgr 前缀）分支：`is_high_depth=True` 且
`data.shape[-1]==4` 时 `temp_format` 由落入 uint8 `'rgba'` 改为
`'rgba64le'`，与 BGR 分支 :1932-1936 的既有正确处理对齐。修复前实测复现：
4ch uint16 + 'rgba'（PyAV 拒收 dtype）或 4ch 被 rgb48le（3ch 形状）拒收，
`from_ndarray` 抛 `ValueError`——带 alpha 的高位深 RGB 序导出必失败。

### AUD-33508 — FIXED（原 :1706-1719 契约注释 :363-364 → 现 :782-835/:1683-1702/:1762-1830/:2465-2488）
根因修复 + 实施中发现并修掉的两个衍生死锁：

1. **输出侧背压**：`_converted_map` 设容量 `_converted_map_capacity =
   convert_workers`（`__init__` :827-833）。`_convert_worker_multi` 入表前
   `while len(map) >= cap and pts != _next_encode_pts: cond.wait(0.5)`
   （:1784-1803）；`_encode_next_converted` pop 后 `notify_all` 唤醒等待
   空位的 worker（:1821-1822）。config 契约注释 :380-383 更新为真实上界
   （输入 ≤ workers+1 帧；输出 ≤ cap + workers 在手 + next 旁路 1 帧）。
2. **next 帧旁路防死锁（设计必要条件）**：输入队列按 pts 严格 FIFO 派发，
   "map 满且全是非 next 帧"时 next 帧可能仍在 worker 手中——硬容量会使
   消费者等它入表、它等空位。`pts == _next_encode_pts` 的帧不受容量限制。
3. **稳态死锁（实测发现）**：主线程 `queue.put`（队满阻塞）与 worker 等
   map 空位互等——消费者（pop）只在 put 成功后运行。`encode_frame` 的
   put 改为 60s 期限内"尝试入队 / `_encode_next_converted(block=False)`
   弹出"交替（:1683-1702）；弹出释放 map 空位 → worker 入表并继续消费
   队列 → 队列腾位。保活性：全部 worker 阻塞入表时 next 帧必在 map
   （可弹）或已旁路入表（FIFO 论证见代码注释）。
4. **close 排空顺序死锁（实测发现）**：原顺序先 `put(None)` 哨兵再排空——
   worker 可能因输出背压停等、不消费输入队列，满队列上 `put(None)` 永久
   阻塞。多 worker 分支改为先排空至 `_next_encode_pts` 追平 `_last_pts`
   （全部帧按序编码完成，此刻 worker 手中无项、队列必空）再投递哨兵
   （:2465-2488）；排空判空移入 `_convert_cond` 锁内（消除 join 超时后
   无锁读 dict 真值的竞态，原 :2315 问题）。单 worker 分支维持原顺序
   （其转换输出队列无界，不会停等）。
5. **会话废弃清理**：`_convert_aborted` 标志（:814-817）——encode_frame /
   close 异常路径置位并 `notify_all`（:1725-1730/:2520-2524）；worker 的
   容量等待与 `queue.get(timeout=0.5)` 轮询均检查该标志退出（:1766-1804），
   失败路径不残留永久阻塞的转换线程（daemon 之外的显式清理保证）。

两个死锁均以真实 PyAV 64x64 h264 + 3 worker + 慢首帧（0.2s）16 帧脚本
复现（faulthandler 栈定位）后修复，修复后 max(map)==cap==3 无积压。

### AUD-33509 — FIXED（原 :2227-2232 与 :2270-2271 → 现 :2308-2361/:2363-2438）
单一真相 + 契约校验：
1. `add_audio_stream` 推导结果存 `self._audio_layout_name`（`__init__`
   :782-784）；`write_audio_samples` 帧布局直接复用（:2400-2403，兜底读
   回 `stream.layout.name`）——流侧 `'5.1'` / 帧侧 `'6c'` 两套推导失配
   消除。实测验证：'6c' 帧入 '5.1' 流在本 PyAV 构建可触发 encode
   EINVAL（ArgumentError 22），两套推导确为缺陷。
2. ChannelLayout 的 `ValueError`（非标准声道数 3/4/5/7…）显式上抛而非
   回退 mono（:2353-2356 注释）；已知调用方 timeline_export.py 两处均
   try/except 包裹降级为无音频，不中断导出。ImportError 回退改为 PyAV
   朴素命名（mono/stereo/Nc），不再回退 'mono'（多声道流标单声道只会
   制造必然失配）。
3. 帧声道数与流布局 `nb_channels` 不符 → 显式 RuntimeError（:2405-2414）。
4. `samples.dtype != float32` → 显式 ValueError 含修复指引（:2415-2421；
   此前 float64 在 from_ndarray 抛裸 ValueError）。
5. close() 复位 `_audio_layout_name`，不跨会话泄漏（:2541）。

### AUD-33600 — FIXED（原 :332 → 现 :332-363）
`VideoExporter.cleanup()`：
1. **先请求取消**：`self._worker.request_cancel()` 在 quit/wait 之前——
   run() 内导出循环下一帧检查退出，wait 才有机会在 4K 导出（单帧 >3s、
   暂停门 0.25s 轮询）场景下成功；

   `requestInterruption()` + `wait(2000)` 二次等待，仍失败以 **error 级**
   日志显式留痕（QThread 析构 qFatal 风险），绝不静默放行；
3. 保留原外层 try/except（quit/wait 自身异常 warning）。
