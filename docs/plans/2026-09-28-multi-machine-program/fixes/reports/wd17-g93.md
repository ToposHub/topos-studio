## 逐条修复摘要

### AUD-35712 — thumbnail_provider 多处裸 `except:`
- 四处裸 except 全部收窄：写探针/列目录处（原 603/628/640）改为 `except OSError`；RAW 内嵌缩略图提取处（原 724）改为 `except (rawpy.LibRawError, ValueError, TypeError, OSError)` 并加 debug 日志。
- 行为差异：非 OSError 异常（如配置导入的 ImportError、探针 TypeError）不再被误当作"目录不可写"改写缓存路径（新增反例测试 `test_non_oserror_from_probe_is_not_swallowed`）。

### AUD-35713 — `_get_cache_path` 每请求 O(变体数×文件数) 全列扫描
- 快路径：三个尺寸变体按精确名直接 `os.path.isfile` stat 命中，多数请求零目录扫描。
- 慢路径（macOS NFD 兼容）：新增模块级 `_nfc_index_for_dir(dir)`——单次 listdir、每条目只 NFC 规范化一次，构建 `{NFC 名: 实际条目名}` 索引并按目录 `(mtime_ns, size)` 指纹缓存（上限 64 目录 LRU）；目录内容增删自动失效。
- 附带（同为每请求 I/O 且使索引缓存永远失效的根因）：目录已存在时改用 `os.access(dir, os.W_OK)` 判定可写性；仅目录缺失时做一次真实 `.write_test` 写探针（保留 R2-5 只读源目录回退平台缓存目录的语义）。旧实现每次请求都创建/删除探针文件，目录 mtime 恒变。

### AUD-35800 — Timecode `__eq__` 忽略 tc_type 而 `__hash__` 包含
- `__hash__` 改为 `hash((to_frame_number(), fps))`，与 `__eq__` 同源。选该方向而非把 tc_type 加入 `__eq__` 的理由：`__lt__/__le__/__gt__/__ge__/__sub__` 全部仅按帧号比较（对 tc_type 不敏感），tc_type 只影响 `to_string` 分隔符显示；相等语义改类型敏感会与比较运算符互相矛盾。

### AUD-35804 — `Timeline.with_track_updated` 对不存在 track_id 静默无操作
- 缺失 track_id 时抛 `ValueError("Track not found: ...")`，与 `with_clip_added/removed/updated` 的既有 "Track not found" 契约对齐。全仓调用点（edit_controller、nested_sequence、captions、automation_recorder 等）均先经 `get_track_by_id` 或持有有效轨道，无受影响路径。

### AUD-35805 — NaN speed/opacity 通过验证
- 两处 `x < lo or x > hi` 改为 `not (lo <= x <= hi)`：NaN 与任何比较均为 False，旧链式比较放行 NaN；新写法让 NaN/±inf 全部被拒。边界值（0.1/4.0、0.0/1.0）仍接受（既有测试钉死）。

### AUD-35806 — 速度帧映射浮点截断 off-by-one
- 新增模块级 `_speed_floor(value)`：到最近整数的距离 ≤1e-9 时吸附，否则 `math.floor`。修复 0.3 等步长的二进制浮点误差（`3/0.3==9.999…998`、`10*0.3==2.999…996`）。
- 应用到审计点名的全部 5 处同型代码：`effective_duration`（原 135）、`timeline_to_source_frame`（原 173）、`source_to_timeline_frame`（原 212）、`with_speed`（原 244）、`with_trim`（原 279）。
- floor 语义保持：真实小数（如 `(199-100)/2==49.5`）仍截断为 49（既有测试钉死，新增测试覆盖）。

### AUD-35809 — hold 模式"文件消失保留前驱帧"分支不可达
- 根因：`_nearest_before(f)` 返回 `<= f` 的最近帧，对 `slot.frame` 查询恒命中自身，`nearest != slot.frame` 永假。
- 修复：改查 `slot.frame - 1` 取严格前驱，并改为受 `max_consecutive_missing` 约束的有界回退循环（前驱文件同样消失时继续回退，连续空洞超限或无前驱则报错）——与 read_slot 文档的 hold 契约一致，防止用远帧冒充；也消除旧递归实现对超长连续删除序列的 RecursionError 风险。

### AUD-35813 — 预留/未知 pixel_format（≥4）叠 Alpha 绕过校验并被误标 YUV 422
- open() 校验：alpha 分支由 `pixel_format == 3` 收紧为 `pixel_format not in (0, 1, 2)`（pf=3 CFA 互斥、pf≥4 预留/未知均拒绝）。
- `_pixel_format_name` 纵深防御：带 Alpha 且 pf 不在 (0,1,2) 时显式 `KeyError`，删除 `'444' if pf == 1 else '422'` 的静默兜底拼名。合法组合（yuva422/444、gbrap）输出不变。

### AUD-35910 — darwin 分支仅凭平台+PyObjC 导入即报 zero_copy=True
- 新增 `_probe_macos_iosurface()`：真实分配最小 IOSurface ring（64×64、3 平面、1 槽），走 `acquire→map→unmap→fence→release` 全链路后关闭池；任一步失败回退 CPU 上传（reason `iosurface_mapping_unavailable:<详情>`）。零拷贝判定自此由"持有已映射资源的进程内探测"背书，与模块 docstring 契约及 Windows/Linux 分支结构一致。
- 探测只触碰 IOSurface CPU 映射，不涉及 OpenGL/Metal，可在能力检测线程执行。本机（macOS 真机）实测探测链路通过。macos_vt/topos_surface.py 仅被导入，未被修改（属并行代理范围）。

### AUD-36000 — GetImmediateContext vtable 槽位 27（实为 CreateDeferredContext）
- `VTABLE_SLOT_GET_IMMEDIATE_CONTEXT` 27 → 40（SDK d3d11.h ID3D11Device 实序：CreateTexture2D=[5]、CreateDeferredContext=[27]、CheckFormatSupport=[29]、GetFeatureLevel=[37]、GetImmediateContext=[40]；真机探针实测过的 [5]/[37] 与该序一致）。
- 修正两处声称"真机验证覆盖此槽"的错误注释。该常量当前仅导出无生产调用点，改值无行为风险；同步更新钉死旧值的 `tests/media/test_windows_hw_d3d11_device_pool.py::test_vtable_slots`（测试文件非源码白名单，但钉死的正是审计判定的错误值，不改则修复无法落地）。

### AUD-36001 — probe 自建 D3D11Device 全部 return 路径泄漏
- `probe_d3d11_export_capability` 拆出 `_probe_d3d11_export_capability_inner`，外层 `try/finally` 经 `_release_probe_device`（防重复释放、释放失败仅 warning）在**全部** 8 个 return 路径（含 ready=True 成功路径与内层异常路径）释放自建 device+immediate context。
- 调用方注入的 device（`device=` 参数）生命周期不归探测管，不释放（测试钉死）。macOS 上提前 return NOT_WINDOWS，不受影响。

### AUD-36002 — from_native 缺必需键抛 KeyError 逃逸
- Mapping 分支先做必需键检查（`texture_handle/width/height`），缺键抛 `ValueError("native decoder 缺少必需字段: ...")`，被 `decode_next` 的 `except (TypeError, ValueError)` 捕获并转为 `decode_contract:` fallback reason——异常不再逃逸到调用方。

### AUD-36003 — close() 无异常保护且状态清理不在 finally
- close() 先清理 Python 侧状态（`_session/_is_open/_last_native_texture`）再调 `close_decoder`；原生关闭失败仅 warning（会话句柄可能泄漏给原生层），状态机保持一致的"已关闭"，`open()` 首行 `self.close()` 的复用路径不再被残留半开状态污染（测试覆盖 close 失败后立即 open 成功）。

### AUD-36100 — done-callback 异常逃逸泄漏信号量槽 / run() 无界等待
- `_render_done`/`_encode_done` 全body 加边界守卫：已知原生错误仍走精确类型 `(OSError, RuntimeError, TypeError, ValueError)`；其余 `Exception` 统一降级为失败 reason（`*_callback_unexpected:<类型>`），释放尚未交出的 frame/target 资源并强制完成 outcome。守卫带 `outcome.done()` 防重复扣减槽位。BaseException（KeyboardInterrupt 等）不吞。
- `run()` 收割 future 加 60s 超时（模块常量 `_OUTCOME_TIMEOUT_S`）：超时把 outcome 落定为失败（`InvalidStateError` 防竞态）、记 `pipeline_future_timeout` 并继续收割，导出线程不再可能永久阻塞。
- 附加：`_tracked_render/_tracked_encode` 在执行器 `submit` 抛出时回滚 pending 计数。

### AUD-36101 — render"target 非空但带 reason"泄漏 target lease
- 失败分支在 `frame.release()` 前先 `render_result.target.lease.release()`——渲染器已分配 target 后失败时，渲染目标池槽位一并归还（测试断言 target_pool.stats().in_use == 0）。

### AUD-36102 — 遥测缺陷：render_waits 恒 0、encode_waits 实为池超时
- surface 池槽位获取超时改记独立字段 `surface_pool_timeouts`（telemetry dataclass 追加默认 0 字段 + to_dict 键，纯增量）。
- `render_waits`/`encode_waits` 改为真实排队计数：提交时仍有同型任务未完成（pending>0）即计一次等待（单工作线程执行器串行执行，按提交时刻判定才能反映排队）。
