## AUD-21601 [Major/bug] products 与 feature_flags 双轨解析同一环境变量，语义已分叉

**状态：FIXED**

**根因**：`src/products/__init__.py::get_enabled_features()` 自行解析
`TOPOS_PRODUCT_MODE` / `TOPOS_DISABLE_FEATURES` 并维护独立预设表，与运行时
门控 `src/shared/feature_flags.py` 的规则已实际分叉：products 侧对
TOPOS_DISABLE_FEATURES 逐项 `lower()`、把 library 钉死在 ALWAYS_ENABLED、
未知模式回退策略不同——同一环境下产品注册/打包校验与运行时门控可得出
不同结论。

**修复**（products/__init__.py）：按证据报告首选方向收敛为单一解析入口——
`get_enabled_features()` 删除本地环境解析，改为委托
`load_feature_flags()` 并把运行时 flags 投影到产品域六特性
（ALL_FEATURES）。两轨从此按构造一致；分叉语义收敛到运行时权威
（library 可被 TOPOS_DISABLE_FEATURES 禁用、禁用名单不做小写化）。
顶层 `from src.shared.feature_flags import load_feature_flags` 依赖方向
products → shared 合法（shared/__init__ 仅 2 行纯 Python，无 Qt/重依赖）。
`get_current_product()`（topos_project_io.py / verify_product_bundle.py 的
实际调用方）为纯预设表查找、非 flag 解析，保持不动。

**影响面核查**：`src/` 运行时无 get_enabled_features 调用方（仅测试），
`get_current_product().name` 两个调用方不受影响；
`scripts/verify_product_bundle.py --source topos-color` 冒烟 PASS。

## AUD-31901 [Major/perf-opportunity] app_restart 未处理冻结打包（frozen）场景

**状态：FIXED**

**根因**：旧代码无条件 `[sys.executable, abspath(sys.argv[0])]` 重启。
PyInstaller/py2app 冻结形态下 sys.argv[0] 是应用可执行文件本体、
sys.executable 是内嵌解释器——让解释器去"执行"一个 .exe/.app 必然失败，
重启功能整体不可用。

**修复**（app_restart.py）：提取 `_build_restart_command() -> tuple[list[str], str]`
（带完整类型注解）：`getattr(sys, "frozen", False)` 时返回
`[abspath(sys.executable)] + sys.argv[1:]`、cwd 为可执行文件所在目录；
仅源码形态走原有 `[sys.executable, script] + argv[1:]` 拼装
（含相对路径转绝对）。`restart_application()` 行为不变（detached Popen +
退出链），三条调用路径（menu/preferences/welcome/project_manager）无需改动。

## AUD-33700 [Major/perf-opportunity] is_enabled 对未知 feature id 失败开放，与 M0 冻结注释矛盾

**状态：FIXED**

**根因**：`FeatureFlags.is_enabled` 的 `getattr(self, feature_id, True)` 对
任何未注册 id（如拼错的 `media_analysys`）返回 True——安全开关失败开放，
与 161–164 行 "referencing an unknown capability must not surface AI
analysis/generation/MCP without explicit opt-in"（M0 冻结契约）直接矛盾。

**修复**（feature_flags.py）：分层失败策略，兼顾 M0 契约与既有宽松消费方：

1. 新增 `_CAPABILITY_ID_STEMS`（由 AI_CAPABILITY_FLAGS +
   COMMERCIAL_AUTOMATION_FLAGS 逐名取首段词干派生：
   {ai, media, cloud, generation, mcp, agent, auto}）。
2. `is_enabled`：已注册字段返回真实值；未注册 id 若首段词干命中能力域
   → **fail-closed False + logger.warning**；未注册的普通 UI id（如
   host_help_sources 探测的页面首段前缀 "app"/"workspace"）保持宽松 True
   + debug 日志（既有锁定行为 `unknown_feature → True` 不受影响）。

**影响面核查**：全部 `FeatureFlags.is_enabled/is_available` 消费方逐一核对
——module_loader 的 5 个 spec id、main_window/dock_layout/
ai_editing_mixin/teaching_animation/topos_project_io/release_manifest/
host_help_sources:196 均为已注册 id 或普通前缀；唯一传未注册 id 的
`host_help_sources.py:256`（page_id 首段，实际取值 composite/deliver/edit/app）
不在能力域词干内，行为不变。ai_harness 的
`is_enabled("topos.auto_caption")` 是 SkillRegistry 不是 FeatureFlags，
无关联。

## AUD-33701 [Major/bug] 产品模式预设静默覆盖 config 中已显式开启的 AI 能力开关

**状态：FIXED**

**根因**：load_feature_flags 中预设（Step 3）晚于 config（Step 4）应用，
`**_ai_capability_defaults()` 会把用户在 config `features.ai_assistant=true`
显式开启的 AI 能力强制压回 False 且无日志——模块级契约（22–25 行）
承诺的 "explicit config entry" 启用路径在设置 TOPOS_PRODUCT_MODE 的
打包场景下静默失效。

**修复**（feature_flags.py）：Step 4 记录 `explicit_config_keys`；Step 3
应用预设时，`key ∈ AI_CAPABILITY_FLAGS 且 config 显式设置且与预设值不同`
→ 保留 config 值并 `logger.info`，不再静默覆盖。其余优先级完全不变：
常规 flag 仍是 preset > config（锁定测试
test_preset_still_overrides_config_for_regular_flags 验证）；
TOPOS_FEATURE_* env var（Step 1）与 TOPOS_DISABLE_FEATURES（Step 2）
仍高于一切。docstring 优先级清单同步补注该豁免。

## AUD-33703 [Major/bug] _resolve_in_dir 未做可执行权限检查，不可执行的 bin/ffmpeg 遮蔽 PATH

**状态：FIXED**

**根因**：docstring 声称"带可执行权限检查"，实现只有 `is_file()`。macOS/
Linux 下 bin/ffmpeg 存在但无执行位（下载残缺、权限剥离、Gatekeeper 隔离）
时，定位器返回坏路径并写入永久缓存，后续子进程 PermissionError——PATH 上
明明有可用 ffmpeg 却因优先命中坏文件而永不回退（which 仅在 result 为
None 时才走）。

**修复**（ffmpeg_locator.py）：`_resolve_in_dir` 在 `is_file()` 之外增加
`os.access(path, os.X_OK)`（`sys.platform != "win32"` 时；Windows 无执行位
概念跳过，与证据建议一致），不满足则 debug 记录并返回 None——候选链继续
遍历，最终落到 PATH 兜底。docstring 与实现一致化。缓存语义不变（仍只在
终态结果上缓存）。
