## 1. AUD-22500 [Major/test-gap/M] — FIXED

**问题**：`test_safety_blocked_recorded`（test_generation_adapter.py:238）从未注入
blocked 候选，唯一断言覆盖除 cancelled 外全部终态（恒真）；generation_adapter.py:350-355
的 SAFETY_BLOCKED 分支零守护。

**核实**：真实链路上 service 门禁
（media_generation_service.py:277-284，`CONTENT_SAFETY_BLOCKED` → `job.fail`）会把
provider 返回的 blocked 候选拒之箱外（早于 `add_candidates`:316），所以审计建议的
"注册返回 blocked 候选的 stub provider"走真实 service 时到不了 adapter 的
SAFETY_BLOCKED 分支——该分支是对"blocked 候选已入箱"情形的二次防线。

**修复**（test_generation_adapter.py，`TestSafetyDiagnostics` 重写为两条）：

1. `test_safety_blocked_candidate_records_diagnostic`：构造
   `safety=ContentSafetyResult(passed=False)` 的 `GeneratedAsset` 直接入
   `svc.generation_bin`（request_id 绑 invocation_id），走公开
   `ad.invoke(inv)` → 断言 `rec.diagnostics` 含 `SAFETY_BLOCKED` 且
   `asset_id` 精确匹配、无 approval/commit/apply 事件（不进 timeline）。
2. `test_provider_blocked_candidate_rejected_before_bin`：注册返回 blocked 候选的
   `_BlockedStubProvider`（`is_demo=True` 走同步路径）→ 端到端断言 run FAILED、
   `rec.artifacts == ()`、bin 零候选、`TAEP_QUALITY_GATE_FAILED` +
   "content safety" 诊断可见、无 timeline 写事件。
