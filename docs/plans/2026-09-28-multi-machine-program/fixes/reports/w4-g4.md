## AUD-31200 [Critical/bug] QTimer 未导入 → 可选模块加载失败时启动即 FATAL

**状态：FIXED**

**根因**：`src/main.py:291` 的 module-failure 状态栏提示调用 `QTimer.singleShot`，但 `src/main.py:104` 的 QtCore 导入只有 `Qt`，`QTimer` 全文件无任何导入。`module_failures` 非空时（flag 启用但可选依赖缺失，`register_builtin_modules` 真实可达路径）抛 `NameError`，被顶层 `except Exception` 捕获后 `sys.exit(1)`——刚显示窗口即退出。

**修复**：`src/main.py:107` 改为 `from PyQt6.QtCore import Qt, QTimer`，附注释说明该导入是 module-failure 通知路径的硬依赖（AUD-31200）。

**验证**：`test_main_module_exposes_qtimer`（断言 `src.main.QTimer is PyQt6.QtCore.QTimer`）+ `test_qtimer_call_site_resolves`（AST 断言 ImportFrom PyQt6.QtCore 绑定 QTimer，且 `QTimer.singleShot` 调用点仍存在）。

## AUD-31500 [Critical/risk] 取消路径 QThread.terminate() 强杀 ONNX 推理线程

**状态：FIXED**

**根因**：`AIPluginEngine.process_plugin`（原 455-460）与 `cancel`（原 487-492）对运行中的 worker 直接 `terminate() + wait()`：terminate 可在线程持有原生锁/`session.run()` 中途杀死线程（ONNX Runtime 原生状态损坏、共享 `_session_cache` 中的 session 被后续推理继承损坏状态）；`wait()` 在 UI 调用路径上无限阻塞冻结界面。且分块推理循环（`_process_tiled`/`_process_upscale`）无任何取消检查点，唯一取消手段就是强杀。

**修复**（`src/shared/ai_models/ai_plugin_engine.py`）——协作取消，terminate 彻底移除（进程退出路径本就不经过本类，无需保留最后手段分支）：

1. `AIPluginWorker` 增加互斥保护的 `_abort` 标志 + `request_cancel()` / `_is_cancelled()` / `_check_cancelled()`（镜像 `ai_mask_engine.AIMaskWorker` 的既有协作取消模式，QMutex 保护）。
2. 新增私有异常 `_InferenceCancelled`；新增 `cancelled(layer_id, instance_id)` 信号——取消不再混入 `finished`（陈旧结果）或 `error`（伪故障）。
3. 取消检查点：
   - `_load_session` 的 provider 循环每次迭代前；
   - `_process` 会话加载完成后（原生模型加载不可中断，已文档化：取消在加载完成后的首个检查点生效，最坏一个加载超时时长）；
   - `_process_tiled` / `_process_upscale` 每个 tile 迭代顶部（推理按 tile 分片，最坏不可中断窗口 = 一个 tile；单 tile 模型 = 一次全图推理，已在类 docstring 与 `cancel()` docstring 文档化）。
4. `run()`：`_InferenceCancelled` 或"异常与取消竞争"一律走 `cancelled` 信号并抑制 `finished`/`error`；取消路径提前释放 `self.image`（4K float32 约 100MB 级输入缓冲）。
5. 引擎侧重入/取消语义：
   - `process_plugin` 重入时对旧 worker 仅 `request_cancel()`，不 terminate、不阻塞 wait；旧 worker 引用移入新增的 `_retiring_workers`（**zombie 模式**：保引用等待自然结束，避免运行中的 QThread 被销毁），新 worker 立即启动。
   - `cancel()` 立即返回（无 `wait()`），由 worker 的 `cancelled` 信号回调清理登记。
   - `_on_worker_finished/_error/_cancelled` 经 `sender()` 做**身份校验**后再清理 `_workers` 条目——防止被替换的陈旧 worker 完成时误删新 worker 的登记（原代码无条件 pop 的潜伏缺陷）。
   - `_sweep_retiring_workers()` 兜底清扫（queued 信号早于 `run()` 返回送达的极端窗口下不提前丢弃运行中线程的引用）。

**验证**：`test_ai_plugin_engine_has_no_terminate_calls`（AST 断言全模块无 `.terminate(` 调用结点）、`test_worker_has_cancel_api`、`test_tiled_loop_checks_cancel_each_tile` / `test_upscale_loop_checks_cancel_each_tile`（首个 tile 后取消 → 第二个 tile 检查点抛出，`session.run` 恰好调用 1 次）、`test_precancelled_worker_runs_no_inference`、`test_cancelled_run_emits_cancelled_only`（cancelled 发射、finished/error 抑制、image 释放）、`test_late_cancel_suppresses_finished`、`test_error_run_emits_error_only`、`test_successful_run_emits_finished`、`test_reentry_requests_cancel_and_keeps_reference`（重入协作取消 + 保引用 + 陈旧 worker 不误删新登记）、`test_cancel_requests_cooperative_cancel_and_cleans_up`、`test_cancel_returns_immediately_and_cleans_bookkeeping`（真实 QThread + 事件循环端到端：`cancel()` < 1s 返回、书记经 cancelled 信号清理、线程自然结束）。

## AUD-32500 [Critical/bug] to_ocio_name 未映射组合静默回退 "lin"，OCIO 引擎整体跳过 ODT 编码

**状态：FIXED**

**根因**：`src/shared/color/color_space_descriptor.py:89` 的 `_OCIO_NAME_MAP.get((prim, transfer), OCIO_LINEAR_NAME)` 把映射 miss（如偏好页可选的 `(bt2020, bt709)`、`(smpte432, smpte2084)` 等）静默折叠为 "lin"；LINEAR 分支（81-86）对非 BT709/AP1 primaries 同样折叠进 "lin"。后果：`OCIOColorProvider.transform` 中 `src_ocio == dst_ocio` → 转换整体跳过，已编码信号被 range 压缩后直接当线性输出，全程无警告。

**修复**（`src/shared/color/color_space_descriptor.py`）：

1. 新增显式回退表 `_OCIO_FALLBACK_NAME_MAP`（11 行，覆盖偏好页全部可选组合：BT2020×SDR 曲线 → srgb/rec709；BT709×PQ/HLG → bt2020_pq/bt2020_hlg；P3_DCI/P3_DISPLAY 各组合 → display_p3/p3_pq/bt2020_hlg）。选表原则：**保留 transfer 曲线**（把已编码信号当线性是更严重的错误），色域近似并在日志中报告。表内回退目标均已核对存在于 `ocio/minimal.ocio`（lin/acescg/srgb/rec709/bt2020_pq/p3_pq/bt2020_hlg/display_p3）。
2. 两表之外的组合（如 TRAW_LOG0、未知 transfer）：启发式保守映射（PQ/ST2084 → bt2020_pq、HLG → bt2020_hlg、其余 → srgb），同样告警，**非 LINEAR transfer 永不返回 "lin"**。
3. LINEAR 分支：非 BT709/AP1 primaries 仍映射 "lin"（bundled config 无其他 gamut 的线性空间，transfer 本就正确）但**显式告警** gamut 矩阵丢失；LINEAR_SCENE（BT709）与 ACESCG_SCENE 保持静默原映射。
4. 告警经 `_warn_ocio_fallback` **每组合每进程只记一次**（`_OCIO_WARNED_COMBOS` set；`to_ocio_name` 位于渲染路径，防刷屏；set.add GIL 原子，并发渲染线程最坏重复一条）。
5. 同步更新 `to_ocio_name` docstring（原文"Unknown/unsupported combinations fall back to the linear working space"已不再成立）。

**验证**：`test_exact_mappings_unchanged`（8 个既有精确映射不变）、`test_ui_selectable_combos_never_map_to_lin`（available_primaries × available_transfers 全遍历：非 LINEAR 组合永不返回 "lin"，且目标恒为 bundled config 八个真实空间之一）、`test_fallback_table_values`、`test_unmapped_combo_warns_once_with_details`（两次调用仅 1 条 WARNING，消息含 primaries/transfer/回退目标）、`test_nonlinear_transfer_never_silent_lin_for_unknown_combo`、`test_linear_non_bt709_primaries_warn_about_gamut_loss`、`test_canonical_linear_scene_stays_silent`。邻接既有测试全部通过（见下），无测试锁定旧的静默 lin 行为（`grep tests/ == "lin"` 仅命中 LINEAR_SCENE 本身）。

**关联影响（正向）**：`composite_viewport.py` 的 ODT LUT 烘焙守卫（`dst_name == OCIO_LINEAR_NAME and transfer != LINEAR` → 退 builtin）此前把这类组合全部踢回 builtin；修复后这些组合解析为真实编码空间，可走 OCIO LUT 路径。

## AUD-32601 [Critical/bug] ConfigManager.get 不支持 default 参数，两参调用抛 TypeError 被吞

**状态：FIXED**

**根因**：`src/shared/config/config_manager.py:647-648` 的 `def get(self, key): return self.config.get(key)`，而仓库内多处按 dict 语义两参调用：`page_controller.py:915-916`（HDR 预览 tonemap/target_peak，两参调用在外层 except 中止整个 `_apply_composite_preview_color_space`）、`color_space_descriptor.py:354`（`_cfg` 内 except 吞掉 → 偏好静默失效）、`color_transform_provider.py:795-796`（色彩引擎选择/OCIO 路径）、`color_manager.py:450`（未包 try，直接上抛）、`detachable_panel_host.py:228`。

**修复**：签名改为 `def get(self, key: str, default=None): return self.config.get(key, default)`，附 docstring 说明 dict.get 语义与受影响调用面；顺带给 `set` 的 `key`/`auto_save` 参数补类型注解（.clinerules：新代码带类型注解）。

**吞点复核（grep 全库）**：两参调用点 `page_controller.py:915-916`、`detachable_panel_host.py:228`、`color_transform_provider.py:795-796`、`color_space_descriptor.py:354`、`color_manager.py:450` 全部落在本修复覆盖范围内；`config_manager.py` 文件内部的 `loaded_config.get(...)` / `self.get('backend')` 等均为 dict 自身或单参调用，不受影响。修复后 `composite_viewport.py:9188` 专为此缺陷包的 `_Cfg` 适配层不再必要（未动，非白名单文件，留待后续清理批次）。

**验证**：`test_missing_key_without_default_returns_none`、`test_missing_key_with_default_returns_default`、`test_existing_key_ignores_default`、`test_real_call_site_patterns_no_longer_raise`（逐字复现 5 处被审查点位的两参调用模式）、`test_descriptor_from_config_with_real_manager`（真实 ConfigManager 注入偏好 → `descriptor_from_config` 解析出 DISPLAY_P3_SRGB，证明原先被吞的偏好路径现在生效）。
