## 1. AUD-18500 [Critical/bug/M] — FIXED

**问题**：`_prepare_layer_texture` 中 deep-u16 效果桥代码块（原 1634–1641 行，
缩进 12）脱出 `if deep_u16:` 块（该块体缩进 16）。由于 deep 分支所有路径
均提前 return，该块实际只在 `deep_u16=False` 时执行，产生两条症状：
(A) deep 导出 + 无 grade + 效果链：1617 行提前 return 槽 0，效果链被静默
丢弃；(B) 8-bit 导出 + planar 源 + 效果链：对从未分配的
`self._tex_mid_u16[0]`（恒为 None）执行 deep 桥，`None.use(0)` 的
AttributeError 被 `_apply_effect_chain_deep_u16` 内部 `except` 吞掉 →
返回 None → 整帧回落 CPU，1668 行的 f1 效果链路径对 planar 源不可达。

**证据核实**：逐行核对缩进（`if deep_u16:` 12 空格、块体 16 空格、
1634–1641 为 12 空格）；注释"无 grade：输入在槽 0，桥输出写槽 1
（避免读写同纹理）"证实该块本应位于 deep 分支 no-grade 路径；
`_ensure_u16_fbo_pair` 仅在 deep 分支调用，故 8-bit 导出下
`_tex_mid_u16[0]` 恒为 None。问题在当前代码存在。

**修复**（`src/features/edit/core/timeline_gpu_export_renderer.py`，
`_prepare_layer_texture`）：
1. no-grade 分支不再无条件提前 return：无 grade 且无效果链才直接交付
   槽 0；带效果链则调用 `_apply_effect_chain_deep_u16(_tex_mid_u16[0],
   ..., out_slot=1)`（输入槽 0、桥输出槽 1，与 grade 路径的槽 1→槽 0
   交替一致，不读写同一纹理，符合无反馈回路约束）。
2. 删除脱出块的原文（deep_tex_u16 7 行），使 8-bit planar 源回落到
   `_prog_yuv` → `_prog_grade` → `_apply_effect_chain`（f1）既有路径。

四条路径语义核对（均无变化/恢复预期行为）：
- deep + grade + 无链：return 槽 1（不变）；
- deep + grade + 链：槽 1 → 桥 → 槽 0（不变）；
- deep + 无 grade + 无链：return 槽 0（不变）；
- deep + 无 grade + 链：槽 0 → 桥 → 槽 1（修复恢复；原被丢弃）；
- 非 deep planar + 链：走 f1 效果链（修复恢复；原整帧 None）。

另同步修正模块头注释中已过时的"deep-u16 链一律回落 CPU"表述
（审查报告指明 T-P1-21 已放开 deep 链，该注释与代码矛盾）。

**测试证据**（`tests/edit/test_fix_renderers_aud3.py`，真实 GL，headless
自动 skip；本机 GL 可用已实跑）：
- `test_gpu_u16_planar_no_grade_effect_chain_applies_effects`：
  422P10 planar 源 + 高斯 blur + `output_u16=True` + 无 grade → 非 None、
  dtype uint16、与无链渲染有 >2% 像素差异（效果真实生效）。
- `test_gpu_u8_planar_effect_chain_uses_f1_path`：同源 + blur +
  `output_u16=False` → 非 None、dtype uint8、效果生效。
- 故障注入：临时还原旧结构后两测试均失败（u8 复现"整帧 None"、
  u16 复现"效果链丢弃"），恢复修复后通过。

## 2. AUD-18600 [Critical/bug/M] — FIXED

**问题**：`render_layer_stack` 把整帧所有 dispatch 编码进同一 command
buffer，循环结束才 `ctx.finish()` 提交；`dispatch` 只编码不提交
（context.py:401-420），`write_buffer` 是对 Shared 存储的立即 CPU memcpy
（context.py:260-296）。一帧含 ≥2 个转场时，第 2+ 个转场对同名
`"stack_wipe_params"` / `"stack_wipe_mask_params"` / `"stack_wipe_mask"`
的 write_buffer 发生在整帧提交之前，GPU 执行时前面的转场读到被复写的
参数/掩码（opacity/progress/transition_mode 串台）。

**证据核实**：dispatch/finish/write_buffer 语义已在
`src/shared/gpu/metal/context.py` 逐一复核属实；调用方
`timeline_export.py:7750` 在遍历 sorted_layers 时可对一帧内多条转场各
append 一个 `GpuWipeElement`，路径可达。GPU 侧同名私有缓冲
（stack_wipe_left/right、stack_wipe_mask_gpu）因单 command buffer 内
encoder 顺序执行而安全，无需改动。问题在当前代码存在。

**修复**（`src/features/edit/core/timeline_metal_export_renderer.py`，
render_layer_stack wipe 分支）：采用"每个转场独立缓冲"方案——新增
`wipe_prefix = f"stack_layer_{layer_index}_"`，三处 CPU 上传改为
`wipe_prefix + "wipe_params"` / `"wipe_mask_params"` / `"wipe_mask"`
（每个 wipe 是 layer_plan 的独立条目，layer_index 天然唯一）。键挂在
既有 `stack_layer_{i}_` 命名域内，自动纳入 4245 行的按索引剪枝逻辑
（plan 缩短时释放），且与层路径的 `prefix + "source_params"` 等同域
不冲突（wipe/layer 条目索引互斥、子名不同）。

**测试证据**（`tests/edit/test_fix_renderers_aud3.py`，录制型 Fake
Metal context——dispatch 只编码、finish 才提交、write_buffer 立即
memcpy，镜像真实时序）：
- `test_metal_two_wipes_use_distinct_param_and_mask_buffers`（CPU 掩码
  路径）：两个转场的 `timeline_wipe_composite` dispatch 在 slot 5 绑定
  的参数缓冲对象互不相同；整帧提交时刻（finish 后）两块缓冲的
  control[0] 仍分别为 0.11/0.77（各自正确）；slot 3 掩码缓冲同样独立；
  旧同名全局键不再存在。
- `test_metal_two_wipes_use_distinct_procedural_mask_param_buffers`
  （mask_spec 路径）：两个 `timeline_transition_mask` dispatch 的参数
  缓冲独立，提交时刻 progress 仍分别为 0.25/0.75。
- 故障注入：临时还原三个同名键后，两测试均在"同一对象"断言处失败
  （`first is not second`），恢复修复后通过。

## 3. AUD-18801 [Critical/bug/M] — FIXED

**问题**：`slide_clip` 逐个 `with_clip_updated` 应用三片段更新，第一步
（slid_clip 移到新位置）时前/后邻居尚未调整，`EditTrack.with_clip_updated`
（timeline_v2.py:2442-2446）对中间态即抛
`ValueError("Updated clip overlaps ...")`。紧邻布局（slide 的典型场景）
下任何非零 delta 都失败，Slide 功能不可用。

**证据核实**：本机复现（A[0,100] B[100,200] C[200,300]）：
slide +30 → `ValueError: Updated clip overlaps with C`；slide -30 →
`... overlaps with A`。与审查仿真一致。问题在当前代码存在。

**修复**（`src/features/edit/core/timeline_ops.py:2138-2158`）：采用
"最终态校验"方案（与同文件 ripple_trim_clip_left/right 的既有修复同构）：
三个替换片段收集进 `replacements` 字典，一次原子
`track._rebuild(clips=new_clips)` 重建，不再经过中间态校验。最终态无
重叠的安全性由既有校验保证：prev 末缘 == slid 新起点、next 新起点 ==
slid 新末缘（duration>0 校验在 2056/2097 行，恒相邻不重叠），与其他
片段的重叠由函数前部的显式检查拒绝，起点 <0 由 2011 行拒绝。顺序
不变性成立（slid 始终保持在 prev 起点之后、next 末缘之前），元组有序
不变量保持。

**测试证据**（`tests/edit/test_fix_renderers_aud3.py`，纯函数）：
- `test_slide_adjacent_positive_delta_returns_final_state`（+30）与
  `test_slide_adjacent_negative_delta_returns_final_state`（-30）：
  断言精确最终布局（A/B/C 的 timeline 与 source 四元组）且无重叠。
- `test_slide_adjacent_matrix_all_deltas_succeed[-60..99]`（6 参数）：
  全部成功、邻接关系保持、总跨度守恒。
- `test_slide_gapped_neighbors_both_directions`：带间隙布局双向 slide。
- `test_slide_invalid_delta_raises_typed_error`：越界 delta（+150/-200）
  仍按契约抛 TimelineOperationError。
- 故障注入：临时还原逐个 with_clip_updated 后，8 个 slide 断言失败
  （复现裸 ValueError），恢复修复后通过。
