## 1. AUD-12602 [Major/bug] import 二次 `ET.parse` 与 `int()` 宽度转换无异常防护 — **FIXED**

### 根因
`import_to_canonical` 在 `inspect` 之后再次裸调 `ET.parse`（TOCTOU 窗口：inspect 后文件被替换/删除/写坏 → ParseError/OSError 直达 Qt 槽）；`width = int(fmt_el.get(...))` 对外部脏值（如 `"1920.0"`）抛未捕获 ValueError。生产调用点 file_controller 导入路径无 try/except。

### 修复（fcpxml_adapter.py）
- 新增 `_parse_fcpxml(source) -> ET.Element`（见第 6 条），import 的二次解析改走该入口，并包 `except (ET.ParseError, FileNotFoundError, OSError, ValueError)` → 返回带 severity=error 诊断（`TAEP_INTERCHANGE_LOSSY`）的空 `ImportResult`，与 inspect 同风格降级。
- 新增 `_parse_int_attr(element, name, default, entries, diagnostics) -> int`：整型属性解析失败/非正 → 回退默认值 + warning 诊断 + CONVERTED 条目；width/height 接入。
- import 返回的 `InterchangeReport` 此前丢弃 inspect 诊断（只透传 entries），现 entries 与 diagnostics 均透传。

### 测试证据
test_fix_wd8g45_aud.py::test_aud_12602_invalid_width_falls_back_with_report、::test_aud_12602_second_parse_failure_returns_error_report（monkeypatch 状态化 `_parse_fcpxml` 模拟第二次解析失败，断言不抛异常、返回错误报告）。

## 2. AUD-12603 [Major/bug] marker/transition/字幕导入未实现且无 DROPPED 条目；多 sequence 静默丢弃 — **FIXED**

### 根因
spine 遍历只认 `asset-clip` 与 `gap`，模块头声明"必须支持"的 marker/cross dissolve/基础字幕被静默跳过；`break` 只取第一个 sequence，其余全丢；两者均无报告条目，违反 TAEP §9.4。

### 修复（fcpxml_adapter.py import）
- **marker**：新增 `_iter_marker_frames(clip_el, clip_start, fps)`，收集 clip（asset-clip/gap）直接子级 `<marker>`（clip 相对时间解释 `start`，与导出侧写入方式一致）；asset-clip 上的 → `TimelineMarker(clip_id=..., track_id=...)`，gap 上的 → 时间线级 marker（clip_id=None）。

- **基础字幕**：`<title>` 提取 `itertext()` 可映射文本 + offset/duration → `SubtitleClip` 落 s1 字幕轨（CONVERTED 条目：仅文本/时长，样式不保证）；空文本或与其他字幕区间重叠 → DROPPED。
- **未知 spine 子元素**：按 tag 计数，逐类输出 DROPPED 条目（如 audition/multicamClip）。
- **多 sequence**：检测到 >1 个 `<sequence>` 时输出 DROPPED 条目（含总数与被丢弃 sequence 名称列表）。

### 测试证据
::test_aud_12603_imports_markers_title_and_cross_dissolve（marker 帧值/归属、transition 双邻 clip_id、字幕文本与 48 帧时长）；::test_aud_12603_unsupported_elements_and_extra_sequences_reported。

## 15. AUD-12800 [Major/risk] 取消/审批竞态下状态转换异常逃逸 execute() — **FIXED**

### 根因
`request_approval` 桥接可长时间阻塞；期间 UI `request_cancel` 已把 run 置终态 CANCELLED，桥返回后 `grant_approval` 抛 `RunNotTransitionableError`；`execute()` 主循环与调用方 chat_run_driver 均无顶层防护 → worker 线程收到未处理异常，AgentTaskResult 契约（应返回 CANCELLED）被破坏。`begin/finish_verification` 存在同型 TOCTOU。

### 修复（agent_task_executor.py）

- **verify 前置检查**：成功/失败两条路径在 `begin_verification`/`finish_verification` 前增加 `is_run_active` 检查（summarize LLM 调用期间的取消窗口），残余窗口由顶层防护覆盖。

## 16. AUD-12901 [Major/risk] shutdown() 无锁清空 executor 且 cancel_futures 丢弃在途 work — **FIXED**

### 根因
① `self._executor = None` 不持锁，与 `_run_work` 读-用序列竞争 → shutdown 后 submit 抛未捕获 RuntimeError（沿 `_try_dispatch`/`notify_finished`/`set_playback_active` 传播到 UI/worker 线程）；② `cancel_futures=True` 丢弃已出队未执行的 future，对应 job 永久 RUNNING，registry active 计数与 is_idle 永不归位。

### 修复（analysis_scheduler.py）
- `shutdown()`：executor 交换移入 `self._lock`；锁内将在途（`_active`）仍活跃 job 统一 `fail("SCHEDULER_SHUTDOWN", ...)`；pending 队列同步终结（QUEUED → request_cancel+complete → CANCELLED；其余活跃 → FAILED）并锁外触发 pending 项 `on_cancel`（与 cancel_all 语义一致；active 项不触发，notify_finished 幂等兜底）；`executor.shutdown` 本体在锁外调用（wait=False 立即返回）。
- `_run_work()`：executor 在锁内读取到局部变量；`executor.submit` 抛 RuntimeError（并发 shutdown）→ **同步降级执行** `_run_work_sync`，保证 job 有终结状态而非异常外抛；executor 为 None 时维持既有同步语义（shutdown 后 submit 安全）。

### 测试证据
::test_aud_12901_shutdown_terminates_jobs_and_post_shutdown_submit_is_safe（异步池 2 个在途 + 1 个 pending：shutdown 后在途 FAILED/SCHEDULER_SHUTDOWN、pending CANCELLED 且 on_cancel 触发、is_idle 真；shutdown 后 submit 同步执行完成，无 RuntimeError）。
