## 设计决策与残留说明

- **AUD-12903 与 R2 既有测试**：修复使 work 正常 `notify_finished` 后，同步 scheduler 下前两个 asset 完成即释放容量、第三个立即出队——`tests/app/test_ai_editing_composition_root_r1.py` 的两个 R2 测试原先**依赖容量泄漏**制造 pending（"ANALYSIS_LOCAL 上限 2，第三个进 pending"），按锁定旧行为协议适配：改用 `sched.set_playback_active(True)` 门控制造 pending 队列（播放期间分析 lane 不出队），断言与契约（pending 取消 → on_cancel 回写 → request 迁移出 RUNNING）完全不变。这是本批唯一的既有测试改动，共 2 个用例。
- **AUD-12905 的锁序**：`counters_lock`（计数/finalize 判定）与 `_state_lock`（request 字典）单向依赖（counters_lock 内绝不取 state_lock；finalize 在释放 counters_lock 后才取 state_lock），无成环死锁面；`on_request_done`/`on_asset_done` 宿主回调一律锁外调用且异常隔离（warning 留痕）。
- **AUD-12906 的成本口径**：`cost_units` 沿用 `JobRegistry.metrics` 的同一 result manifest 约定；当前内置 provider 不上报成本时累计恒 0、检查点不触发（默认 `AnalysisBudget()` 全 None 时三处检查点全部 no-op，既有测试零行为变化）。`max_cost_units=0` 语义为"不允许任何成本"（首个检查点即拦）。
- **AUD-12909 的方向语义**：只收紧"签发侧绑定、expected 缺省"这一绕过方向；反方向（签发侧 None、expected 携带值）保持放行——这是 `test_approval_service.py::test_scope_diff_hash_none_in_grant_is_unconstrained` 锁定的旧 grant 向后兼容行为，且该方向不存在越权面（grant 本就未绑定该字段）。
- **AUD-13020 的合并策略**：采用审计建议的"写前重读合并"而非 fcntl 文件锁（跨平台、无新依赖）；合并只吸收未知 session_id、冲突以本实例为准（本实例刚执行过用户操作，数据较新）。合并仅在写路径发生，`list_sessions` 仍只展示当前工程目录（既有 project-scope 语义不变）。
- **AUD-13103 的向后兼容**：`operation_summaries` 仅在双侧都存在时比较——预览/提交任一侧为旧式编译结果（无该属性）时不强行比较，`plan_id`/`operation_count` 的原比较条件同步统一为"双侧都可用才比"（原实现双侧齐全时不等才 False，语义等价，仅单侧缺失时从"跳过"变为显式 continue，行为不变）。
