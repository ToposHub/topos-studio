## 逐条明细

### AUD-29704 [Major/risk] tags/schema_version 类型错误逃逸 PresetError，预设扫描崩溃 — FIXED

- `PresetManifest.from_dict` 的两处裸转换改为显式归类：`tuple(tags)`（非可迭代 tags：int/float/None → TypeError）与 `int(schema_version)`（"abc"/None/list → ValueError/TypeError）均捕获后 `raise PresetError(...) from None`。单个裸字符串 tags 归一为一个标签（`("intro",)`）而非按字符拆分。
- `__post_init__` 的 tags 规范化推导式同样加 (TypeError, ValueError) → PresetError 防线，直接构造 `PresetManifest(tags=5)` 也不再逃逸。
- 扫描层验证：`MgPresetLibrary` 对含 `tags: 5` 的损坏 preset.json 只跳过该条并记录 `library.errors`，同根下的正常预设照常注册（测试 `test_scan_survives_corrupted_manifest_and_degrades_single_preset`）。

### AUD-29705 [Major/bug] preview 字段无校验，路径遍历/绝对路径可把 GIF 写到库外 — FIXED

- 新增 `normalize_preview_path()` 并在 `__post_init__` 中执行：拒绝空/空白、反斜杠分隔符、POSIX 绝对路径、Windows 绝对/UNC/盘符相对路径（`PurePosixPath.is_absolute()` + `PureWindowsPath.is_absolute()`/`.drive`）、以及任何 `..` 组件（`PurePosixPath.parts` 检查）。manifest 自身不知道所在文件夹，但以上全部拒绝后，所有消费点 `folder / manifest.preview`（library.py:65 读、:261 写、:354 导入大小检查）在构造层即保证锚定于预设文件夹内——is_relative_to 语义的无基等价表达。
- 库内相对子路径（如 `previews/nested.gif`）与默认 `preview.gif` 照常通过；越界值抛 PresetError，由扫描器的单条降级路径吸收（与 AUD-29704 同一防线）。
- 全部 15 个捆绑预设为 build.py 代码预设（默认 preview 名），扫描无回归。

### AUD-29708 [Major/risk] 全尺寸 CPU 渲染 + GIF 编码为同步 API，UI 线程直调可冻结数秒 — FIXED

- preview.py 新增 `PresetGifPreviewJob(QThread)`：`run()` 在工作线程调用既有同步核心 `render_preset_gif`（场景在构造期快照，渲染只读），结果经 `succeeded(object: Path)` / `failed(str)` 队列信号回 UI 线程；任何异常以字符串浮出而非吞掉。模式与库内既有 worker（`agent_v2_chat_worker.AgentV2ChatWorker`、面板 `_PreviewRenderJob`）一致；调用方持引用、终态信号里清引用（docstring 已注明 GC 中的运行线程会 abort 的陷阱）。
- 端到端测试：`start()` 后真实 GIF 在非调用线程渲染成功、文件落盘、信号送达（`test_real_render_runs_on_worker_thread_and_writes_gif`）；成功/失败两条信号路径单测覆盖。
- 现状核对：UI 面板的"重新生成预览"按钮已由 AUD-30600（wd16g77 批）用面板内私有 QThread 修复；本批把该能力沉到 preview.py 作为可复用的正式 API。**遗留接线（白名单外，见"遗留与建议"1）**：`presets/library.py:261` `save_preset` 仍在 UI 线程同步渲染预览 GIF（motion_graphic_editor_window.py:2727 触发）。

### AUD-29801 [Major/risk] render_draw_svg 裸 float(stroke_width) 触发 ValueError 进入渲染线程 — FIXED

- 新增 `_stroke_width(content, default=3.0)`：`float()` 失败（TypeError/ValueError）与非有限值（nan/inf/−inf，`math.isfinite` 检查）一律回落默认 3.0；数值字符串（"4.5"）与数值（6, 2.25）行为不变。这是 .clinerules "SVG 数值属性 float() 失败要有默认值路径" 的直接落地。
- 同函数中 points 坐标对的原有 (TypeError, ValueError)→跳过 防线保持不变。

### AUD-29803 [Major/bug] data_uri 无大小/类型上限，任意大资产整读并 base64 内联 — FIXED

- 模块级常量 `MAX_DATA_URI_ASSET_BYTES = 8 MiB`（原始字节；base64 后约 ×4/3）+ `image/*` MIME 白名单前缀。
- `AssetResolver.data_uri` 现按序短路：未解析 → None；非 image/*（含无扩展名的 octet-stream）→ None；`stat().st_size` 超限 → None（读取前拒绝，不整读大文件）；`read_bytes()` 的 OSError → None；读回后按实际字节数复检（防 stat/read 之间文件增长）。消费方 svg_renderer.py:477 与 html_native_overlay.py:638 对 None 已有占位符/回退路径，行为等价于"资产缺失"降级，不产生新异常。
- 小尺寸 PNG 正常内联为 `data:image/png;base64,...`（回归测试钉住）。

### AUD-30018 [Major/bug] `if layer_metadata:` 恒为真，保守净化回退成死代码，全部实例化获自由 profile — FIXED

- 根因：schema 键在条件判断**之前**无条件注入 `layer_metadata`，故条件永真。修复：路由改判模板自身元数据 `source_metadata = template.metadata`（注入前），非空 → `build_html_layer_from_source` 自由 profile 路径；空 → 恢复文档承诺的保守 `HtmlSanitizer` 回退路径。schema 键两条路径都注入（Motion Graphic inspector 的参数类型信息与渲染 profile 路由解耦）。
- 行为验证：空元数据模板实例化后 layer.metadata 无 `render_profile`、作者自带的 `onerror=` 被保守净化剥除；非空元数据模板保持自由 profile（onerror 保留、render_profile=motion_graphic_freeform）——AUD-30017 测试组（test_fix_w6g7_aud30017.py）刻意构造非空元数据走自由路径的 28 例全部不受影响。经 promote_html_layer 产出的模板必然携带 build_html_layer_from_source 的非空元数据，编辑器主流程不受路由修复影响。

## 遗留与建议（均为白名单外接线，非本批缺陷）

1. **save_preset 的同步预览渲染**（AUD-29708 的最后一个 UI 线程调用点）：`src/features/teaching_animation/presets/library.py:261` 建议改为持有 `PresetGifPreviewJob`（本批 API）异步渲染，成功信号里补 `record`/日志，失败走既有 `_logger.warning` 降级；调用方 `motion_graphic_editor_window.py:_save_preset_triggered` 需接受"预览稍后生成"的语义（可先落 manifest/scene、GIF 到位后刷新卡片）。另可顺带让面板 `_PreviewRenderJob`（asset_library_panel.py:149）复用本批类消除重复。
2. **`asset_library_panel.py:769`** `record.folder / record.manifest.preview` 的读取路径现由 manifest 构造层保证安全，无需改动；若未来引入外部 zip 导入，建议在解包侧同样拒绝越界 preview 名。
3. `MAX_DATA_URI_ASSET_BYTES`（8 MiB）与 spike 预算 `max_data_uri_bytes`（32 KB，浏览器 HTML 页内联）语义不同（SVG 场景资产 vs 页面内联资源），如有统一预算需求建议在渲染 ADR 中分别登记。
