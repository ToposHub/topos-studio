# Files 原生 PyQt6 界面迁移与后端实施计划

日期：2026-11-16。负责人：**Codex 负责 UI、绘制、交互、Qt 展示模型和宿主接线；用户负责后端业务、数据、任务调度和工程事务。**

范围以用户最新要求为准：**先完成有实用价值的功能，不把所有旧功能照搬一遍。** 优先闭环为「找素材 → 看清内容 → 多选 → 拖入媒体池 / 时间线」。旧 Files 保留作为兼容入口；暂缓功能不构成原生核心版发布阻塞，也不删除旧数据或插件。

## 0. 产品设计方向（2026-11-16 用户补充后更新）

**按现代创作素材库重新设计界面与信息架构。旧 Files 提供能力和数据兼容参考，新界面的布局与交互由素材工作流决定。** 旧菜单、视图数量、弹窗、工具摆放不作为必须复刻的需求。

| 设计决策 | 具体标准 |
| --- | --- |
| 素材内容优先 | 中央卡片区占据主要空间；真实封面、名称、时长/大小形成清楚层次；无真实图片时显示分类占位 |
| 清晰的视觉层级 | 统一 Topos 深色主题；功能区复用 PanelSplitter 的黑色1px分隔线；目录、卡片标题、辅助信息分级；橙色用于选中边框/焦点 |
| 轻量导航 | 路径默认显示简洁位置层级，点击后编辑完整路径；左侧Home为根，目录展开时才异步读取；不列出系统盘根目录 |
| 集中检索 | 去掉独立大标题/搜索行；路径栏末尾放搜索图标，点击展开最多200px输入框，Esc收起并清除检索；内容栏保留类型、排序和视图 |
| 按需显示信息 | 右侧信息栏可开关；宽窗口选择后可显示，窄窗口自动收起；信息按预览/标题/字段排列，避免长段文本 |
| 主操作明确 | 核心是选择、预览、拖入编辑；更多工具放次级菜单，旧宿主入口不占据底栏主操作位置 |
| 密度可调 | 卡片大小滑杆；窄窗口收起辅助栏，把空间给内容；列表服务高密度检索 |
| 功能按价值收敛 | 保留浏览、检索、预览、选择、拖拽、基本标记；高级图库与独立工具不自动进入原生路线图 |

新增功能先回答：是否缩短找素材或开始编辑的步骤、是否日常使用、是否已有更合适的独立工具。没有明确收益的功能继续暂缓。设计验收同时检查视觉层级、内容空间、可读性、可达操作和流程步数，不能以按钮数量或与旧界面相似度验收。

### 1.2 核心版完成后的用户体验

1. 进入 Files 即可浏览个人目录、磁盘和常用素材目录，返回原位置不会丢选区和滚动位置。
2. 通过缩略图、文件名、类型、时长、尺寸、搜索和筛选找到素材。
3. 单选显示技术信息；Space / 双击进入预览；可继续看上下一个文件。
4. 多选后拖入媒体池指定 Bin，或拖到时间线指定轨道和帧位置。
5. 放到时间线时自动导入或复用素材，正确建立音视频关联；失败给出原因。
6. 评分、标签、颜色用于日常筛选；低频工具从完整 Files 打开。

## 4. UI 方案与实现责任（Codex）

### 4.1 布局

```text
┌ 位置 ‹ › ↑   Home › 当前目录  [按需搜索]  搜索 刷新 信息 ···┐
├ 浏览位置 ──┬ 当前目录           类型  排序  卡片/列表 ┬─┤
│ Home       │ ┌────────┐ ┌────────┐ ┌────────┐     │信息│
│ ├Documents │ │真实封面│ │真实封面│ │真实封面│     │预览│
│ 后续按需： │ └────────┘ └────────┘ └────────┘     │标题│
│ 固定素材库 │ 名称/时长   名称/大小   名称/时长     │字段│
│            │     多选、预览、原生拖出              │可关│
├────────────┴───────────────────────────────────────┴───┤
│ 数量 / 已选 / 后台任务进度                    卡片大小 │
└────────────────────────────────────────────────────────┘
```

左侧现在提供以Home为根的惰性目录树，复用既有`/api/tree`。按实际路径隐藏系统目录、Home下的Library/Applications及.app包；Home不能向上进入系统根层级。外接素材目录仍可经更多菜单的选择文件夹访问，不对素材盘内名为Library/System的普通目录做通用名称屏蔽。过滤仅作用于UI，不删除文件、不改索引或后端访问政策。右侧为可折叠只读信息栏；低频旧工具从更多菜单进入。

### 4.2 视觉与可访问性

- 使用项目 `C` 主题常量、全局控件与字体，橙色选中；不另造独立品牌主题。
- 使用 model/view + delegate 复用绘制，不为每个素材创建一组 QWidget。
- 网格优先保证缩略图区域、文件名和选中状态可读；信息缺失显示占位，不显示假时长。
- 功能区横向边界使用`C.PANEL_DIVIDER`的1px细线，竖向边界复用共享`PanelSplitter`，保留原生拖动命中范围。导航、目录工具栏、底栏收紧间距；窄面板可收起信息栏和左侧栏。
- 所有按钮具备 tooltip / accessibleName；文案走 I18N；动态文件名按纯文本显示。
- 复杂媒体能力未接通时显示真实状态；不靠假缩略图或固定成功提示冒充接入。

### 4.3 交互规则

| 场景 | 行为 |
| --- | --- |
| 单击 / Ctrl/Cmd / Shift / 空白区 | 原生选择；视图切换保持同一组稳定身份 |
| 双击目录 | 请求目录；成功后更新当前路径和历史；失败不提交历史 |
| 双击文件 / Space | P0 先经旧分派预览；后续接原生预览容器 |
| Enter | 文件视图打开选中项；路径编辑框导航；标签输入提交；作用域独立 |
| Esc | 先取消局部交互/关闭预览；不误取消其他面板任务 |
| Backspace | 文件视图转上级；输入框内仅删除文字 |
| Ctrl/Cmd+C | 文件视图复制本地 URL；输入框维持文本复制 |
| Delete / F2 / Ctrl/Cmd+V | 等真实文件任务接通才启用；本轮不发虚假写入成功 |
| 多选拖出 | 标准 `text/uri-list`；CopyAction；保持可见排序；本轮排除目录 |
| 拖到集合 / 磁盘目录 | 后续明确「引用添加」与「物理复制/移动」；本轮不混用 |

### 5.1 B08：拖拽链路应按这个顺序实现

1. UI 捕获 URLs / 已有 asset IDs 和目标 Bin，或 sequence_id/track_id/frame/fps/revision；外部文件无需已有 asset ID。
2. 接收端立即完成轻量校验并接受/拒绝 Qt drop，提取请求值；不把 `QDropEvent` 对象带入后台。
3. 后台只做探测、路径去重准备和可取消工作；结果回 UI/工程提交线程，并重新检查活动工程、revision、轨道锁和目标有效性。
4. 用户中途切工程/删轨道/撤销/关闭时取消或明确拒绝过期结果，不能插入新工程或错误序列。
5. 通过既有提交入口导入/复用 asset，批次插入 clip；沿用 AddClip / InsertLinkedAsset / MacroCommand 等既有机制，不从 Files 直接改模型。
6. 明确失败策略：整批失败回滚，或允许部分成功并明确报告；事务失败后 dirty/revision/history 不得只推进一半。
7. 明确 Undo 的领域边界：片段插入和新素材导入是否同一次撤销，由后端定义并测试。不能把旧会话文件撤销栈当工程 Undo。
8. 新文件探测期间只显示已知的占位预览；不得捏造真实时长。已知时长可借缓存展示，并在落轨前验证 fps/帧数换算。

现有外部 drop 在 UI 中等待 future 的注释并不意味着异步不可行：应复制事件值后调度任务，再于合法提交线程完成后续事务。

## 6. UI / 后端接口契约

以下为**拟定契约**，不是已经存在的全部 Python API。先冻结最小可用字段，再逐项实现，避免双方各猜一套。

### 6.1 读取与状态

| 对象 | 必要字段 | 规则 |
| --- | --- | --- |
| Location | kind、稳定 key、display_name、path/查询描述、可写/在线/锁状态 | 真实目录与 search/collection/trash 等虚拟位置分开；虚拟位置不作为 mkdir/paste 目标 |
| Entry | library identity、path、name、media_type、is_dir、size_bytes、mtime、availability | 路径本地化/Unicode由后端统一；身份和路径不要假设永久相同 |
| TechnicalMetadata | duration_seconds、fps（可表达分数）、width/height、codec、probe_status | 单位明确；缺失为 None/unknown；不能默认为一段假视频 |
| UserMetadata | rating、tags、comments、color、flag、revision | 用户字段按 patch 提交；多选未改字段不写回 |
| QueryResult | request_id、generation、location、entries、total、cursor、truncated、revision | 晚到响应和过期缓存不覆盖新位置；分页排序稳定 |
| Thumbnail | entry identity、source_version、size/DPR、status、image/cache reference | 不把大图 blob 写入工程；UI 只创建/绘制适合显示的图像 |
| Capability | key、available、reason、version | 后端未接通的操作禁用或转完整 Files；不显示成功 |

### 6.2 请求、任务和错误

| 契约 | 约定 |
| --- | --- |
| UI query | 参数不可变；携带请求身份和目标上下文；支持取消；回填不触发二次请求 |
| 文件/媒体命令 | command_id、operation、targets、options、expected_revision/context |
| JobProgress | job_id、stage、completed/total、bytes/速度（如有）、cancellable |
| JobResult | successes、failures、cancelled、changed identities、可读诊断；部分成功单独表达 |
| Error | code、message、retriable、target、details；锁/离线/不支持/冲突/取消可区分 |
| 事件 | entries_changed、metadata_changed、thumbnail_ready、job_updated、locations_changed、capabilities_changed |
| 线程 | QObject/Widget 只在归属线程修改；图像解码/扫描/探测在 worker；GL/ModernGL 用既有渲染队列 |

### 6.3 本轮过渡适配与未来替换

```text
当前：NativeFilesPanel → directory_requested
                      → NativeFilesTransport / Qt 异步网络
                      → 既有 /api/list → 既有业务与数据

后续：NativeFilesPanel → 相同 UI 接口 / controller
                      → Files facade → 复用的业务 service
                                      ↘ 旧 HTTP routes 也调用该 service
```

transport 属 UI 接线，业务留在现有后端。不能在原生 UI 里复制 `routes.py` 的目录扫描、SQL、探测、文件复制等逻辑。

本轮公开 UI 接口：`navigate(path)` 请求；`set_loading(path)`；`set_entries(path, entries)` 成功回填；`show_error(path, message)`；`directory_requested`、`file_activated`、`legacy_requested`；`selected_file_urls()` / `mime_data_for_selection()`。

## 7. 数据、插件与兼容策略

1. 保留现有 topos.db / 历史 metadata.db 的选择和合并、NFC/NFD 规则；不新建空库让原生界面看起来“迁移完成”。
2. 保留旧功能数据与入口，P0 原生切默认时允许低频操作留在完整 Files。旧数据库内部的合法绝对路径与 `.topos` 工程包的机器路径策略分别处理，不做一次性盲替换。
3. 当前文件会话 Undo 只覆盖部分 rename/delete，最多20条，无完整 Redo；迁移不扩大已有承诺。文件任务与工程 command 分域。
4. 保留 10 个插件：ai_library_browser、audio_pro、code_editor、decode_benchmark、format_factory、image_editor、image_factory、shutdown_timer、topos_image、video_pro。优先原生接播放器和常用 Qt 工具，其他继续兼容宿主。
5. 旧 JS/HTML 注入和文件 handler 不能直接当原生 QAction 使用，需 action/provider 适配；迁移不承诺所有 Web 编辑器改写为 Qt。
6. 视频 in/out 标记虽已有后端 API，当前注释仍写播放器打点 UI 待接；按新增整合能力对待，不虚标为已有端到端功能。
7. 目录软锁不是加密。原生列表沿用既有锁检查；解锁在旧 Files 完成后刷新；后续 tree/search/thumb/文件任务都要遵守同一访问政策。
8. 原生与 Library 双向同步维持防递归；目录同步仅成功后广播；评分同步维持单一元数据提交入口。
