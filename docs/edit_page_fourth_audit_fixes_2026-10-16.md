## 工程兼容与发布

- Edit 内容 schema 升为 v4，包格式版本不变。v3→v4 只补缺省相位/原点，保留未知字段；详见 [采样相位说明](edit_sampling_phase_v4.md)。旧文件已丢失的相位无法逆推，本轮不宣称能恢复历史错误切片。
- 项目事务发布顺序：先验证项目/父子序列提案，再更新历史与 canonical 状态，最后刷新面板、预览和音频；一个有效提交只前进一次项目 revision。
- Undo/Redo 恢复内容，发布 revision 保持单调。取消、拒绝、无效输入和 no-op 不新增内容或历史，也不清空有效 Redo。
- 项目事务 Undo 若发现相关素材/子序列已被其他操作修改或引用，会明确拒绝并保留历史；无关素材修改保持原样。
- GPU 工作继续使用既有 worker/context 生命周期；没有在 UI 槽直接执行 GPU 渲染。

## 明确的能力边界

本轮修复现有流程的数据错误与失败处理，不把第三轮 F01–F16 所列专业工作流的新建设施声明为已实现。需要区分“准确执行/明确拒绝”与“支持所有组合”：

- 跨源 FPS 的速度曲线换源/切角需要有理数曲线控制域；当前在任何 split 或历史变更前拒绝，支持同 FPS 曲线与常速跨 FPS。
- 父级 Nest 变速/反放/曲线的音频重采样仍需成熟 F07 实现；带音频交付明确阻断不支持组合，不能当作无声成功。
- 本轮短片与固定像素测试不代表已证明 4K60、长时 VFR/HDR、耳听、多设备音频漂移、全部硬编或外部软件交换均通过。

历史错误、脚本 fixture 错误与当前产品错误分别记录，见证据 README；不将审计脚本自身异常当作产品缺陷。
