# TOPOS 边缘锯齿感诊断报告（2026-09-21）

> 现象（用户观察）：文件大小已与同档 ProRes 对齐，但无论哪个档位，物体
> 边缘总有"锯齿感"（台阶感），ProRes 几乎没有。
> 本文用同源语料（`tests/test_videos/`，P0 基准清洗后的 2K/4K 对）做
> 逐帧取证，定位根因并量化"追平代价"。

## 2. 实证发现

### 2.1 码流事实：全帧单一 qp（空间零分配）

逐 slice 解析（每帧抽样 10 帧 × 6 文件）：**所有 slice 的 qp_delta 恒为
0**——每一帧整个画面用同一个 qp 编码：

| 文件 | 每帧 qp_base |
| --- | --- |
| 2K proxy | 75–86 |
| 2K lt | 72–82 |
| 2K standard | 69–79 |
| 2K hq | 67–76 |
| 4K proxy | 73–83 |
| 4K standard | 67–74 |

对照：ProRes（SMPTE RDD 36）**每个 16×16 宏块头自带 quant_scale**，Apple
编码器按局部内容逐宏块分配码率——边缘/细节宏块给精细标度，平坦区给粗
标度。这是两个编码器最根本的结构差异。

### 2.2 步长换算：低档位下边缘频率无形状保护

> **勘误（2026-09-21 合并 dev 后核实）**：产品 422 档位自 P5.1
> （ADR-C033）起使用 **flat 矩阵（qmatrix_id=0，全系数 16）**，语料包帧头
> qmatrix_id=0 实证。本节初稿按 Standard 矩阵（id=1，几何 `16·1.25^(u+v)`）
> 推算的"HF:DC = 23:1"前提**不成立**，撤回；flat 下所有频率系数同步长。
> 其余各节（单一 qp、栅格比、色度差、qp 扫描代价）为实测，不受影响。

`kQpScale` 每 4 qp 翻倍（`quant.c`）；flat 矩阵下像素域步长（M 首行 13 →
F_DC = 10816·mean 换算，10-bit 语料 `bd_qp_offset=0`）：

| 档位 | qp（帧头实测） | 全频率统一步长 |
| --- | --- | --- |
| 2K proxy | 75–86 | 1.3–8.6 LSB |
| 2K lt | 72–82 | 0.8–4.3 |
| 2K standard | 69–79 | 0.5–2.6 |
| 2K hq | 67–76 | 0.3–1.5 |

单一系数步长看似不大，但强边缘块的 8×8 DCT 把对比度铺到几十个显著 AC
系数上，每个 ±步长/2 的独立误差在像素域叠加（实测 MAE_edge 12.9 LSB 与
此一致）。关键结构点是：**flat 矩阵没有任何频率形状保护——边缘谐波与
平坦 DC 同步长，而编码器又没有空间 qp 分配去补偿**，边缘成为唯一暴露
误差的区域。

### 2.3 关键反直觉：边缘误差幅度其实打平

2K 全档位 ×2 帧均值（母版 bicubic 1080p 为参照）：

| 档位 | edge PSNR ProRes | edge PSNR TOPOS | U PSNR P/T | V PSNR P/T |
| --- | --- | --- | --- | --- |
| proxy | 38.22 | 37.48 | 49.1 / 47.9 | 46.3 / 45.5 |
| lt | 41.30 | 41.23 | — | — |
| standard | 42.36 | **42.49** | 53.5 / 51.5 | 50.7 / 49.0 |
| hq | 43.15 | **43.72** | 54.9 / 53.4 | 52.2 / 51.0 |

边缘 PSNR 在 standard/hq 甚至反超。"锯齿感"不是误差**幅度**差异，而是
误差的**形状**差异。

### 2.4 误差形状：TOPOS 块网格化 vs ProRes 颗粒化

- **8×8 栅格残留集中度**（残差能量落在块界线上的倍数，1.0=中性）：
  standard **1.232 vs 1.075**、hq **1.154 vs 1.035**（TOPOS vs ProRes）。
  TOPOS 的量化误差系统性组织在 8px 节奏上——斜边上的块界台阶 = 肉眼
  可见的锯齿；ProRes 的残差接近空间白化的颗粒，同样能量下几乎不可见。
- **锐度保持率**（边缘 Laplacian 能量比）：ProRes 1.63 vs TOPOS 1.52
  （standard）。ProRes 重建携带更高高频能量（保留/再现画面颗粒），
  RGB 对比图里肉眼可见细颗粒；颗粒对台阶有"抖动掩蔽"效应。TOPOS 的
  熵编码+死区把孤立小系数清零，画面更"干净"，台阶因此裸露。
- **活动度-误差相关性**：两者相当（0.32 vs 0.32–0.68）——"ProRes 把
  误差推离边缘"的假设**不成立**，差异在残差的组织结构而非落点。

### 2.5 色度全面落后 1–2.5 dB（所有档位）

U/V PSNR：proxy −1.2/−0.9、standard −1.9/−1.7、hq −1.4/−1.2 dB。
4:2:2 色度上采样 + BT.709 后，彩色边（用户截图中的陶罐沿类）的色台阶
叠加在亮度台阶上。色度与亮度共用 qp、无独立保护。

### 2.6 决定性实验：空间分配缺失的价格标签

对 2K 母版第 100 帧固定 qp 扫描（对照同帧 ProRes proxy，185,007 B/帧）：

| qp | 字节/帧 | vs ProRes 体积 | 边缘 PSNR | 栅格比 | U PSNR |
| --- | --- | --- | --- | --- | --- |
| 82 | 111,012 | 0.60× | 35.6 | 1.44 | 50.6 |
| **76** | **168,705** | **0.91×（同尺寸点）** | **39.9（−4.3 dB）** | 1.22 | 54.0 |
| 74 | 202,082 | 1.09× | 41.6 | 1.18 | 55.0 |
| 72 | 248,694 | 1.34× | 43.1 | 1.14 | 56.0 |
| 70 | 313,592 | **1.70×（追平点）** | 44.8 | 1.11 | 57.0 |

同尺寸下 TOPOS 平均质量更高（DC/平坦区近无损、整体 PSNR 赢），但边缘
结构输；**用均匀 qp 硬追平 ProRes proxy 的边缘指标需要 1.3–1.7× 体积**。
这就是"逐宏块空间分配"被 ProRes 占据的价值区间。

## 3. 根因链

```
全帧单一 qp（无逐块/逐段分配；ProRes 逐宏块 quant_scale）
  × flat 矩阵（频率零形状保护：边缘谐波与平坦 DC 同步长，盈余全部
    堆在低频/平坦区——同尺寸下平均 PSNR 赢、边缘结构输）
  × 死区 Q/4 + 熵编码清零孤立小系数（去噪→台阶裸露，无颗粒掩蔽）
  × 色度共用 qp、无独立保护（U/V 落后 1–2.5 dB）
⇒ 同尺寸下"平均质量赢、边缘结构输"：
   残差块网格化（8px 台阶）+ 无颗粒掩蔽 + 彩色边色台阶 = 锯齿感
```

与既有裁决一致：P3 带级亮度 AQ（±4、无码率重分配）判负；P5 单帧 RD
probe 定位"高 qp 量化粗糙"。本次取证把结论坐实：**缺口不在量化器取整
方式（对称就近+Q/4 死区已率优），而在空间分配结构**。

## 4. 改进方向（按杠杆排序）

1. **段级/块级 qp 自适应**（治本）：V8/V9 段目录已带 `qp_delta_biased`
   位流字段，视频写路径切 V8/V9 是前置（与 P5 kQpScale 战役同一次
   minor 版本窗口）；活动度驱动 qp 分配 + 帧级码率守恒。
2. **色度保护**（低风险快赢）：422 档 `chroma_qp_offset` 负偏（位流
   已支持逐平面 slice qp_delta，纯编码端），先拿回 1–2 dB 色度。
3. **边缘均衡矩阵变体**（新 `qmatrix_id`，需 minor 版本）：flat 是
   "频率零形状保护"；把平坦区盈余换成边缘精度——低频略粗、高频略细
   （HF:LF 步长比 < 1）。
4. **颗粒保留**（治"塑料感"，配合 1）：死区对小系数的清除在"边缘
   结构"指标下重新裁决（P3 时代的裁决口径是纯码率效率）。

## 5. 优化战役裁决（2026-09-21 当日落地）

按 §4 方向实施 A/B（487 帧全量语料、产品全链路、码控体积守恒；
工具 `tools/bench_topos_variant.py`，数据 `bench_out/edge_jag/variants/`）：

| 变体 | 内容 | 裁决 |
| --- | --- | --- |
| v1/v2 | `chroma_qp_offset` −2/−4 | **否决**——零和：色度 +1.0~+2.7 dB 全部从 luma（含边缘）抢来（−0.6~−1.3 dB），对锯齿主诉不利 |
| v3 | **`qmatrix_id=4`「边缘均衡」**（低频略粗/高频略细，HF:LF≈0.4；色度表随行细化） | **采用**——同体积边缘 PSNR 2K proxy/standard/hq **+0.66/+0.54/+0.29 dB**、4K proxy/lt **+1.01/+0.78 dB**，全帧 Y +0.1~0.5，色度持平，编解码速度与 flat 在噪声带内不可区分 |
| v3' | 色度表加细（0.92，HF=6~7） | 否决——出血超过收益，全指标回落 |
| v4 | v3 + 色度偏移 −2 | 否决——抵消 v3 的边缘收益 |

**生效域**（4K standard −0.50 dB / 4K hq −0.20 dB 实测负收益后的分界）：
netproxy/proxy/lt 恒生效；standard/hq 仅宽 <3840 生效（`_effective_qmatrix_id`
域外回退 flat=0，位流最老字段值，任何解码器可读）。

**性能**：矩阵变化是查表替换（SIMD 内核不变），机制上零开销；实测编码
20.5–26.3 fps、解码 237–522 fps（1080p），v0/v3 区间重叠。**速度未被
画质优化牺牲。**

### 治本项（后续，需 minor 版本战役）

§4.1 段级/块级 qp 自适应仍是追平/超越 ProRes 边缘的主路径（V8/V9 段目录
位流字段已备）；本轮矩阵变体把"均匀 qp 的频率形状"修正后，其边际收益
需要重新评估。

### 5.1 追加 A/B：kQpScale 高 qp 细化（2026-09-21 晚，P5-go 首轮验证）

画质对齐计划 P5 评估轮的 go 项（qp>60 段步长放缓）首轮实测。实验构建
`build/exp-qp6/`（clang 参数与 release 一致）：qp≤63 冻结，qp64..95 改为
32768·2^((qp−64)/6)（每 6 qp 翻倍，qp95 由 7.05M 细至 1.18M）。产品全链路
同预算编码，基线即语料位流（字节级核对过与当前库一致）。解码用匹配库
（指标工具 `tools/diagnose_edge_jaggies.py`，数据 `bench_out/edge_jag/qp6/`）。

| 档位 | 实际 qp 区间 | ΔPSNR 全图 | ΔPSNR 边缘 | 体积 |
| --- | --- | ---: | ---: | --- |
| 4K standard | 67–74 | **+0.53** | **+0.44** | −0.1% |
| 2K hq | 68–76 | −0.10 | −0.06 | −0.2% |
| 2K proxy | 75–86 | −0.17 | −0.15 | +1.5% |
| 4K proxy | 73–83 | −0.24 | −0.18 | −0.2% |

裁决要点：

1. **收益是内容谱型的函数，不是 qp 段的函数**——2K hq（68–76）与 4K
   standard（67–74）qp 区间几乎重合而符号相反：原生 4K 纹理的高频能量
   密度让"保 AC"划算；母版下采样的 2K 内容偏平滑，"保 DC"划算。
2. **单一全局新表不成立**。可采纳形态是**按档位选表 + em 版本载体**：
   4K standard/hq 族用细化表，其余档维持现行表（与 id4 的生效域分界
   互补：id4 管 2K 与 4K proxy/lt，细化表管 4K standard/hq）。
3. **旧解码器会静默误读异表码流**：用 release 库解码 exp 表码流得
   12.7 dB 垃圾画面（无任何报错）——"显式版本字段、旧解码器拒读"不是
   流程洁癖，是物理必需。
4. 速度无回退（exp 编码 228.4 fps vs 基线 220.4 fps，2K proxy 档）。
5. 对用户主诉（2K 各档锯齿）此杠杆**无收益**——2K 感知块效应的下一段
   落在 P6 去块滤波（intra-only 编解码两侧一致的输出端滤波，无预测环
   漂移风险），应与 em 版本战役同载体立项。

### 5.3 P6/P5-go 落地：输出去块 + 细化表（2026-09-21 深夜，已发布）

**版本载体**：帧头 flags bit2=DEBLOCK / bit3=QPT2（V7-R4/R5）。旧解码器对
保留 flags 位非零干净拒绝（CRC 与保留位规则双保险，已用旧构建实测）；
编码器 API 经 reserved[5] 选载（em8 V7-R2 intra 产品路径，域校验与
qmatrix_id=4 同形：4:2:2 / 10-bit / profile 3）。

**生效域**：全部 4:2:2 10-bit 视频档开 DEBLOCK；4K standard/hq 叠加
QPT2。4444/4444xq/lp/raw 不变。target-size 缩放交付暂不过滤（批 3）。

**A/B（同码率，同母版语料，匹配库解码）**：
- 4K standard：全图 +0.53 / 边缘 +0.44 dB，块指数 1.216→1.201（QPT2 主导）
- 2K proxy/standard/hq、4K proxy：PSNR +0.02~+0.12，块指数持平微降
  （v1 去块强度保守——真边缘保护优先，主观块效应改善以对比文件为准）
- 门禁 PASS（0 违规）；编解码速度无回退

**工程备忘**（实现期踩坑，供后续批次参考）：
1. 产品 intra 是 em=8（V7-R2，major 7）——em=9 是未启用的 V8 段化试验
   格式（sized 路径显式拒绝），二者命名易混。
2. 解码分流：TPIC 包（directory_minor=0）走 tc_decode_slices →
   dec_frame_finalize（去块钩子位）；v7b（TPLD 目录）走专用解码器。
3. 解码 API stride=0 表示 tight，钩子侧必须做 0→width 兜底（首版缺失
   导致行别名化——全部写入首行，表现为"滤波只影响一行"）。
4. 跨表解码不报错只出垃圾（异表 12.7 dB），版本位任何情况下不可省。

### 5.2 各档编解码速度基准（2026-09-21 晚修正版；24 核 Intel Mac，487 帧全量）

工具 `tools/bench_topos_speed.py`，汇总 `bench_out/edge_jag/speed/speed_all.json`。
**口径决定数字**，引用时必须带口径：

| --- | ---: | ---: |

| lt | 300–308 | 87 |
| standard | 224–235 | 77 |
| hq | 184–192 | 60 |
| 4444 | 126–146 | 45 |
| 4444xq | 114–117 | 35 |

解码线程扫描（2K proxy）：w1 46 / w4 158 / w8 305 / w16 492 / 默认 500 fps；
（4K proxy）：w1 12 / w4 41 / w8 82 / w16 151 / 默认 158 fps——近线性扩展，
解码吞吐由 slice 线程预算决定。

编码（导出管线口径，含源喂入）：

| 喂入口径 | 2K 编码 fps | 4K 编码 fps |
| --- | ---: | ---: |
| 同档位 ProRes 直通（语料生成器口径，无转换） | 251（proxy） | — |
| 同尺寸 444 母版（含 444→422 逐帧转换） | 45.6–59.1 | — |

**初测误读警示**：本节初版以 4 线程探针测出 2K proxy 168 / hq 64 /
4K proxy 42 fps——是限流值而非产品值（默认池为其 2.7–3.8 倍）。解码
吞吐结论必须带线程口径，单点测速前先确认 `set_max_slice_workers` 状态。

时间线卡顿评估（修正）：默认池下单 clip 解码 2K 各档 117–548 fps、
4K proxy 158 fps，均远超 25 fps 实时线；仅 4K 4444/4444xq（35–45 fps）
余量偏紧。故典型档位的卡顿主因不在解码器单点吞吐，应查：多 clip 并存
时 `DECODE_WORKER_BUDGET` 份额摊薄（近线性扩展意味着份额减半即速度减
半）、App 侧合成/GPU 上传开销、或非 TOPOS 素材路径。

## 6. 局限与备注

- 语料为车内场景（强曲线、弱色彩边），用户素材（厨房、陶罐）色彩边更
  强，色度项（2.5 节）权重会更高。
- 指标均基于 Y/U/V 平面与 BT.709 线性 RGB；未模拟应用渲染管线的缩放
  核。若预览路径对 TOPOS 与 ProRes 使用不同缩放（如最近邻 vs 双线性），
  观感锯齿会被进一步放大——排查时可把两路解码导出 PNG 后在同一查看器
  对比，以剥离渲染路径因素。
- 取证工具与原始 JSON/面板已入库（`bench_out/edge_jag/`），可复跑。
