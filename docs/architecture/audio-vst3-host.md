# VST3 audio inserts

Topos Studio can host a limited class of locally installed VST3 effects in its track, bus and master FX racks. Install the optional dependency with `python -m pip install '.[vst3-host]'` in the Python environment that runs Topos. In the rack, choose **+ → Add VST3 plug-in**, choose the installed bundle and select a component. The dialog probes stereo processing at the current sample rate before committing the insert. Click an inserted plug-in to edit its exposed parameters or re-register the same binary on another workstation.

The initial backend is Spotify Pedalboard 0.9.26, which provides a maintained VST3 binding and works in Topos's GPL-3.0 source distribution. The supported deployment is the macOS or Linux Python build. This feature is disabled in frozen distributions until they can launch a compatible child interpreter. Vendor binaries remain separately installed. [Pedalboard API](https://spotify.github.io/pedalboard/reference/pedalboard.html)

- The project uses the existing track, bus and master FX chain and undo stack. Each insert saves a schema version, a SHA-256 bundle fingerprint, an exact component name and normalized parameter overrides. Unknown fields survive serialization. Paths come from explicit local scans and do not travel in project state.
- The child process loads the VST3 binary. Scan uses a short-lived child. An active insert gets a separate child and a fixed shared PCM mapping. Control messages are length-bounded and include an instance generation and block index. The process boundary contains crashes and hangs. Plugins still have the child process's local user privileges.
- Loads verify the bundle fingerprint and probe stereo PCM. The adapter requires zero reported latency throughout processing. For playback, loading is asynchronous and an insert that is still loading or fails supplies silence with instance diagnostics. Rendering stops on a failed insert. The host accepts an explicit bypass through the existing rack controls.
- Audio production uses bounded requests from the buffered render producer. A per-worker deadline bounds a miss. Hard realtime, multiple simultaneous demanding inserts and device latency have no qualification yet.
- This beta supports stereo effects and their exposed normalized parameters. It does not host instruments, plugin-native editor windows, opaque preset state, transport and tempo, sample-offset automation, sidechains, nonzero latency, or validated multichannel layouts. The effect chain has a bounded tail feed window, pending support for plug-in-declared tails.

`tests/edit/test_hosted_vst3.py` validates the project identity and failure behavior. Set `TOPOS_TEST_VST3` to an installed zero-latency stereo effect to run the opt-in native worker test, which checks scan, parameter readback, shared PCM processing, reopen and worker failure. Vendor DSP may start with nondeterministic state. Use a deterministic unity or exact-delay plug-in for sample equality qualification.
