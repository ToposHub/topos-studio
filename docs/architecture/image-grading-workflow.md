# 图片调色工作流

Studio 的 `image` 工作模式与独立 Color 产品使用图层调色界面；Studio 视频模式继续使用节点界面。图层界面选择集中在 `uses_image_layer_workflow()`，工作模式的页面范围由既有 feature flags 管理。

## 图片工作区的工具范围

Studio 图片模式默认关闭 Edit、Mixer 和视频 Composite 页面，保留 Library、Color、Deliver。独立 Color 同样以图片工作流过滤 UI；`get_work_mode()` 的产品能力语义保持不变，UI 使用 `get_workspace_work_mode()`。运行窗口冻结启动时的模式，修改偏好后重启应用切换，图片与视频布局继续独立保存。

图片模式的 Library 页面由素材浏览面板占满。默认布局、旧布局恢复和命名布局加载都应用这条页面规则，独立信息面板与调色视口只在各自工作区显示。素材浏览器内的侧栏、调色集和按需查看文件信息仍由浏览器管理。

图片模式在没有已保存布局时使用专用 Color 排列。左侧是调色集、画廊、3D LUT 和 Effects，预览位于两侧栏之间，右侧信息与裁剪在上、图层在下，底部显示三组调色工具。还原已保存布局时保留用户停靠位置与比例。Batch Export 的显示与停靠菜单入口只在 Deliver 有效，即使旧布局将它保存为可见也不会出现在 Color。

图片隐藏 Tracker（包括稳定器）、关键帧、时间线片段条、音频混音器及视频导出工作区。`PanelDescriptor.work_mode` 为菜单提供过滤，`_enforce_work_mode_dock_visibility()` 在布局恢复后隐藏并禁用对应 dock action，阻止旧状态和延迟回调重新打开视频工具。Window → Panels、原生 dock 弹出菜单与调色工具栏保持一致；同一 dock 的重复描述仅贡献一个菜单项。遮罩的发送跟踪器入口及调色轮关键帧按钮一同隐藏。示波器、色彩通道 Mixer、颗粒和图片遮罩仍可用。

Deliver 图片页复用已有 `ExportPanel(image_mode=True)`，不构造视频 `DeliverWorkspace`，只显示 Batch Export。进入时独立水合当前图片尺寸和路径，支持缩放。图片 Batch Export 隐藏并关闭 Composite 应用选项，快速导出隐藏视频标签及 Composite 来源；图片 Deliver 菜单和快捷键不注册时间线、字幕与视频队列操作。停留在 Deliver 的图片工程保存也复用 Color 快照，避免延迟保存写回旧调色。视频入口维持原有工作流。

## 图片降噪

此前视频面板重设计移除了 Classic 和 AI 的 UI，基础双边滤波、ONNX AI 后端与宿主回调仍在。本次图片模式恢复 Basic/AI，视频保留原时域/空域两列。历史代码没有独立 Advanced 算法，所谓高级项是 AI 的分块、重叠和混合等设置。

模型位置复用共享 `get_models_dir("denoise")`；缺少 ONNX 模型时显示诊断并禁用 AI 应用，基础降噪可用，不自动下载模型。图片请求继续走现有异步 worker、任务上下文校验、history 和 source bake 提交流程。处理期间锁定 Reset、模式及参数，完成或失败后恢复，避免 Reset 被旧任务的结果覆盖。隐藏的视频参数及未知字段按原样保留，不因图片 UI 恢复或重置而丢失。

## 打开与编辑

画布接收单个本地图片、视频或 `.topos` 文件的拖放请求，通过 `file_open_requested` 交给既有文件控制器处理。画布不解码文件、不创建工程，也不执行 GPU 操作。图片直接建立 single-asset Color session，不要求媒体池或时间线面板存在。图片模式优先按图片格式识别 DNG，避免与视频格式集合重叠时误走视频路径；真实视频仍受既有模式校验约束。

图层停靠面板及菜单连接既有 `LayerOpsMixin` 和 ImageEngine，新增、删除、复制、可见性、混合模式和不透明度使用既有图层历史与渲染信号。程序化面板回填沿用状态锁。图层是调色效果的堆栈，当前改动不提供 Photoshop 式多素材合成或像素绘画。

图片变更在 `_trigger_autosave()` 内立即标记工程 dirty，随后才启动 2 秒去抖保存；不能等定时器执行后才允许关闭检查发现变更。重置、撤销和重做成功后也进入此入口，避免已保存工程在这些操作后直接换图而丢失修改。

## 调色集

素材库左侧与 Color 的调色集停靠面板共享 `GradeSetModel`。图片工作区首次启动时创建固定的默认调色集，后续启动复用同一个集合，并恢复上次选中项。集合和有序成员路径存入现有 Files catalog 的独立 scope，拖放和批量右键添加只写引用。从桌面把图片拖入 Color 画布或编辑窗口时，打开第一张可读图片并将整批图片引用按拖入顺序加入当前集合，没有有效选择时用默认集。同一原图可以在多个集中出现。Color 点击卡片走既有图片打开和工程恢复流程，成功加载后更新活动卡片。

旁置工程打开前核对源图身份。两张图片同名但扩展名不同时，已有 `.topos` 保留原归属，另一张使用包含原扩展名的旁置路径。调色集成员按路径引用，素材移动或改名后需要重新加入新路径。

调色集卡片在后台解码原图和预览，准备完成后通过既有文件控制器载入工程。RAW 和普通图片各允许一个前台解码任务，连续点选只提交最新的请求，正在看的图片保留到新图准备完成。停留在一张照片时，单独预取其后一个可见普通图片。最近解码的原始像素按文件版本缓存，最多八张、总量不超过 512 MiB，应用退出时释放。首次渲染等画布尺寸和调色资源同步后提交。如果视口读取静图纹理时共享 GL 锁被示波器或缩略图任务占用，视口自动重试绘制已发布的帧。对比视图起初复用原图纹理，裁剪等操作替换工作图像时保留原有对照纹理。

素材库位置树将素材库、调色集、磁盘依次作为可折叠分组。每个调色集作为独立文件夹样式的条目，点击打开，拖放图片添加成员引用。

停靠对象 `dockGradeSets` 默认与画廊、3D LUT 和 Effects 同组。旧图片布局首次进入 Color 时补一次默认位置，此后由各布局的 Qt 状态保存停靠区、标签组和浮动状态。调色集复用素材库的卡片绘制和布局，缩短图片之间的间距。默认自适应模式按图像比例从左向右铺满整行，稀疏末行保持接近滑杆设定的尺寸。网格模式使用等宽列。面板至少可显示一整排，其余卡片纵向滚动。顶部单行提供集合选择、缩略图缩放、文件格式与星级筛选、排序和布局切换，下方用单条横线分隔卡片区。图片通过拖放或卡片区右键菜单添加。筛选和排序通过视图模型应用，集合存储仍保留加入顺序。视频工作区不注册这个面板实例。

卡片默认隐藏文件名并收起文字区域。右键菜单的「显示文件名」开关写入应用偏好。图片成功打开后，实际文件名显示在 Color 预览工具栏中央，关闭图片工程时清除。

缩略图按可见卡片异步请求。调色集可见时，当前照片停稳 300 毫秒后，渲染线程从已发布的视口纹理裁掉留边、缩小并回读，长边最多 192 像素。放大或显示蒙版时，可以使用示波器已完成的同版本全图；全图不可用时保留已有预览。卡片刷新不启动新的调色渲染。切换照片、离开 Color 或关闭应用时，已保存的完整预览通过 Files 后台线程压缩为质量 48 的 JPEG，写入现有的有界缩略图缓存。缓存按原图和旁置工程版本校验，素材库与调色集共同使用。仅浏览的照片无需创建工程或持久化调色预览。星级读取素材所属的 Files 库，素材库评分写入成功后更新调色集卡片。

在当前照片的右键菜单复制其图层调色，在另一张卡片的菜单粘贴时打开该照片，再将复制的调色图层叠加到它现有图层之上，形成单步撤销。复制保留可移用的调色、曲线、LUT、效果和矢量遮罩。依赖源图像的像素遮罩、AI 和烘焙数据排除在外，复制结果给出提示。LUT 在后台验证并存入剪贴板自己的暂存区，粘贴时将其注册进目标工程的资源会话。切图后建立独立撤销历史及 LUT 上下文。

首次打开图片只建立内存预览，调色状态有变化后才自动创建工程。编辑稳定约两秒后，使用现有工程归档 worker 保存当前图层快照。切换图片或关闭窗口时，有待保存的修改则立即启动后台保存，写入成功后继续原操作。写入失败时保留当前图片及修改，并在状态栏报告错误。新照片默认将工程写入原图旁的 `.topos`，同名冲突沿用图片身份校验和扩展名旁置规则。保存完成才采用该工程路径并清除已写入的脏状态。素材库在异步校验旁置工程属于当前图片后显示「已调色」角标，保存完成会触发对应卡片检查。

## 效果与 LUT

`ColorLayerResourceController` 将共享资源浏览器接入当前真实 Layer，复用效果目录、PluginManager、LUT registry 和引擎接口。资源身份、参数 schema 和可用性在提交时验证。没有图层执行后端的资源明确禁用；不向隐藏节点写入效果。

资源操作进入图层撤销历史，并触发预览、dirty 状态及保存同步。参数手势暂存至提交，取消不改模型。异步结果校验工程、来源、图层对象身份，切换图片、撤销替换图层和关闭窗口会使旧目标失效。LUT 缩略图使用独立缩略图服务。

## 工程与兼容

无媒体池的图片工程仍使用既有 EditProject 容器与 canonical ColorStack，保存为 `standalone_image` 类型的 `.topos`。类型推断依据工程内容，而非单靠当前 UI 模式；空视频工程及媒体池中的普通图片不会被误转为图片调色工程。独立 Color 可以重开图片工程，时间线工程仍检查产品能力。

保存复用 SaveRouter 的引擎到 ColorStack 同步。首次另存为也必须获取当前图层状态，不能依赖延迟自动保存已经执行。取消和失败保留原路径及未保存状态；完成较早快照的保存不能清除后续编辑的 dirty 状态。资源封装继续遵循既有工程依赖收集规则，无工程 schema 变更。

- `tests/app/test_image_project_without_media_pool.py`：可选面板、图片类型判定、工程保存与重开、取消及失败路径。

2026-11-23 验证：相关 UI、控制器、工程封装、Layer、History、Color session 与 LUT 回归共 661 项通过。Studio 图片模式和独立 Color 的原生窗口均完成拖放与首存重开；Studio 另完成 LUT 资源重开解析，以及已保存工程再次调色后立即关闭选 Save、重开恢复最新曝光。窗口样图为 128×96、渲染输出 float32；本轮未测 4K 吞吐或各 RAW 相机格式的完整矩阵。
