# 子智能体审查任务通用说明（必须完整阅读并遵守）

项目背景：Topos Color——PyQt6 + ModernGL 的 HDR 图像/视频套件，分层 products→features→shared→app。
渲染走独立渲染线程/任务队列；GPU 资源按 deferred-release 模式释放；HDR 内部处理（float16/32）；4K 实时性能基准。
铁律（.clinerules 摘要）：UI 线程不得操作 OpenGL；程序化更新控件须状态锁防递归信号；浮点字面量显式 .0；
循环上限编译期常量；HDR 内部数据不得无理由 clamp(0.0,1.0)；不得宽泛 except 掩盖领域错误；外部数据须验证。

你的任务书（assignment 文件）列出了本次要审查的批次与文件。对每个批次：
1. Read 通读该批次全部文件（长文件分多次 offset/limit 读完，不许跳读）。
2. 按下列九个维度逐文件审查：线程安全 / GPU 资源生命周期 / GLSL·HDR 正确性 / 信号防递归 /
   状态提交一致性（undo·redo·revision·持久化）/ 异常与取消路径 / 输入验证 / 性能模式 / 类型注解缺失（Suggestion 级）。
3. 写批次报告到任务书指定的输出路径（Write 工具），格式见下。一个批次一个报告文件。

报告格式（每个文件一节；发现按严重度降序）：
## <相对路径> (行数: N)
### 发现
- [AUD-XXXXX] [Critical|Major|Suggestion] <一句话标题>
  - 位置: <file>:<line>
  - 证据: <从文件中摘出的真实代码 3–8 行>
  - 影响: <具体后果>
  - 建议: <修复方向>
  - 置信度: 高/中/低
### 通过项
- <检查过且无问题的维度，一行一个>

问题编号：只能使用任务书给定的编号区间（每批次独占一段区间，防止并行冲突）。
严重度：Critical=可致崩溃/数据丢失/渲染错误；Major=功能缺陷或明确风险；Suggestion=质量改进。

红线：除任务书指定的报告文件外不得创建/修改任何文件；不得运行改变文件系统/仓库状态的命令（grep/find 等只读命令可用）；
对 src/ 全程只读。每条发现必须 Read 到真实行号、贴真实代码，禁止猜测；不确定标低置信度并说明；宁缺毋滥。
纯 re-export 或空文件可直接标"通过（无逻辑）"并说明导出了什么。
完成后最终消息只写 2–4 句：各严重度计数、Critical 标题列表、已写的报告路径。不要粘贴报告内容。
