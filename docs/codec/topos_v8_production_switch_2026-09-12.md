# V8 生产切换评审建议（批 5 终项 → 用户拍板）

日期：2026-09-12 · 前置：批 0~5 全部完成 · 计划：`topos_v8_format_plan_2026-09-12.md` §6
性质：决策建议。两个拍板项在文末，均需用户确认后执行。

## 一、评审输入（全部为实测，来源逐条标注）

### 1.1 正确性面（全部 ✓）

- **conformance（批 5）**：golden_v8 3 记录字节+解码像素双冻结（fold
  `f2378492ce84738b`）；fuzz 512 ctest + 4096 手动全过、ASan 全量
  ctest 84/84；损伤 conceal 矩阵 20 例（瓦片域定界 + 不污染逐值断言）。
- **差分（批 2~4）**：编码/解码/GPU 三方位位精确；q-hash oracle
  round-trip 4 几何 × 4 qp；GPU 全链路 == CPU 5/5。
- **兼容（硬门禁保持）**：V1~V7 全部 golden 不变（pytest golden 钉死项
  每批全绿）；老二进制拒绝 V8 双钉（V7 扫描入口显式拒绝 + tpcC 白名单）。

### 1.2 码率面（拍板项 1 的事实）

| 档位 | V8 vs V7-R2 同 qp | 来源 |
|---|---|---|
| qp≤30（18 真实素材配置） | **+1.21~2.7%**，好于预测下沿 | 批 2（±1pp 预测带内）+ 批 0 |
| qp44 常规瘦源 | 均值 3.3~3.9% ✓ | 批 0 |
| qp44 极瘦源（8K prores422HQ 上采样） | **+5.2~5.8%，单点超 5% 封顶** | 批 0 §2.3 |

### 1.3 性能面（拍板项 2 的事实）

| 口径（4K 422 10bit qp30 真实素材） | 数值 | 来源 |
|---|---|---|
| CPU 解码同口径对照（V8 / V7-R2） | 29.0ms / 28.8ms（V8 劣化 **0.7%**，门槛 5%）；批 4 的 22.8ms 属另一 GPU 校准全链口径，不与 28.8ms 相除 | 批 3 §三 / 批 4 |
| GPU 解码全链（当前 kernel） | 88.2ms（rANS 69.8 + wsd 18.4），相对批 4 同口径 CPU 22.8ms **慢 3.86×** | 批 4 |
| 自动择优 | `gpu_if_faster` 按设计回退 CPU（calib.json 落档） | 批 4 |

- §6 成功标准「GPU 4K ≤20ms」在当前 kernel 设计下**不可达**（批 4 修正：
  A3 §1.1 线性外推被聚合吞吐实测推翻，≈1.7ns/sym 是二分发散+重整化访存
  的设计瓶颈）；优化路径已登记（链交错 ILP 预期 2~4× / LDS 驻留 /
  统一内存重测），属下一窗口。
- **V8 的价值主张 = GPU 解锁（6K/8K 时间线回实时）**。在 GPU 不胜 CPU 的
  机器上，切默认只付码率账、收不到性能益。

## 二、成功标准（计划 §6）结项对照

| 条款 | 判定 |
|---|---|

## 三、拍板项

### 拍板项 1：qp44 极瘦源超封顶的修正路径

批 0 §2.3 三选一，本评审建议：

- **采纳 a（现在）**：qp≥40 档接受 ≤6%（账仍成立：半档 qp ≈10% 码率的
  代价换 8K 回实时；超出仅极瘦源单点 0.2~0.8pp）。
- **缓行 b（9B 目录变体，qp44 8K → ≤4.3%）**：为 0.2~0.8pp 做格式手术
  （目录项双编码 + 编解码器双路径 + golden 重冻结），性价比不足；
  **重开条件**：8K 瘦码流素材成为真实工作流，或实测超 6%。
- c（tile_rows=64，5.33→5.14%）不推荐单用（批 0 实测收益不足）。

### 拍板项 2：生产默认何时 reserved[0]=8 → 9

**建议：现在不切，维持 V7-R2 默认；V8 保持显式 opt-in（reserved[0]=9）。**
理由：正确性面已全部达标、工具链已就绪（CLI/容器/golden/fuzz/conformance
全绿），但 GPU 解码在本机劣于 CPU 3.86×——切默认 = 纯付 +1.2~2.7% 码率、
零用户可感收益。**切换条件（满足其一即重开本评审）**：

1. kernel 优化落地后校准基准（`tools/bench_v8_gpu_decode.py`）实测
   GPU ≤ CPU（4K，目标机 dGPU）；或统一内存机器（Apple Silicon）实测
   GPU 胜——免 PCIe 上载后链路结构不同（批 4 登记项）；
2. 产品立项 6K/8K 时间线（GPU 是唯一回实时路径，性能需求压过码率账）；
3. 编辑器 GPU 产品化窗口完成（直留纹理 + ring buffer + CRC 重叠，见
   `topos_v8_editor_integration_2026-09-12.md`——无 GPU 路径的默认切换
   只剩成本）。

**切换协议（届时执行）**：编辑器编码默认翻 9 → 按内容类型灰度（先 qp≤30
胖码流，码率 Δ ≤2% 档）→ 观测 golden/码率看板 → 全量。**回滚**：默认翻
回 8 即刻生效；V8 包解码路径永久保留（加法版本机，V8 流不因回滚失效）。

### 附：拍板项 2 的一个中间态选项（供参考，不建议现在做）

"qp≤30 内容默认 V8、qp>30 维持 V7"的按档默认——技术上可信号化，但在
GPU 性能条件满足前，它仍是无收益的码率支出，且增加双版本并存的运维面。
仅当条件 2（6K/8K 立项）先行满足时值得考虑。
