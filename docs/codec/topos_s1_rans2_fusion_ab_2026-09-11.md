# S1：rans2 解码融合路径移植——A/B 负结果记录（2026-09-11）

速度计划（`topos_speed_optimization_plan_2026-09-11.md`）P1 首项 S1 的
执行与判定。**结论：位精确差分通过、系统级 A/B 噪声级（−1.1%~+3.4%
混合正负），未过 ≥+3% 晋级门，代码全量回退零入库。** 解码速度轴的
C 代码候选至此全部关闭（见 §4）。

## 1. 实现形态（最小融合）

P0 剖析预测 sink 路径占解码 47~53%（单块 dinv 43~48%）。按 M10-2B/C
实测负结果，稀疏收集与批 4 IDCT **维持禁用**，仅移植生产验证过的结构
要素到新函数 `tc_color_rans2_scan_to_plane`（装配与通用 core 共享
`tc_rans2_setup` 单一定义点，域检查零漂移）：

1. EOB 紧随 DC → 闭式常数填充（rowmask 0，免 memset/免 dinv 调用
   ——通用 core 的 rowmask 恒 ≥1 使 DC-only 块走完整内核）；
2. 带 AC 块零填+散射后单块内核直存；
3. 存储调用内联展开，消除每块 sink→reduced→store→store_xy 的
   3 层调用边界；
4. coefficient_limit 高频丢弃（discard_ac）与 color_scan.h 同构。

## 2. 验证与测量

- **位精确差分 ✅**：23 个产品包（4K/2K 444 qp70、4K 422 qp62，
  C043 定标落点）旧/新 dylib 解码平面 SHA256 逐字节一致；
- **路径激活验证 ✅**：新 dylib 采样栈 `tc_color_rans2_scan_to_plane`
  33 次出现、`tc_c1_store_sink`/`tc_color_rans2_decode_core` 0 次
  ——排除"未走到新路径"的假阴性；
- **系统级交错 A/B**（prof_decode，5 轮交错取中位，新旧同 -O2 perf
  构建，i9-9900K）：

| 单元 | 1t 旧→新 | 16t 旧→新 |
|---|---|---|
| 4K 444 pro444（qp70） | 5.7→5.7（**−1.1%**） | 43.4→43.6（+0.5%） |
| 2K 444 pro444（qp70） | 22.8→22.7（−0.7%） | 158→154（−2.9%） |
| 4K 422 hq（qp62） | 9.6→9.8（+1.7%） | 79→82（+3.4%） |

三单元混合正负、幅度在本机噪声带内（1t ±1~3%、16t ±3~15%）→
**未过门，回退**。

## 3. 机理（为何结构性收益不存在）

P0 的"sink 占 47~53%"归因中，主体是 AVX2 rowmask 内核**本体**时间
（43~48%）——该内核已按 M10-2B/C 判定为该分解的向量化上限。本次
消除的三项成本实测均 <1%：3 层小函数调用边界（编译器已较好保持
reader 状态）、256B memset（约 8~16 周期/块）、DC-only 闭式快路
（本素材命中率 ~5%，P0 实测 dinv 调用 ≈ store 块数 95%）。
**采样归因的"结构占比"不等于"可消除占比"**——与 ADR-C041/scan-opt
的微基准教训同源，本批是其结构版本。

## 4. 解码速度轴收官判定

C 代码候选已从四个独立方向关闭：

| 方向 | 结论 | 证据 |
|---|---|---|
| 符号原语（交错/重整化/LUT/寄存器驻留） | 平台 | ADR-C041 + scan_opt |
| IDCT 内核（稀疏/批 4/小 nnz 特化） | 向量化上限 | M10-2B/C + 剖析报告 ~15% 高风险 |
| 切片装配（LUT 重建/分配） | <2% 不可见 | P0 M0.3 |
| 块循环结构（sink 融合，本批） | 噪声级 | 本报告 |

**本微架构（Skylake i9-9900K）解码速度 = 现状地板**。计划中解码侧
目标（4K 444 ≥1.05×→1.2×）撤回；解码提升窗口 = Metal/GPU 轨道或
新 ISA 平台迁移（ADR-C041 §4 既定方向）。编码轴（S4/S5）不受影响，
继续执行。
