# 解码扫描循环微优化——负结果记录（2026-09-11）

战役遗留清单第 5 项「解码扫描循环微优化（~10% 上限）」的执行与判定。
**结论：两个最优候选均无系统级收益，全部回退，条目以负结果闭环。**
NT-store 试验一并给出延期判定。代码零变更入库（本报告 + 战役清单更新）。

## 1. 重剖析（当前产品默认 rans2；perf 构建；1080p 真实调色素材）

基线（prof_decode，交替 best-of）：rans2 qp63 单线程 34~38 fps /
16t 230~250 fps；qp44 单线程 14 fps / 16t 103 fps。采样分布
（`sample`，主线程 dec_slice_job 内）：

| 素材点 | rANS 符号循环（内联原语） | 融合反变换内核（AVX2） | CRC 等 |
|---|---|---|---|
| rans2 qp63 | ~45% | ~52% | ~3% |
| rans2 qp44 | ~69% | ~27% | ~4% |

（旧报告的"扫描循环 37%"是 VLC 口径；VLC/rANS 解码速度实测相当，
±3%。）单线程数字稳定（交替 A/B ±1%）；多线程在本机噪声 ±3~15%，
只作参考。

## 2. 候选一：重整化批量化（clz + bswap 单次装载）

- 设计：x < L 时所需字节数 n = ceil((clz(x)−8)/8) 与逐字节 while
  逐位等价（37 万样本暴力对照零失配；x·2^8n < 2^31 无溢出）；
  一次 4 字节装载 + bswap 右移拼装（**字节序陷阱**：逐字节循环使
  先消费字节居高位，初版按低位拼装——被 test_rans_slice 差分当场
  击毙，差分装甲有效性的活例）。
- 结果：单线程交替 A/B **0%**（±1%）；多线程淹没于噪声。
- 判定：保留成本（新增快路径分支 + 可移植回退）无对应收益，**回退**。

## 3. 候选二：融合 LUT（u32 打包 {f, g=slot−cum, sym}）

- 设计：现行 u8 sym-LUT + 模型 freq/cum 是两级依赖装载
  （LUT→sym→freq/cum，各 4~5 周期 load-to-use）——融合为单次 u32
  装载（f<<18|g<<6|sym，31b）；表 4KB→16KB/模型。
- 微基准（4M 符号连续流，单模型常驻 L1）：**+23% 原语吞吐**
  （5.74→4.67 ns/sym），符号一致性断言通过。
- 系统级 A/B（交替 3 轮取中位）：**全线变慢**——
  rans2 qp44 单线程 −1.4~−2.7%、8t −3.8%、16t −5.9%；qp63 −0.4~−6.1%
  （vlc 对照 +0.4~+3.0% ≈ 噪声）。**回退**。
- 机制（为何微基准收益被反噬）：真实解码器逐符号混用 3~11 个模型
  （rans2 上下文行），16KB×11 = 176KB LUT 足迹压 L2，且每 slice 重建
  写放大 4×；乱序引擎中两级装载与散写/上下文选择等其他 µops 重叠，
  原语装载链并非整个循环体的关键路径——微基准的连续单模型流恰好
  把它变成了关键路径。**教训：rANS 原语优化必须在多模型切换的工作
  集尺度上评估，微基准会系统性高估。**

## 4. NT-store 试验：延期判定

- 依据：16t 天花板是内存带宽（旧报告 7.3×，融合内核 16t 膨胀 1.9×）；
  NT-store 收益预期 5~10% 且仅限 8K 16t 带宽受限场景。
- 延期理由：(a) 本机 16t 测量噪声 ±3~15%，高于预期收益的一半，诚实
  判定不可行；(b) 正确实现需按块行批量流写（per-block 散点 16B NT
  store 无法利用 WC 合并），存储路径重构成本高；(c) 产品全部配置
  已 ≥2× 实时（8K HQ 50fps/16t），无产品痛点。待出现 8K 多路解码
  需求或安静测量环境再启。

## 5. 战役条目闭环

「解码扫描循环微优化（~10% 上限）」的两个最优候选实测为零/负收益，
~10% 上限估计过于乐观（源自采样归因对内联原语的高估）。解码速度
维持现状；与 ProRes 的残余差距（算法密度差）维持「内核重写级长期
议题、当前无产品痛点」的既有判定。

## 6. 复现

```bash
cd native/topos_codec && cmake --build build/perf -j8 --target topos_codec
cc -O2 -Iinclude -Isrc tools/prof_decode.c -o /tmp/dec/prof_decode \
   build/perf/topos_codec.dylib -rpath "$PWD/build/perf"
# 素材：binding 编码 /tmp/dec/{rans2,vlc}_qp{44,63}.tpc（flat, 1080p）
TOPOS_SLICE_THREADS={1|8|16} /tmp/dec/prof_decode <f.tpc> <iters>
# 交替 A/B：新旧 dylib 各拷一份目录，prof_decode -rpath 指向各自目录
```
