# C4 落档：4K 444 解码 16t 扩展性调查（2026-09-12）

速度计划 v2 C 轴 C4 项（0.5 批调查）。**核心结论：记录在案的
"4K 444 解码 16t = 3.8~4.1× 扩展"主要是测量口径伪影——矩阵工具
经无状态 `ToposCodec.decode()` 计时，每帧支付 47.7MB（4K444）ctypes
数组零填 + 47.7MB bytes 拷贝的串行开销，把 native ~22ms 的 16t 解码
拖到 ~45ms。直测 native 扩展性为 8.5×（1t 与矩阵逐值吻合）；
C4 的"3.8→≥5×"目标经口径修正即已达成，无需 native 改动。**

## 证据链（合成 4K 444 10bit pro444，bpp 4.29 ≈ 矩阵实拍 4.30）

线程扩展性扫描（C harness，预分配平面直调 `tc_frame_decode`）：

| 线程 | ms/帧 | 加速比 |
|---|---|---|
| 1 | 185.0 | 1.00×（矩阵 decode_1t p50 = 182.8ms ✓ 吻合） |
| 2 | 94.5 | 1.96× |
| 4 | 47.6 | 3.89× |
| 8 | 28.1 | 6.58× |
| 12 | 23.5 | 7.87× |
| 16 | 21.8 | **8.47×** |

同机三口径（16t）：A 无状态 `decode()`（矩阵口径）45.1ms ≈ 矩阵
decode_mt p50 44.2ms ✓；B `ToposDecoder`+views（产品热路径）23.4ms；
C 直调 22.0ms。A−C ≈ 23ms/帧 = 绑定侧串行开销（零填 + 双拷）。

## 归因补全

- 尾部失衡（结构性上限）：4K 444 slice_rows=16 → 51 slices / 16 线程
  = 3.19 波 → 尾部 ≤1 slice ≈ 6% 浪费——非主要限制；
- 内容归因（合成 4bpp，`sample` 16t）：rANS2 解码核 ~70% / 反量化+IDCT
  sink ~30%——熵主导区扩展性好；计划中"worker 86% 忙"的实拍口径
  （sink 47~53%）在绑定开销掩盖下测得，其带宽墙结论待真实素材在
  修正口径下复测；
- 单流地板与 µarch 结论不受影响（1t 逐值一致）。

## 连带修复（绑定层，同 C3 语义）

`ToposCodec.decode()` 输出平面改为 **per-thread grow-only scratch、
各平面连续平铺**（`from_buffer` 偏移切片，无重叠；TLS 保持 decode()
多线程并发契约——stage10 四线程并发解码测试钉死）：

- 无状态路径 45.1 → 28.3ms/帧（剩余 ~6ms 为 API 契约的返回 bytes
  自有拷贝，不可免；高频路径仍建议 ToposDecoder+views 的 23.4ms）；
- 矩阵工具未来复测将以修正后的无状态口径运行（数字会整体改善，
  与旧 JSON 不可直接并列——已在报告标注）。

## 验收

- tests/native 46/46（含四线程并发 decode、RSS 浸泡新口径）；
- tests/media（source/alpha/export/image_source）171/171——解码平面
  平铺正确性（逐像素 roundtrip）由这些测试覆盖；
- 扩展性扫描脚本口径见本文表格。

## 防重开

- "4K 444 16t 3.8×" 不再作为 native 扩展性论据引用（口径伪影，
  本报告三口径对照钉死）；
- 无状态 decode 的每帧平面零填（2026-09-12 修复前形态）不再回退。
