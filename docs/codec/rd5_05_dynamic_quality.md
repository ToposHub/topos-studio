# RD5-05：动态质量策略

## 已落地

- 播放和 scrub 统一使用有界 `AUTO_2K` 目标；12K/16K 时间线不会因为交互状态切换而提交完整源尺寸解码。
- 暂停后使用 200 ms 延迟定时器提交一次 `FULL` 当前帧请求，满足 150–250 ms 的计划窗口；FULL 结果异步完成后替换当前预览。
- 每次质量切换都会递增 renderer generation、清理未开始的 worker 队列和旧缓存。旧 generation 的完成信号在 worker 与 renderer 两侧都被丢弃，因此播放恢复后不会被迟到的 FULL 帧回闪覆盖。
- 普通交互任务在入队时捕获目标尺寸；后台播放预缓冲始终使用 AUTO_2K，避免暂停后的 FULL 刷新顺带放大预取内存。
- worker 继续采用 latest-only 队列合并；队列最大长度为 2，新请求会淘汰尚未开始的旧请求，防止长时间播放或快速拖动造成无限积压。

## 语义边界

`FULL` 指时间线的实际几何，不等于默认播放质量。用户显式设置预览比例时，该设置优先于自动暂停 FULL 切换。解码器是否能够以任意几何直接产出平面，仍由 Topos native request/context 能力决定；不支持时保留既有 fallback 和诊断。
