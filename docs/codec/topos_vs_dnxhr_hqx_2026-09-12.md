# Topos 422 10-bit vs DNxHR HQX——同规格编解码速度对照（2026-09-12）

**问题**：Topos 同规格（422 10-bit 母版档）的编解码速度能超过 DNxHR HQX 吗？

**结论**：

- **编码：能，全档位两种口径都超过**。最接近档（Topos hq，档位设计
  对标 ProRes HQ，码率 0.73×）：2K **1.95×**（边际）/4.6×（墙钟），
  4K **1.26×**（边际）/3.5×（墙钟）。4K 下 HQX 60 帧墙钟编码本身
  **低于实时**（0.67×），Topos hq 仍有 2.37× 实时。
- **解码：分口径**。短片墙钟口径 Topos 全档胜（hq 1.09×~1.24×，
  低档至 3.6×）；长片边际口径 **HQX 反超**——除 proxy 档持平
  （2K 1.09× / 4K 1.00×）外，HQX 边际解码（2K 754fps / 4K 221fps）
  比 Topos 快 1.4~2.7×。这与 C5 判定（Topos 解码 rANS 内核占比
  66~68%）互相印证：解码熵层是当前短板，正是 A2 GPU 化/C5 的靶子。

---

## 一、口径

- 机器：i9-9900K（8C/16T）+ RX 6900 XT；源 = 真实素材
  （`tests/test_videos` 派生，同 ``topos_real_footage_matrix_2026-09-12``
  的 60 帧 raw yuv422p10le，25p，ffmpeg 默认线程）。
- **Topos**：`bench_tier_speed.py` 产品档率控，纯 encode/decode 调用
  计时（不含 IO/启动）→ 天然是**边际**口径；数据 = 已提交的
  `tierspeed_real2k_422_2026-09-12.json` / `tierspeed_real4k_422_2026-09-12.json`。
- **DNxHR HQX**：`bench_dnxhr_hqx.py`，ffmpeg 同源 raw →
  `-c:v dnxhd -profile:v dnxhr_hqx`，3 次取中位数，双口径：
  - **wall**：60 帧单次墙钟（= 既有 prores_ref 口径；含进程启动
    ~0.2-0.6s 与 raw demux，短片体感）；
  - **marginal**：60 帧 vs 300 帧斜率（编码 300 帧 = `-stream_loop 4`
    循环同源；解码 300 帧 = concat 5×60 帧 mov）——扣固定开销的
    长片口径，对 ffmpeg 更公平。
  - HQX 码率由 profile+分辨率固定（1080p25 = 183.5 Mbps、
    UHD-25p = 728.3 Mbps，CBR 式）。斜率含 raw demux 读（页缓存热），
    为 ffmpeg 侧残余不利项。
- 质量 RD 未测（沿用档位设计对标声明，未新增证据）；HQX 码率与
  ProRes HQ 参照（192.9/656.7 Mbps）同量级。

## 四、要点

1. **编码全档胜出（两种口径）**：HQX 为固定码率 CBR 式档，Topos 全部
   档位编码更快——最低限的 hq 档也有 1.26×（4K 边际）~1.95×（2K
   边际），且是在 0.73× 码率下达成。4K 墙钟下 HQX 低于实时
   （16.7fps < 25fps），Topos hq 仍 2.37× 实时。4K 边际两次斜率法
   （20↔60 帧、60↔300 帧）区间 1.06×~1.26×，run-to-run ±10% 内。
2. **解码：HQX 长片更快，Topos 短片墙钟更快**。HQX 边际解码 2K
   754fps（30× 实时）/4K 221fps（8.9×）——CBR 固定 VLC 码表 + 简单
   逆变换 + ffmpeg 重线程的熵层红利。Topos 除 proxy 档持平外边际
   0.37×~0.72×。这与 C5 真实素材判定（r2e 内核占解码 66~68%）同向：
   解码是 Topos 当前相对短板，A2 解码 GPU 化（预计 ~2×）与 C5 小 nnz
   内核特化正是针对这里。
3. **码率口径**：HQX 固定 2K 183.5 / 4K 728.3 Mbps；Topos hq 为
   133.2 / 531.8 Mbps（0.73×），档位设计对标 ProRes HQ。
4. ffmpeg 边际含 raw demux（页缓存热，残余不利）；Topos 计时不含源
   读取——两口径均已在 §一 声明。
