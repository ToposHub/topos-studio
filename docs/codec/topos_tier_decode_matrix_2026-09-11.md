# Topos 产品档位解码速率矩阵（2K/4K × 六档，2026-09-11）

与编码矩阵（`topos_tier_speed_matrix_2026-09-11.md`）同源同格的真实素材
解码测量：产品码控路径出包（首帧 sized + 反馈单遍、rans2、flat、444 含
ADR-C042 定标），逐帧 `tc_frame_decode` 计时（真实输出平面），
p50/p95（每格 5 轮 × 60 帧 = 300 样本），1t 与满配 16t 两档
（`tc_dev_set_thread_count`）。参照：ffmpeg prores_ks 同档 mov 解码
（`-f null`，默认/`-threads 1`，两次取优）。

- 机器：i9-9900K（8C16T）；源同编码矩阵（真实素材解码 raw 60 帧）；
- 与旧表 `topos_tier_decode_matrix_2026-09-10.md` 的口径差异：旧表为
  合成素材 + V2 熵 + P4 定标 + 422 四档；本表为真实素材 + rans2 +
  C042 定标 + 六档（含 444 家族首次入表）。数字不可跨表直读；
- harness：`native/topos_codec/tools/bench_tier_decode.py`；证据 JSON：
  `tools/tierdec_*_2026-09-11.json`（六份）。

## 观察

1. **2K 全档 ≥3.2× 实时**（满配）；4K 422 家族 1.5~2.0×；**4K 444
   家族 0.8~0.9× 实时（21~22 fps）——低于 25p 回放**，且 extreme p95
   尾部 11 fps。这是 444 家族首次入解码矩阵（旧表仅 422 四档）+
   C042 重定标把码率抬到 ProRes 4444/XQ 同档后的真实负载；
2. 战役旧口径"解码：全部产品配置 ≥2× 实时（4K 77~278）"系合成素材 +
   V2 熵 + P4 定标 + 无 444 档的测量，**在本矩阵口径下不成立**
   （4K hq 1.5×、4K 444 0.8~0.9×）——解码轴结论与 ADR-C041 一致：
   符号环在本微架构已达实用平台，444 的 1.5× 样本量直接兑现为速度；
3. vs ffmpeg prores 解码 0.5~1.0×：ffmpeg 的 SIMD VLC 解码器在纯解码
   吞吐上领先，Topos 的速度赢面在编码侧（2.7~8.0×，见编码矩阵）。
   解码侧的可动杠杆 = SIMD IDCT（~15%，位精确风险高，ADR-C041 定性
   不启动）与 metal 后端迁移（并行轨道）；
4. 1t 行为符合池调度预期（满配的 ~1/4~1/2）：后台缓存/导出场景
   `set_slice_threads(1)` 可避免与前台争抢，代价按上表折算；
5. 码率与编码矩阵逐格一致（同 sized+反馈路径），解码计时不含源 IO
   与显示路径。

---

**ADR-C043 加注（2026-09-11 晚）**：C043 目标码率下调后复测结论——
解码速率与码率基本无关（14 格两点实测 −12%~+18% 噪声级；逐块
IDCT/写回为固定成本），本表数值在新定标下仍然成立；4K 444 低于
实时的结论与杠杆（SIMD IDCT / metal 后端）不变。详见 ADR-C043。
