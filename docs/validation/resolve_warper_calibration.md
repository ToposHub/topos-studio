# Resolve 色彩扭曲器校准

## Color 页实时拖动与分布背景复测（2026-11-25）

在真实 Topos 主窗口中打开 1280×720 的暂停视频，连续在同一个 Corrector 依次调色相–饱和度、色度–亮度和 Chroma Warp。直接从发布到 Color 查看器的 GPU 纹理读取画面，同时记录按住、松手和稳定后的色彩分布。修复前，色相–饱和度设置先写入节点后，新增第二种模式会超过通用图参数的递归上限。色度–亮度的拖动期间和松手后均未改变已发布的像素。

图节点现在允许 Warper 保留三种模式的结构化状态。拖动提交到合并渲染队列，已计算的色彩分布持续显示到同源新样本返回。图像或帧的身份变更会丢弃旧样本。全画面示波器运行与查看器内的 Warper 取样分开。

| 同一节点的拖动 | 按住时，受影响像素占比（至少 3 个 8 位码值） | 松手稳定后相对按住的最大差 |
| --- | ---: | ---: |
| 色相–饱和度，红色辐射线 | 6.75% | 0 |
| 色度–亮度，Grid 1 中间点 | 17.20% | 0 |
| Chroma Warp，普通笔画 | 6.20% | 0 |

三次拖动各发送 12 个鼠标移动事件，每次记录到 15 次渲染或纹理任务提交，包含一次结束后的纹理同步。修复前仅第一种模式的同手势就记录到 41 次提交。上述采样期间三个面板的色彩分布持续可见。带并行分支的节点也复跑了三种模式。120 毫秒间隔开始下一笔时，第二笔按住 620 毫秒仍持续预览，Esc 撤掉该笔草稿，撤销和重做恢复前两次提交。

首次生成响应仍有开销，色度–亮度的第一帧变化在本次冷启动中于约 0.6 秒处读到。响应纹理尺寸与交付算法沿用原值。原始记录和复跑脚本在本机 `/tmp/topos-warper-live.6aDKtV`。

## 网格联动与选区交互复测（2026-11-25）

在 Resolve Studio 20.2.1.6 的隔离工程操作三种面板。测试环境为 macOS 15.3.1、AMD Radeon RX 6800。交互按绘图区归一化，色彩测试采用 DaVinci YRGB、Rec.709 Gamma 2.4、Full 电平和同一张 1920×1080 图卡。两端中性 TIFF 逐码一致。

| 操作 | 实测行为与 Topos 实现 |
| --- | --- |
| 色相–饱和度拖拽 | 最外圈点拖动时，同一辐射线向中心依次变形。内点在相邻锁点间变形，左右相邻辐射线保持原位。以 156 像素半径横移 24 像素为例，五个内环横向偏移依次约为 4、8、12、16、20 像素。 |
| 中心白点 | 屏幕位移带动所有辐射线，外圈保持原位。白点也支持亮度编辑。白点位置与亮度参与保存、撤销和交付。 |
| 色度–亮度两张网格 | 分别测试四角、边缘中点和网格内部。控制点从已变形位置开始拖动，未锁定点插值跟随。另一张网格保留自己的控制点。 |
| 网格辅助工具 | 对照单点、框选、画选、相邻点扩选／缩选、锁点、拉点、推点和单点复位。HS 最外圈扩选包含沿辐射线向里的一点和外圈左右两点。HS 推拉从单击开始，CL 推拉作用于点击所在的网格单元。范围条可新建、调整端点和整体移动所选区间。 |
| Chroma Warp | 普通笔画沿源到目标显示范围，点对点围绕源点，固定点显示自己的圈。389 像素宽的图中，笔画范围设为 0.020、0.040、0.080 时，半径约 22、41、78 像素，固定点 0.040 的半径约 16 像素。两种笔画单击均创建独立的曝光点，固定点只开放色度范围。 |
| 查看器与手势 | 暂停时悬停显示取色位置，按住 Option 点击网格点隔离它影响的颜色。使用真实 Topos Canvas 验证了红色色块保留、绿色色块遮黑，松手取消覆层。视图关闭、切换节点和回拖到原位的测试覆盖了预览与历史收尾。 |

Topos 使用时间线 OpenGL 导出与生产预览入口复测。误差按 4,096 个独立色块统计，单位为 10 位 RGB 码值。原图列表示未调色图卡到 Resolve 的 RMSE。白点留出方向未进入拟合。

| 用例 | 原图 RMSE | Topos RMSE | Topos P95 / 最大差 |
| --- | ---: | ---: | ---: |
| HS 红色外圈，拖动约 24 / −16 像素 | 34.45 | 19.98 | 75.74 / 269.02 |
| HS 红色第三环，同位移 | 24.23 | 3.40 | 13.00 / 44.13 |
| HS 红色外圈，Hue 0.04 / Sat 1.20，第三环锁定 | 33.98 | 15.46 | 60.36 / 221.16 |
| HS 白点，留出方向约 19 / 4 像素 | 36.58 | 10.01 | 38.21 / 113.72 |
| HS 白点亮度 0.60 | 21.46 | 9.69 | 23.64 / 37.04 |
| CL Grid 1 右边缘中点上移 | 16.07 | 2.07 | 6.62 / 13.69 |
| CL Grid 1 中心斜拖 | 49.58 | 20.31 | 61.47 / 223.83 |
| CL Grid 2 中心斜拖 | 81.59 | 23.63 | 79.54 / 198.23 |
| CW 普通笔画，短距离 | 12.88 | 6.10 | 20.45 / 99.09 |
| CW 普通笔画，较长距离 | 26.40 | 9.06 | 27.40 / 108.30 |
| CW 点对点，较长距离 | 23.96 | 11.62 | 39.91 / 155.66 |
| CW 普通单击点，曝光 +0.50 | 10.68 | 6.99 | 6.08 / 136.59 |
| CW 点对点单击点，曝光 +0.50 | 9.06 | 3.74 | 4.78 / 60.21 |

Topos 的预览与最终 TIFF 在这些用例中的最大差小于 0.008 个 10 位码值。HS 外圈、CL 两轴同时调整和部分高饱和颜色仍有可见的跨软件差异。网格锁点的复杂组合、其他色彩空间、高密度网格、HDR 及完整影调组合尚未完成跨软件验收。Option 使用当前节点输入的低分辨率采样，颜色边缘精度随取样分辨率变化。

同设定的 HS 第三环锁点改变了 Resolve 的影响边界。Topos 未应用锁点响应时，相对同一 Resolve 锁点 TIFF 的 RMSE 为 15.58，当前锁点响应为 15.46。局部锁定的边界仍是近似。两种 CW 单击曝光在 Resolve 导出中也有差异，Topos 当前共用单击点的曝光权重。

屏幕截图、采集与复测脚本、原始 TIFF、Topos 交付及 `production-metrics.json` 位于本机 `/tmp/topos-resolve-warper.xMnAsE`。Resolve 操作完成后已回到原工程。白点校准可用 `python -m tools.resolve_warper_calibration <captures> <output.npz> --white-point` 复现。 [Blackmagic Design 调色师指南](https://documents.blackmagicdesign.com/UserManuals/DaVinci-Resolve-20-Colorist-Guide.pdf)

## 三种模式实测（2026-11-25）

Resolve Studio 20.2.1.6 使用 DaVinci YRGB、Rec.709 Gamma 2.4、Full 电平。输出为同一张 1920×1080 图卡的 16 位 RGB TIFF。两端中性帧逐码一致。每项取 4,096 个独立色块，额外对拍 1,024 点灰阶。表内误差是 10 位 RGB 码值。色相–饱和度的基准是 Topos v2，其他两种模式的基准是未调色的图卡。

| 留出操作 | 基准 RMSE | 新 RMSE | 新 P95 / 最大差 |
| --- | ---: | ---: | ---: |
| 色相–饱和度，蓝色第五环 Hue 0.303333 / Sat 0.83 | 15.40 | 9.25 | 29.73 / 147.34 |
| 色相–饱和度，绿色第二环 Hue 0.626 / Sat 0.48 | 18.44 | 4.06 | 8.74 / 81.47 |
| 色相–饱和度，蓝色第五环反向加饱和度 | 39.90 | 16.36 | 59.82 / 152.68 |
| 色相–饱和度，绿色第二环较小调整 | 12.43 | 2.99 | 8.78 / 60.46 |
| 色度–亮度，Grid 1 色度与亮度 | 29.39 | 12.67 | 44.05 / 156.86 |
| 色度–亮度，Grid 1 与轴角 30° | 37.06 | 14.05 | 51.01 / 147.11 |
| 色度–亮度，Grid 1 和 Grid 2 混合 | 55.18 | 18.58 | 61.04 / 200.20 |
| 色度扭曲，点到点笔画 | 23.96 | 11.91 | 41.67 / 157.40 |

八组蓝色外环和绿色内环的单轴 TIFF 用于构建 HSP v3。加入实测响应后，这些设置的独立色块误差为 0.32–1.30。新视频节点在 Rec.709 Gamma 2.4 HSP 下使用 v3，已有 v1/v2 节点按保存版本工作。旧版网格可从面板菜单显式升级，保留点位和锁点。用已有工具生成新数据时加 `--refined`。[校准工具](../../tools/resolve_warper_calibration.py) · [留出回归数据](../../tests/color/fixtures/resolve_warper_rec709_g24_v3.npz)

色度–亮度采用两个有符号的色度轴，中心横移可以给灰阶着色。Grid 1 中心上移 0.10 的独立色块 RMSE 从 25.16 降至 3.40。普通色度扭曲笔画的红、蓝、绿三个设置从 11.95、20.14、29.13 降至 2.78、3.60、5.08。它们用于估计投影和响应，色块数据独立留出。默认曝光保留实测的线性亮度权重。

实机确认两张网格工具可以叠加，两者与色度扭曲分开启用。Topos 在节点中保存三套控制及当前启用模式。两套网格及笔画由预览和交付共享计算结果。相同节点的时间线预览和 16 位 TIFF 最大差为 0.008 个 10 位码值。拖拽采纳松手位置，连续手势使用一次历史记录。查看器的密度和取色在暂停时从所选节点输入的低分辨率纹理采样。

该次校准适用于上述 SDR 条件，最大差集中在部分高饱和色块。网格联动、色相中心白点与 Option 预览的后续实测见本页首节。 [色度留出回归数据](../../tests/color/fixtures/resolve_chroma_rec709_g24.npz) · [Blackmagic Design 调色师指南](https://documents.blackmagicdesign.com/UserManuals/DaVinci-Resolve-20-Colorist-Guide.pdf)

## 色相–饱和度算法 v2 历史记录

v2 发布时，Rec.709 Gamma 2.4 视频时间线的空白色相–饱和度网格显示 HSP，首次有效编辑使用 v2。v1 网格仍可在色彩扭曲器的 **⋯ → 将色相–饱和度算法升级到 v2** 主动升级，操作保留网格位移和锁定点，可撤销。

v2 从相同的 full-range Rec.709 Gamma 2.4 图卡中测量不同色相、饱和度和亮度的响应。渲染线程将节点网格编成连续的三维颜色响应。组合 Hue 和 Sat 时，切向移动随目标饱和度变化。其他点使用保亮度的参数模型，第一环的影响向外更快衰减。CPU、OpenGL、Metal 预览和导出使用相同的响应纹理。

Resolve Studio 20.2.1.6 的七组单项调整用于生成响应。以下设置整组留出。每组均以 4,096 个独立 RGB 色块比较，数值是 10 位 RGB 码值的均方根误差。

| 留出的设置 | v1 RMSE | v2 RMSE | 比 v1 降低 |
| --- | ---: | ---: | ---: |
| 青色第三环，Hue 0.43 + Sat 0.44 | 13.35 | 1.38 | 89.7% |
| 红色第三环，Hue 0.04 | 7.33 | 3.33 | 54.5% |
| 蓝色第五环，Hue 0.303 + Sat 0.83 | 21.62 | 15.45 | 28.6% |
| 绿色第二环，Hue 0.626 + Sat 0.48 | 19.40 | 18.44 | 4.9% |

七组单项调整的独立色块误差为 0.05–0.96 个码值。最内环的洋红色相误差从 2.25 降至 0.05，红色反向色相从 35.97 降至 0.96。蓝色外环和绿色内环仍主要使用参数模型。高密度网格、大范围多点联动、锁点影响和 HDR 工作空间尚未跨软件实测。

在 AMD Radeon RX 6800 上，四组色卡的 OpenGL 与 CPU、Metal 与 CPU 的 RMSE 分别低于 0.007 和 0.067 个 10 位码值。使用已缓存的 12×12 响应纹理时，单节点 4K OpenGL 图渲染约为 9.7 ms。高密度网格的多点拖拽需要重建纹理，延迟高于单点拖拽。

从 Resolve 捕获中重新生成响应可运行 `python -m tools.resolve_warper_calibration <captures> <response.npz> --validation <validation.npz>`。[生成工具](../../tools/resolve_warper_calibration.py) · [独立色块回归](../../tests/color/test_warper_response.py)

## 色相–饱和度算法 v1

以下是历史 v1 算法的实测记录。HSP 网格的拖拽支持实时预览，松手保存一次修改，Esc 取消本次拖拽。Hue 和 Sat 显示顶点的目标坐标，正向 Hue 从红走向品红。Luma 的中性值为 0.50，默认 6 环网格第三环的 Sat 显示为 0.58。

渲染在 Rec.709 的线性 RGB 上使用从 Gamma 2.4 样本拟合的径向和色相响应。网格允许独立设定两个轴的分辨率。环方向的预滤波在网格变化时更新，像素采样跨红色接缝连续。工程保存网格位移与算法版本。OpenGL、Metal、CPU 图执行和点态 LUT 烘焙都从同一网格重建响应。

### 测量

Resolve Studio 20.2.1.6 使用 DaVinci YRGB、Rec.709 Gamma 2.4、Full 电平。复用一级调色的 RGB 图卡，渲染 16 位 RGB TIFF，直接读取色块码值。拟合使用 `33³` RGB 网格中的子集。验证使用 4,096 个独立的 RGB 色块，另有 1,024 个灰阶检查中性色。配套脚本生成和读取图卡，比较无需查看器截图或 ICC。 [图卡工具](../../tools/resolve_primary_calibration.py)

| Resolve 设置 | Topos 相对未调色输入的 RGB RMSE 降幅 | 绝对 RMSE（10 位码值） |
| --- | ---: | ---: |
| 红色第三环，Sat 0.74 | 77.6% | 5.76 |
| 红色第三环，Hue 输入 0.075 | 63.7% | 10.31 |
| 红色第三环，Luma 0.63 | 84.9% | 1.84 |
| 青色第三环，Hue 0.43、Sat 0.44 | 69.4% | 13.35 |

采用相同设置比较独立色块。降幅指误差相对「用原始图卡作为输出」的改善。四组操作设置均参与拟合。更高密度网格、跨点叠加、极端调整以及 HDR 工作空间的跨软件误差仍待测量。

本机 OpenGL 与 CPU 的误差低于 0.001 个 10 位码值，Metal 与 CPU 的误差低于 0.064 个。四个样本中，OpenGL 与 Resolve 的灰阶最大差值约 0.25 个 10 位码值。

锁点约束画布顶点，临近编辑的渲染影响仍随插值连续衰减。自动锁定的色域响应、取色分布、Chroma–Luma 和 Chroma Warp 未纳入本轮实测校准。 [Blackmagic Design 调色师指南](https://documents.blackmagicdesign.com/UserManuals/DaVinci-Resolve-20-Colorist-Guide.pdf)
